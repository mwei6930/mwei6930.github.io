NLP 建模

NLP 建模是设计一个把语言输入映射为有用输出的函数的过程。输入可以是句子、文档、句子对或提示词，输出可以是一个标签、一串标签、生成序列、分数，或下一个 token 的概率分布。

关键在于，模型并不是简单放在预处理之后的黑箱，它决定系统能够使用哪类语言证据。线性模型主要观察带权特征；RNN 通过循环记忆读取序列；Transformer 允许 token 直接与其他 token 比较。因此，选择模型的同时，也是在选择系统表示上下文的方式。

Raw Text -> Tokenisation -> Representation -> Model -> Prediction / Generation

学习 NLP 模型时，一个实用方法不是先记忆模型名称，而是先提出以下问题：

  • 输入是什么？
  • 输出是什么？
  • 模型尝试估计什么概率？
  • 模型架构能够使用多大范围的上下文？
  • 最终输出如何解码？

NLP 中的建模意味着什么？

在 NLP 中，模型是一个对语言结构进行评分或预测的参数化函数。“参数化”表示模型包含可以学习的数值，例如线性分类器中的权重，或 Transformer 内部的矩阵。训练过程会改变这些参数，使正确输出获得高于错误输出的分数。

可以这样理解：表示方法为模型提供原材料，而模型决定如何组合这些材料。如果表示中包含词频，模型会学习哪些词重要；如果表示中包含 token 嵌入，模型会学习这些 token 的意义如何相互作用。

对于分类任务，模型可能估计：

\[ P(y \mid x) \]

其中 \(x\) 是输入文本，\(y\) 是输出标签。

对于生成任务，模型可能估计：

\[ P(y_1, y_2, ..., y_T \mid x) \]

其中输出是一个 token 序列。

一个模型通常包含三个概念组成部分：

组成部分 作用 示例
输入表示 把文本转换为向量 BoW、TF-IDF、嵌入、上下文嵌入
上下文建模架构 跨 token 组合信息 线性模型、CNN、RNN、Transformer
预测头 把隐藏表示转换为输出 分类头、token 分类器、LM head

通过更换预测头，同一种架构可以用于不同任务。例如，一个 Transformer 编码器可以用于情感分类、token 分类、检索或跨度抽取。

Representation answers: what does each token/document look like numerically?
Architecture answers: how does information move between tokens?
Prediction head answers: what kind of output do we want?

NLP 中的输入－输出形式

选择模型架构前，必须先定义任务的输入－输出结构。许多 NLP 任务可以按照输入和输出的形状分类。这个步骤看似简单，却非常重要：如果输出只有一个标签，分类器就足够；如果每个 token 都需要一个标签，模型就必须保留 token 级表示；如果输出是一条新句子，模型还需要解码过程。

红色块表示输入，绿色块表示模型状态，蓝色块表示输出。原图使用循环单元绘制，但其输入－输出拓扑同样适用于 CNN 和 Transformer：架构决定如何建模上下文，任务形式决定需要什么形状的预测。

序列到标签建模

序列到标签建模把完整输入序列映射为单个输出标签。其核心难点是压缩：模型必须把可变长度文本转换为一个固定大小的决策信号。无论评论很短还是很长，最终都必须形成一个预测。

Input:  "This movie was surprisingly good"
Output: Positive

模型需要把整个序列压缩成一个表示，可以采用以下方式：

  • 对词嵌入求平均
  • 使用 RNN 的最终隐藏状态
  • 使用 BERT 类模型的 [CLS] 表示
  • 对 Transformer 的 token 表示进行池化

常见任务：

任务 输入 标签
情感分类 评论文本 positive／negative
垃圾邮件检测 邮件文本 spam／not spam
主题分类 新闻文章 politics／sport／finance
意图检测 用户话语 book_flight／cancel_order

一种典型的概率形式是：

\[ \hat{y} = \arg\max_y P(y \mid x) \]

Python：使用 TF-IDF＋逻辑回归实现序列到标签 
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import Pipeline

texts = [
    "the movie was excellent",
    "great story and acting",
    "the film was boring",
    "terrible pacing and weak plot"
]
labels = [1, 1, 0, 0]

model = Pipeline([
    ("tfidf", TfidfVectorizer()),
    ("clf", LogisticRegression())
])

model.fit(texts, labels)
print(model.predict(["excellent acting"]))

序列到标签序列建模

序列到标签序列建模为每个输入 token 预测一个标签。与文档分类不同，模型不能只构建一个句子级向量；它必须保留每个 token 位置的信息，因为每个 token 都需要自己的预测。

Input:  John   works  at  Google
Output: B-PER  O      O   B-ORG

这种形式也称为序列标注或 token 分类。

常见任务：

任务 输出标签含义
POS 标注 每个 token 的语法类别
命名实体识别 实体跨度与类型
组块分析 短语边界
槽位填充 用户话语中的语义槽位

对于输入序列 \(x_1, ..., x_n\)，模型预测：

\[ y_1, ..., y_n \]

通常，输入与输出长度相同。

序列标注示意图：

Python：Token 分类输出形状 
import torch
import torch.nn as nn

batch_size = 2
seq_len = 5
hidden_dim = 16
num_tags = 4

hidden_states = torch.randn(batch_size, seq_len, hidden_dim)
classifier = nn.Linear(hidden_dim, num_tags)

logits = classifier(hidden_states)
print(logits.shape)  # [batch_size, seq_len, num_tags]

序列到序列建模

序列到序列建模把一个输入序列映射为另一个输出序列，输出长度可以与输入长度不同。这种任务比分类更困难，因为模型必须同时决定内容和顺序。例如，翻译系统需要先理解源句，再使用可能不同的词序生成流畅的目标句。

Input:  I love natural language processing
Output: J'aime le traitement du langage naturel

典型任务：

任务 输入 输出
机器翻译 源语言句子 目标语言句子
摘要 长文档 短摘要
问答 问题＋段落 答案文本
Text-to-SQL 用户问题 SQL 查询

模型估计：

\[ P(y_1, ..., y_m \mid x_1, ..., x_n) \]

通常会自回归地分解为：

\[ P(y \mid x) = \prod_{t=1}^{m} P(y_t \mid y_{<t}, x) \]

语言建模

语言建模根据先前 token 预测下一个 token。这个任务看似简单，却能提供非常丰富的学习信号：文本中的每个位置都可以成为一个训练样本。通过学习预测后续内容，模型也会学习语法、常见事实、篇章模式和许多语言表层规律。

Input:  Natural language processing is
Output: [fun, difficult, useful, ...]

语言模型估计一个 token 序列的概率：

\[ P(w_1, w_2, ..., w_n) \]

根据链式法则：

\[ P(w_1, ..., w_n) = \prod_{i=1}^{n} P(w_i \mid w_1, ..., w_{i-1}) \]

在现代仅解码器 Transformer 中，这对应于下一个 token 预测：

\[ P(w_i \mid w_{<i}) \]

语言模型可用于：

  • 文本生成
  • 自动补全
  • 聊天机器人
  • 代码生成
  • 评估句子似然
  • 大型神经模型预训练
使用 transformers 进行下一个 Token 预测 
from transformers import AutoTokenizer, AutoModelForCausalLM
import torch

model_name = "gpt2"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name)

prompt = "Natural language processing is"
inputs = tokenizer(prompt, return_tensors="pt")

with torch.no_grad():
    outputs = model(**inputs)

next_token_logits = outputs.logits[0, -1]
next_token_id = next_token_logits.argmax().item()

print(tokenizer.decode([next_token_id]))

成对与匹配建模

成对建模接收两段文本，预测二者之间的关系或相似度分数。这种形式常见于搜索和推理任务，因为目标意义取决于两段文本之间的关系，而不是某一段文本本身。

Text A: A dog is running in the park.
Text B: An animal is moving outdoors.
Output: entailment / high similarity

常见任务：

任务 输入文本对 输出
自然语言推断 前提＋假设 entailment／contradiction／neutral
语义文本相似度 句子 A＋句子 B 相似度分数
问答检索 查询＋段落 相关性分数
重复检测 问题 A＋问题 B duplicate／not duplicate

两种常见建模方式：

方式 方法 优势
Cross-encoder 将两段文本共同编码 准确率高，能够完整交互
Bi-encoder 分别编码，再比较向量 检索效率高

NLP 建模的概率视角

许多 NLP 模型都可以从概率角度理解：模型要么根据文本预测标签，要么生成文本，要么在输入条件下生成输出。概率视角使用统一语言连接不同任务：模型为期望输出分配高概率，为不期望输出分配低概率。

判别式建模

判别式模型直接建模不同输出之间的决策边界。它不解释输入文本如何生成，而是专注于为给定输入选择正确标签。实践中，许多监督式 NLP 系统都属于判别式模型，因为最终目标是准确预测。

判别式模型直接建模：

\[ P(y \mid x) \]

它们学习不同输出类别之间的边界。

示例：

模型 任务
逻辑回归 情感分类
线性 SVM 文档分类
BERT 分类器 意图检测
CRF 标注器 序列标注

当目标是预测且存在已标注数据时，通常优先考虑判别式模型。

生成式建模

生成式模型对数据生成过程进行建模，尝试描述文本和标签可能如何产生。当需要生成新文本、估计似然，或使用不同类别下单词出现方式的假设时，这种建模方式很有用。

在分类中，生成式模型可能估计：

\[ P(x, y) = P(y)P(x \mid y) \]

随后使用贝叶斯规则进行预测：

\[ P(y \mid x) = \frac{P(x \mid y)P(y)}{P(x)} \]

朴素贝叶斯是经典示例。对于文档 \(d\) 和类别 \(c\)：

\[ P(c \mid d) \propto P(c) \prod_i P(w_i \mid c) \]

生成式语言模型还会估计一段文本出现的可能性：

\[ P(w_1, ..., w_n) \]

条件生成

条件生成模型根据输入文本生成输出文本。它位于分类和纯语言建模之间：模型具有生成性，因为它产生一个序列；同时具有条件性，因为生成序列应取决于给定输入。

条件生成模型根据输入文本生成输出文本：

\[ P(y \mid x) \]

但与简单分类不同，这里的 \(y\) 是一个序列。

示例：

任务 条件概率
翻译 \(P(\text{target sentence} \mid \text{source sentence})\)
摘要 \(P(\text{summary} \mid \text{document})\)
对话 \(P(\text{response} \mid \text{conversation})\)

条件生成通常需要解码，因为模型必须选择一个输出 token 序列。

将架构理解为上下文建模

NLP 架构定义模型如何在 token 之间传递信息。不同模型家族的主要区别在于其上下文建模策略。这正是建模的核心：语言意义经常依赖上下文，各种架构最重要的差异，就是允许一个 token 以什么方式影响另一个 token。

架构 上下文策略 擅长 弱点
传统序列模型 相邻隐藏标签或状态之间的转移 在有限数据下进行结构化序列预测 强独立性假设和人工特征
线性模型 除非特征显式编码，否则没有真正的 token 间上下文 快速基线 词序建模较弱
CNN 模型 局部 n-gram 窗口 局部短语模式 长距离上下文有限
RNN／LSTM／GRU 循环隐藏状态 序列上下文 难以并行
Transformer 模型 token 间自注意力 全局上下文 注意力成本随序列长度二次增长

传统概率序列模型

传统序列模型专门处理输入和预测均为有序序列的问题。其核心认识是：输出标签不应彼此独立地预测。例如，在命名实体识别中，I-PER 通常跟在 B-PER 或另一个 I-PER 之后；在词性标注中，限定词后面出现形容词或名词的概率通常高于再次出现限定词。逐 token 独立分类的模型可能为每个位置给出单独看来合理的标签，却生成整体上不合理的标签序列。

对于观察到的 token 序列 \(x=(x_1,\ldots,x_T)\) 和标签序列 \(y=(y_1,\ldots,y_T)\)，结构化预测搜索：

\[ y^* = \arg\max_{y \in \mathcal{Y}(x)} \operatorname{score}(x,y) \]

这里，\(T\) 是序列长度，\(x_t\) 是位置 \(t\) 上观察到的 token，\(y_t\) 是其隐藏或预测标签，\(\mathcal{Y}(x)\) 是输入 \(x\) 的合法标签序列集合，\(y^*\) 是得分最高的完整序列。与独立 token 分类最重要的区别在于，score 不仅评估当前 token 的证据，还评估相邻标签之间的相互作用。

Observed words:    The       bank      raised     rates
Hidden POS tags:   DET  ->   NOUN  ->  VERB  ->   NOUN

单词 bank 既可以是名词，也可以是动词。周围单词提供词汇证据，而 DET -> NOUN 等转移提供结构证据。传统序列模型的主要差异，在于它们建模哪种概率、允许使用什么特征，以及采用局部归一化还是全局归一化。

隐马尔可夫模型

隐马尔可夫模型（Hidden Markov Model, HMM）是一种生成式序列模型。单词是可观察变量，而词性标签等语言状态是隐藏变量。它描述了这样一个生成过程：某个隐藏状态产生当前观察值，随后转移到下一个隐藏状态。

圆圈表示隐藏 POS 状态，实线箭头表示标签之间的转移概率，蓝色框列出各状态对应的单词发射概率。因此，一条高概率标签路径必须同时符合语法标签转移和观察到的单词。

来源：Speech and Language Processing，第 17 章，图 17.9

对于一阶 HMM，单词与标签的联合概率为：

\[ P(x,y) =P(y_1) \prod_{t=2}^{T}P(y_t\mid y_{t-1}) \prod_{t=1}^{T}P(x_t\mid y_t) \]

第一项 \(P(y_1)\) 是从标签 \(y_1\) 开始的概率。转移概率 \(P(y_t\mid y_{t-1})\) 衡量前一个标签之后出现 \(y_t\) 的可能性；发射概率 \(P(x_t\mid y_t)\) 衡量状态 \(y_t\) 产生观察词 \(x_t\) 的可能性。把这些局部决策相乘，就得到一条完整路径的概率。

这种分解依赖两项简化假设：

  • 当前标签只依赖前一个标签，即一阶马尔可夫假设；
  • 当前单词只依赖其当前隐藏标签。

这些假设使精确推断更加高效，但在语言学上限制很强。一个单词可能依赖远距离上下文、形态、大小写或周围词，而基本发射模型无法直接使用这些信息。未知词和罕见词还需要平滑或回退特征。

HMM 预测选择给定单词后概率最大的标签序列：

\[ y^*=\arg\max_y P(y\mid x) =\arg\max_y P(x,y) \]

第二个等式在最大化过程中成立，因为对每个候选标签序列而言，\(P(x)\) 都是常数。如果有 \(K\) 个标签和 \(T\) 个 token，枚举所有序列大约需要检查 \(K^T\) 条路径。Viterbi 算法只保留以每个状态结束的最佳部分路径，从而避免这种组合爆炸：

\[ \delta_t(j) = \max_i\left[\delta_{t-1}(i)a_{ij}\right]b_j(x_t) \]

在这个递推式中，\(\delta_t(j)\) 是位置 \(t\) 上以状态 \(j\) 结束的最佳路径概率；\(i\) 遍历所有可能的前一状态；\(a_{ij}=P(y_t=j\mid y_{t-1}=i)\) 是转移概率；\(b_j(x_t)=P(x_t\mid y_t=j)\) 是发射概率。回溯指针记录使每个最大值成立的前一状态 \(i\)。处理完最后一个 token 后，沿这些指针反向回溯即可重建全局最佳路径。

# Log probabilities turn products into sums and prevent numerical underflow.
def safe_log(probability):
    return math.log(max(probability, 1e-12))

scores = []       # scores[t][tag] = best log-score ending in tag at t
backpointers = [] # backpointers[t][tag] = best previous tag

# Step 1: initialize paths using the start and first-word probabilities.
first_scores = {
    tag: safe_log(start[tag]) + safe_log(emission[tag].get(words[0], 1e-6))
    for tag in tags
}
scores.append(first_scores)
backpointers.append({tag: None for tag in tags})

# Step 2: extend only the best path into each current tag.
for position in range(1, len(words)):
    current_scores = {}
    current_backpointers = {}

    for current_tag in tags:
        candidates = {
            previous_tag: (
                scores[position - 1][previous_tag]
                + safe_log(transition[previous_tag][current_tag])
                + safe_log(emission[current_tag].get(words[position], 1e-6))
            )
            for previous_tag in tags
        }
        best_previous = max(candidates, key=candidates.get)
        current_scores[current_tag] = candidates[best_previous]
        current_backpointers[current_tag] = best_previous

    scores.append(current_scores)
    backpointers.append(current_backpointers)

# Step 3: start from the best final tag and follow pointers backward.
best_final_tag = max(scores[-1], key=scores[-1].get)
best_path = [best_final_tag]

for position in range(len(words) - 1, 0, -1):
    best_path.append(backpointers[position][best_path[-1]])

best_path.reverse()
print(list(zip(words, best_path)))
# [('the', 'DET'), ('bank', 'NOUN'), ('closed', 'VERB')]

代码说明 Viterbi 不只是为每个单词单独选择最佳标签。bank 的解释是作为能够最好解释完整句子的整条路径的一部分而选出的。

最大熵马尔可夫模型

最大熵马尔可夫模型（Maximum Entropy Markov Model, MEMM）改变了建模方向。它不再由隐藏状态生成单词，而是根据前一个标签和可观察输入特征，直接预测当前标签：

\[ P(y\mid x) =\prod_{t=1}^{T}P(y_t\mid y_{t-1},x,t) \]

符号 \((x,t)\) 表示分类器可以检查位置 \(t\) 周围甚至整个输入的特征，而不只是当前单词。因此，MEMM 可以使用大小写、前缀、后缀、相邻 token、地名词典或其他相互重叠的特征，而无需为这些特征构造生成概率模型。每个局部分布通常由最大熵分类器或逻辑回归分类器实现。

它的弱点是局部归一化。在每个状态上，所有外出转移的概率之和必须为一。如果某个状态只有一条合法外出边，那么无论观察值是什么，该边的概率都是一；如果另一个状态存在很多候选，就必须把概率分配给这些候选。这会造成标签偏置问题（label-bias problem）：模型偏好经过外出选择较少状态的路径，而且无法充分利用后续证据修正这些决策。

条件随机场

线性链条件随机场（Conditional Random Field, CRF）是针对完整标签序列的判别式全局归一化模型。一种常见形式使用 token 证据和标签转移共同构建序列分数：

\[ \operatorname{score}(x,y) =\sum_{t=1}^{T}s_t(y_t,x) +\sum_{t=2}^{T}A_{y_{t-1},y_t} \]

这里，\(s_t(y_t,x)\) 是在位置 \(t\) 分配标签 \(y_t\) 的发射分数或特征分数，\(A_{y_{t-1},y_t}\) 是从前一标签到当前标签的已学习转移分数。与 HMM 发射概率不同，\(s_t\) 可以使用任意相互重叠的输入特征；在神经 CRF 中，它通常由 BiLSTM 或 Transformer 编码器产生。

通过全局归一化，分数被转换为条件概率：

\[ P(y\mid x) =\frac{\exp(\operatorname{score}(x,y))}{Z(x)}, \qquad Z(x)=\sum_{y'\in\mathcal{Y}(x)}\exp(\operatorname{score}(x,y')) \]

\(\exp(\operatorname{score}(x,y))\) 把不受限制的实数分数转换为正值。配分函数 \(Z(x)\) 对所有可能标签序列 \(y'\) 的正值求和，使最终概率总和为一。由于所有路径在同一个分母下竞争，后续证据可以影响完整路径之间的偏好，从而减轻 MEMM 中的局部标签偏置问题。

训练过程最大化正确序列的条件对数似然。前向算法利用动态规划高效计算 \(Z(x)\)，无需显式枚举每条路径；推断时，Viterbi 解码把求和替换为最大化，从而找出得分最高的序列。

在命名实体识别中，即使 token 级分类器分别为 I-ORG 和 B-PER 分配了高分，CRF 仍可以学到 I-ORG 很少出现在 B-PER 之后。它不能保证在每套标注方案下都输出合法序列，但为模型提供了显式学习标签依赖关系的机制。

传统序列建模在现代 NLP 中仍然有用。神经编码器与 CRF 分别解决问题的不同部分：

Tokens -> BiLSTM or Transformer -> contextual token scores -> CRF -> best label sequence

编码器对输入中的丰富上下文进行建模，CRF 则建模输出标签之间的依赖关系。当标签一致性很重要、训练数据有限，或输出方案包含强局部约束时，这种组合最有价值。对于规模很大的预训练编码器，简单的独立 token 分类头可能已经表现良好，而且更容易训练和部署，因此应通过实验判断是否需要 CRF，而不是自动加入。

模型 概率视角 输入特征 输出依赖 主要局限
HMM 生成式 \(P(x,y)\) 受限的发射模型 状态转移 强独立性假设
MEMM 判别式 \(P(y_t\mid y_{t-1},x,t)\) 灵活的重叠特征 前一标签 局部归一化与标签偏置
CRF 判别式 \(P(y\mid x)\) 灵活特征或神经特征 全局评分的标签链 训练与解码成本更高
独立神经标注器 逐 token 的 \(P(y_t\mid x)\) 上下文编码器 无显式标签转移 可能产生不一致的标签序列
神经编码器＋CRF 全局 \(P(y\mid x)\) 上下文神经特征 已学习的转移 增加实现和推断成本

总之，HMM 解释隐藏状态如何生成观察值，MEMM 允许使用丰富证据但每次只归一化一个决策，CRF 则直接比较完整标签序列。它们构成了经典概率 NLP 与现代神经序列标注之间的重要桥梁。

线性模型

线性模型使用带权特征为文本评分。虽然简单，但它们仍然重要，因为能够建立强基线。如果线性模型表现很好，任务可能主要依赖表层词汇线索；如果表现很差，任务可能需要词序、句法或更深层的上下文建模。

线性模型使用带权特征为文本评分：

\[ f(x)=w^Tx+b \]

在传统 NLP 中，\(x\) 通常是 BoW、TF-IDF 或 n-gram 特征。

Input sentence: "not very good"
Features: not=1, very=1, good=1, not_good=1
Model score: sum(feature value * feature weight)

线性模型本身没有上下文感知能力，必须通过以下特征人工加入上下文：

  • bigram
  • trigram
  • 否定特征
  • 词典特征
  • 句法特征

基于 CNN 的模型

CNN 经常与图像联系在一起，但同样可以用于文本。在文本 CNN 中，卷积过滤器在词嵌入上滑动，检测类似局部 n-gram 的模式。模型并非一次读取完整句子，而是在句子中扫描能够强烈指示类别的局部模式。

Embeddings -> Convolution Filters -> Max Pooling -> Classifier

例如，宽度为 3 的过滤器可以检测如下有用短语模式：

not very good
really loved this
waste of time

Python 文本 CNN 框架 
import torch
import torch.nn as nn
import torch.nn.functional as F

class TextCNN(nn.Module):
    def __init__(self, vocab_size, embed_dim, num_classes):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim)
        self.conv = nn.Conv1d(
            in_channels=embed_dim,
            out_channels=100,
            kernel_size=3
        )
        self.fc = nn.Linear(100, num_classes)

    def forward(self, token_ids):
        x = self.embedding(token_ids)      # [batch, seq_len, embed_dim]
        x = x.transpose(1, 2)              # [batch, embed_dim, seq_len]
        x = F.relu(self.conv(x))           # [batch, channels, new_seq_len]
        x = F.max_pool1d(x, kernel_size=x.size(2)).squeeze(2)
        return self.fc(x)

RNN／LSTM／GRU

RNN 按顺序处理文本。每个时间步上，模型使用当前 token 和前一个隐藏状态更新隐藏状态。这个隐藏状态是模型对已读内容的持续摘要，因此 RNN 天然符合语言从左到右的结构。

\[ h_t = \tanh(Wx_t + Uh_{t-1} + b) \]

隐藏状态充当先前上下文的记忆。

Python BiLSTM Token 分类器 
import torch
import torch.nn as nn

class BiLSTMTagger(nn.Module):
    def __init__(self, vocab_size, embed_dim, hidden_dim, num_tags):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim)
        self.lstm = nn.LSTM(
            embed_dim,
            hidden_dim,
            batch_first=True,
            bidirectional=True
        )
        self.classifier = nn.Linear(hidden_dim * 2, num_tags)

    def forward(self, token_ids):
        embeddings = self.embedding(token_ids)
        outputs, _ = self.lstm(embeddings)
        return self.classifier(outputs)

model = BiLSTMTagger(10000, 128, 64, 5)
batch = torch.tensor([[11, 22, 33, 44]])
print(model(batch).shape)  # [batch, seq_len, num_tags]

基于 Transformer 的模型

Transformer 使用自注意力建模上下文。它不逐个处理 token，而是允许每个 token 直接关注序列中的其他 token。这样，长距离依赖的信息路径更短：两个相距很远的单词可以在一个注意力层中交互，而无需经过许多循环步骤。

对于每个 token 表示 \(x_i\)，模型构造：

\[ q_i = W_Qx_i, \quad k_i = W_Kx_i, \quad v_i = W_Vx_i \]

缩放点积注意力为：

\[ \text{Attention}(Q,K,V)=\text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V \]

前馈网络 在每个位置应用非线性变换
残差连接 稳定深层网络
层归一化 归一化隐藏激活
位置编码 注入词序信息

编码器－解码器 编码器注意力＋解码器交叉注意力 翻译、摘要

预测头与输出结构

预测头把隐藏表示转换为任务所需的输出结构。同一个主干模型可以支持多种预测头。这种分离解释了预训练模型为什么如此灵活：主干学习通用语言表示，预测头则把这些表示适配到具体任务。

Backbone hidden states -> Prediction Head -> Task-specific Output

同一个 BERT 主干支持四种输出结构。句对和单句分类读取 [CLS] 的上下文表示；抽取式问答预测开始与结束位置；token 标注从每个 token 表示中预测一个标签。红色箭头表示各任务预测头从何处读取证据。

来源：BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding，图 4

这张图具体展示了主干与预测头的分离：改变任务不一定需要替换语言编码器，改变的是选择哪些隐藏状态，以及如何把它们映射到目标输出空间。

分类头

分类头把一个序列表示映射为类别 logit。

对于编码器模型，通常使用 [CLS] 向量：

\[ z = W h_{CLS} + b \]

\[ P(y \mid x)=\text{softmax}(z) \]

可用于：

  • 情感分类
  • 主题分类
  • 意图检测
  • 自然语言推断

Token 分类头

Token 分类头把每个 token 表示映射为标签分布。

\[ z_t = W h_t + b \]

可用于：

  • POS 标注
  • NER
  • 组块分析
  • 槽位填充
Input hidden states: [h_1, h_2, ..., h_n]
Output logits:       [z_1, z_2, ..., z_n]

语言建模头

语言建模头把隐藏状态映射为词表 logit。

\[ z_t = W h_t + b \]

\[ P(w_{t+1} \mid w_{\le t})=\text{softmax}(z_t) \]

输出维度等于词表大小。

hidden state -> vocabulary logits -> probability over all tokens

编码器－解码器输出层

在编码器－解码器模型中，解码器为每个生成位置产生一个隐藏状态，每个解码器隐藏状态再被映射为词表 logit。

encoder input -> encoder states
previous output tokens -> decoder states -> vocabulary distribution

解码器还可以通过交叉注意力关注编码器状态。

解码与推断

对于分类，推断通常很简单：选择分数最高的标签。

对于生成，推断更为复杂，因为模型必须选择完整输出序列。生成模型不会直接输出一份完成的答案，而是在每一步反复输出下一个 token 的概率分布。解码就是把这些逐步分布转换为最终文本的过程。

每个解码步骤上，模型产生词表上的概率分布：

\[ P(y_t \mid y_{<t}, x) \]

解码算法决定下一步选择哪个 token。

贪心解码

贪心解码在每一步选择概率最高的 token。

\[ y_t = \arg\max_w P(w \mid y_{<t}, x) \]

红色路径先选择 nice，因为它具有最大的即时概率，随后选择 woman，完整概率为 \(0.5\times0.4=0.20\)。经过 dog 的路径初始局部概率较小，因此贪心解码不会探索其后概率更高的 has。

来源：Hugging Face - How to generate text

示例：

Step 1: choose "I"
Step 2: choose "love"
Step 3: choose "NLP"

优点：

  • 简单
  • 快速
  • 结果确定

缺点：

  • 局部选择可能造成全局较差的结果
  • 经常产生缺少变化的通用输出
  • 无法从早期错误中恢复
Python 贪心解码框架 
def greedy_decode(next_token_fn, start_token, end_token, max_len=20):
    output = [start_token]

    for _ in range(max_len):
        probs = next_token_fn(output)
        next_token = max(probs, key=probs.get)
        output.append(next_token)

        if next_token == end_token:
            break

    return output

束搜索

束搜索在每个解码步骤保留得分最高的 \(k\) 个部分序列，\(k\) 称为束宽。

当束宽 \(k=2\) 时，nice 和 dog 都能在第一步保留下来。下一步中，路径 The dog has 达到 \(0.4\times0.9=0.36\)，优于贪心路径的 \(0.20\)。该图说明，保留多个候选假设可以从局部第二优选择中恢复。

来源：Hugging Face - How to generate text

beam width = 3
keep only the best 3 partial sequences after each step

优点：

  • 比贪心解码探索更多候选
  • 通常能提高翻译和摘要质量
  • 在不使用采样时结果确定

缺点：

  • 慢于贪心解码
  • 束宽较大时可能产生平淡输出
  • 仍不能保证找到真正的全局最优解

常见评分方式是对数概率之和：

\[ score(y)=\sum_{t=1}^{T}\log P(y_t \mid y_{<t},x) \]

通常还会加入长度归一化，因为原始对数概率倾向于选择短序列。

基于采样的解码

基于采样的解码从模型概率分布中随机抽取 token。

它不总是选择最大概率 token，而是进行采样：

\[ y_t \sim P(\cdot \mid y_{<t}, x) \]

常见策略：

方法 思想 效果
温度 将 logit 除以温度 控制随机性
Top-k 采样 只从前 \(k\) 个 token 中采样 移除概率极低的 token
Top-p 采样 从累计概率达到 \(p\) 的最小集合中采样 自适应调整候选集合大小

蓝色柱构成累计概率刚刚超过 \(p\) 的最小候选集合。左图中的分布较平坦，top-p 会保留更多可能单词；右图中的分布较尖锐，只需少量单词即可达到阈值。因此，与 top-k 不同，候选数量会随模型不确定性变化。

来源：Hugging Face - How to generate text

温度在 softmax 之前修改 logit：

\[ P(w)=\text{softmax}(z_w / T) \]

温度 行为
低温度 更安全、更确定
高温度 更多样、风险更高

开放式生成可能存在许多有效后续内容，因此广泛使用采样。

选择建模策略

选择 NLP 模型取决于任务形式、数据规模、计算预算、延迟要求和可解释性要求。没有任何一个模型能够在所有 NLP 任务中始终最佳。小型业务分类任务可能从透明的 TF-IDF 基线中获得更多收益，而开放式生成则需要自回归语言模型。

情况 推荐起点 原因
小型已标注分类数据集 TF-IDF＋逻辑回归 强且可解释的基线
局部短语模式很重要 文本 CNN 捕捉类似 n-gram 的特征
token 级序列标签 BiLSTM 或编码器 Transformer 使用每个 token 周围的上下文
翻译／摘要 编码器－解码器 Transformer 输入和输出均为序列
开放式生成 仅解码器 Transformer 天然适合下一个 token 生成
大规模检索 Bi-encoder 高效向量搜索
文本对分类追求最高准确率 Cross-encoder 两段文本完整交互

一个实用的建模流程：

1. Define input-output formulation
2. Build a simple baseline
3. Check failure cases
4. Choose architecture based on context requirement
5. Choose prediction head
6. Choose decoding strategy if generation is needed
7. Evaluate with task-appropriate metrics

因此，NLP 建模不只是选择一个著名架构，而是要把任务结构与正确的概率视角、上下文机制、输出头和推断方法相匹配。
