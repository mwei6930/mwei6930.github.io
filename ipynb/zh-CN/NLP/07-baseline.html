NLP 中的基线、基准与最先进水平

只有在共享评估协议下与恰当的参考系统比较，NLP 结果才有意义。基线确立起点，基准定义系统相互比较的环境，而最先进水平声明描述特定设置下已经报告的最强结果。

本章把三个概念连接为一套研究工作流，重点说明如何构建有信息价值的基线、理解基准究竟标准化了什么，以及如何判断表面上的改进是否公平、可复现、高效且具有实际意义。

从构建模型到比较模型

训练模型并得到一个分数，本身不能证明模型有用。假设情感分类器达到 \(89\%\) 准确率，这个数字看起来不错；但若 \(90\%\) 的测试样本属于正面类别，一个始终预测 positive、完全不阅读文本的系统就能达到 \(90\%\)。此时，训练出来的模型反而不如平凡基线。

模型比较首先要固定实验条件：

Same task definition
    -> Same data and split
    -> Same preprocessing
    -> Same evaluation metric
    -> Baseline result
    -> Candidate result
    -> Performance and cost comparison

令 \(M_b\) 为基线评估分数，\(M_c\) 为候选模型分数，则绝对改进为：

\[ \Delta M = M_c - M_b \]

\(\Delta M\) 表示在共享协议下候选模型提高了多少个指标点。若基线 macro-F1 为 \(0.72\)，候选模型为 \(0.76\)，则 \(\Delta M=0.04\)。但这只是分析起点：还要询问改进在不同随机种子下是否稳定、系统是否使用相同数据，以及四个百分点能否抵偿额外延迟、内存、标注或训练成本。

有价值的比较不会只依赖一个基线，而会建立一条基线阶梯，其中每一级检验不同假设：

基线层级 使用的信息 回答的问题
多数类或随机 仅标签分布 系统能否胜过忽略文本的预测？
启发式或词典 人工编写的词汇规则 明显语言线索能否解决大部分任务？
稀疏线性模型 词与 n-gram 统计 表层模式是否已经足够？
轻量神经模型 学习型嵌入与词序 学习到的上下文结构是否增加价值？
预训练模型 从大规模语料迁移的知识 预训练对任务有多大帮助？
基于提示的模型 指令与示例 通用模型能否在不进行任务特定训练时解决任务？

这条阶梯把模型开发变成诊断。如果复杂 Transformer 只略微超过 TF-IDF 加逻辑回归，任务可能主要由词汇线索决定，数据集可能太小，或评估没有奖励更深层理解。如果关键词规则异常强，数据可能包含标注捷径。因此，基线不只是弱竞争者，也是理解任务与数据集真正要求的测量工具。

NLP 中的基线

基线是一个简单、明确、可复现的参考系统，用来评估所提出的方法。简单不等于差：TF-IDF 加线性分类器在文档分类中可以很强；BM25 在词汇检索中仍然难以超越；抽取式启发规则在某些摘要数据集上也可能具有竞争力。

基线同时承担多个角色：

  • 下界： 确立一个有意义的系统至少应超过的性能；
  • 合理性检查： 揭示错误标签、数据泄漏、指标实现错误或模型没有学到东西；
  • 诊断控制： 检验词汇线索、标签先验、词序或预训练是否解释了性能提升；
  • 研究参照： 使结果能与过去和未来工作比较；
  • 工程参照： 判断额外复杂度是否值得其运行成本。

基线应在查看最终测试结果前选定。看到测试分数后反复发明新基线，会让测试集参与模型开发，并削弱比较的可信度。

什么构成良好的基线？

良好基线应与任务相关、足够简单而易于理解、足够强而具有信息价值，且成本低到容易复现。它还应明确自己使用哪些信息，以及故意忽略哪些信息。

属性 为什么重要 警示信号
适配任务 输出结构与真实问题一致 把多数类预测作为唯一 NER 基线
可复现 他人能重建同一分数 缺少划分、种子、预处理或模型版本
可解释 行为可用于诊断数据集 只称为“基线”的大型不透明模型
有竞争力 超越它才有意义 只与刻意设置的弱方法比较
资源透明 成本差异保持可见 只报告准确率，却隐藏百倍算力增长
稳定 结果不依赖一次幸运运行 只报告最好种子，不给均值与波动

基线选择应与研究声明对应。考虑三种候选声明：

研究声明 必要比较
“模型从文本中学习” 数据无关基线
“上下文建模有帮助” TF-IDF 或平均嵌入等对词序不敏感的模型
“预训练有帮助” 从零训练的相同下游架构，或冻结编码器

这接近受控实验：基线应移除声明所依赖的机制，同时让其他条件尽可能可比。

还应区分几个相关术语：

  • 基线是能对任务作出预测的参考系统；
  • 消融移除或修改所提模型的一个组件，以识别其贡献；
  • 控制条件隔离一种替代解释，例如打乱标签或随机化特征；
  • Oracle 使用推理时通常不可获得的信息，用来估计乐观上界。

例如，始终把标准段落排在第一位的 oracle 检索器，可用于测量下游 QA 的最高可能性能，但它使用答案信息，因此不是可部署基线。

数据无关基线

数据无关基线忽略输入文本 \(x\)。预测可以利用训练集中的标签分布，但词汇、句法和语义都不起作用。它们是防止类别不平衡造成误导性结果的第一道检查。

假设分类问题有 \(K\) 个类别，训练集类别比例为 \(p_1,\ldots,p_K\)，其中 \(p_k\) 是类别 \(k\) 的样本占比，且 \(\sum_{k=1}^{K}p_k=1\)。

最常见策略是：

策略 预测规则 预期行为
多数类 始终预测 \(\arg\max_k p_k\) 准确率接近 \(\max_k p_k\)
均匀随机 以概率 \(1/K\) 抽取每个类别 期望准确率为 \(1/K\)
分层随机 以概率 \(p_k\) 抽取类别 \(k\) 期望准确率为 \(\sum_k p_k^2\)
常量类别 始终预测指定类别 测试特定类别或指标边界情况

对于类别比例为 \(0.70\)、\(0.20\) 和 \(0.10\) 的数据集：

\[ \text{Majority accuracy}=\max(0.70,0.20,0.10)=0.70 \]

\[ \text{Uniform expected accuracy}=\frac{1}{3}\approx0.333 \]

\[ \text{Stratified expected accuracy}=0.70^2+0.20^2+0.10^2=0.54 \]

分层随机值表示独立抽取的预测标签与真实标签落入同一类别的概率。多数类策略准确率更高，却对两个少数类都具有零召回率。因此，必须使用任务真正关注的同一组指标评估基线；macro-F1 会暴露总体准确率隐藏的问题。

Scikit-learn 通过 DummyClassifier 提供这些策略，其预测会有意忽略输入特征。most_frequent、prior、stratified、uniform 和 constant 的正式行为可参见 DummyClassifier 文档。

Python：比较数据无关分类基线 
from sklearn.dummy import DummyClassifier
from sklearn.metrics import accuracy_score, f1_score

# The text is passed to the API, but every dummy strategy ignores it.
X_train = [f"training document {i}" for i in range(10)]
y_train = ["positive"] * 7 + ["neutral"] * 2 + ["negative"]

X_test = [f"test document {i}" for i in range(10)]
y_test = ["positive"] * 7 + ["neutral"] * 2 + ["negative"]

strategies = {
    "majority": DummyClassifier(strategy="most_frequent"),
    "uniform": DummyClassifier(strategy="uniform", random_state=42),
    "stratified": DummyClassifier(strategy="stratified", random_state=42),
}

for name, baseline in strategies.items():
    # Step 1: fit learns only the class distribution from y_train.
    baseline.fit(X_train, y_train)

    # Step 2: predict without examining any text content.
    predictions = baseline.predict(X_test)

    # Step 3: report both accuracy and macro-F1.
    # Macro-F1 gives every class equal importance.
    accuracy = accuracy_score(y_test, predictions)
    macro_f1 = f1_score(
        y_test,
        predictions,
        average="macro",
        zero_division=0,
    )

    print(f"{name:10s} accuracy={accuracy:.3f} macro_f1={macro_f1:.3f}")

如果文本模型不能稳定超过这些基线，下一步不应自动扩大模型。应先检查标签、数据划分、优化过程和评估管线。模型可能没有学到东西，或输入文本本身没有足够信息预测目标。

启发式与语言学基线

启发式基线会读取输入，但不从带标签样本中学习决策规则。它使用人工指定的知识，例如关键词、情感词典、正则表达式、形态特征、大小写、地名词典或句法模式。

在词典情感分析中，为每个识别出的 token \(w_i\) 分配极性值 \(\ell(w_i)\)。简单的文档分数为：

\[ s(x)=\sum_{i=1}^{n}\ell(w_i) \]

\(x=(w_1,\ldots,w_n)\) 是分词后的文本，\(n\) 是 token 数，\(\ell(w_i)\) 可以为正、负或零。预测可使用阈值：

\[ \hat y= \begin{cases} \text{positive}, & s(x)>0 \\ \text{neutral}, & s(x)=0 \\ \text{negative}, & s(x)<0 \end{cases} \]

这个分数可解释，因为每个词的贡献清晰可见；缺陷也同样明显：语言含义不是简单求和。否定可能翻转极性，程度副词会改变强度，词义随领域变化，讽刺还可能与字面含义相反。

比较以下示例：

文本 朴素词汇解读 语言问题
The service was excellent. 正面 直接的词汇线索
The service was not excellent. 若不处理否定则为正面 否定作用域
The battery is sick. 在一般英语中为负面 领域与俚语含义
Great, it crashed again. 含正面词汇 讽刺与篇章上下文

下面的基线增加一个较小的否定窗口。它仍然故意保持局限，但代码明确了假设，也为后续模型生成有价值的失败样本。

Python：带简单否定处理的词典情感基线 
import re

LEXICON = {
    "excellent": 2,
    "great": 2,
    "good": 1,
    "helpful": 1,
    "bad": -1,
    "terrible": -2,
    "crashed": -2,
    "slow": -1,
}
NEGATIONS = {"not", "never", "no", "hardly"}

def tokenize(text):
    # Keep a transparent tokenizer so every rule is inspectable.
    return re.findall(r"[a-z']+", text.lower())

def lexicon_sentiment(text, negation_window=3):
    tokens = tokenize(text)
    score = 0
    remaining_negation_scope = 0

    for token in tokens:
        # Step 1: open a short negation scope after a negation word.
        if token in NEGATIONS:
            remaining_negation_scope = negation_window
            continue

        # Step 2: look up the token's manually assigned polarity.
        contribution = LEXICON.get(token, 0)

        # Step 3: reverse polarity while the token is in negation scope.
        if contribution != 0 and remaining_negation_scope > 0:
            contribution *= -1

        score += contribution
        remaining_negation_scope = max(0, remaining_negation_scope - 1)

    # Step 4: convert the transparent numeric score into a label.
    if score > 0:
        return "positive", score
    if score < 0:
        return "negative", score
    return "neutral", score

examples = [
    "The service was excellent.",
    "The service was not excellent.",
    "Great, it crashed again.",  # The rule still misses sarcasm.
]

for text in examples:
    print(text, "->", lexicon_sentiment(text))

当带标签数据稀缺、法规要求决策可追溯，或领域专家已经拥有高精度规则时，启发式基线尤其有价值。它们也适用于弱监督：用规则为更大规模的无标签语料生成带噪标签。

其主要限制是维护成本。每个新领域、语言变体和失败模式都可能要求新增规则。因此，启发式基线应同时报告总体性能与覆盖率：若高精度规则只在 \(5\%\) 的样本上触发，而另一个分类器对所有样本都作预测，两者不能直接比较，除非拒答本身就是任务的一部分。

经典机器学习基线

经典 NLP 基线从带标签数据学习，但保持表示与决策函数相对简单。标准管线是：

Raw text
    -> token and n-gram counts
    -> TF-IDF weighting
    -> linear classifier
    -> label probabilities or decision scores

这条管线往往比其简单外表更强。文本向量高维且稀疏，许多分类任务包含预测力很强的词或短语。线性模型可以为每个特征分配一个权重，并高效组合数千个较弱词汇信号。

对多分类线性模型，类别 \(k\) 的分数为：

\[ z_k=w_k^Tx+b_k \]

\(x\) 是 TF-IDF 文档向量，\(w_k\) 是类别 \(k\) 的特征权重，\(b_k\) 是偏置项。逻辑回归使用 softmax 把分数转换为概率：

\[ P(y=k\mid x)=\frac{e^{z_k}}{\sum_{j=1}^{K}e^{z_j}} \]

指数使每个值为正，分母把 \(K\) 个类别值归一化为和为一。对类别 \(k\) 具有较大正权重的特征会提高该类别分数，较大负权重则降低分数。

常见经典基线的假设不同：

模型 主要优点 典型限制
多项式朴素贝叶斯 极快，对词频有效 条件独立假设，决策边界较不灵活
逻辑回归 概率输出与可解释权重 上下文限于提供的特征
线性 SVM 稀疏文本上的强间隔分类器 未经校准的分数不是概率
字符 n-gram 线性模型 对拼写变化与形态变化鲁棒 可能利用正字法捷径

特征表示已在文本表示中解释。这里的实验重点是：该基线用来判断新模型是否真正超过了表层词汇统计。

Python：TF-IDF、逻辑回归与特征检查 
import numpy as np
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import StratifiedKFold, cross_validate
from sklearn.pipeline import Pipeline

texts = [
    "excellent acting and a moving story",
    "a thoughtful and beautifully written film",
    "the performances were warm and convincing",
    "smart dialogue with a satisfying ending",
    "I loved the pacing and the characters",
    "a delightful film with excellent music",
    "the plot was engaging and original",
    "good acting carried the entire movie",
    "a boring story with terrible dialogue",
    "the film was slow and painfully predictable",
    "bad acting and a disappointing ending",
    "I hated the flat characters",
    "the plot was confusing and unoriginal",
    "a dull movie with forgettable music",
    "terrible pacing ruined the experience",
    "the story was weak and badly written",
]
labels = np.array(["positive"] * 8 + ["negative"] * 8)

# Step 1: put representation and classifier in one reproducible pipeline.
baseline = Pipeline([
    ("tfidf", TfidfVectorizer(
        ngram_range=(1, 2),  # Learn words and short phrases such as "not good".
        sublinear_tf=True,   # Reduce the dominance of repeated terms.
    )),
    ("classifier", LogisticRegression(max_iter=1000, random_state=42)),
])

# Step 2: use the same folds for every future candidate model comparison.
cv = StratifiedKFold(n_splits=4, shuffle=True, random_state=42)
scores = cross_validate(
    baseline,
    texts,
    labels,
    cv=cv,
    scoring={"accuracy": "accuracy", "macro_f1": "f1_macro"},
)

print("Mean accuracy:", scores["test_accuracy"].mean())
print("Mean macro-F1:", scores["test_macro_f1"].mean())

# Step 3: fit once on all available training data for feature inspection.
baseline.fit(texts, labels)
vectorizer = baseline.named_steps["tfidf"]
classifier = baseline.named_steps["classifier"]

feature_names = vectorizer.get_feature_names_out()
weights = classifier.coef_[0]

print("Most positive features:", feature_names[np.argsort(weights)[-5:]])
print("Most negative features:", feature_names[np.argsort(weights)[:5]])

特征检查是基线诊断价值的一部分。如果模型主要根据电影名称、用户名或格式伪影预测情感，它可能以错误原因获得高分。Transformer 也可能学到同一捷径，但在线性透明基线中更容易发现。

当任务依赖长距离组合、隐含含义、世界知识或上下文词义时，经典基线较弱。尽管如此，不应跳过它们。一个无法超过经过合理调优的稀疏线性模型的新神经网络，还没有证明其复杂度合理。

轻量神经基线

轻量神经基线连接稀疏线性模型与大型预训练 Transformer。它们从任务数据学习稠密表示，并能检验词序或局部上下文是否重要，同时不会把数十亿 token 的预训练知识引入为额外信息源。

三个常见选择是：

基线 上下文机制 诊断问题
平均嵌入分类器 平均 token 嵌入 在不考虑词序时，稠密词汇表示是否有帮助？
Text CNN 在局部窗口上卷积 局部短语与类似 n-gram 的模式是否重要？
BiLSTM 双向循环上下文 序列上下文是否改善任务？

对平均嵌入基线，token 嵌入 \(e_1,\ldots,e_n\) 的平均值为：

\[ h=\frac{1}{n}\sum_{i=1}^{n}e_i \]

\(e_i\in\mathbb{R}^d\) 是第 \(i\) 个 token 的 \(d\) 维嵌入，\(n\) 是非 padding token 数，\(h\) 是固定大小的句子表示。分类器随后预测：

\[ P(y\mid x)=\operatorname{softmax}(Wh+b) \]

平均操作故意忽略顺序：若 token 嵌入相同，dog bites person 和 person bites dog 包含相同 token，因此得到相同表示。这一弱点具有控制实验价值。如果在相同训练条件下 BiLSTM 显著优于平均模型，词序和上下文组合很可能确实产生了贡献。

Python：支持 mask 的平均嵌入分类器 
import torch
import torch.nn as nn

class MeanEmbeddingClassifier(nn.Module):
    def __init__(self, vocab_size, embedding_dim, num_classes, pad_id=0):
        super().__init__()
        self.embedding = nn.Embedding(
            num_embeddings=vocab_size,
            embedding_dim=embedding_dim,
            padding_idx=pad_id,
        )
        self.classifier = nn.Linear(embedding_dim, num_classes)

    def forward(self, token_ids, attention_mask):
        # Step 1: map token IDs to trainable dense vectors.
        token_vectors = self.embedding(token_ids)

        # Step 2: give real tokens weight 1 and padding tokens weight 0.
        mask = attention_mask.unsqueeze(-1).to(token_vectors.dtype)
        masked_vectors = token_vectors * mask

        # Step 3: average only the non-padding token vectors.
        token_count = mask.sum(dim=1).clamp(min=1.0)
        sentence_vector = masked_vectors.sum(dim=1) / token_count

        # Step 4: produce one score for each class.
        return self.classifier(sentence_vector)

model = MeanEmbeddingClassifier(
    vocab_size=20_000,
    embedding_dim=128,
    num_classes=3,
)

token_ids = torch.tensor([
    [15, 82, 41, 0, 0],
    [91, 37, 12, 66, 5],
])
attention_mask = (token_ids != 0).long()

logits = model(token_ids, attention_mask)
print(logits.shape)  # [batch_size=2, num_classes=3]

CNN 与 BiLSTM 架构已在 NLP 建模中解释。在基线实验中，它们应故意保持较小，使用与其他候选系统相同的分词器和训练划分，并获得有记录的调参预算。否则，一个调优不足的神经基线会让所提模型看起来虚假地更强。

轻量神经模型不保证超过稀疏线性模型。当标签有限且词汇线索很强时，TF-IDF 可能泛化更好、训练更快且更容易调试。正因为结果并非预先确定，这种比较才有信息价值。

预训练与基于提示的基线

现代 NLP 实验通常需要预训练参考系统，因为只在目标数据集上训练，会忽略通过迁移学习轻易获得的知识。不过，“使用预训练模型”包含多种实质不同的设置。

设置 更新的参数 是否需要任务样本 主要比较问题
冻结编码器＋线性头 仅任务头 带标签样本 不改变编码器时，预训练特征是否有用？
完整微调 编码器与任务头 带标签样本 标准任务适配后的预训练性能如何？

对于冻结编码器，令 \(f_{\phi}\) 为参数 \(\phi\) 固定的预训练模型：

\[ h=f_{\phi}(x), \qquad \hat y=g_{\theta}(h) \]

Python：冻结 Transformer 编码器并使用逻辑回归 
import numpy as np
import torch
from sklearn.linear_model import LogisticRegression
from transformers import AutoModel, AutoTokenizer

checkpoint = "distilbert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(checkpoint)
encoder = AutoModel.from_pretrained(checkpoint)
encoder.eval()

# Freeze the encoder: the downstream classifier is the only learned component.
for parameter in encoder.parameters():
    parameter.requires_grad = False

@torch.no_grad()
def encode_texts(texts, batch_size=16):
    all_vectors = []

    for start in range(0, len(texts), batch_size):
        batch_texts = texts[start:start + batch_size]
        encoded = tokenizer(
            batch_texts,
            padding=True,
            truncation=True,
            return_tensors="pt",
        )

        # Step 1: obtain one contextual vector for every token.
        token_vectors = encoder(**encoded).last_hidden_state

        # Step 2: mean-pool real tokens while excluding padding positions.
        mask = encoded["attention_mask"].unsqueeze(-1)
        pooled = (token_vectors * mask).sum(dim=1) / mask.sum(dim=1)
        all_vectors.append(pooled.cpu().numpy())

    return np.vstack(all_vectors)

# X_train_text and X_test_text must use the same split as other baselines.
train_vectors = encode_texts(X_train_text)
test_vectors = encode_texts(X_test_text)

classifier = LogisticRegression(max_iter=1000, random_state=42)
classifier.fit(train_vectors, y_train)
predictions = classifier.predict(test_vectors)

任务特定基线

正确基线取决于输出结构。多数类分类器适用于文档分类，但不足以作为机器翻译或检索的唯一参考。每项任务都需要能产生相同输出类型、并能在与候选系统相同协议下测量的基线。

文本分类

对单标签分类，一条可辩护的最小阶梯是：

Majority class
    -> Keyword or lexicon rule
    -> TF-IDF + logistic regression / linear SVM
    -> Frozen pretrained encoder
    -> Fine-tuned pretrained encoder

多数类基线检测标签不平衡，规则系统检测明显捷径，线性模型检测稀疏词汇特征是否已经解决任务，预训练基线再量化迁移学习的贡献。

多标签分类需要不同的朴素参考，因为每个样本可以拥有多个标签。一个有用的数据无关基线按照训练流行率预测各标签，或始终预测流行率超过固定阈值的标签。完全匹配准确率可能过于苛刻，因此应根据任务目标报告 micro-F1、macro-F1 和逐标签召回率。

对层次分类，扁平多数标签会忽略父子结构。更强的基线可以预测标签层次中最常见的有效路径。基线必须遵守与所提系统相同的输出约束。

序列标注

序列标注为每个 token 预测一个标签，相邻标签之间通常存在依赖。合适基线包括：

  • 始终预测外部标签 O；
  • 为每个已知 token 分配其训练中最常见的标签；
  • 使用大小写、后缀或地名词典规则；
  • 使用带局部特征的 HMM 或 CRF；
  • 使用小型 BiLSTM 或预训练 token 分类器。

最常见标签基线可以写为：

\[ \hat y(w)=\arg\max_k \operatorname{count}(w,k) \]

\(\operatorname{count}(w,k)\) 是 token \(w\) 在训练中被赋予标签 \(k\) 的次数。未见 token 回退到全局最常见标签或基于形态的规则。

对命名实体识别而言，始终预测 O 可能因为大多数 token 都不是实体而获得很高 token 准确率，但实体级精确率、召回率和 F1 全为零。这不代表基线无用；它恰好揭示 token 准确率为何不适合作为应用主指标。传统结构化模型见 NLP 建模，span 评估见 NLP 评估。

语言建模与生成

生成任务要求基线生成完整输出，而不是类别标签。适合的基线高度依赖应用：

任务 简单基线 更强参考基线
语言建模 Unigram 模型 平滑 n-gram 语言模型
摘要 首句或 Lead-3 抽取式句子排序系统
机器翻译 复制源文本或短语表 统计机器翻译或小型编码器－解码器
对话 最常见回答 从相似训练上下文中检索回答
数据到文本 固定模板 带槽位特定规则的模板

模型基线与解码基线不同。把 Transformer 与 n-gram 模型比较会改变概率模型；在保持 Transformer 不变时比较贪心解码与束搜索，只改变推理。两种比较都有用，但支持不同声明。

只有在分词与评估 token 对齐时，语言模型困惑度才可比较。词级 n-gram 模型与子词 Transformer 可能在不同单位上分配概率，因此原始困惑度会误导。生成质量还应包括任务特定自动指标与人工检查，而不能只依赖似然。

检索与排序

检索系统为查询排序文档。因此，基线必须在同一文档集合上产生有序列表。常见层级是：

Random ranking
    -> Popularity or recency ranking
    -> TF-IDF cosine similarity
    -> BM25
    -> Dense bi-encoder retrieval
    -> Cross-encoder reranking

随机排序检查指标实现；流行度或新近度基线检查非文本捷径；TF-IDF 和 BM25 建立强词汇检索参考；稠密检索则测试超越精确词项重叠的语义匹配。

所有系统必须使用同一语料库、查询集、相关性判断与候选池规则。如果稠密系统先用 BM25 获取候选项，它就不能与端到端 BM25 直接比较，除非明确披露两阶段设置。索引构建时间、存储、查询延迟和重排序深度也是系统成本的一部分。

实际基线选择可总结为：

任务属性 最低基线 推荐强基线
不平衡分类 多数类与分层 dummy TF-IDF＋类别感知线性模型
词汇驱动分类 关键词规则 词／字符 n-gram 线性模型
token 对齐输出 O 或最常见标签 CRF 或轻量 token 分类器
自由生成 复制／模板／Lead-3 小型预训练编码器－解码器
词汇检索 随机排序 BM25
语义检索 BM25 稠密双编码器＋有记录的重排序器

最佳基线集合通常较小但具有层次：包含一个平凡下界、一个强传统方法，以及一个能隔离所声明机制的参考。下一节说明数据集、指标、划分和协议如何把这些比较组织成 NLP 基准。

NLP 基准评测

基线回答“所提模型应超过哪个简单或成熟系统？”，基准则回答更广的问题：“不同系统应在什么共享条件下测量？”这一区分很重要，因为模型、指标和测试数据集本身并不能构成有意义的比较。分数 90 可能表示 accuracy、macro-F1、span F1、BLEU 或人工偏好率；它可能来自公开开发集、隐藏测试集，也可能来自曾经影响模型选择的测试集。只有知道完整测量协议，数字才可解释。

因此，基准评测位于模型开发与科学声明之间：

\[ \text{models} \longrightarrow \text{shared protocol} \longrightarrow \text{comparable evidence} \longrightarrow \text{claim} \]

NLP 评估章节解释单个指标如何诊断模型行为；本章关注更大的契约：决定所有模型必须共享哪些数据、任务形式、适配过程、指标和报告规则。

什么是 NLP 基准？

NLP 基准是用于测量某项明确能力或一组能力的、标准化且可复用的评估环境。它通常包含一个或多个数据集，但不只是数据集；还会规定样本如何转为模型输入、哪个划分用于开发、是否允许微调或提示、如何把预测转换成答案、哪些指标为主，以及如何报告结果。

相关术语彼此联系，但不能互换：

术语 提供什么 不保证什么
数据集 文本、标签、元数据，通常还有 train/dev/test 划分 统一模型接口、指标或报告策略
评估 把预测与期望行为比较的测量过程 其他研究者使用同一过程
基准 共享任务、数据、协议、指标与比较规则 所测能力覆盖现实语言使用
排行榜 公开排列提交的基准结果 科学有效性、可复现性或实际价值

可以把基准形式化为一项规范：

\[ \mathcal{B}=(\mathcal{D},\mathcal{T},\mathcal{S},\mathcal{A},\mathcal{M},\mathcal{R}) \]

其中：

  • \(\mathcal{D}\) 是数据及其来源、标注策略、许可证和版本；
  • \(\mathcal{T}\) 是任务定义，包括输入－输出格式与目标构念；
  • \(\mathcal{S}\) 是划分策略，例如随机、文档级、时间、领域留出或隐藏测试划分；
  • \(\mathcal{A}\) 是适配协议，例如完整微调、冻结特征、零样本提示或固定数量示例；
  • \(\mathcal{M}\) 是指标集合以及归一化或聚合规则；
  • \(\mathcal{R}\) 是报告契约，包括随机种子、置信区间、算力、模型版本和必需的子群结果。

改变其中一个元素就可能改变科学问题。在 SST-2 上微调 BERT 测量监督式任务适配；在相同句子上提示冻结语言模型，则测量特定提示下的指令遵循。数据集相同，基准条件却不同。

对包含 \(n\) 个样本的测试集，基准分数通常是经验估计：

\[ \widehat{M}(f)=\frac{1}{n}\sum_{i=1}^{n}m\!\left(f(x_i),y_i\right) \]

\(f\) 是被评估系统，\(x_i\) 是第 \(i\) 个输入，\(y_i\) 是标准目标，\(m\) 是逐样本评分规则。对准确率而言，预测正确时 \(m=1\)，否则为 0。\(\widehat{M}\) 上的帽子很重要：分数只是有限样本上的估计，不是模型在所有未来文本上的永久能力。即使实现无误，小型或缺乏代表性的测试集也会产生不确定估计。

假设两个情感系统在同一批 1,000 条评论上评估。模型 A 在反复依据该测试集选择提示后报告 89% accuracy；模型 B 在隐藏测试集上报告 87% macro-F1，并提供逐领域结果。更大的数字不能证明 A 更好，因为指标、测试暴露与报告粒度都不同。基准的作用就是在看到结果前消除这些自由度。

可信基准应具备：

属性 实际问题
有效 任务是否真的代表基准所声称的能力？
可靠 小幅抽样或标注变化后，主要结论是否保持？
有区分力 测试能否区分实质不同的系统？
有代表性 领域、用户、语言和难度是否与预期用途相关？
可复现 他人能否重建输入、协议和分数？
抗投机 是否难以在不改善目标能力时提高分数？
透明 是否记录局限、排除项、不确定性和已知污染？

最后一点是概念性的：基准不会发现“语言理解”的含义，而是由设计者把这个宽泛概念的选定部分操作化为可观察行为。良好基准会明确这种选择，而不是把分数当成普遍智能。

基准的组成

基准始于一个构念，即希望测量的能力或行为。对命名实体识别，构念可以是从新闻文本中可靠抽取人名、组织与地点；随后再把抽象目标转化为样本、标签、划分、接口和指标。弱基准常常先拿到一个现成数据集，再事后为它附加宽泛能力名称。

主要组件形成一条测量链：

组件 设计决策 忽略后的典型失败
构念 定义能力与目标人群 把狭窄任务解释为一般理解
任务接口 定义输入、输出、标签、上下文和允许工具 模型解决的是不同任务形式
数据 记录来源、时间、领域、语言、标注和许可证 隐藏伪影或人群偏差决定分数
划分策略 按正确单位分离 train/dev/test 近重复文档跨划分泄漏
适配协议 固定微调、提示、检索与示例规则 额外监督被误认为模型更好
指标 选择主指标、诊断指标、子群指标与成本指标 一个平均值隐藏真实失败
聚合 规定方向、尺度、权重和缺失任务策略 总分无声偏向某些任务
报告 记录版本、种子、不确定性、算力与预测 结果无法审计或复现

划分单位在 NLP 中尤其重要。当多个句子来自同一文章、对话、患者、作者或模板时，随机划分句子并不安全。共享措辞可能让模型识别来源，而不是泛化到新来源。正确划分可能必须在文档、用户、时间、语言或领域层级进行。

指标还必须匹配它所代表的决策。医疗实体抽取可能需要对危险疾病保持高召回率，生产检索系统则可能关注固定延迟预算下的召回率。如果不解释 F1 与预期用途的关系，“使用 F1”本身不是基准设计理由。

下面的示例把部分基准契约写成可执行代码：验证标签空间、计算声明的主指标、加入 bootstrap 置信区间，并为精确测试 ID 记录指纹。指纹不是为了隐藏测试集，而是为了检测意外的划分变化。

import hashlib

import numpy as np

def fingerprint_ids(example_ids):
    """Create a stable identity for the ordered test examples."""
    payload = "\n".join(map(str, example_ids)).encode("utf-8")
    return hashlib.sha256(payload).hexdigest()


def macro_f1(y_true, y_pred, labels):
    return f1_score(
        y_true,
        y_pred,
        labels=list(labels),
        average="macro",
        zero_division=0,
    )


def bootstrap_interval(y_true, y_pred, metric_fn, seed=42, rounds=2000):
    """Estimate test-sample uncertainty by resampling paired predictions."""
    y_true = np.asarray(y_true)
    y_pred = np.asarray(y_pred)
    rng = np.random.default_rng(seed)
    scores = []

    # Each round samples test positions with replacement, preserving pairs.
    for _ in range(rounds):
        indices = rng.integers(0, len(y_true), size=len(y_true))
        scores.append(metric_fn(y_true[indices], y_pred[indices]))

    lower, upper = np.percentile(scores, [2.5, 97.5])
    return float(lower), float(upper)


def evaluate_predictions(spec, example_ids, y_true, y_pred):
    # Step 1: reject accidental benchmark or label changes.
    assert fingerprint_ids(example_ids) == spec.test_split_fingerprint
    assert set(y_true).issubset(spec.labels)
    assert set(y_pred).issubset(spec.labels)

    # Step 2: calculate both the primary score and a useful diagnostic score.
    metric_fn = lambda truth, pred: macro_f1(truth, pred, spec.labels)
    score = metric_fn(np.asarray(y_true), np.asarray(y_pred))
    interval = bootstrap_interval(
        y_true,
        y_pred,
        metric_fn,
        seed=spec.seed,
    )

    # Step 3: emit a machine-readable record for later comparison.
    return {
        "benchmark": asdict(spec),
        "accuracy": accuracy_score(y_true, y_pred),
        "macro_f1": score,
        "macro_f1_95pct_bootstrap_ci": interval,
        "n_test": len(y_true),
    }


# These IDs and predictions would normally come from the locked test run.
test_ids = ["review-101", "review-102", "review-103", "review-104"]
spec = BenchmarkSpec(
    name="ProductSentiment",
    version="1.0",
    labels=("negative", "neutral", "positive"),
    primary_metric="macro_f1",
    test_split_fingerprint=fingerprint_ids(test_ids),
)

report = evaluate_predictions(
    spec,
    test_ids,
    y_true=["positive", "negative", "neutral", "negative"],
    y_pred=["positive", "neutral", "neutral", "negative"],
)
print(json.dumps(report, indent=2))

Bootstrap 区间回答一个有限但有用的问题：如果从同一观察人群再次抽取相似测试样本，分数可能变化多少？它无法修正标注偏差、领域不匹配、污染或反复针对测试集调参。统计精度与基准有效性是两件事。

可执行评估器应配有基准卡，记录预期用途、禁止用途、收集日期、标注质量、子群覆盖、许可证、已知泄漏和变更历史。代码使协议可重复，文档则使其含义可审查。

单任务基准

单任务基准集中于一种输入－输出关系，例如情感分类、命名实体识别、抽取式问答、机器翻译或下一 token 预测。它可以包含多个领域或测试集，但每个系统都解决同一种基本任务。范围较窄使错误更易解释，也能让指标针对输出结构定制。

基准示例 输入－输出结构 典型主指标 最直接测量的内容
SST-2 句子 \(\rightarrow\) 情感标签 Accuracy 电影评论句子的二元情感分类
CoNLL-2003 NER token 序列 \(\rightarrow\) 实体 span 实体级 F1 新闻文本中实体边界与类型的严格恢复
SQuAD 段落和问题 \(\rightarrow\) 答案 span Exact Match 和 token F1 数据集标注规则下的抽取式阅读理解
WMT 翻译任务 源句子 \(\rightarrow\) 译文 BLEU、chrF、COMET 和／或人工判断 指定语言对与测试年份的翻译质量
WikiText-103 先前 token \(\rightarrow\) 下一 token 概率 Perplexity 特定维基百科派生分布上的预测语言建模

SQuAD 论文说明了为什么任务与评分器必须一起阅读。假设参考答案为 Denver，系统预测 Denver, Colorado。归一化后字符串不同，因此 Exact Match 为 0；token precision 为 \(1/2\)，token recall 为 \(1\)，token F1 为：

\[ F_1=\frac{2PR}{P+R}=\frac{2(1/2)(1)}{1/2+1}=\frac{2}{3} \]

\(P\) 是预测 token 中与参考重叠的比例，\(R\) 是参考 token 中被预测找回的比例。Exact Match 奖励严格边界选择，token F1 提供部分得分。只报告其中一个，会改变对同一错误的解释。

Python：简化的 SQuAD 风格 Exact Match 与 token-F1 评分器 
from collections import Counter
import re
import string


def normalize_answer(text):
    """Apply the normalization choices that define this scorer."""
    text = text.lower()
    text = "".join(char for char in text if char not in string.punctuation)
    text = re.sub(r"\b(a|an|the)\b", " ", text)
    return " ".join(text.split())


def exact_match(prediction, reference):
    return float(normalize_answer(prediction) == normalize_answer(reference))


def token_f1(prediction, reference):
    pred_tokens = normalize_answer(prediction).split()
    ref_tokens = normalize_answer(reference).split()

    # Step 1: handle answers that normalize to an empty sequence.
    if not pred_tokens or not ref_tokens:
        return float(pred_tokens == ref_tokens)

    # Step 2: count overlapping tokens, including repeated occurrences.
    overlap = Counter(pred_tokens) & Counter(ref_tokens)
    common = sum(overlap.values())
    if common == 0:
        return 0.0

    # Step 3: combine partial-answer precision and recall.
    precision = common / len(pred_tokens)
    recall = common / len(ref_tokens)
    return 2 * precision * recall / (precision + recall)


def score_qa_example(prediction, references):
    """Credit the best matching valid human reference."""
    return {
        "exact_match": max(exact_match(prediction, ref) for ref in references),
        "token_f1": max(token_f1(prediction, ref) for ref in references),
    }


example = score_qa_example(
    prediction="Denver, Colorado",
    references=["Denver", "the city of Denver"],
)
print(example)

该实现为便于解释而有意简化。真实提交必须使用基准官方评分器及其版本，因为看似微小的归一化选择、多参考答案处理、Unicode 处理或分词都可能改变排名。

单任务基准特别适合开发任务特定架构、调试输出约束，或衡量定义清楚的部署场景。主要局限是外部有效性：SQuAD 高分不代表开放域问答可靠，CoNLL-2003 高 F1 也不代表能在临床记录、社交媒体或另一种语言上稳健识别实体。

多任务基准

多任务基准组合多个任务，防止模型仅专精于一个狭窄数据集却显得能力广泛。这不同于多任务训练：模型可以分别在每个基准任务上训练、跨任务微调一个共享模型，或使用零样本提示；允许哪种方式由基准适配协议决定。

GLUE在共享平台上集合多种自然语言理解任务与诊断集。SuperGLUE则在 GLUE 快速进展后提供更困难的任务集合。对表示模型，MTEB通过检索、分类、聚类、语义相似度和句对分类等任务族评估嵌入。即使排行榜把结果压缩成一个数字，这些套件实际测量的是性能轮廓。

基准首先要为每个任务 \(j\) 产生分数 \(s_j\)。若任务单位或指标方向不同，可以归一化：

\[ \widetilde{s}_j= \begin{cases} \dfrac{s_j-l_j}{u_j-l_j}, & \text{if higher is better},\\[6pt] \dfrac{u_j-s_j}{u_j-l_j}, & \text{if lower is better}. \end{cases} \]

\(l_j\) 与 \(u_j\) 是任务 \(j\) 声明的上下参考点。第二种形式反转错误率或延迟等指标，使归一化后始终是越大越好。聚合分数可计算为：

\[ B=\frac{\sum_{j=1}^{J}w_j\widetilde{s}_j}{\sum_{j=1}^{J}w_j} \]

\(J\) 是任务数，\(w_j\) 是每项任务的权重。相等的 \(w_j\) 让每项任务影响相同，不考虑测试集大小；按样本量加权则让大型数据集影响更大。两者都不“中立”，都会编码基准认为什么更重要。

总体平均值可以隐藏差异极大的模型：

模型 情感 NLI 检索 宏平均
模型 A 90 90 40 73.3
模型 B 75 75 70 73.3

模型 A 在分类上更强但检索较弱，模型 B 更平衡。如果产品依赖检索，相同平均值并不表示两个模型可以互换。基准报告应在标题分数旁保留逐任务分数、最差任务性能、离散程度和任务覆盖率。

Python：聚合多任务基准，同时保留覆盖率与弱任务 
import pandas as pd


results = pd.DataFrame(
    [
        # Bounds and direction are part of the benchmark specification.
        {"task": "sentiment", "score": 0.90, "lower": 0.50, "upper": 1.00,
         "higher_is_better": True, "weight": 1.0},
        {"task": "nli", "score": 0.84, "lower": 1 / 3, "upper": 1.00,
         "higher_is_better": True, "weight": 1.0},
        {"task": "retrieval_mrr", "score": 0.61, "lower": 0.00, "upper": 1.00,
         "higher_is_better": True, "weight": 1.0},
        {"task": "generation_error", "score": 0.18, "lower": 0.00, "upper": 0.50,
         "higher_is_better": False, "weight": 1.0},
    ]
)

expected_tasks = {"sentiment", "nli", "retrieval_mrr", "generation_error"}

# Step 1: refuse partial or duplicated benchmark submissions.
assert set(results["task"]) == expected_tasks
assert not results["task"].duplicated().any()

# Step 2: map every metric to a declared 0-to-1 direction and scale.
high_better = (
    (results["score"] - results["lower"])
    / (results["upper"] - results["lower"])
)
low_better = (
    (results["upper"] - results["score"])
    / (results["upper"] - results["lower"])
)
results["normalized"] = high_better.where(
    results["higher_is_better"],
    low_better,
).clip(0, 1)

# Step 3: report the headline score together with its hidden structure.
macro_score = results["normalized"].mean()
weighted_score = (
    (results["normalized"] * results["weight"]).sum()
    / results["weight"].sum()
)

report = {
    "macro_score": macro_score,
    "weighted_score": weighted_score,
    "worst_task": results.loc[results["normalized"].idxmin(), "task"],
    "worst_task_score": results["normalized"].min(),
    "task_gap": results["normalized"].max() - results["normalized"].min(),
    "coverage": len(results) / len(expected_tasks),
}

print(results[["task", "score", "normalized"]])
print(report)

只有在上下界具有明确含义时，归一化才可辩护。基于当前排行榜模型随意进行 min-max 缩放，会让新模型提交后旧分数发生变化。稳定参考点、原始任务分数与聚合规则都应公开。

多任务基准扩大了广度，但在语言、领域、交互形式和指标选择上仍可能狭窄。一组英语分类数据集比单个分类测试更广，却不是对多语言生成、对话、安全、事实性或现实效用的完整测试。

整体式与能力导向基准

传统基准套件常从收集现有数据集开始；能力导向基准则先上升一个层级：先决定要观察哪些能力、情境、用户和风险，再选择覆盖该设计空间的任务与指标。两者区别是“我们能运行哪些数据集？”与“什么证据能区分我们关心的行为？”

过去的基准集合通常为每个数据集附上一个标准指标。HELM 则按任务、领域、人群、时间和语言分解场景，再评估多个输出属性。未填充的分支会显式显示覆盖缺口，而不是把已实现子集默认为完整。

来源：Holistic Evaluation of Language Models，图 2

HELM 是这一方法的典型案例。在原始框架中，场景不只是数据集名称，而代表一种使用情境；在测量多个指标前，模型适配方式会被标准化。准确率仍然重要，但鲁棒性、校准、公平性、偏差、毒性与效率揭示了准确率单独无法表达的权衡。

整体式基准不会给模型 \(f\) 只赋一个标量，而会产生向量：

\[ \mathbf{s}(f,c)= \left[ s_{\text{quality}}, s_{\text{robustness}}, s_{\text{calibration}}, s_{\text{fairness}}, s_{\text{safety}}, s_{\text{efficiency}} \right] \]

\(c\) 表示被评估场景，每个分量测量不同的期望属性。两个模型可能无法简单排序：一个更准确但更慢、更不鲁棒；另一个牺牲少量准确率，却有更低延迟和更稳定的子群行为。立即平均所有维度，会隐藏真实用户必须作出的决定。

能力问题 合适的场景变化 平均准确率之外的证据
模型能否理解改写？ 保持含义、改变措辞或句法 一致性与性能下降
它能否利用知识而非答案格式线索？ 平衡选项并加入对抗干扰项 按扰动类型的准确率
生成对不同用户群体是否安全？ 只改变人口属性指代的配对提示 毒性、拒绝质量与子群差距
置信度能否支持下游决策？ 跨难度与领域的问题 校准误差与选择性准确率
能否在资源预算内部署？ 固定硬件、batch size 和上下文长度 延迟、吞吐、内存与能耗代理

能力导向评估特别适合通用语言模型，因为同一文本接口支持许多应用。代价是复杂性：能力标签可能含糊，社会属性可能存在争议，自动评审器会引入另一个模型的偏差，穷尽覆盖也不可能。负责任的整体式基准应明确能力空间中哪些部分尚未测量。

实践结论不是每项研究都需要数百个测试，而是基准覆盖应由研究声明决定。声称改进情感分类器的论文可能需要聚焦的域内、领域偏移、鲁棒性、子群和效率测试；声称得到普遍更好语言模型的论文，则需要广泛得多的证据。

领域特定与多语言基准

通用基准往往不能充分代表真实领域的术语、文档结构、用户目标与错误代价。在电影评论上表现好的模型可能无法处理临床否定；能从新闻抽取组织的模型可能误解法律主体名称；流畅的通用模型也可能生成医学上似是而非却危险的答案。领域特定基准收窄目标人群，使标签和指标能够反映专家用途。

基准族 覆盖 为什么通用基准不足
BLURB 生物医学 NER、关系抽取、句子相似度、分类与 QA 生物医学术语、证据惯例和任务分布不同于开放域文本
LegalBench 法律与 NLP 研究者贡献的法律推理任务 正确推理可能依赖法律概念、司法辖区与专家解释
金融 NLP 基准 报告、申报文件、数值 QA、情感与风险语言 金融极性和重要性不同于一般情感
内部部署基准 真实产品流量、政策、失败严重度与延迟 公开数据很少精确匹配用户人群与运行约束

专家不仅要标注样本，也要定义目标。在临床 NLP 中，标注者分歧可能来自真正有歧义的证据，而非粗心；在法律中，答案可能取决于司法辖区或短提示省略的假设。若基准强制唯一标准标签，就应记录如何解决歧义。

多语言基准又增加一个维度。例如，XTREME 基准旨在跨多项任务与多种语言评估跨语言泛化，而不是把英语性能当成多语言能力代理。多语言协议必须区分几种设置：

设置 训练或提示数据 测试数据 核心问题
单语言评估 目标语言数据 相同目标语言 模型能否直接服务该语言？
零样本跨语言迁移 通常为源语言监督 未见目标语言 学到的知识能否跨语言迁移？
Translate-train 翻译后的监督数据 原生或翻译目标数据 机器翻译对适配有多大帮助？
Translate-test 源语言模型 翻译成源语言的测试输入 翻译加源语言模型能否解决任务？
多语言联合训练 多种语言的数据 已见与未见语言 联合学习能否改善广泛和低资源覆盖？

翻译测试集支持受控比较，但翻译腔可能简化句法或抹去文化特定现象。独立创作的测试集更自然，却更难精确匹配跨语言难度。两者都不是普遍最优，因此基准来源应说明采用哪种构建方式。

若 \(S_\ell\) 是语言 \(\ell\) 的分数，总共包含 \(L\) 种语言，则语言宏平均为：

\[ S_{\text{macro-lang}}=\frac{1}{L}\sum_{\ell=1}^{L}S_\ell \]

不论测试集大小，每种语言权重相同。两个补充统计量是：

\[ S_{\text{worst-lang}}=\min_{\ell}S_\ell, \qquad G_{\text{lang}}=\max_{\ell}S_\ell-\min_{\ell}S_\ell \]

\(S_{\text{worst-lang}}\) 暴露服务最差的语言，\(G_{\text{lang}}\) 测量最强与最弱语言间范围。这能防止强英语分数或几种相近高资源语言掩盖其他语言的严重失败。

Python：报告多语言性能，避免大型测试集主导 
import pandas as pd


scores = pd.DataFrame(
    [
        {"language": "English", "family": "Germanic", "n": 5000, "score": 0.91},
        {"language": "German", "family": "Germanic", "n": 1200, "score": 0.86},
        {"language": "Spanish", "family": "Romance", "n": 1400, "score": 0.84},
        {"language": "Swahili", "family": "Atlantic-Congo", "n": 500, "score": 0.58},
        {"language": "Arabic", "family": "Afro-Asiatic", "n": 700, "score": 0.64},
    ]
)

# Step 1: a micro average weights languages by their number of test examples.
micro = (scores["score"] * scores["n"]).sum() / scores["n"].sum()

# Step 2: a language macro average gives each language one vote.
language_macro = scores["score"].mean()

# Step 3: average within families first so one heavily represented family
# does not dominate the summary simply because it contains more languages.
family_scores = scores.groupby("family")["score"].mean()
family_macro = family_scores.mean()

# Step 4: retain distribution-sensitive diagnostics beside every average.
report = {
    "micro_by_examples": micro,
    "macro_by_language": language_macro,
    "macro_by_family": family_macro,
    "worst_language": scores.loc[scores["score"].idxmin(), "language"],
    "worst_language_score": scores["score"].min(),
    "language_gap": scores["score"].max() - scores["score"].min(),
}

print(scores.sort_values("score"))
print(family_scores.sort_values())
print(report)

领域与多语言基准提高了相关性，但不会自动保证公平。按语言名称覆盖仍可能遗漏方言、语码转换、识字水平、本地实体与文化特定任务。因此，结果应沿数据所支持的维度拆分，而不能只依赖多语言平均值。

基准饱和

当领先系统接近基准有效上限，以至于进一步分数提高不再提供有意义的能力差异信息时，基准就饱和了。这个上限可能是人类估计、标注一致性、指标分辨率，或数据集伪影允许的最简单策略。饱和不表示底层 NLP 问题已经解决。

多个有影响力的基准在相对短时间内从初始系统接近估计人类表现。超过水平参考线只表示在该基准评分规则下超过其人类估计，不表示获得了人类水平语言能力。

来源：Dynabench: Rethinking Benchmarking in NLP，图 1

令 \(s_0\) 为初始参考分数，\(s_h\) 为估计人类分数，\(s\) 为当前模型分数。朝参考点的归一化进展为：

\[ P=\frac{s-s_0}{s_h-s_0} \]

\(P=0\) 对应初始参考，\(P=1\) 达到人类估计，\(P>1\) 则超过它。这种归一化是描述性的，不能证明人类与模型行为等价。人类估计可能来自只获得有限说明的标注者，而模型可能利用词汇伪影或记忆相关样本。

常见饱和信号包括：

  • 分数差异小于随机种子或置信区间波动；
  • 大量提交在顶部持平，但子群失败仍然很大；
  • 测试错误只剩少数，使单个标注决定改变排名；
  • 反复改进来自基准特定提示或集成；
  • 域内分数很高，但在挑战集或偏移集上大幅下降；
  • 排行榜提升与下游效用没有关系。

出现饱和时，仅增加更难样本不一定足够。有效重设计应追问旧测试为什么失去区分力。解决方案可能是新的隐藏集、时间划分、对抗收集的失败、诊断类别、更严格污染控制、专家审核，或同时衡量鲁棒性和成本的指标。

Dynabench 提出人机协同收集：标注者创建能骗过当前系统的有效样本，这些失败成为新评估或训练数据，后续系统再面对更新轮次。旧轮次仍应保留，因为解决新失败却忘记旧能力并不算进步。

应对饱和的最佳方式通常是基准组合，而不是单一替代：保留稳定测试用于纵向比较，加入挑战集测试已知弱点，使用新数据评估当前泛化，并在声明涉及实际使用时报告真实部署测量。

数据污染与排行榜过拟合

基准有效性假设测试答案能为泛化提供新证据。若评估内容、标签或近似变体影响了模型训练或选择，数据污染就破坏这一假设。现代 NLP 污染可能发生在多个层级：

泄漏路径 示例 为什么分数误导
数据集内泄漏 近重复文章同时出现在训练与测试中 模型识别内容，而非泛化到新文档
预训练污染 公开基准问题与答案出现在 Web 规模预训练数据中 记忆或基准熟悉度参与表面零样本能力
微调污染 评估样本进入指令微调或偏好数据 即使没有显式基准标签，任务也不再未见
提示开发泄漏 测试样本指导提示措辞、示例或解码设置 测试集实际成为验证集
排行榜泄漏 反复提交揭示哪些修改提高隐藏测试分数 团队在看不到单个标签时仍能适应测试噪声

精确重复检测必要但不充分。模板、改写、答案解释、翻译版本和包含答案的段落，即使字符串不完全相同，也能传递基准信息。NAACL 研究 Investigating Data Contamination in Modern Benchmarks for Large Language Models展示了检索式重叠分析与无法访问模型训练数据时的行为测试。

对文本 \(a\) 与 \(b\)，一种简单近重复信号是其 \(n\)-gram 集合的 Jaccard 相似度：

\[ J(a,b)=\frac{|G_n(a)\cap G_n(b)|}{|G_n(a)\cup G_n(b)|} \]

\(G_n(a)\) 是文本 \(a\) 中连续 \(n\)-token 序列的集合。分子统计共享 \(n\)-gram，分母统计任一文本中出现的所有唯一 \(n\)-gram。\(J=1\) 表示集合相同，\(J=0\) 表示完全没有共享。较长 \(n\)-gram 更精确识别复制段落；较短 \(n\)-gram 更敏感，但偶然匹配更多。

Python：使用规范化词 n-gram 审计训练－测试近重复 
import re
import unicodedata


def normalize_for_overlap(text):
    # Step 1: normalize Unicode, lowercase, and keep word-like tokens.
    text = unicodedata.normalize("NFKC", text).lower()
    return re.findall(r"\w+", text, flags=re.UNICODE)


def word_ngrams(text, n=5):
    tokens = normalize_for_overlap(text)
    return {
        tuple(tokens[start:start + n])
        for start in range(len(tokens) - n + 1)
    }


def jaccard(left, right):
    if not left and not right:
        return 1.0
    if not left or not right:
        return 0.0
    return len(left & right) / len(left | right)


def find_suspicious_pairs(train_texts, test_texts, n=5, threshold=0.50):
    # Step 2: precompute fingerprints so tokenization is performed once.
    train_sets = [word_ngrams(text, n=n) for text in train_texts]
    test_sets = [word_ngrams(text, n=n) for text in test_texts]
    matches = []

    # Step 3: compare every pair for a small audit dataset.
    # At web scale, replace this quadratic loop with MinHash/LSH or retrieval.
    for test_index, test_set in enumerate(test_sets):
        for train_index, train_set in enumerate(train_sets):
            similarity = jaccard(test_set, train_set)
            if similarity >= threshold:
                matches.append(
                    {
                        "train_index": train_index,
                        "test_index": test_index,
                        "jaccard": similarity,
                    }
                )

    # Step 4: review high-overlap pairs rather than deleting them blindly.
    return sorted(matches, key=lambda row: row["jaccard"], reverse=True)


train_examples = [
    "The battery lasts for ten hours after a complete charge.",
    "The support team answered my request within one day.",
]
test_examples = [
    "After a complete charge, the battery lasts for ten hours.",
    "Customer support was friendly but could not solve the problem.",
]

print(find_suspicious_pairs(train_examples, test_examples, n=3, threshold=0.30))

重叠只是需要审核的证据，不是自动裁决。公式化法律文本、常见定义或短句可能自然重叠；反过来，语义改写可以携带同一答案，却几乎不共享词汇。严谨审计会结合精确哈希、词汇检索、语义检索、元数据与时间戳检查，以及人工审核。

排行榜过拟合与此相关，但不要求字面数据泄漏。假设第 \(k\) 次提交的真实泛化性能为 \(\mu_k\)，观察到的隐藏测试分数为：

\[ \widehat{s}_k=\mu_k+\varepsilon_k \]

\(\varepsilon_k\) 是采样噪声或基准特定波动。若研究者提交许多变体并保留最大的 \(\widehat{s}_k\)，选择依据同时包含高 \(\mu_k\) 和异常为正的 \(\varepsilon_k\)。因此，\(\max_k\widehat{s}_k\) 往往高估所选模型在新数据上的表现。这也是测试集被自适应反复查询后失去独立性的原因。

实际保护措施包括：划分前按文档去重、基于日期的测试集、私有或轮换测试、提交次数限制、与最终测试不同的公开开发集、新的确认集、数据来源记录，以及报告基准影响模型或提示选择的频率。可复用留出集理论形式化说明了为何不受限制的自适应复用会损害有效性。

没有一种措施能解决所有泄漏：

风险 有用检测 有用缓解
精确重复 加密哈希 划分前去重
近重复 n-gram、MinHash 或语义检索 把相关文档分到同一划分
Web 预训练暴露 语料搜索、时间戳、行为探针 新鲜／私有测试与透明污染审计
提示过拟合 提示历史与独立确认集 最终评估前冻结提示

NLP 中的最先进水平

最先进水平通常缩写为 SOTA，常被当作永久附着在某个模型上的头衔。在研究中，更准确的理解是一个有条件的经验声明：截至目前比较的系统中，某系统在特定基准版本、指标、适配协议、资源设置和时间下获得了最强已报告结果。

这一区分直接来自上一节。基准定义测量环境，SOTA 声明则指出该环境中的当前领先结果；如果环境改变，声明也可能改变：

\[ \text{SOTA claim} = \text{system} + \text{benchmark conditions} + \text{comparison evidence} + \text{time} \]

因此，模型可以是排行榜 SOTA，却未必可复现地更好、实践中更可取，或资源效率更高。本节会区分这些含义，让“SOTA”成为分析起点而非终点。

SOTA 究竟意味着什么？

精确的 SOTA 声明应回答：在哪项任务上最好、在哪里测量、遵循哪些规则、与谁比较，以及截至何时。“我们的模型达到最先进 NER 性能”过于宽泛。可辩护的表述更接近：“在官方 CoNLL-2003 英语测试划分与实体级 F1 评分器下，截至实验日期，我们微调系统在所包含的可比系统中获得最高已报告均值。”

声明坐标包括：

坐标 必须固定的问题 示例
任务与人群 测量哪种语言行为与文本人群？ 英语新闻命名实体识别
基准版本 使用哪些数据、划分、标签和评估器？ CoNLL-2003 与官方实体级评分器
指标 哪个目标决定“最好”？ Macro-F1、Exact Match、BLEU、MRR 或人工偏好
适配方式 允许哪些监督与工具？ 完整微调、零样本提示、检索或外部 API
资源约束 是否限制算力、延迟、内存、成本或模型大小？ 内存不超过 8 GB，p95 延迟不超过 50 ms
比较集合 包含哪些基线和先前系统？ 采用相同协议的已发表系统
统计单位 结果是最佳运行、种子均值还是置信区间？ 五个种子的均值与标准差
时间与访问 何时比较，当时可用哪个模型版本？ 在声明日期评估的检查点或 API 快照

令 \(\mathcal{F}(C)\) 为满足比较约束 \(C\) 的系统集合。受约束 SOTA 系统可表示为：

\[ f^*=\underset{f\in\mathcal{F}(C)}{\arg\max}\; \mathbb{E}_{r\sim\mathcal{R}}\left[\widehat{M}(f;r)\right] \]

\(f\) 是候选系统，\(C\) 包含允许训练数据、延迟上限等规则，\(\widehat{M}\) 是基准分数，\(r\) 表示初始化、数据顺序、采样或提示选择带来的随机性。期望要求在声明的变化来源上取得典型表现，而非最幸运的一次运行。当困惑度或延迟等指标越低越好时，用 \(\arg\min\) 替换 \(\arg\max\)。

实践中，许多论文无法观察真正期望，而是用少量运行的均值估计：

\[ \overline{s}=\frac{1}{K}\sum_{k=1}^{K}s_k, \qquad s_{\mathrm{sd}}=sqrt{\frac{1}{K-1}\sum_{k=1}^{K}(s_k-\overline{s})^2} \]

\(K\) 是独立运行次数，\(s_k\) 是第 \(k\) 次分数，\(\overline{s}\) 是样本均值，\(s_{\mathrm{sd}}\) 描述运行间波动。仅因 90.3 大于 90.1，\(90.3\pm0.5\) 的候选模型并不明显优于 \(90.1\pm0.2\) 的基线；两者分布重叠，观察差异可能小于普通训练波动。

多种有效 SOTA 可以共存：

SOTA 形式 优化目标 示例声明
绝对 SOTA 不受资源限制时最高主基准分数 官方测试集最佳实体级 F1
受约束 SOTA 满足固定预算系统中的最高分 100 ms 延迟以内最佳 F1
数据高效 SOTA 固定带标签样本量下最佳分数 最佳 32-shot 意图分类准确率
领域 SOTA 指定文本人群上的最佳结果 单一医院数据集最佳临床 NER
Pareto SOTA 在性能与一种或多种成本上不被支配 没有模型同时更准确且更便宜

这些声明回答不同研究问题。以五倍推理成本换取 0.2 个百分点可能是绝对 SOTA，而稍弱的蒸馏模型可能是受约束或 Pareto SOTA。只要条件明确，两种描述都诚实。

最深层限制是 SOTA 相对于基准。The Benchmark Lottery 表明，改变基准任务子集会改变算法排名。与社区所选任务更契合的方法可能看起来普遍更强，但另一组任务可能偏好另一方法。“在此基准上最好”绝不能无声变成“最擅长语言”。

排行榜 SOTA

排行榜 SOTA 是评估服务器或公开结果表上最高的已接受分数。排行榜是有用基础设施：标准化评分器、保护隐藏标签、保留历史比较，也让进展易于查看。但它不是完整科学仪器，因为排名会把所有实验选择压缩为一个有序数字。

不同排行榜条目可能使用不同模型规模、外部数据、集成成员数、检索访问、提示调优、测试时计算或超参数搜索预算。如果没有按这些条件划分赛道，第一名回答的是“哪个已提交系统分数最高？”，而不是“哪个算法本质更好？”

候选模型与上一领先者的观察差异为：

\[ \widehat{\Delta}=\widehat{s}_{\text{candidate}}-\widehat{s}_{\text{leader}} \]

当指标越高越好时，\(\widehat{\Delta}>0\) 足以排列两个显示分数，却不足以证明候选模型具有可靠更高的总体性能。两个分数都含有测试样本不确定性、训练随机性、实现差异，以及可能针对排行榜进行的适配。

超参数搜索还会造成另一种不对称。若一个模型获得更多试验，其最佳观察运行就有更多机会受益于有利配置与随机噪声。

在这个情感分类示例中，小型搜索预算下逻辑回归的期望验证表现更好；有更多超参数配置时，CNN 变得更好。只报告每个模型最佳运行，会隐藏为获得该结果所需的搜索量。

若 \(H\) 个超参数配置产生验证分数 \(v_1,\ldots,v_H\)，模型选择报告：

\[ v_{\max}=\max_{1\le h\le H}v_h \]

随着 \(H\) 增大，即使底层搜索空间没有改善，\(v_{\max}\) 也倾向上升。这可能来自找到真正更好的配置、有利噪声，或两者共同作用。因此，公平排行榜比较应报告调优策略与预算，而不只是最终超参数。

配对 bootstrap 可以检验候选模型是否在同一批样本的重采样版本上持续优于领先者。配对很重要，因为两个系统面对完全相同的输入。

Python：估计排行榜改进声明的不确定性 
import numpy as np
from sklearn.metrics import f1_score


def macro_f1(y_true, y_pred):
    return f1_score(y_true, y_pred, average="macro", zero_division=0)


def paired_bootstrap_difference(
    y_true,
    leader_predictions,
    candidate_predictions,
    metric_fn=macro_f1,
    rounds=5000,
    seed=42,
):
    y_true = np.asarray(y_true)
    leader_predictions = np.asarray(leader_predictions)
    candidate_predictions = np.asarray(candidate_predictions)

    assert len(y_true) == len(leader_predictions) == len(candidate_predictions)
    rng = np.random.default_rng(seed)

    # Step 1: calculate the observed candidate-minus-leader difference.
    observed = (
        metric_fn(y_true, candidate_predictions)
        - metric_fn(y_true, leader_predictions)
    )

    # Step 2: resample shared test positions and preserve paired predictions.
    differences = []
    for _ in range(rounds):
        indices = rng.integers(0, len(y_true), size=len(y_true))
        differences.append(
            metric_fn(y_true[indices], candidate_predictions[indices])
            - metric_fn(y_true[indices], leader_predictions[indices])
        )

    differences = np.asarray(differences)
    lower, upper = np.percentile(differences, [2.5, 97.5])

    # Step 3: report an interval instead of reducing the result to rank alone.
    return {
        "observed_difference": float(observed),
        "bootstrap_95pct_interval": (float(lower), float(upper)),
        "fraction_of_resamples_candidate_better": float(
            np.mean(differences > 0)
        ),
    }


# Replace these short arrays with predictions from the locked test run.
y_true = ["pos", "neg", "neutral", "pos", "neg", "neutral", "pos", "neg"]
leader = ["pos", "neg", "neutral", "neutral", "neg", "pos", "pos", "neg"]
candidate = ["pos", "neg", "neutral", "pos", "neutral", "neutral", "pos", "neg"]

print(paired_bootstrap_difference(y_true, leader, candidate))

可复现 SOTA

可复现 SOTA 表示优越性声明可以重建，并在文档化条件下重新运行时保持可信。只发布最终分数远远不够；其他研究者需要产生输入、模型状态、预测与分数的全部产物。

相关术语在不同领域用法不一，但对 NLP 可作如下实用区分：

层级 核心问题 典型要求
可重复性 原团队能否再次得到结果？ 相同代码、数据、环境与协议
计算可复现性 其他团队能否重跑公开管线？ 完整产物、版本与说明
独立复现 独立实现是否支持同一结论？ 重建方法并进行可比评估
复制／泛化 发现能否在新设置中保持？ 新数据集、语言、领域或人群

如果结果依赖不可获得的检查点或私有预处理，它可以被原团队重复，却无法被他人复现；如果同一代码只在充满伪影的单一数据集复现分数，它可能计算可复现，却不能泛化。这些代表不同证据强度。

  • 评估器实现、指标版本、人工说明或评审模型快照；
  • 原始预测、失败请求、重试策略与后处理。

Show Your Work 强调，仅有测试分数无法揭示寻找模型所用的计算过程。复现研究同样观察到不同种子、环境和依赖版本导致的结果变化。因此，可复现 SOTA 既要报告最终产物，也要报告产生它的搜索过程。

对于重复运行，候选模型应在匹配条件下与强基线比较。报告候选模型的五个种子，却从另一篇只用一个种子的论文复制基线最佳分数，会造成不对称比较。理想情况下，两者使用相同数据、评估器、种子数量、停止策略与调优预算。

实验清单可把主要依赖转为机器可读格式。哈希标识精确文件；它们不能证明数据质量，但能揭示意外替换。

实践 SOTA

实践 SOTA 是最能满足真实用例目标与约束的系统，未必拥有最高公开基准分数。生产文本来自不同用户、领域、时间、设备和语言；系统还面临基准可能不测量的延迟、成本、隐私、安全、维护和可靠性要求。

考虑心理健康支持平台的情绪分类器。排行榜可能奖励精选英语数据集上最高平均 macro-F1；部署则要求对痛苦相关类别高召回、对语码转换与非正式文本可靠、置信度经过校准、可本地推理、p95 延迟低于 100 ms，并提供人工升级路径。若模型提高 0.4 macro-F1 却违反隐私或延迟目标，它就不是实践中更好的系统。

最清晰的形式是约束优化：

\[ \begin{aligned} \max_f \quad & Q(f) \\ \text{subject to}\quad & L_{p95}(f)\le L_{\max},\\ & C_{1k}(f)\le C_{\max},\\ & \operatorname{Mem}(f)\le M_{\max},\\ & R_g(f)\ge R_{\min}\quad \text{for every critical group }g. \end{aligned} \]

\(Q(f)\) 是选定质量指标，\(L_{p95}\) 是第 95 百分位延迟，\(C_{1k}\) 是每 1,000 个输入的成本，\(\operatorname{Mem}(f)\) 是峰值内存，\(R_g\) 是关键群体 \(g\) 的必要可靠性指标，例如召回率。约束在比较质量前排除不可用模型，通常比用任意权重把一切合并为效用分数更清楚。

实践评估应反映完整系统。检索增强 QA 服务包含查询重写、检索、重排序、提示构建、生成、引用抽取、安全过滤与重试；只报告生成器分数，会忽略用户实际体验的管线。同样，分类器端到端延迟包含分词、batch、数据传输和后处理，而不只是一次 GPU 前向传播。

效率与 Pareto 最优模型

效率感知评估把性能与资源使用视为独立目标。更大模型可能只提高零点几个基准分，却需要更多内存、训练算力、推理延迟或能耗。只选择最大分数，等于假设任何性能增量都值得任意成本，而这在研究或部署中很少成立。

不同生命周期阶段有不同成本：

阶段 代表性成本 为什么重要
开发 预训练、微调、失败运行、超参数搜索、数据处理 决定研究可及性与找到模型的总成本
部署 延迟、吞吐、加速器内存、能耗与每请求价格 随每个文档或生成 token 持续累积
维护 监控、重训练、建索引、迁移与评估 决定数据和基础设施变化后系统能否持续有用

参数量和 FLOPs 是有用的硬件无关代理，但不能替代实际延迟或能耗测量。FLOPs 相近的模型可能因序列长度、内存访问、稀疏性、batch、量化和实现质量而在硬件上表现不同。公平报告应说明硬件、精度、batch size、输入长度、生成长度、预热，以及是否包含预处理。

前沿上的模型代表性能与 FLOPs 间不同的高效权衡。若某点位于另一点的右下方，它被支配：另一模型既更强又更便宜。即使没有刷新绝对最高分，Pareto 改进也具有科学价值。

来源：On the Concept of Resource-Efficiency in NLP，图 1

对越高越好的质量 \(Q\) 和越低越好的成本向量 \(\mathbf{c}\)，当以下条件成立时，模型 \(a\) 支配模型 \(b\)：

\[ Q(a)\ge Q(b), \qquad c_j(a)\le c_j(b)\;\;\text{for every cost }j, \]

并且至少有一个严格不等式。也就是说，\(a\) 在任何目标上都不差，且至少一项更好。若没有被评估替代方案支配某模型，它就是 Pareto 最优；所有这类模型组成 Pareto 前沿。

该定义避免任意交换率。诸如“准确率减 \(0.01\times\) 延迟”的加权效用可以排序模型，但系数只编码某个用户偏好。Pareto 前沿先排除明显劣势选项，再让用户按真实约束从前沿模型中选择。

Python：计算并绘制 NLP 模型的多成本 Pareto 前沿 
import matplotlib.pyplot as plt
import pandas as pd


models = pd.DataFrame(
    [
        {"model": "linear", "macro_f1": 0.86, "latency_ms": 4, "memory_gb": 0.3},
        {"model": "small", "macro_f1": 0.90, "latency_ms": 18, "memory_gb": 1.4},
        {"model": "distilled", "macro_f1": 0.915, "latency_ms": 42, "memory_gb": 2.8},
        {"model": "medium", "macro_f1": 0.919, "latency_ms": 95, "memory_gb": 6.2},
        {"model": "large", "macro_f1": 0.923, "latency_ms": 210, "memory_gb": 13.0},
        {"model": "inefficient-run", "macro_f1": 0.907, "latency_ms": 120, "memory_gb": 8.0},
    ]
)


def dominates(left, right):
    """Higher F1 is better; lower latency and memory are better."""
    no_worse = (
        left["macro_f1"] >= right["macro_f1"]
        and left["latency_ms"] <= right["latency_ms"]
        and left["memory_gb"] <= right["memory_gb"]
    )
    strictly_better = (
        left["macro_f1"] > right["macro_f1"]
        or left["latency_ms"] < right["latency_ms"]
        or left["memory_gb"] < right["memory_gb"]
    )
    return no_worse and strictly_better


# Step 1: mark a model as dominated if any competitor is no worse everywhere.
dominated_by = []
for index, candidate in models.iterrows():
    dominators = [
        competitor["model"]
        for other_index, competitor in models.iterrows()
        if other_index != index and dominates(competitor, candidate)
    ]
    dominated_by.append(dominators)

models["dominated_by"] = dominated_by
models["pareto_optimal"] = models["dominated_by"].map(len).eq(0)
frontier = models[models["pareto_optimal"]].sort_values("latency_ms")

# Step 2: visualize one cost dimension while Pareto status uses both costs.
for _, row in models.iterrows():
    color = "tab:blue" if row["pareto_optimal"] else "lightgray"
    plt.scatter(row["latency_ms"], row["macro_f1"], color=color)
    plt.annotate(row["model"], (row["latency_ms"], row["macro_f1"]))

plt.plot(frontier["latency_ms"], frontier["macro_f1"], color="tab:blue")
plt.xlabel("p95 latency (ms, lower is better)")
plt.ylabel("Macro-F1 (higher is better)")
plt.title("Performance-latency view of the Pareto frontier")
plt.show()

print(models[["model", "pareto_optimal", "dominated_by"]])

Green AI 主张在性能旁报告计算价格。简单的开发成本近似为：

\[ C_{\text{dev}}\propto E_T\,D_T\,H \]

\(E_T\) 是一个训练执行单元的成本，\(D_T\) 表示处理的训练数据量或更新单元数，\(H\) 表示模型开发试验数，包括超参数搜索。两篇论文可能都只训练一次相同最终架构，却因其中一篇搜索数百个配置而产生完全不同的开发成本。

对于处理 \(N\) 个输入的部署系统，简化生命周期成本为：

\[ C_{\text{life}}(N)=C_{\text{dev}}+N\,C_{\text{inf}} \]

\(C_{\text{inf}}\) 是每个输入的平均端到端推理成本。压缩模型可能需要昂贵蒸馏阶段，却在每次请求上节省成本。如果模型 \(A\) 的开发成本高于 \(B\)，但推理成本更低，盈亏平衡流量为：

\[ N^*=\frac{C_{\text{dev},A}-C_{\text{dev},B}} {C_{\text{inf},B}-C_{\text{inf},A}} \]

大约处理 \(N^*\) 个输入后，累积推理节省抵消额外开发成本。公式假设成本稳定且质量可比；真实分析还应包含维护、硬件利用率和预期系统寿命。

效率报告应匹配声明：

声明 最低有用测量
训练更快 达到固定质量的时间与算力，包括搜索
模型更小 参数、检查点大小、峰值内存与质量
推理更快 指定硬件上的端到端延迟分布与吞吐
生成更便宜 输入／输出 token、请求、重试与货币成本
能耗更低 实测能耗、硬件利用率、位置与工作负载
数据高效学习 匹配带标签数据预算下的学习曲线

Pareto SOTA 扩展了进步定义。匹配现有质量并将延迟减半的方法，即使没有提高最高分也很有意义。反之，远超现有成本范围的绝对 SOTA 应诚实描述为新的性能极值，而不是自动成为所有用户的最佳模型。

如何批判性阅读 SOTA 声明

SOTA 声明应被视为一个结构化论证。论文提出系统更好；基准、基线、统计分析、资源报告和产物构成证据。批判性阅读要判断证据是否支持声明的精确措辞。

首先把标题改写为条件形式：

在基准版本 \(B\)、指标 \(M\)、适配协议 \(A\)、比较集合 \(P\)、资源设置 \(C\) 与评估日期 \(t\) 下，系统 \(f\) 获得结果 \(s\)。

句子中缺失的任何内容都可能引入歧义。下面问题构成实用审计：

问题 警示信号 更强证据
声明范围是什么？ 从一个英语数据集推出“最佳 NLP 模型” 任务、领域、语言与版本特定表述
基线有竞争力吗？ 只有弱或过时参考 重跑强经典、神经与预训练基线
协议匹配吗？ 数据、提示、检索或调优预算不同 相同划分、评估器、适配规则与预算
改进大于不确定性吗？ 一个最佳种子或舍入后 0.1 分收益 种子分布、配对区间与效应量
测试集受保护吗？ 按测试反馈反复选择提示或模型 冻结选择并使用独立最终集
指标测量所需行为吗？ 开放生成只用一个重叠指标 互补自动、人工与诊断评估
改进广泛还是局部？ 只给聚合分数 逐任务、子群、难度与错误类别结果
结果可复现吗？ 缺少代码、检查点、提示或评估器版本 不可变产物、原始预测与清单
改进代价是什么？ 无搜索、硬件、延迟或 token 报告 开发与部署资源测量
能否超越基准迁移？ 无领域偏移或时间评估 跨数据集、鲁棒性与部署对齐测试

假设论文报告 92.4 macro-F1，而上一结果为 92.1。新系统从 30 个种子中选择最佳结果，基线则复制自只用一个种子的论文；测试差异的配对 95% 区间为 \([-0.1,0.6]\)，p95 延迟高三倍，也没有发布预测。正确结论不是“结果毫无价值”，而是不同证据层级支持不同陈述：

  • 它可能是已报告排行榜改进，因为 92.4 是最高显示分数；
  • 它还不是可靠性能改进，因为区间包含零且选择预算不对称；
  • 它还不是可复现 SOTA，因为产物与运行分布不完整；
  • 对延迟敏感用途，在证明质量收益值得成本前，它不是实践 SOTA。

证据强度可以看作阶梯：

证据层级 可合理声称的内容
最高单次已报告运行 候选排行榜结果
匹配种子下的均值与变化 更稳定的管线内优势
配对不确定性与受控调优预算 基准收益并非普通噪声的证据
发布产物与独立复现 可复现基准优势
跨领域、多语言或时间确认 更广泛泛化证据
部署对齐的质量、安全与资源测试 指定用途的实践优越性

即使聚合收益在统计上可靠，误差分析仍必不可少。候选模型可能改善高频简单样本，却恶化稀有关键标签。在情感计算中，更高平均情绪分数可能与对痛苦、讽刺或语码转换文本更低的召回率并存。改进方向与平均幅度同样重要。

因此，SOTA 应报告为轮廓，而不是奖杯：

维度 核心结果
排行榜 精确基准版本下的官方分数与排名
可靠性 逐运行分数、不确定性与匹配比较预算
可复现性 代码、数据／检查点修订、配置与预测
泛化 领域、语言、子群、鲁棒性与时间结果
实践性 端到端质量、延迟、成本、安全、隐私与维护
效率 开发成本、推理成本与 Pareto 状态

当“最先进水平”用于标识当前证据边界，即显式条件下观察到的最佳结果时，它最有信息价值；把局部边界描述为普遍优越性则会误导。下一步需要设计公平比较，使数据、评估、调优、随机性和报告足够规范，从而让任何 SOTA 结论都可辩护。

设计公平比较

公平比较是一种实验：允许系统间预期研究的差异发生变化，同时控制、匹配或报告其他解释。如果新编码器比基线获得更多带标签数据、更大搜索预算、不同测试划分和更有利的评估器，最终分数就无法隔离编码器本身的价值。

其逻辑接近受控实验：

实验概念 NLP 比较
处理 被测试的方法变化，例如新损失或架构
对照 不包含该变化的强基线
结果 预先声明的基准指标与诊断度量
实验单位 文档、对话、用户、查询或其他独立单位
受控条件 数据、预处理、评估器、调优策略、种子和硬件规则
干扰变量 随机初始化、实现细节、API 漂移与标注者差异

令 \(P\) 表示共享实验协议，\(m_{\text{new}}\) 与 \(m_{\text{base}}\) 只在待研究组件上不同。目标比较为：

\[ \Delta(P)= \mathbb{E}\!\left[M(m_{\text{new}};P)\right] - \mathbb{E}\!\left[M(m_{\text{base}};P)\right] \]

\(M\) 是评估度量，期望覆盖声明的随机性。只有在其余 \(P\) 共享时，把 \(\Delta(P)\) 解释为新组件的效果才合理。结论仍然依赖协议：改变数据人群或资源约束可能改变 \(\Delta\)。

公平不意味着强迫所有系统使用相同内部机制。线性分类器与 Transformer 自然会采用不同优化器。公平意味着在清楚定义的比较制度下给每种方法合理机会，并暴露仍然存在的不对称。

相同数据与数据划分

除非数据访问本身就是研究变量，否则所有系统应从相同样本学习，并在相同样本上评估。“使用相同数据集”还不够精确：不同版本可能有修正标签、删除的重复项、不同许可证、划分分配和预处理。即使一个测试样本发生变化，也可能影响接近的排行榜结果。

划分必须保护正确的独立单位。NLP 数据常含相关观察：

  • 同一文档中的多个句子；
  • 同一对话中的多轮交互；
  • 同一用户撰写或描述同一商品的评论；
  • 从同一源句生成的改写；
  • 跨网站复制的文章；
  • 只替换实体值的重复模板；
  • 来自同一患者、作者、说话人或时间段的记录。

如果相关样本跨越训练－测试边界，模型可能识别来源、风格或模板，而不是泛化到真正的新单位。因此，当目标部署单位是新文档或新用户时，句子级随机划分并不合适。

泛化问题 合适划分 NLP 示例
同一人群中的新样本 随机或分层划分 单一稳定数据集合中的平衡意图分类
新文档、用户或对话 群组感知划分 完整留出作者或对话线程
未来语言使用 时间划分 用 2025 年前评论训练，在之后评论上测试
新领域或体裁 领域留出划分 在商品评论上训练，在餐厅评论上测试
新语言 语言留出划分 在没有目标语言标签时训练多语言表示
有限数据下的模型选择 嵌套或群组感知交叉验证 只在内层训练折调优，外层折用于评估

三向划分职责不同：

划分 允许用途 禁止用途

预处理必须在训练边界内拟合。若在划分前计算 TF-IDF 词表、归一化统计、标签频率权重、特征选择或学习型分词器，都可能泄漏测试信息。标签不是唯一泄漏来源；查看测试文本也会暴露词汇、主题、长度或领域信息。

相同评估协议

两个系统即使接收相同测试样本，也可能被不同方式评估。评估协议包含原始输入到最终分数间的每一次变换：

\[ x \xrightarrow{\;P\;} x' \xrightarrow{\;A,f\;} z \xrightarrow{\;G\;} \widehat{y} \xrightarrow{\;M(\widehat{y},y)\;} s \]

\(P\) 是预处理与输入构造，\(A\) 是允许的适配过程，\(f\) 是模型，\(z\) 是原始输出，\(G\) 是解码与后处理，\(\widehat{y}\) 是最终预测，\(M\) 是评估器，\(s\) 是分数。公平比较应共享这些组件，或明确指出哪个组件属于被测试方法。

指标名称本身不能定义协议：

报告标签 会改变数值的选择
F1 二元、micro、macro、weighted、token 级或实体级平均
BLEU 分词、大小写、平滑、参考集与实现签名
ROUGE 词干化、句子切分、变体、参考聚合与软件版本
Exact Match Unicode、标点、冠词、空白与多参考归一化
Perplexity 分词器、stride、上下文窗口、token 计数与特殊 token 处理
LLM-as-judge 分数 评审模型／版本、量表、顺序、温度与重试策略

在序列标注中，不能给一个系统 token 级 F1，另一个系统严格实体级 F1。在生成任务中，除非这些资源对所有系统都允许或被声明为研究干预，否则某模型不应使用更长最大输出、更多束候选或外部检索。

提示也是协议的一部分。零样本比较应使用相同任务指令、标签描述、输出模式、示例策略、温度、最大 token 与解析器。当某模型需要不同聊天模板时，应报告精确模板，并解释如何保持语义等价。

后处理同样需要审查。把未知标签映射到多数类、丢弃失败生成、重试格式错误答案，或只抽取模式内部文本，都可能提高分数。评估器应按预先声明规则计入失败，而不是静默删除。

from dataclasses import dataclass
import hashlib
import json

from sklearn.metrics import classification_report, f1_score


@dataclass(frozen=True)
class EvaluationProtocol:
    benchmark_version: str
    labels: tuple[str, ...]
    primary_metric: str
    average: str
    failed_output_policy: str
    evaluator_version: str

    def fingerprint(self):
        payload = json.dumps(self.__dict__, sort_keys=True).encode("utf-8")
        return hashlib.sha256(payload).hexdigest()


PROTOCOL = EvaluationProtocol(
    benchmark_version="ProductSentiment-1.0",
    labels=("negative", "neutral", "positive"),
    primary_metric="macro_f1",
    average="macro",
    failed_output_policy="count_as_incorrect",
    evaluator_version="sentiment-eval-1.2.0",
)


def evaluate_submission(gold_rows, prediction_rows, protocol):
    # Step 1: align by immutable ID rather than relying on row order.
    gold = {row["example_id"]: row["label"] for row in gold_rows}
    predictions = {row["example_id"]: row.get("prediction") for row in prediction_rows}
    assert set(gold) == set(predictions), "Missing or extra prediction IDs"

    y_true = []
    y_pred = []
    failures = 0

    # Step 2: apply one declared failure policy to every system.
    for example_id in sorted(gold):
        target = gold[example_id]
        prediction = predictions[example_id]

        if prediction not in protocol.labels:
            failures += 1
            # A reserved invalid label is always counted as incorrect.
            prediction = "__INVALID_OUTPUT__"

        y_true.append(target)
        y_pred.append(prediction)

    # Step 3: compute every score through the same implementation.
    score = f1_score(
        y_true,
        y_pred,
        labels=list(protocol.labels),
        average=protocol.average,
        zero_division=0,
    )

    return {
        "protocol_sha256": protocol.fingerprint(),
        "macro_f1": score,
        "failed_outputs": failures,
        "per_class": classification_report(
            y_true,
            y_pred,
            labels=list(protocol.labels),
            output_dict=True,
            zero_division=0,
        ),
    }

应由一个中央评估器为每个系统保存的预测评分。这样可以避免各模型脚本实现略有差异的指标，也使后续审计成为可能。对于成熟基准，应直接使用官方评估器，并记录其版本或 commit。

超参数与计算预算

模型质量同时取决于方法，以及为找到良好配置投入的资源。超参数包括学习率、batch size、正则化、提示措辞、示例数量与顺序、检索深度、解码温度和停止标准。即使没有计算梯度，从多个方案中选择也属于模型开发。

总搜索成本可写为：

\[ B_{\text{search}}(m)=\sum_{h=1}^{H_m}C(m,h) \]

\(H_m\) 是方法 \(m\) 尝试的配置数，\(C(m,h)\) 是训练并评估配置 \(h\) 的成本。成本可以用加速器小时、墙钟时间、FLOPs、能耗、token、API 价格或研究相关的其他资源衡量。

相等试验数与相等算力是不同制度。大型模型十次试验可能比线性模型一百次更昂贵；反过来，只允许一次试验又可能不公平地惩罚已知需要调优的方法。研究问题应决定预算规则：

预算制度 规则 回答的问题
相等配置数 采样相同数量设置 相同调优机会下哪个方法更好？
相等算力 相同总加速器小时、FLOPs 或货币成本 哪个方法最有效利用固定开发资源？
相等墙钟时间 相同开发截止时间 在现有基础设施上哪种方法交付最快？
方法适配调优 每种方法获得合理搜索空间 每个成熟方法合理可达到怎样的性能？
固定性能目标 测量达到固定分数所需成本 哪种方法最高效达到可用质量？

没有普遍公平的制度。论文应声明制度、给出理由并报告实际预算。搜索空间与搜索算法同样重要：学习率范围选择不佳的基线，不会因为运行许多试验就成为强基线。

所有调优必须只使用训练和开发数据。若使用交叉验证，超参数选择属于内层折，性能估计属于外层折。在最终测试集上调优会把它变成开发集。

期望最佳开发分数是预算的函数：

\[ g_m(b)=\mathbb{E}\left[\max_{h:\,B_h\le b}v_{m,h}\right] \]

\(v_{m,h}\) 是配置 \(h\) 的验证性能，\(B_h\) 是累积搜索成本，\(g_m(b)\) 描述方法 \(m\) 花费预算 \(b\) 后预期可达的表现。比较完整预算－性能曲线，比比较两个最终最大值更有信息。

多个随机种子

现代 NLP 系统具有随机性。随机初始化、mini-batch 顺序、dropout mask、数据子采样、train-dev 划分、提示示例、解码与分布式 kernel 都可能改变结果。单个种子会把方法质量与一次随机轨迹混在一起。

不同随机来源应明确命名，而不是藏在一个整数后：

随机来源 改变什么 建议处理
参数初始化 任务特定权重的起点 重复训练种子
数据顺序与增强 优化路径与同时出现的样本 控制并记录 sampler 种子
划分构造 哪些样本属于 train/dev/test 锁定测试划分，单独分析划分变化
少样本示例 上下文样本与顺序 重复或预先声明示例集合
随机解码 生成输出 确定性测试固定解码，或重复生成
人工评估分配 哪位评审看到哪个输出与顺序 按记录的设计随机化，并建模评审效应

Measuring the Instability of Fine-Tuning 强调，标准差只捕捉不稳定性的一个方面。两个模型族可能平均分相近，却对哪些具体样本正确存在分歧。

对于 \(K\) 次种子运行，前文已定义样本均值和标准差。均值的估计标准误为：

\[ SE(\overline{s})=\frac{s_{\mathrm{sd}}}{\sqrt{K}} \]

在近似正态假设下，小样本置信区间可使用 Student \(t\) 分布：

\[ \overline{s}\pm t_{K-1,\,0.975}\frac{s_{\mathrm{sd}}}{\sqrt{K}} \]

\(t_{K-1,0.975}\) 是自由度 \(K-1\) 时的 97.5 百分位。区间表示对声明运行分布均值估计的不确定性。只有三或五个种子时，区间可能很宽且受异常值影响，这正是应该展示所有种子分数的原因。

样本 \(i\) 的预测一致性可定义为：

\[ C_i=\max_{c\in\mathcal{Y}} \frac{1}{K}\sum_{k=1}^{K} \mathbb{1}\!\left[\widehat{y}^{(k)}_i=c\right] \]

\(\mathcal{Y}\) 是标签集合，\(\widehat{y}^{(k)}_i\) 是种子 \(k\) 对样本 \(i\) 的预测。\(C_i=1\) 表示所有运行一致，\(C_i=0.6\) 表示五次运行中有三次采用最常见预测。即使聚合分数稳定，低一致性样本也能识别不稳定决策边界。

def summarize_runs(values, confidence=0.95):
    count = len(values)
    mean = values.mean()
    standard_deviation = values.std(ddof=1)
    standard_error = standard_deviation / math.sqrt(count)
    critical = t.ppf((1 + confidence) / 2, df=count - 1)

    return pd.Series(
        {
            "runs": count,
            "mean": mean,
            "standard_deviation": standard_deviation,
            "ci_lower": mean - critical * standard_error,
            "ci_upper": mean + critical * standard_error,
            "minimum": values.min(),
            "maximum": values.max(),
        }
    )

统计显著性

统计显著性询问：在指定零假设下，观察差异是否令人意外。它不衡量效应大小、实践重要性，也不表示方法“真正更好”的概率。大型测试集可使微小效应显著，而独立单位不足时，重要效应也可能仍不确定。

对系统 \(A\) 与 \(B\)，常见零假设为：

\[ H_0:\;\Delta=M(A)-M(B)=0 \]

备择假设可以是双侧 \(H_1:\Delta\ne0\)，也可以在观察结果前已合理确定方向时使用单侧 \(H_1:\Delta>0\)。看到有利方向后才选择单侧检验会夸大证据。

评估单位至关重要。两个系统处理相同样本，因此预测成对；但同一对话中的话语或同一文档中的句子并不独立。当文档或对话才是独立单位时，重采样或置换也应在该层级进行。

健全比较不会直接从两个分数跳到 p 值，而会定义评估单位、检查假设、选择合适的配对过程、估计效应量与不确定性、考虑功效，并报告完整设计。

来源：NLPStatTest: A Toolkit for Comparing NLP System Performance，图 1

合适检验取决于输出结构、指标和假设。The Hitchhiker’s Guide to Testing Statistical Significance in NLP 提供了详细的 NLP 特定决策流程。

比较设置 可能方法 重要条件
分类的成对正确性 McNemar 精确或渐近检验 每个独立单位提供成对二元结果
不可逐样本分解的语料指标 配对 bootstrap 或近似随机化 重采样或交换正确的独立单位
逐单位数值分数 配对 \(t\) 检验、置换或 Wilcoxon 符号秩 检查分布与对称性假设
多个种子 运行级差异或层次分析 不要把测试样本与种子视为同一随机性
人工评分 混合效应模型或聚类 bootstrap 同时考虑样本与评审者依赖
多任务或多模型比较 家族错误率或错误发现率校正 声明假设族

近似随机化检验观察预测与系统名称的配对是否重要。每次随机化在随机选择的评估单位内交换两个预测，再重新计算指标差异。

若 \(d_{\mathrm{obs}}\) 是观察差异，\(d_b\) 是第 \(b\) 次随机化后的差异，则双侧 Monte Carlo p 值为：

\[ p=\frac{1+\sum_{b=1}^{B}\mathbb{1}\!\left[|d_b|\ge|d_{\mathrm{obs}}|\right]}{B+1} \]

\(B\) 是随机化次数。分子和分母加 1，避免有限模拟报告精确为零的 p 值。较小的 \(p\) 表示在 \(H_0\) 所隐含的可交换性下，至少同样极端的差异较少见。

import numpy as np
from sklearn.metrics import f1_score


def macro_f1(y_true, y_pred):
    return f1_score(y_true, y_pred, average="macro", zero_division=0)


def approximate_randomization(
    y_true,
    predictions_a,
    predictions_b,
    unit_ids,
    metric_fn=macro_f1,
    rounds=10000,
    seed=42,
):
    y_true = np.asarray(y_true)
    predictions_a = np.asarray(predictions_a)
    predictions_b = np.asarray(predictions_b)
    unit_ids = np.asarray(unit_ids)

    assert len(y_true) == len(predictions_a) == len(predictions_b) == len(unit_ids)
    unique_units = np.unique(unit_ids)
    rng = np.random.default_rng(seed)

    # Step 1: calculate the observed paired metric difference.
    observed = metric_fn(y_true, predictions_b) - metric_fn(y_true, predictions_a)
    extreme = 0

    # Step 2: swap complete documents/conversations, not correlated rows.
    for _ in range(rounds):
        swap_unit = dict(
            zip(unique_units, rng.integers(0, 2, size=len(unique_units)).astype(bool))
        )
        swap_mask = np.array([swap_unit[unit_id] for unit_id in unit_ids])

        randomized_a = predictions_a.copy()
        randomized_b = predictions_b.copy()
        randomized_a[swap_mask] = predictions_b[swap_mask]
        randomized_b[swap_mask] = predictions_a[swap_mask]

        randomized_difference = (
            metric_fn(y_true, randomized_b)
            - metric_fn(y_true, randomized_a)
        )
        extreme += abs(randomized_difference) >= abs(observed)

    # Step 3: return both effect size and evidence against the null.
    return {
        "observed_macro_f1_difference": float(observed),
        "two_sided_p_value": (extreme + 1) / (rounds + 1),
        "randomization_rounds": rounds,
        "independent_units": len(unique_units),
    }

p 值应与观察差异和置信区间一起报告。效应回答“有多大”，区间回答“精度如何”，检验则回答与 \(H_0\) 相容性的更窄问题。

多重比较需要校正。若研究尝试许多模型、任务、提示、种子和指标，至少获得一个有利结果的概率会增加。应在测试前声明主假设；对次要假设族，可用 Holm 校正控制家族错误率，或 Benjamini-Hochberg 控制错误发现率，并说明如何定义假设族。

统计显著不等于实践显著。可靠增加 0.05 个 macro-F1 点未必值得十倍推理成本；集中于关键安全类别的小幅平均收益却可能重要。最小有意义效应应连接到研究或部署决策。

建立基线阶梯

基线阶梯从暴露数据结构的测试开始，且只在每一级回答新问题时向上推进：

层级 系统 诊断问题
1 多数标签 任何模型能否超过类别先验？
2 分层随机 性能是否超过频率匹配的随机策略？
3 带否定处理的情感词典 显式极性知识能解释多少？
4 词／字符 TF-IDF＋逻辑回归 词汇模式是否足以获得强性能？
5 冻结预训练编码器＋线性分类器 不适配编码器时，通用上下文表示是否有用？
6 完整微调预训练编码器 最强标准预训练基线是什么？
7 DAPT＋相同微调 无标签域内适配是否增加价值？

最重要的比较是第 7 级对第 6 级。只把 DAPT 与 TF-IDF 比较，只能表明大型预训练管线优于经典基线，不能隔离领域自适应预训练的效果。

每一级使用相同外层划分与官方评估器。确定性系统运行一次；随机神经系统运行相同的五个声明种子。各模型族使用适合的搜索空间，并报告实际成本。

开发过程不接触最终测试标签：

  1. 使用训练数据与群组感知开发折拟合并调优每个基线；

from pathlib import Path
import json
import time


def execute_job(job, train_fn, predict_fn, evaluate_fn, output_root="results"):
    run_name = f"{job['model']}__seed-{job['seed']}"
    run_directory = Path(output_root) / run_name
    run_directory.mkdir(parents=True, exist_ok=False)

    # Step 1: train only from the locked training/development artifacts.
    started = time.perf_counter()
    model, training_record = train_fn(
        model_name=job["model"],
        seed=job["seed"],
        train_path="data/locked/train.jsonl",
        development_path="data/locked/dev.jsonl",
    )
    training_seconds = time.perf_counter() - started

    # Step 2: produce raw predictions without reading final test labels.
    prediction_path = run_directory / "test_predictions.jsonl"
    inference_record = predict_fn(
        model=model,
        input_path="data/locked/test_inputs.jsonl",
        output_path=prediction_path,
    )

    # Step 3: use the same central evaluator for every saved prediction file.
    evaluation = evaluate_fn(
        gold_path="data/private/test_gold.jsonl",
        prediction_path=prediction_path,
        expected_protocol_sha256=job["evaluator_sha256"],
    )

    # Step 4: persist score, cost, and provenance together.
    manifest = {
        **job,
        "training_seconds": training_seconds,
        "training": training_record,
        "inference": inference_record,
        "evaluation": evaluation,
    }
    (run_directory / "manifest.json").write_text(
        json.dumps(manifest, indent=2, sort_keys=True),
        encoding="utf-8",
    )
    return manifest


# `train_fn`, `predict_fn`, and `evaluate_fn` are injected interfaces.
# The same orchestration code is used for every rung of the baseline ladder.

  • 验证测试 ID 与协议哈希一致；
  • 检查任何模型是否缺失或重复预测；
  • 从原始输出重新计算指标；
  • 检查标签分布与失败输出计数；
  • 把运行日志与声明搜索预算比较；
  • 审计一部分模型分歧与标注错误；

撰写可辩护的结论

薄弱结论会过度泛化：

我们的方法为情感分析建立了新的最先进水平，并证明领域适配普遍有益。

实验不支持跨所有领域与语言的“情感分析”，也不支持普遍有益。它只研究一个基准、一套适配语料、一个编码器族与一种协议。

可辩护结论与证据匹配：

在锁定的 ProductSentiment-1.0 群组／时间测试划分上，在训练期商品文本上继续进行掩码语言预训练，使五个匹配微调种子的平均 macro-F1 从 0.817 提高到 0.829。收益同时伴随更高的最差类别 F1（0.754 到 0.781）与几乎不变的 p95 推理延迟（48 到 50 ms），但额外需要 36 GPU-hours 开发计算。在预注册的配对评估下，不确定性区间与随机化检验支持正向基准效应。该结果表明 DAPT 对此商品评论设置有帮助；它不能证明能迁移到其他领域、语言、编码器或持续变化的未来数据。

该结论包含：

  • 基准与划分范围；
  • 干预与最强可比基线；
  • 声明种子上的平均效应；
  • 与领域相关的诊断证据；
  • 部署与开发成本；
  • 不把统计证据当作效应量；
  • 明确的泛化边界。

局限应说明：无标签 DAPT 数据可能在语义上与带标签商品类别重叠；测试期只覆盖一次时间偏移；情感标签简化了混合观点；若没有作者 ID，按商品群组划分不能消除作者相关性；多语言或语码转换文本可能得到不同结果。

是否称候选模型为 SOTA 取决于比较集合。如果它超过相同基准协议下所有可比已发表结果，可以称为排行榜 SOTA。即使没有最高绝对分数，该研究仍可对 DAPT 的贡献提出有价值的因果式声明。科学价值不要求为每项改进附上 SOTA。

实用研究工作流

完整工作流通过明确关卡把想法转化为声明：

\[ \text{question} \rightarrow \text{benchmark contract} \rightarrow \text{baseline ladder} \rightarrow \text{controlled development} \rightarrow \text{locked evaluation} \rightarrow \text{uncertainty and cost} \rightarrow \text{bounded claim} \rightarrow \text{reproducible artifacts} \]

  1. 定义研究问题。 明确所提机制与比较对象。“领域自适应预训练能否提高留出商品类别的情感 F1？”可检验；“能否构建更好的模型？”不可检验。

  2. 定义目标人群与独立单位。 标识语言、领域、时间、人群，以及单位是句子、文档、对话、作者还是群组。

  3. 编写基准契约。 锁定数据集修订、划分策略、适配规则、主指标、诊断项、评估器、资源约束与禁止信息。

  4. 选择最小有意义效应。 查看测试结果前，决定怎样的收益在科学或实践上值得关注；这会影响样本量、功效与解释。

  5. 构建基线阶梯。 按需要包含数据无关、启发式、经典、轻量神经与强预训练基线。确保最近邻基线能隔离所提变化。

  6. 声明开发预算。 规定搜索空间、试验／算力上限、停止规则、提示开发策略，以及失败运行如何计费。

  7. 只依据训练与验证证据开发。 在不查看最终测试标签或反复获取排行榜反馈的情况下进行误差分析、消融与试验。

  8. 冻结最终协议。 保存划分 ID、评估器与提示哈希、所选配置、种子列表、模型修订和计划统计分析。

  9. 运行所有计划实验。 为每个基线、候选模型与种子生成不可变预测和清单。记录失败，而不是静默排除。

  10. 集中评分。 使用一个评估器，验证 ID、计入格式错误输出，并从保存预测生成聚合与诊断指标。

  11. 量化不确定性与稳定性。 根据声明，区分测试样本、训练种子、划分、提示与人工评审者带来的变化。

  12. 比较效应与成本。 报告绝对收益、区间、实践阈值、子群行为、开发计算、端到端推理成本与 Pareto 状态。

  13. 审计错误与有效性威胁。 检查分歧、标注问题、捷径、污染、领域偏移与关键失败类别。

  14. 撰写有边界的结论。 让每个词都匹配证据，并区分排行榜、可复现、实践与 Pareto SOTA。

  15. 发布证据包。 在许可范围内发布代码、配置、环境、产物修订、预测文件、清单、种子级结果与记录的局限。

接受结果前，应用三个最终关卡：

关卡 通过条件 失败后的行动
有效性 数据、任务、指标与独立单位匹配声明 缩小或重设计声明与基准
可靠性 效应在声明随机性与不确定性分析下保持 收集更多证据或报告不确定结果
效用 相对于成本、风险和预期用途，收益有意义 选择实践／Pareto 替代方案或修改约束

工作流不保证候选模型获胜，而保证无论出现什么结论都可解释。强基线击败复杂方案是有用证据；不确定差异是有效结果；Pareto 前沿上的便宜模型可能比微小绝对 SOTA 收益更有价值。

因此，基线、基准与 SOTA 共同构成一门研究规范。基线确立必须超过什么，基准定义如何收集证据，公平比较隔离结果为何不同，而 SOTA 只描述这些边界内部证据所支持的最强结论。
