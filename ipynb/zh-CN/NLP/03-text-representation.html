文本表示

离散表示（基于频率）

离散表示是 NLP 中最早使用的文本表示方法之一。它把每个单词视为唯一符号，并根据该单词在词表中的位置将其表示为向量。这类方法通常产生高维稀疏向量，也就是向量中的绝大多数值都为零。离散表示简单且容易解释，但无法捕捉单词之间的语义相似性。

独热编码

独热编码（One-Hot Encoding）是自然语言处理中把单词转换为数值的最简单方法之一。其基本思想是为词表中的每个单词分配一个唯一索引，再把该单词表示为一个满足以下条件的向量：

  • 与该单词对应的位置为 1
  • 其余所有位置均为 0

如果词表大小为 \(V\)，那么每个单词都会被表示为一个 \(V\) 维向量。

局限性：

  • 向量维度很高，计算成本高、效率低且占用大量内存
  • 无法捕捉语义关系或语义相似性
  • 只能表示训练词表中已经出现的单词
Python 实现 
def one_hot_encode(text):
    words = text.split() # Split the text by whitespace
    vocabulary = set(words) # Keep the elements unique in the set
    word_to_index = {word: i for i, word in enumerate(vocabulary)} # Assign index for each word in vocabulary, output will be like {word0 : 0, word1: 1, ...}
    one_hot_encoded = []
    for word in words: # For every word, create the vector with 0 and lenght of vocabulary firstly, then set the corresponding position to 1 according to the word index
        one_hot_vector = [0] * len(vocabulary) 
        one_hot_vector[word_to_index[word]] = 1
        one_hot_encoded.append(one_hot_vector)
    return one_hot_encoded, word_to_index, vocabulary

词袋模型（BoW）

词袋模型（Bag of Words, BoW）是一种简单且应用广泛的文本数值向量表示方法。其核心思想是根据单词在文档中出现的频率表示文档，而不考虑单词出现的顺序。

在词袋模型中，首先使用语料库中所有不同单词构建词表。随后，每篇文档被表示为一个长度等于词表大小的向量，向量中的每个元素表示某个特定单词在该文档中出现的次数。

局限性：

  • 忽略词序与语法
  • 无法捕捉单词之间的语义关系
  • 当词表很大时，向量会变得维度极高
Python 实现 
"""
Document
   ↓
Tokenization
   ↓
Count word frequency
   ↓
Map to vocabulary index
   ↓
Vector representation
"""
import numpy as np

# vocabulary (normally built from a corpus)
vocab = ["cat", "dog", "fish"]

# word -> index
word_to_index = {word: i for i, word in enumerate(vocab)}

def bow_encode(document):
    vector = np.zeros(len(vocab))
    
    words = document.split()
    
    for word in words:
        if word in word_to_index:
            vector[word_to_index[word]] += 1
    
    return vector

doc = "cat dog cat"

print(bow_encode(doc))

TF-IDF

\(\text{TF-IDF: } w_{t,d} = tf_{t,d} \times idf_{t}\)

TF-IDF（Term Frequency–Inverse Document Frequency，词频－逆文档频率）是一种建立在词袋模型之上的加权文本表示方法。它不仅衡量某个词在当前文档中出现的频率，也衡量该词在整个语料库中的重要程度。

其基本思想是：如果一个词在当前文档中频繁出现、但在其他文档中很少出现，它就应当获得较高权重。相比简单词频，TF-IDF 包含更多信息，因为在大量文档中普遍出现的词会被降低权重。TF-IDF 广泛用于文本分类、信息检索、关键词抽取和文档相似度任务。不过，它和其他离散表示一样仍然产生稀疏向量，也无法捕捉单词之间的语义或上下文关系。

词频（Term Frequency）：

  • \(\text{Raw TF: } TF(t,d) = \text{count}(t,d)\)

  • \(\text{Normal TF: } TF(t,d) = \frac{\text{Number of times term t appears in document d}}{\text{Total number of terms in documnet d}}\)

  • \(\text{Log TF: } tf_{t,d} = \begin{cases} 1 + \log_{10}(\text{count}(t,d)) & \text{if } \text{count}(t,d) > 0 \\ 0 & \text{otherwise} \end{cases}\)

  • \(\text{Binary TF: } TF(t,d) = \begin{cases} 1 & t \in d \\ 0 & \text{otherwise} \end{cases}\)

  • \(\text{Augmented TF: }TF(t,d) = 0.5 + 0.5 \frac{\text{count}(t,d)} {\max_{t'} \text{count}(t',d)}\)

逆文档频率（Inverse Document Frequency）（\(N\) 表示文档数量，\(df(t)\) 表示 token \(t\) 出现于多少篇文档）：

  • \(\text{Raw IDF: } IDF(t,D) = \log \frac{\text{Total number of documents in corpus N}}{\text{Number of documnents containing term t}}\) \(idf(t) = \log\left(\frac{N}{df_t} \right)\)
  • \(\text{Smoothed IDF: } idf(t) = \log \left(\frac{N}{1+df_t} \right) + 1\)
  • \(\text{Probabilistic IDF: }idf(t) = \log\left(\frac{N - df_t}{df_t} \right)\)
  • \(\text{Max IDF: }\log\left(\frac{\max_{t' \in D} d_{t'}}{1 + d_t}\right)\)

示例

假设有以下语料库：

  • D1: data science is fun
  • D2: data science uses data
  • D3: machine learning is fun

现在计算词项 \(data\) 在文档 \(D2\) 中的对数 TF-IDF。

对数缩放后的词频定义为：

\[ tf(t,d) = \begin{cases} 1 + \log_{10}(count(t,d)) & \text{if } count(t,d) > 0 \\ 0 & \text{otherwise} \end{cases} \]

因为 \(count(data, D2) = 2\)，

\[ tf(data, D2) = 1 + \log_{10}(2) \approx 1.301 \]

逆文档频率为：

\[ idf(t) = \log_{10}\left(\frac{N}{df_t}\right) \]

这里 \(N = 3\)，并且 \(df_{data} = 2\)，因此：

\[ idf(data) = \log_{10}\left(\frac{3}{2}\right) \approx 0.176 \]

所以 TF-IDF 值为：

\[ tfidf(data, D2) = tf(data, D2) \times idf(data) \]

\[ tfidf(data, D2) = 1.301 \times 0.176 \approx 0.229 \]

Python 实现 
import math
from collections import Counter

def compute_tfidf(documents):
    """
    Compute TF-IDF vectors for a list of documents.
    
    Parameters:
        documents (list[str]): A list of input documents.
        
    Returns:
        tfidf_vectors (list[dict]): TF-IDF vector for each document.
        vocabulary (list[str]): Sorted list of all unique terms.
        idf (dict): IDF value for each term.
    """
    
    # Step 1: Tokenize documents
    tokenized_docs = [doc.lower().split() for doc in documents]
    
    # Step 2: Build vocabulary
    vocabulary = sorted(set(word for doc in tokenized_docs for word in doc))
    
    # Step 3: Compute document frequency (df)
    N = len(documents)
    df = {}
    for term in vocabulary:
        df[term] = sum(1 for doc in tokenized_docs if term in doc)
    
    # Step 4: Compute IDF
    idf = {}
    for term in vocabulary:
        idf[term] = math.log10(N / df[term])
    
    # Step 5: Compute TF-IDF for each document
    tfidf_vectors = []
    
    for doc in tokenized_docs:
        term_counts = Counter(doc)
        tfidf = {}
        
        for term in vocabulary:
            count = term_counts.get(term, 0)
            
            # Log-scaled TF
            if count > 0:
                tf = 1 + math.log10(count)
            else:
                tf = 0
            
            tfidf[term] = tf * idf[term]
        
        tfidf_vectors.append(tfidf)
        
    return tfidf_vectors, vocabulary, idf


# Example usage
documents = [
    "data science is fun",
    "data science uses data",
    "machine learning is fun"
]

tfidf_vectors, vocabulary, idf = compute_tfidf(documents)

print("Vocabulary:")
print(vocabulary)

print("\nIDF values:")
for term, value in idf.items():
    print(f"{term}: {value:.3f}")

print("\nTF-IDF vectors:")
for i, vec in enumerate(tfidf_vectors, start=1):
    print(f"\nDocument D{i}:")
    for term in vocabulary:
        print(f"{term}: {vec[term]:.3f}")

    "A journey of a thousand miles begins with a single step." ]

    feature_index = tfidf_matrix[doc_index, :].nonzero()[1]

        print(f"{word}: {tfidf_value}")
    print("\n")

BM25（Okapi Best Matching 25）

BM25（Best Matching 25）是一种信息检索排序函数，用于估计文档与搜索查询之间的相关性。它依据词频、词项稀有程度和文档长度归一化为文档评分，通常被认为是 TF-IDF 在检索领域中的先进演化形式。BM25 的核心思想是通过词项匹配估计文档相关性，同时用更符合实际情况的假设改进 TF-IDF：

  • TF 饱和（词频效应）：某个词在文档中出现得越频繁通常越重要，但其贡献会逐渐饱和，从而避免过度强调。与 TF-IDF 不同，BM25 对词频使用饱和函数。这意味着随着某个词在文档中的出现次数增加，它对总分的贡献仍会上升，但增幅不断减小。例如，频率从 1 增加到 2 会显著提高相关性，而从 10 增加到 11 的影响很小。这可以防止文档仅通过大量重复同一词项获得不公平优势。
  • IDF（词项重要性）：罕见词包含的信息更多，因此对相关性的贡献更大。IDF 衡量一个词项在整个文档集合中的重要程度。如果某个词出现在大量文档中，例如 “the” 或 “is”，它的区分能力较弱，IDF 也较低。相反，“transformer” 或 “BM25”等罕见词具有较高 IDF，因为它们包含更多有用信息。因此，IDF 会突出更有助于区分相关文档的词项。
  • 长度归一化：对较长文档施加惩罚，避免它们仅因偶然包含查询词而获得偏高分数。长文档本来就更有可能偶然出现查询词，BM25 使用因子 \(\frac{|D|}{\text{avgdl}}\) 进行文档长度归一化。这样，精准匹配查询的短文档就不会受到不公平劣势，最终得到更均衡的排序。
  • 参数 \(k_1\) 与 \(b\)（控制机制）：BM25 使用两个关键超参数 \(k_1\) 和 \(b\)。\(k_1\) 控制词频的影响；较大值会提高 TF 的作用并减弱饱和效应，较小值则使分数更快饱和。\(b\) 控制文档长度归一化强度：\(b = 0\) 表示不做长度归一化，\(b = 1\) 表示完全归一化。实际应用中，\(k_1\) 通常设为 1.2 到 2.0，\(b\) 通常设为 0.75。二者共同平衡词频和文档长度的影响。

优点： - 词频饱和：能够认识到一个词的重要程度不会随出现次数线性增长。 - 文档长度归一化：惩罚过长文档，使不同长度的内容能够公平比较。

缺点： - 仅考虑词汇匹配：依赖完全一致的词语匹配，无法理解语义或同义词。 - 需要调参：性能取决于 \(k_1\) 和 \(b\)，最佳取值可能随数据集变化。

BM25 = IDF × TF_saturation × Length_normalization

\(\text{BM25}(D, Q) = \sum_{i=1}^{n}\text{IDF}(q_i)\cdot\frac{f(q_i, D)\cdot (k_1 + 1)}{f(q_i, D) + k_1 \cdot \left(1 - b + b \cdot \frac{|D|}{\text{avgdl}}\right)}\)

\(\text{BM25}(D, Q) = \sum_{i=1}^{n} \log\left(\frac{N - n_i + 0.5}{n_i + 0.5}\right) \cdot \frac{f(q_i, D)\cdot (k_1 + 1)} {f(q_i, D) + k_1 \cdot \left(1 - b + b \cdot \frac{|D|}{\text{avgdl}}\right)}\)

  • \(D\)：文档。
  • \(Q\)：查询。
  • \(q_i\)：\(Q\) 中第 \(i\) 个查询词项。
  • \(n\)：\(Q\) 中查询词项的数量。
  • \(\text{IDF}(q_i)\)：查询词项 \(q_i\) 的逆文档频率。
  • \(N\)：集合中的文档总数。
  • \(n_i\)：包含查询词项 \(q_i\) 的文档数量。
  • \(|D|\)：文档 \(D\) 的长度。
  • \(\text{avgdl}\)：集合中的平均文档长度。
  • \(k_1\)：控制词频饱和的超参数，常用值约为 \(1.2\) 到 \(2.0\)。
  • \(b\)：控制文档长度归一化的超参数，常用值为 \(0.75\)。

Python 实现 
import math
from collections import Counter, defaultdict


class BM25:
    def __init__(self, corpus, k1=1.5, b=0.75):
        """
        corpus: list[list[str]]
        Example:
        [
            ["this", "is", "a", "document"],
            ["this", "document", "is", "about", "nlp"]
        ]
        """
        self.corpus = corpus
        self.k1 = k1
        self.b = b
        self.N = len(corpus)
        self.doc_len = [len(doc) for doc in corpus]
        self.avgdl = sum(self.doc_len) / self.N

        self.doc_freq = defaultdict(int)
        self.term_freqs = []

        for doc in corpus:
            tf = Counter(doc)
            self.term_freqs.append(tf)

            for term in tf:
                self.doc_freq[term] += 1

    def idf(self, term):
        n_i = self.doc_freq.get(term, 0)

        return math.log((self.N - n_i + 0.5) / (n_i + 0.5) + 1)

    def score(self, query, doc_index):
        score = 0.0
        doc_tf = self.term_freqs[doc_index]
        doc_len = self.doc_len[doc_index]

        for term in query:
            f = doc_tf.get(term, 0)
            if f == 0:
                continue

            numerator = f * (self.k1 + 1)
            denominator = f + self.k1 * (
                1 - self.b + self.b * doc_len / self.avgdl
            )

            score += self.idf(term) * numerator / denominator

        return score

    def rank(self, query):
        scores = []

        for i in range(self.N):
            scores.append((i, self.score(query, i)))

        return sorted(scores, key=lambda x: x[1], reverse=True)

corpus = [
    "machine learning is useful",
    "deep learning is a part of machine learning",
    "natural language processing uses machine learning",
    "cooking recipes and food"
]

tokenized_corpus = [doc.lower().split() for doc in corpus]

bm25 = BM25(tokenized_corpus)

query = "machine learning"
tokenized_query = query.lower().split()

results = bm25.rank(tokenized_query)

for doc_id, score in results:
    print(score, corpus[doc_id])

向量相似度

将文本转换为 BoW 或 TF-IDF 等向量表示后，我们经常需要衡量两篇文档有多相似。具体做法是计算两篇文档向量表示之间的相似度。两种常见的向量相似度度量是点积（Dot Product）和余弦相似度（Cosine Similarity）。

点积

点积通过将两个向量的对应元素相乘并求和来衡量二者的相似程度。

对于两个向量：

\[ \mathbf{A} = (a_1, a_2, ..., a_n) \]

\[ \mathbf{B} = (b_1, b_2, ..., b_n) \]

点积定义为：

\[ A \cdot B = \sum_{i=1}^{n} a_i b_i \]

如果两个文档向量共享许多取值较大的单词维度，它们的点积就会更大。但是，点积会受到向量长度影响。
即使文档之间并不十分相似，较长的文档也经常产生更大的点积。

余弦相似度

余弦相似度是 NLP 中应用最广泛的相似度度量之一。它不直接比较原始向量值，而是衡量两个向量之间的夹角。两个向量之间的余弦相似度定义为：

\[ \cos(\theta) = \frac{A \cdot B}{||A|| \, ||B||} \]

其中：

  • \(A \cdot B\) 是两个向量的点积
  • \(||A||\) 和 \(||B||\) 是两个向量的模（长度）

余弦相似度的取值范围是：

  • 1 → 两个向量完全相同
  • 0 → 两个向量正交（没有相似性）
  • -1 → 两个向量方向相反

由于余弦相似度对向量长度进行了归一化，它适合比较大小不同的文档。因此，它被广泛用于信息检索、文档聚类和文本相似度任务。

Python 相似度实现 
import numpy as np
from sklearn.metrics.pairwise import cosine_similarity

# Example TF-IDF-like document vectors
A = np.array([1, 2, 0, 1])
B = np.array([0, 1, 1, 1])

# Dot product
dot_product = np.dot(A, B)
print("Dot product:", dot_product)

# Cosine similarity from scratch
cosine = np.dot(A, B) / (np.linalg.norm(A) * np.linalg.norm(B))
print("Cosine similarity:", cosine)

# Cosine similarity using scikit-learn
cosine_sklearn = cosine_similarity([A], [B])[0][0]
print("Cosine similarity (sklearn):", cosine_sklearn)

分布式表示（词嵌入／基于预测）

One-Hot、BoW、TF-IDF 和 BM25 等离散表示主要使用符号身份或频率统计表示单词。它们实用且容易解释，但通常产生稀疏向量，无法直接捕捉语义相似性。例如，在独热编码空间中，cat、dog 和 car 彼此之间的距离完全相同，尽管 cat 与 dog 在语义上明显更接近。

分布式表示通过把每个单词表示为一个低维稠密向量来解决这一问题。它不再为每个单词单独设置一个维度，而是把每个单词表示为连续向量空间中的一个点。

其关键假设是分布假设（distributional hypothesis）：

出现在相似上下文中的单词，往往具有相似意义。

例如，如果 doctor 和 nurse 经常出现在 hospital、patient 和 medicine 等单词附近，那么它们在嵌入空间中的向量也应彼此接近。

与离散表示相比，分布式表示通常具有以下特点：

  • 稠密：向量中的大多数值不为零。
  • 低维：常见维度包括 50、100、300、768 等。
  • 具有语义信息：相似单词通常具有相似向量。
  • 可复用：预训练嵌入可以迁移到下游 NLP 任务。

不过，传统词嵌入通常是静态的：无论上下文如何，每个单词只有一个固定向量。例如，在 river bank 和 bank account 中，bank 使用同一个向量。这个问题推动了 ELMo、BERT 和 GPT 等上下文嵌入的发展。

表示方法 向量类型 捕捉语义 捕捉上下文 典型用途
One-Hot 稀疏 否 否 基本编码
BoW／TF-IDF 稀疏 较弱 否 分类、检索
Word2Vec／GloVe／FastText 稠密 是 否 单词相似度、特征初始化
ELMo／BERT／GPT 稠密 是 是 现代 NLP 系统

Word2Vec

Word2Vec 是一种神经词嵌入方法，它从大型文本语料中学习稠密词向量，不需要人工标注数据，而是直接从原始文本构造自监督学习问题。

其核心思想是：

  • 可以通过一个单词周围的单词理解它。
  • 如果两个单词出现在相似上下文中，它们的嵌入也应变得相似。

Word2Vec 有两种主要架构：

  • CBOW：根据周围上下文词预测中心词。
  • Skip-gram：根据中心词预测周围上下文词。

假设有句子：

I love natural language processing

如果中心词是 natural，窗口大小为 2，那么：

context = [I, love, language, processing]
center  = natural

Word2Vec 通过调整向量，使真实单词－上下文组合获得高于无关组合的分数，从而学习嵌入。

一种常用评分函数是点积：

\[ score(w, c) = v_w \cdot v_c \]

其中：

  • \(v_w\) 是目标词向量。
  • \(v_c\) 是上下文词向量。
  • 点积越大，表示单词与上下文越匹配。
CBOW

CBOW 是 Continuous Bag of Words 的缩写。它使用周围上下文词预测中心词。

学习任务为：

\[ P(w_t \mid w_{t-m}, ..., w_{t-1}, w_{t+1}, ..., w_{t+m}) \]

其中：

  • \(w_t\) 是目标中心词。
  • \(m\) 是上下文窗口大小。
  • 周围词作为输入。

示例：

Sentence: I love natural language processing
Input context: I, love, language, processing
Target word: natural

CBOW 通常对上下文词向量求平均或求和，再使用结果预测缺失的中心词。

特点：

  • 训练速度快于 Skip-gram。
  • 对高频词表现良好。
  • 由于上下文向量会被平均，对罕见词不够敏感。
  • 常用于训练效率非常重要的场景。
Skip-gram

Skip-gram 的方向与 CBOW 相反：它使用中心词预测周围上下文词。

学习任务为：

\[ P(w_{t-m}, ..., w_{t-1}, w_{t+1}, ..., w_{t+m} \mid w_t) \]

示例：

Sentence: I love natural language processing
Input word: natural
Target context: I, love, language, processing

Skip-gram 不使用上下文预测一个词，而是使用一个中心词预测多个上下文词。

特点：

  • 训练速度慢于 CBOW，因为它会生成更多训练对。
  • 对罕见词通常表现更好。
  • 能够学习更细粒度的语义关系。
  • 当嵌入质量比训练速度更重要时，通常更适合。
负采样

朴素 Word2Vec 模型需要在整个词表上计算概率，当词表很大时成本极高。负采样（Negative Sampling）可以提高训练效率。

它不再询问：

整个词表中，哪一个单词才是正确的上下文词？

而是询问：

这个单词－上下文组合是真实的，还是伪造的？

对于如下真实组合：

(natural, language)

我们会抽取若干伪造组合，例如：

(natural, banana)
(natural, table)
(natural, window)

模型学习为真实组合分配高分，并为伪造组合分配低分。

目标函数可以写为：

\[ \log \sigma(v_w \cdot v_c) + \sum_{i=1}^{k} \log \sigma(-v_w \cdot v_{n_i}) \]

其中：

  • \((w,c)\) 是真实的单词－上下文组合。
  • \(n_i\) 是负样本。
  • \(k\) 是负样本数量。
  • \(\sigma\) 是 sigmoid 函数。
Word2Vec 总结
模型 输入 输出 优点 缺点
CBOW 上下文词 中心词 速度快、适合高频词 对罕见词较弱
Skip-gram 中心词 上下文词 适合罕见词、嵌入质量较高 训练较慢
使用 gensim 的 Python 实现 
from gensim.models import Word2Vec

sentences = [
    ["natural", "language", "processing", "is", "fun"],
    ["machine", "learning", "is", "useful"],
    ["deep", "learning", "uses", "neural", "networks"],
    ["language", "models", "learn", "word", "representations"]
]

# sg=0 means CBOW, sg=1 means Skip-gram
model = Word2Vec(
    sentences=sentences,
    vector_size=50,
    window=2,
    min_count=1,
    sg=1,
    workers=1
)

print(model.wv["language"])
print(model.wv.most_similar("learning"))

GloVe

GloVe 是 Global Vectors for Word Representation 的缩写。Word2Vec 从局部预测任务中学习，而 GloVe 则从全局单词共现统计中学习嵌入。

其基本思想是：单词意义可以由它在整个语料库中与其他单词共同出现的频率刻画。

首先，GloVe 构建共现矩阵 \(X\)，其中：

\[ X_{ij} = \text{number of times word } j \text{ appears in the context of word } i \]

随后，它学习词向量，使向量点积近似等于共现次数的对数：

\[ w_i^T \tilde{w}_j + b_i + \tilde{b}_j \approx \log(X_{ij}) \]

其中：

  • \(w_i\) 是目标词向量。
  • \(\tilde{w}_j\) 是上下文词向量。
  • \(b_i\) 和 \(\tilde{b}_j\) 是偏置项。
  • \(X_{ij}\) 是共现次数。

为什么使用对数？

原始共现次数可能非常大，而且分布高度偏斜。取对数可以减弱极高频组合的影响。

特点：

  • 使用全局语料统计。
  • 在词语类比任务上通常表现良好。
  • 产生静态词嵌入。
  • 需要构建共现矩阵，对大型词表可能占用大量内存。

类比示例：

\[ vector(king) - vector(man) + vector(woman) \approx vector(queen) \]

Python GloVe 风格共现示例 
from collections import defaultdict
import numpy as np

sentences = [
    ["natural", "language", "processing", "is", "fun"],
    ["machine", "learning", "is", "useful"],
    ["language", "models", "learn", "representations"]
]

window_size = 2
cooccurrence = defaultdict(float)

for sentence in sentences:
    for i, word in enumerate(sentence):
        start = max(0, i - window_size)
        end = min(len(sentence), i + window_size + 1)
        for j in range(start, end):
            if i == j:
                continue
            context_word = sentence[j]
            distance = abs(i - j)
            cooccurrence[(word, context_word)] += 1.0 / distance

for pair, count in cooccurrence.items():
    print(pair, count)

# In the real GloVe algorithm, these co-occurrence counts are used
# to learn dense vectors whose dot products approximate log counts.
使用 gensim 加载预训练 GloVe 的 Python 示例 
import gensim.downloader as api

# This downloads pretrained vectors, so it requires internet access.
glove = api.load("glove-wiki-gigaword-50")

print(glove["language"])
print(glove.most_similar("language", topn=5))

result = glove.most_similar(
    positive=["woman", "king"],
    negative=["man"],
    topn=1
)
print(result)

FastText

FastText 是 Facebook AI Research 开发的 Word2Vec 扩展方法。其关键思想是把一个单词表示为一组字符 n-gram，而不是把整个单词视为不可拆分的原子单位。

例如，使用字符 3-gram 时，单词 where 可以表示为：

<wh, whe, her, ere, re>

完整词向量由各个子词单位的向量组合而成。

这种方法很有用，因为具有相似形态的单词可以共享信息。例如：

run, runs, running, runner

这些单词共享子词模式，因此 FastText 能够学习相互关联的表示。

优点：

  • 处理罕见词的能力优于 Word2Vec。
  • 如果字符 n-gram 已知，即使某个词不在词表中也可以生成向量。
  • 适合形态变化丰富的语言。
  • 能够捕捉前缀、后缀和词形模式。

局限性：

  • 仍然产生静态嵌入。
  • 子词相似并不总是意味着语义相似。
  • 比 Word2Vec 稍复杂。
方法 主要信号 处理 OOV 静态或上下文
Word2Vec 局部预测 否 静态
GloVe 全局共现 否 静态
FastText 子词＋预测 较好 静态
使用 gensim 的 Python FastText 实现 
from gensim.models import FastText

sentences = [
    ["run", "runs", "running", "runner"],
    ["natural", "language", "processing"],
    ["machine", "learning", "models"]
]

model = FastText(
    sentences=sentences,
    vector_size=50,
    window=3,
    min_count=1,
    workers=1,
    sg=1
)

print(model.wv["running"])
print(model.wv.most_similar("run"))

# FastText can infer a vector for a word that was not directly seen,
# as long as its character n-grams are informative.
print(model.wv["runners"])

词嵌入评估

词嵌入主要有两种评估方式：内在评估（intrinsic evaluation）和外在评估（extrinsic evaluation）。

内在评估

内在评估不使用完整的下游 NLP 系统，而是直接测试嵌入本身的质量。

常见内在任务包括：

  • 词语相似度：检查嵌入相似度是否与人类给出的相似度判断一致。
  • 词语类比：求解 king - man + woman = queen 等类比问题。
  • 最近邻：检查与给定单词最相似的词。
  • 聚类：检查语义相关单词能否聚集在一起。

通常使用余弦相似度：

\[ \text{sim}(w_1, w_2) = \frac{v_{w_1} \cdot v_{w_2}}{||v_{w_1}|| ||v_{w_2}||} \]

示例：

similarity(cat, dog) > similarity(cat, table)
外在评估

外在评估衡量嵌入能否提高下游 NLP 任务的表现，例如：

  • 情感分析
  • 命名实体识别
  • 机器翻译
  • 文本分类
  • 问答

这种方式通常比内在评估更有意义，因为高质量嵌入应当能够帮助真实任务。不过，它的成本也更高，因为需要训练并评估完整模型。

词嵌入中的常见问题
  • 一词多义：一个单词可能有多种意义，但静态嵌入只能为它分配一个向量。
  • 偏见：嵌入可能从训练语料中学到社会或文化偏见。
  • 领域不匹配：在新闻数据上训练的嵌入可能不适合法律或医疗文本。
  • OOV 词：未知词可能没有对应嵌入，Word2Vec 和 GloVe 尤其如此。
Python 词语相似度与类比评估 
import gensim.downloader as api

# Requires internet access the first time it downloads the model.
model = api.load("glove-wiki-gigaword-50")

# Word similarity
pairs = [
    ("cat", "dog"),
    ("cat", "table"),
    ("king", "queen")
]

for w1, w2 in pairs:
    print(w1, w2, model.similarity(w1, w2))

# Word analogy: king - man + woman ? queen
print(
    model.most_similar(
        positive=["king", "woman"],
        negative=["man"],
        topn=5
    )
)

# Nearest neighbors
print(model.most_similar("language", topn=5))
Python 外在评估框架 
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score
from sklearn.model_selection import train_test_split
import numpy as np

# Suppose each document has already been converted into one embedding vector.
X = np.array([
    [0.8, 0.1, 0.3],
    [0.7, 0.2, 0.2],
    [0.1, 0.9, 0.4],
    [0.2, 0.8, 0.5]
])
y = np.array([1, 1, 0, 0])

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.5, random_state=42

pred = clf.predict(X_test)
print("Accuracy:", accuracy_score(y_test, pred))

上下文嵌入

Word2Vec、GloVe 和 FastText 等传统词嵌入属于静态嵌入，每个单词只有一个固定向量。

例如，单词 bank 在下面两个句子中具有相同嵌入：

I deposited money in the bank.
The boat stopped near the river bank.

但是，bank 在这两个上下文中的意义不同。上下文嵌入根据周围单词动态生成词语表示，从而解决这一问题。

其核心思想是：

\[ \text{embedding}(word) = f(word, context) \]

所以，同一个单词可以在不同句子中获得不同向量。

模型 架构 方向 表示类型
ELMo BiLSTM 双向 上下文词嵌入
BERT Transformer Encoder 双向 上下文 token 嵌入
GPT Transformer Decoder 从左到右 上下文 token 嵌入／生成

ELMo（基于 LSTM）

ELMo 是 Embeddings from Language Models 的缩写。它使用深层双向 LSTM 语言模型产生上下文词嵌入。

ELMo 使用两个语言模型：

  • 从左向右读取文本的前向语言模型。
  • 从右向左读取文本的后向语言模型。

因此，每个单词的表示可以同时依赖它前面和后面的单词。

对于单词 \(w_t\)，ELMo 使用以下范围的信息：

\[ w_1, ..., w_{t-1}, w_t, w_{t+1}, ..., w_n \]

ELMo 的重要性：

  • 它是从静态嵌入迈向上下文嵌入的重要一步。
  • 能够表示同一个单词在不同上下文中的不同意义。
  • 能够改进许多序列标注和分类任务。

局限性：

  • 基于 LSTM，因此比 Transformer 更难并行计算。
  • 通常用作特征提取器，而不是进行完整模型微调。
  • 后来在很大程度上被 BERT 等 Transformer 模型取代。
Python ELMo 风格上下文嵌入示例 
# ELMo is commonly accessed through libraries such as AllenNLP.
# Installation can be heavy, so this is a reference example.

from allennlp.commands.elmo import ElmoEmbedder

elmo = ElmoEmbedder()

sentences = [
    ["I", "deposited", "money", "in", "the", "bank", "."],
    ["The", "boat", "stopped", "near", "the", "river", "bank", "."]
]

for sentence in sentences:
    embeddings = elmo.embed_sentence(sentence)
    # Shape: (3 layers, sentence_length, embedding_dim)
    print(sentence)
    print(embeddings.shape)

BERT（基于 Transformer）

BERT 是 Bidirectional Encoder Representations from Transformers 的缩写。它使用 Transformer 编码器架构学习深层双向上下文表示。

与从左到右的语言模型不同，BERT 可以让一个 token 同时关注其左右两侧的单词。

示例：

The [MASK] sat on the mat.

BERT 使用左右两侧上下文共同预测被遮盖的单词。

BERT 的预训练主要使用掩码语言建模（Masked Language Modeling, MLM）：

  • 随机遮盖句子中的部分 token。
  • 使用周围上下文预测被遮盖的 token。

例如：

Input:  Natural language [MASK] is useful.
Target: processing

BERT 表示广泛用于：

  • 文本分类
  • 命名实体识别
  • 问答
  • 语义文本相似度
  • 自然语言推断

特点：

  • 擅长语言理解任务。
  • 使用双向上下文。
  • 通常会针对下游任务进行微调。
  • 并非天然为从左到右的文本生成设计。
使用 transformers 的 Python BERT 嵌入示例 
import torch
from transformers import AutoTokenizer, AutoModel

model_name = "bert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModel.from_pretrained(model_name)

sentences = [
    "I deposited money in the bank.",
    "The boat stopped near the river bank."
]

inputs = tokenizer(sentences, padding=True, return_tensors="pt")

with torch.no_grad():
    outputs = model(**inputs)

# last_hidden_state shape: (batch_size, sequence_length, hidden_size)
token_embeddings = outputs.last_hidden_state

# A simple sentence embedding can be made by averaging token embeddings.
attention_mask = inputs["attention_mask"].unsqueeze(-1)
sentence_embeddings = (token_embeddings * attention_mask).sum(dim=1) / attention_mask.sum(dim=1)

print(sentence_embeddings.shape)
使用 BERT 预测被遮盖单词的 Python 示例 
from transformers import pipeline

fill_mask = pipeline("fill-mask", model="bert-base-uncased")

results = fill_mask("Natural language [MASK] is useful.")

for item in results[:5]:
    print(item["token_str"], item["score"])

GPT

GPT 是 Generative Pre-trained Transformer 的缩写。它使用 Transformer 解码器架构，并以自回归语言模型目标进行训练。

其学习目标是预测下一个 token：

\[ P(w_t \mid w_1, w_2, ..., w_{t-1}) \]

例如：

Input:  Natural language processing is
Target: useful

GPT 从左向右读取文本，每次生成一个 token，因此特别适合生成任务。

常见 GPT 类应用包括：

  • 文本生成
  • 摘要
  • 对话系统
  • 代码生成
  • 指令遵循
  • 问答

BERT 与 GPT 对比：

比较方面 BERT GPT
架构 Transformer Encoder Transformer Decoder
方向 双向 从左到右
主要目标 预测被遮盖 token 预测下一个 token
优势 理解 生成
典型用途 分类、NER、QA 生成、对话、补全
使用 transformers 的 Python GPT 风格文本生成 
from transformers import pipeline

generator = pipeline("text-generation", model="gpt2")

outputs = generator(
    "Natural language processing is",
    max_new_tokens=30,
    num_return_sequences=1
)

print(outputs[0]["generated_text"])
Python 下一个 token 预测框架 
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

model_name = "gpt2"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name)

text = "Natural language processing is"
inputs = tokenizer(text, return_tensors="pt")

with torch.no_grad():
    outputs = model(**inputs)

next_token_logits = outputs.logits[0, -1, :]
top_tokens = torch.topk(next_token_logits, k=5)

for token_id, score in zip(top_tokens.indices, top_tokens.values):
    print(tokenizer.decode(token_id), score.item())

总结：如何选择文本表示

目标 合适的表示方法
简单基线分类 BoW／TF-IDF
搜索与排序 BM25
词语相似度或聚类 Word2Vec／GloVe／FastText
处理罕见词或形态复杂的单词 FastText
上下文敏感的语言理解 BERT／ELMo
文本生成 GPT

在现代 NLP 系统中，上下文嵌入通常是默认选择。不过，TF-IDF 和 BM25 等经典方法依然重要，因为它们简单、快速、可解释，而且是非常强的基线。
