分词

分词（Tokenisation）是把原始文本拆分为更小单位的过程，这些单位称为 token。token 随后会被映射为 token ID 和嵌入向量，再输入 NLP 模型。

Raw text -> Tokens -> Token IDs -> Embeddings -> Model

一个 token 可以是单词、字符、子词、标点，也可以是 [CLS]、[SEP]、<pad> 或 <unk> 这样的特殊符号。

分词看似只是一个很小的预处理步骤，却会显著影响：

  • 词表规模
  • 序列长度
  • 未知词处理
  • 多语言覆盖能力
  • 模型效率
  • 困惑度等 token 级评估指标

基本分词方法

空白符分词

最简单的方法是按照空白符拆分文本。

I love natural language processing
-> [I, love, natural, language, processing]

对于简单英语文本，这可以作为一个合理的基线，但它存在许多边界情况：

  • 有些语言不使用空格分隔单词。
  • 标点会与单词粘连。
  • 复合词可能成为罕见且很长的独立 token。
  • don't 等缩写形式存在切分歧义。
  • 新名字、拼写错误和领域术语可能全部变成未知词。
Python 空白符分词 
text = "I love natural language processing."

tokens = text.split()
print(tokens)

# Output: ['I', 'love', 'natural', 'language', 'processing.']
# Problem: punctuation remains attached to the final word.

基于规则的分词

基于规则的分词器使用人工编写的规则或正则表达式处理标点、缩写、数字和其他特殊情况。

I love NLP.
-> [I, love, NLP, .]

与单纯按空白符切分相比，基于规则的分词更加可控，但规则通常与特定语言绑定，而且容易在新表达或边界情况上失效。

Python 正则表达式分词 
import re

text = "Don't split U.S.A. too badly!"

# Simple rule: match words or individual punctuation symbols
pattern = r"\w+|[^\w\s]"
tokens = re.findall(pattern, text)

print(tokens)

字符级分词

字符级分词把文本拆分为单个字符。

token -> [t, o, k, e, n]

优点：

  • 词表非常小。
  • 不存在真正的未知词问题。
  • 能够处理罕见词和拼写错误。

缺点：

  • 会产生很长的序列。
  • 单个字符的语义信息较弱。
  • 更长的序列会提高建模成本。
Python 字符级分词 
text = "tokenisation"

characters = list(text)
print(characters)

单词级分词

单词级分词把每个单词视为一个 token。

I like chocolate
-> [I, like, chocolate]

优点：

  • 直观且容易阅读。
  • 序列短于字符级分词。
  • 当词表能够覆盖目标领域时效果良好。

缺点：

  • 词表可能变得非常庞大。
  • 罕见词和未见词会导致 OOV 问题。
  • 具有联系的不同词形可能被视为彼此无关的 token。

为什么需要子词分词？

子词分词是在单词级分词与字符级分词之间取得的一种折中。

unhappiness -> [un, happiness]
tokenization -> [token, ization]
lowest -> [low, est]

它可以用更小的已知片段表示罕见词或未见词，同时使序列长度短于纯字符级分词，因此非常实用。

方法 词表规模 序列长度 能否处理罕见词 主要弱点
字符级 小 长 可以 更难建模语义
单词级 大 短 较差 OOV 问题
子词级 中等 中等 可以 token 边界可能不直观

字节对编码（BPE）

字节对编码（Byte Pair Encoding, BPE）是一种常见的子词分词算法。它从较小的单位开始，不断把频繁相邻的符号对合并成更大的单位。

算法流程如下：

  1. 从单个字符组成的词表开始。
  2. 统计训练数据中相邻符号对的出现次数。
  3. 把出现最频繁的相邻符号对合并成一个新词表项。
  4. 重复上述过程，直到词表达到目标规模。

示例：

low      -> l o w _
lowest   -> l o w e s t _
newer    -> n e w e r _

如果 l + o 经常共同出现，BPE 可能先把它合并为 lo。随后，lo + w 可能变成 low，而 low + e 又可能变成 lowe。

训练完成后，BPE 会按照已经学到的合并规则及其顺序对新输入进行切分。

优点：

  • 具有良好的开放词表能力。
  • 从数据中自动学习子词。
  • 能够平衡词表规模与序列长度。
  • 是现代 NLP 系统中的强基线。

缺点：

  • 符号对频率不一定具有语言学意义。
  • token 边界可能不直观。
  • 不同训练语料会产生不同的合并规则。
Python 简化 BPE 训练示例 
from collections import defaultdict

corpus = {
    tuple("low_"): 5,
    tuple("lowest_"): 2,
    tuple("newer_"): 6,
    tuple("wider_"): 3,
    tuple("new_"): 2
}

def get_pair_counts(vocab):
    counts = defaultdict(int)
    for symbols, freq in vocab.items():
        for i in range(len(symbols) - 1):
            counts[(symbols[i], symbols[i + 1])] += freq
    return counts

def merge_pair(pair, vocab):
    merged_vocab = {}
    merged_symbol = "".join(pair)

    for symbols, freq in vocab.items():
        new_symbols = []
        i = 0
        while i < len(symbols):
            if i < len(symbols) - 1 and (symbols[i], symbols[i + 1]) == pair:
                new_symbols.append(merged_symbol)
                i += 2
            else:
                new_symbols.append(symbols[i])
                i += 1
        merged_vocab[tuple(new_symbols)] = freq

    return merged_vocab

vocab = corpus
merge_rules = []

for step in range(8):
    pair_counts = get_pair_counts(vocab)
    best_pair = max(pair_counts, key=pair_counts.get)
    merge_rules.append(best_pair)
    vocab = merge_pair(best_pair, vocab)

    print(f"Step {step + 1}: merge {best_pair} -> {''.join(best_pair)}")
    print(vocab)

WordPiece

WordPiece 是 BERT 类模型使用的一组子词分词方法。它与 BPE 一样，从较小片段构建词表；两者的重要区别在于训练时如何选择下一个新增片段。

有两个相关但容易混淆的概念：

版本 核心思想 常见解释
标准 WordPiece 加入能够最大程度提高语言模型似然的片段 似然／困惑度目标
HuggingFace WordPiece 加入关联分数最高的片段对 freq(ab) / (freq(a) * freq(b))

这两个版本在推断阶段通常使用相同规则：采用最长匹配优先进行切分，并使用 ## 等连续片段标记。

标准 WordPiece

最初的 WordPiece 思想并不只是“合并出现次数最多的符号对”。它提出的是一个更依赖模型的问题：

如果把这个新子词加入词表，在当前分词模型下，语料能够得到多大程度的更好表示？

简化后的训练流程如下：

步骤 操作 直觉
1 从小词表开始 通常包含字符和特殊 token
2 标记词内片段 在 BERT 类词表中，连续片段使用 ##
3 生成候选新片段 通常是在词内部相邻的片段
4 为每个候选项评分 估计其对语料似然／困惑度的改善
5 加入最佳候选项 词表增加一个片段
6 重复 达到目标词表规模时停止

因此，标准 WordPiece 最适合被理解为一种以提高似然为目标的词表构建算法。它偏好让分词后语料更容易建模的片段，而不一定选择原始频率最高的片段。

Initial pieces:
[u, ##n, ##a, ##f, ##f, ##a, ##b, ##l, ##e]

Possible learned pieces over time:
[u, ##n, ##aff, ##able, unaffable]

在推断阶段，词表训练完成后，分词器不会重新运行这一训练目标，而只是使用现有词表切分每个新单词。

Python 贪心 WordPiece 分词 
def wordpiece_tokenize(word, vocab, unk_token="[UNK]"):
    tokens = []
    start = 0

    while start < len(word):
        end = len(word)
        matched = None

        while start < end:
            piece = word[start:end]
            if start > 0:
                piece = "##" + piece

            if piece in vocab:
                matched = piece
                break

            end -= 1

        if matched is None:
            return [unk_token]

        tokens.append(matched)
        start = end

    return tokens

vocab = {
    "[UNK]",
    "un", "##aff", "##able",
    "token", "##ization",
    "play", "##ing"
}

for word in ["unaffable", "tokenization", "playing", "unknownword"]:
    print(word, "->", wordpiece_tokenize(word, vocab))

HuggingFace WordPiece

HuggingFace 课程中的解释，也是教学材料中经常出现的版本，使用一个具体的符号对评分公式来描述 WordPiece：

\[ score(a,b) = \frac{freq(ab)}{freq(a) \times freq(b)} \]

这个版本同样通过合并相邻片段扩展词表，但它选择的是关联分数最高的符号对，而不是原始频率最高的符号对。

分母非常关键。如果 a 和 b 各自都很常见，那么较高的共同出现频率不一定包含很多信息；相反，如果两个罕见片段经常共同出现，由于二者具有很强的关联，其分数会变高。

符号对 符号对频率 第一个片段频率 第二个片段频率 HuggingFace WordPiece 分数
u + n 20 100 80 0.0025
q + z 5 6 7 0.1190

BPE 会选择 u + n，因为它的原始频率更高；HuggingFace 风格的 WordPiece 则可能选择 q + z，因为这两个片段之间的联系强得多。

简化后的 HuggingFace 风格训练流程如下：

步骤 操作
1 把单词拆分为初始字符片段
2 统计单个片段的频率
3 统计相邻片段对的频率
4 为每个片段对计算 freq(ab) / (freq(a) * freq(b))
5 合并分数最高的片段对
6 重复操作，直到词表达到目标规模
Python HuggingFace 风格 WordPiece 符号对评分 
from collections import defaultdict

corpus = {
    ("u", "##n", "##a", "##f", "##f", "##a", "##b", "##l", "##e"): 10,
    ("u", "##n", "##h", "##a", "##p", "##p", "##y"): 8,
    ("q", "##z"): 5,
}

def get_wordpiece_scores(corpus):
    token_freqs = defaultdict(int)
    pair_freqs = defaultdict(int)

    for tokens, word_freq in corpus.items():
        for token in tokens:
            token_freqs[token] += word_freq
        for pair in zip(tokens, tokens[1:]):
            pair_freqs[pair] += word_freq

    scores = {}
    for pair, pair_freq in pair_freqs.items():
        left, right = pair
        scores[pair] = pair_freq / (token_freqs[left] * token_freqs[right])

    return pair_freqs, token_freqs, scores

pair_freqs, token_freqs, scores = get_wordpiece_scores(corpus)

for pair, score in sorted(scores.items(), key=lambda x: x[1], reverse=True):
    print(pair, "pair_freq=", pair_freqs[pair], "score=", round(score, 4))

连续片段标记：##

BERT 类 WordPiece 词表通常使用 ## 标记连续片段。

unaffable -> [un, ##aff, ##able]
playing   -> [play, ##ing]

该标记告诉模型，一个片段是单词的开头，还是前一个片段的延续。

Token 含义
play 可以作为单词开头
##ing 必须接在某个词首片段之后
token 可以作为单词开头
##ization 必须接在某个词首片段之后

最长匹配优先分词

词表训练完成后，WordPiece 通常使用贪心的最长匹配优先策略切分新单词。

例如，假设词表包含：

un, ##aff, ##able, ##a, ##ble

那么：

unaffable -> un + ##aff + ##able

分词器首先从当前位置开始，寻找词表中能够匹配的最长片段。如果找不到任何有效片段，经典 BERT 风格 WordPiece 通常会把整个单词转换为 [UNK]。

BPE、标准 WordPiece 与 HuggingFace WordPiece 对比

方法 训练决策 核心直觉
BPE 合并出现最频繁的相邻符号对 频繁共同出现的片段很有用
标准 WordPiece 加入对语料似然／困惑度改善最大的片段 更好的词表应当带来更好的建模效果
HuggingFace WordPiece 合并 freq(ab) / (freq(a) * freq(b)) 最高的符号对 强关联比原始频率更重要

Unigram／SentencePiece

通常与 SentencePiece 联系在一起的 Unigram 分词，采用与 BPE 和 WordPiece 相反的构建方向。

它不是从小词表开始向上合并，而是从一个大型候选词表开始，不断删除作用较小的片段。

高层算法如下：

  1. 从一个包含字符、高频子串和完整单词的大型词表开始。
  2. 估计每个片段对于解释语料的作用。
  3. 删除贡献最小的片段。
  4. 重复操作，直到词表达到目标规模。

SentencePiece 的一个重要优势是可以直接处理原始文本，不需要依赖空白符预分词。它通常使用 ▁ 这样的可见标记表示空格。

I like NLP
-> [▁I, ▁like, ▁NLP]
Python SentencePiece 示例 
# pip install sentencepiece

import sentencepiece as spm

# Train a model from a text file.
# spm.SentencePieceTrainer.train(
#     input="corpus.txt",
#     model_prefix="spm_demo",
#     vocab_size=1000,
#     model_type="unigram"
# )

sp = spm.SentencePieceProcessor(model_file="spm_demo.model")

text = "I like natural language processing."

print(sp.encode(text, out_type=str))
print(sp.encode(text, out_type=int))

字节级 BPE

字节级 BPE 从字节而不是字符或单词开始。字节能够表示任意文本，因此这种方法对罕见符号、emoji、拼写错误和多语言输入具有很强的覆盖能力。

GPT 类分词器通常使用字节级 BPE 或相关变体。

其中一个细节是，空格经常会被编码为 token 的一部分。例如，GPT-2／RoBERTa 风格的分词器可能使用 Ġ 表示某个 token 出现在空格之后。

"Hello world" -> [Hello, Ġworld]

优点：

  • 覆盖能力极强。
  • 不存在真正的未知字符。
  • 对网页文本和多语言文本具有较强鲁棒性。

缺点：

  • token 可能很难阅读。
  • token 数量可能不符合直觉。
Python GPT-2 字节级 BPE 示例 
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("gpt2")

examples = [
    "Hello world",
    "Hello   world",
    "I love pizza!"
]

for text in examples:
    print(text)
    print(tokenizer.tokenize(text))
    print(tokenizer.encode(text))

特定语言的分词

不同语言不能使用完全相同的分词方式。

对于中文、日文和泰文等语言，单词边界并不总是由空格标出。在传统 NLP 流水线中，分词本身可能是一个独立任务。

中文示例：

我喜欢自然语言处理
-> [我, 喜欢, 自然语言, 处理]

现代多语言模型通常使用子词或字节级分词，而不是显式词语切分；不过，在部分任务中，专门的分词工具仍然很有用。

Python 使用 jieba 进行中文分词 
# pip install jieba

import jieba

text = "我喜欢自然语言处理"
print(list(jieba.cut(text)))

现代模型中的分词

现代 NLP 模型通常使用子词分词。

模型家族 常见分词方式
BERT WordPiece
GPT 类模型 BPE／字节级 BPE 变体
T5／ALBERT／XLNet 变体 SentencePiece／Unigram 变体
Llama 类模型 BPE／SentencePiece 变体

分词会改变序列长度，因此也会影响模型成本。在 Transformer 中，自注意力的计算量随序列长度近似二次增长，所以一个产生大量 token 的分词器会使相同文本的处理成本更高。

分词也会影响评估。例如，语言模型困惑度依赖所采用的分词方式，因此使用不同分词器得到的困惑度通常不能直接比较。

特殊 Token

许多神经 NLP 模型会加入特殊 token 来表示结构。

Token 含义
[CLS] 分类 token，BERT 经常使用
[SEP] 句子或片段之间的分隔符
[MASK] 掩码语言建模中的被遮盖 token
<s> 序列开始
</s> 序列结束
<pad> 批处理时使用的填充 token
<unk> 未知 token

特殊 token 属于词表的一部分，并拥有各自独立的嵌入向量。

Python Token ID 与特殊 Token 
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained("bert-base-uncased")

text = "Natural language processing is useful."
encoded = tokenizer(text)

print("Tokens:", tokenizer.convert_ids_to_tokens(encoded["input_ids"]))
print("Token IDs:", encoded["input_ids"])
print("Special tokens:", tokenizer.special_tokens_map)

总结

分词方法 核心思想 优点 缺点
空白符分词 按空格切分 简单基线 无法处理许多语言和边界情况
规则／正则分词 使用人工规则 更加可控 与语言绑定且容易失效
字符级 拆分为字符 没有 OOV 问题 序列非常长
单词级 拆分为单词 直观 词表庞大且存在 OOV 问题
BPE 合并出现最频繁的相邻符号对 强子词基线 频率不一定具有实际意义
WordPiece 使用似然式或关联式评分构建子词词表 用于 BERT 类模型 边界可能不直观
Unigram／SentencePiece 从大词表开始，逐步剪除片段 能够直接处理原始文本 训练过程更复杂
字节级 BPE 在字节上运行 BPE 覆盖能力极强 token 可能很难阅读

一条实用的经验法则是：

  • 简单的经典模型基线可以使用单词级分词。
  • 大多数神经 NLP 模型可以使用 BPE 或 WordPiece。
  • 当多语言覆盖和原始文本鲁棒性很重要时，可以使用 SentencePiece 或字节级方法。
