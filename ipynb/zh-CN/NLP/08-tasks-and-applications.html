NLP 任务与应用

NLP 任务把开放式语言问题转化为可学习契约。契约规定哪些信息进入系统、必须产生什么输出、有哪些监督信号，以及如何判断成功。“理解这条评论”还不是任务；“给定一条评论，预测 positive、neutral 或 negative 之一”才是任务，因为输入、输出空间与评估目标都已明确。

同一真实应用往往包含多个任务。客服助手可能要分类意图、抽取商品名、检索政策、生成回答，并估计用户是否越来越沮丧。把整个产品当成一个不透明生成问题，会隐藏这些不同错误模式；任务分解使数据收集、模型选择、评估和人工审核更容易推理。

本章按任务所产生的信息结构进行分组：

任务族 典型输入 典型输出 核心问题
理解与预测 一段文本、文本对或 token 序列 标签、关系或对齐标签 文本表达或蕴含什么？
知识访问 查询加语料集合或段落 排序证据或答案 相关信息在哪里？
生成 源文本、对话上下文或指令 新文本序列 应生成什么文本？
情感计算 语言及可选说话人／上下文信号 情感倾向、情绪、评价或共情行动 表达、体验或适合回应的情感是什么？

这些组并非刚性边界。抽取式问答预测 token span，生成式问答则产生序列；信息检索既可以是完整搜索任务，也可以是检索增强生成器的内部组件。真正有用的习惯，是在选择模型前识别实际输入－输出契约。

从语言问题到任务形式

任务族、输入、输出与监督

任务形式可以用样本数据集描述：

\[ \mathcal{D} = \{(x_i, y_i)\}_{i=1}^{N}, \]

其中 \(N\) 是样本数，\(x_i\) 是第 \(i\) 个样本的输入表示，\(y_i\) 是期望输出。符号看似简单，但 \(x_i\) 和 \(y_i\) 的含义会改变整个学习问题。

  • 在文档分类中，\(x_i\) 是一篇文档，\(y_i\) 是一个标签；
  • 在命名实体识别中，\(x_i = (x_{i1}, \ldots, x_{iT})\) 是 token 序列，\(y_i = (y_{i1}, \ldots, y_{iT})\) 是对齐标签序列；
  • 在自然语言推断中，\(x_i\) 是 (premise, hypothesis) 文本对，\(y_i\) 是二者的语义关系；
  • 在翻译中，\(x_i\) 是源语言序列，\(y_i\) 是长度可能不同的目标语言序列；
  • 在检索中，一个训练样本可以包含查询、一个相关文档与一个或多个不相关文档。

监督来源同样重要。专家提供的标准标签、用户点击、出版方对齐的翻译，以及另一个模型生成的回答，并不具有相同可靠性或含义。训练前要询问：目标由什么过程产生，它是否真正代表预期构念？

现代模型可以用统一的 text-to-text 接口呈现多种任务。translate English to German: 或 summarize: 等前缀告诉模型生成什么。这统一了软件接口，却不会消除任务差异：分类仍需标签校准，翻译仍需充分性，摘要仍需事实性检查。

图中翻译、可接受性分类、语义相似度和摘要共享同一个 text-to-text 模型接口。来源：Raffel et al., Exploring the Limits of Transfer Learning with a Unified Text-to-Text Transformer。

任务契约

稳健任务契约记录的不只是任务名称，还应说明：

契约元素 问题 示例
预测单位 什么对象接收一次预测？ 一条客服消息
输入上下文 可使用哪些证据？ 消息加前两轮对话
输出模式 哪些值合法？ {intent, confidence, entities}
标签语义 每个目标代表什么？ refund_request 表示明确要求退钱
监督来源 谁或什么创建目标？ 两位经过培训、带仲裁的标注者
拒答策略 何时允许系统拒绝？ 置信度低于校准阈值
主指标 优化什么行为？ 意图间 macro F1
关键切片 哪些区域必须单独检查质量？ 短消息、语码转换、新商品
下游行动 预测后会发生什么？ 路由到财务队列
错误成本 哪些错误最重要？ 漏掉账户被盗报告

该契约防止一种常见失败：为错误的业务问题训练出准确模型。例如，预测消息主题并不等于预测应由哪个团队处理。主题与历史路由可能相关，但路由还取决于政策、紧急程度和可用人员。

Python：表示并验证任务契约 
from dataclasses import dataclass
from typing import Callable

@dataclass(frozen=True)
class TaskContract:
    name: str
    input_fields: tuple[str, ...]
    output_labels: tuple[str, ...]
    main_metric: str
    allow_abstention: bool = True

    def validate_example(self, example: dict) -> None:
        # Step 1: verify that every required input is present.
        missing = [field for field in self.input_fields if field not in example]
        if missing:
            raise ValueError(f"missing input fields: {missing}")

        # Step 2: verify that supervised targets follow the declared schema.
        if "label" in example and example["label"] not in self.output_labels:
            raise ValueError(f"unknown label: {example['label']}")

contract = TaskContract(
    name="support_intent",
    input_fields=("message", "previous_turn"),
    output_labels=("refund", "delivery", "account", "other"),
    main_metric="macro_f1",
)

training_example = {
    "message": "The reset link has expired again.",
    "previous_turn": "I cannot sign in.",
    "label": "account",
}

contract.validate_example(training_example)
print("example matches the task contract")

任务契约也是通向评估的桥梁。指标必须反映输出结构，测试集必须反映预期上下文。token 分类器不能只用文档准确率评估，对话代理也不能只用单条回答的流畅度评估。

理解与预测任务

理解任务把语言映射为受限输出，例如类别、关系或附着在每个 token 上的标签。其输出比开放文本更容易验证，但表面简单可能隐藏有关标签含义、上下文与类别不平衡的困难决策。

文本分类

文本分类为一段文本分配一个或多个标签。文本可以是句子、评论、邮件、文档或完整对话。常见应用包括主题路由、垃圾邮件检测、意图识别、毒性检测、情感分析和文档编码。

对含 \(K\) 个类别的单标签分类，模型估计：

\[ p(y=k \mid x), \qquad k \in \{1, \ldots, K\}. \]

\(x\) 是输入文本，\(y\) 是类别变量，\(p(y=k \mid x)\) 是模型对类别 \(k\) 正确的估计概率。预测类别通常为：

\[ \hat{y} = \arg\max_k p(y=k \mid x). \]

argmax 选择概率最大的类别，却不能说明该概率是否校准，也不能说明模型在此输入上是否值得信任。在高影响工作流中，使用阈值或拒答规则可能比始终选择一个标签更合适。

应区分三种输出设置：

设置 输出规则 示例
二分类 两个标签之一 spam vs not spam
多分类 \(K\) 个标签中恰好一个 billing, delivery, account, other
多标签 标签的任意子集 一条投诉可以同时是 delivery 和 refund

分类质量高度依赖预测单位。一整条评论可以标为负面，即使它赞扬商品、只批评配送。如果应用需要这种区分，基于方面的情感分析或 span 抽取会比文档级分类更合适。

Python：训练可复现 TF-IDF 分类基线 
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report
from sklearn.pipeline import Pipeline

train_texts = [
    "My parcel still has not arrived",
    "Please refund the duplicate charge",
    "The password reset link has expired",
    "Where can I download the invoice?",
]
train_labels = ["delivery", "refund", "account", "billing"]

test_texts = [
    "The tracking page has not changed for a week",
    "I was charged twice and need my money back",
]
test_labels = ["delivery", "refund"]

# Step 1: learn lexical features only from the training split.
# Keeping vectorization inside the pipeline prevents test-data leakage.
model = Pipeline([
    ("tfidf", TfidfVectorizer(ngram_range=(1, 2), min_df=1)),
    ("classifier", LogisticRegression(max_iter=1000, random_state=7)),
])

# Step 2: fit the complete baseline under one reproducible configuration.
model.fit(train_texts, train_labels)

# Step 3: inspect predictions and class probabilities, not only accuracy.
predictions = model.predict(test_texts)
probabilities = model.predict_proba(test_texts)

for text, label, scores in zip(test_texts, predictions, probabilities):
    confidence = max(scores)
    print(f"{label:>8}  confidence={confidence:.3f}  text={text}")

print(classification_report(test_labels, predictions, zero_division=0))

即使最终系统使用 Transformer，这个词汇基线仍有价值。如果复杂模型没有显著超过 TF-IDF，数据集可能奖励关键词而不是上下文推理。基线章节说明如何控制这类比较，评估章节则详细解释 macro F1、校准与切片分析。

序列标注

序列标注为每个输入位置预测一个对齐输出。给定 token：

\[ x = (x_1, x_2, \ldots, x_T), \]

模型产生标签：

\[ y = (y_1, y_2, \ldots, y_T). \]

\(T\) 是 token 数，\(x_t\) 是第 \(t\) 个 token，\(y_t\) 是对应标签。对齐是其定义性属性：输出位置 \(t\) 描述输入位置 \(t\)。常见任务包括词性标注、命名实体识别、组块分析、槽位填充与错误检测。

token 分类器可以根据上下文表示独立预测每个 \(y_t\)。条件随机场等结构化模型还会为标签间转移评分。当有效输出存在依赖时，这很有用，例如 I-PER 通常跟在 B-PER 或 I-PER 后，而不会直接跟在 O 后。

词性标注

词性标注为每个 token 分配名词、动词、形容词或限定词等语法类别。标签取决于上下文：book 在 read the book 中是名词，在 book a ticket 中是动词。POS 标签支持句法分析、信息抽取、语言学分析与规则式后处理，尽管现代上下文模型可能在内部学到大量相同信息。

标签集代表理论与实践选择。较小的通用标签集支持跨语言比较，细粒度语言特定标签集则捕捉特定语法的重要差异。分词与标注必须一致：缩写、标点、多词表达和子词片段都需要明确对齐规则。

命名实体识别

命名实体识别找出提及实体的 span，并分配人物、组织、地点、商品或日期等类型。它通常用 BIO 标签表示：

Wei       B-PER
joined    O
Sydney    B-LOC
Data      B-ORG
Lab       I-ORG

B-X 开始类型为 X 的实体，I-X 延续它，O 表示实体之外的 token。NER 不只是检测专有名词。领域实体可能小写（iPhone、基因名称），普通词可能成为商品名，医学、法律、金融与客服所需的本体也各不相同。

Python：把 BIO 标签转换为实体 span 
tokens = ["Wei", "joined", "Sydney", "Data", "Lab", "today"]
tags = ["B-PER", "O", "B-LOC", "B-ORG", "I-ORG", "O"]

def bio_to_spans(tokens, tags):
    spans = []
    current_tokens = []
    current_type = None
    start = None

    # Step 1: append a sentinel O tag so the final entity is closed.
    for index, (token, tag) in enumerate(zip(tokens + [None], tags + ["O"])):
        prefix, entity_type = (tag.split("-", 1) + [None])[:2]

        # Step 2: close the current entity when a new span or O begins.
        if current_tokens and (prefix in {"B", "O"} or entity_type != current_type):
            spans.append({
                "text": " ".join(current_tokens),
                "type": current_type,
                "token_start": start,
                "token_end": index,  # exclusive
            })
            current_tokens, current_type, start = [], None, None

        # Step 3: start or continue a valid entity span.
        if prefix == "B":
            current_tokens = [token]
            current_type = entity_type
            start = index
        elif prefix == "I" and current_type == entity_type:
            current_tokens.append(token)

    return spans

for entity in bio_to_spans(tokens, tags):
    print(entity)

序列标注通常应在用户真正关注的结构上评估。对 NER，只有边界与类型都正确，实体才正确。因为大多数 token 为 O，token 准确率可能看起来很高，而系统实际上漏掉几乎所有实体。

自然语言推断

自然语言推断（NLI）预测 hypothesis 是否可由 premise 推出。标准标签为：

标签 含义 示例
entailment premise 提供充分支持 A child is running -> Someone is moving
contradiction hypothesis 与 premise 冲突 A child is running -> Nobody is moving
neutral premise 既不能证明也不能否定 A child is running -> The child is late for school

模型估计 \(p(y \mid p, h)\)，其中 \(p\) 是 premise，\(h\) 是 hypothesis，\(y\) 是关系标签。NLI 要求词汇知识、否定、量词、指代消解、世界知识，有时还需要语用假设，因此广泛用于诊断句对推理。

标签具有方向性。若 A poodle is a dog 蕴含 A dog is present，反向并不能推出有一只贵宾犬。数据集伪影也可能让任务比预期容易。例如，标注者编写矛盾样本时常使用 nobody 等特征词，使模型无需阅读 premise 就能利用 hypothesis。

Python：检查 NLI 预测的方向与一致性 
examples = [
    {
        "premise": "Every approved request received a confirmation email.",
        "hypothesis": "Some approved requests received confirmation emails.",
        "label": "entailment",
    },
    {
        "premise": "No account was suspended.",
        "hypothesis": "At least one account was suspended.",
        "label": "contradiction",
    },
]

def build_pair(premise, hypothesis):
    # Step 1: preserve field names so their direction cannot be swapped silently.
    return f"premise: {premise} hypothesis: {hypothesis}"

for item in examples:
    forward = build_pair(item["premise"], item["hypothesis"])
    reverse = build_pair(item["hypothesis"], item["premise"])

    # Step 2: create a directional contrast case for evaluation.
    print("gold:", item["label"])
    print("forward:", forward)
    print("reverse:", reverse)
    print()

应用中，NLI 可用于事实核验、一致性检查、零样本分类，以及检测生成答案是否得到证据支持。不过，NLI 分数不是通用真相检测器；结果取决于提供的 premise 与训练数据学到的关系定义。

理解任务 输出粒度 最适合 主要风险
文本分类 句子或文档 路由、主题、意图 标签隐藏局部证据
序列标注 token 或 span NER、槽位、语言标签 边界与分词不匹配
NLI 文本间关系 蕴含与一致性 标注伪影与缺少世界上下文

知识访问任务

知识访问任务把语言请求连接到当前输入之外存储的信息。检索返回证据候选，问答把证据转化为直接答案。在现代系统中两者常被串联，但仍应分开评估，因为生成器无法恢复检索器从未提供的证据。

信息检索与排序

信息检索（IR）接收查询 \(q\) 与文档集合 \(\mathcal{C}\)，然后按估计相关性排序文档。结果是有序列表，而不是一个类别标签：

\[ d_{(1)}, d_{(2)}, \ldots, d_{(k)}, \]

其中 \(d_{(1)}\) 是排名最高的文档，\(k\) 是返回数量。搜索引擎、法律取证、文献搜索、客服知识库与 RAG 系统都依赖此操作。

BM25 等词汇检索奖励精确词项重叠，同时校正文档长度与常见词。稠密检索把查询和文档编码为向量，再使用点积或余弦相似度。词汇检索擅长名称、标识符与稀有词；相关文本措辞不同时，稠密检索更强。混合检索组合两种信号：

\[ s_{\text{hybrid}}(q,d) = \alpha s_{\text{lexical}}(q,d) + (1-\alpha)s_{\text{dense}}(q,d). \]

\(s_{\text{lexical}}\) 与 \(s_{\text{dense}}\) 是归一化分数，\(\alpha \in [0,1]\) 控制平衡。只有分数位于可比尺度时，公式才有意义。排名融合通过组合排名位置而非原始分数，规避了校准问题。

检索监督可以来自专家相关性判断、点击、购买、引用或问答对。行为信号数量丰富，却受现有排名偏置：用户无法点击从未看见的相关结果。

Python：使用倒数排名融合组合词汇与稠密排名 
lexical_ranking = ["doc_policy_7", "doc_refund_2", "doc_account_4"]
dense_ranking = ["doc_refund_2", "doc_policy_7", "doc_delivery_9"]

def reciprocal_rank_fusion(rankings, k=60):
    scores = {}

    # Step 1: convert each rank into a bounded contribution.
    # The constant k prevents the top position from dominating too strongly.
    for ranking in rankings:
        for rank, document_id in enumerate(ranking, start=1):
            scores[document_id] = scores.get(document_id, 0.0) + 1 / (k + rank)

    # Step 2: sort the merged candidates by their accumulated rank evidence.
    return sorted(scores.items(), key=lambda item: item[1], reverse=True)

for document_id, score in reciprocal_rank_fusion(
    [lexical_ranking, dense_ranking]
):
    print(f"{score:.5f}  {document_id}")

检索的首要问题通常是召回：候选集合是否包含所需证据？重排序器可以改善顺序，却无法找回缺失文档。检索质量还取决于文档分段、元数据过滤、新鲜度、重复项和访问权限，这些会在现代系统章节继续展开。

问答

问答（QA）为自然语言问题产生答案。任务会随证据来源与答案表示方式变化。

QA 设置 证据 输出
抽取式 提供的段落 连续文本 span
多项选择 问题加候选项 一个候选标签
开放域 大型外部集合 检索证据加答案
生成式 段落、检索文档或模型知识 自由形式答案序列
对话式 当前问题加对话历史 依赖上下文的答案

在抽取式 QA 中，编码器为每个上下文 token 生成表示，两个预测头估计开始与结束概率：

\[ P(i,j \mid q,c) = P_{\text{start}}(i \mid q,c) P_{\text{end}}(j \mid q,c), \qquad i \leq j. \]

\(q\) 是问题，\(c\) 是上下文，\(i\) 是答案起点，\(j\) 是终点。模型选择联合分数高的有效 span。乘积假设起点与终点头提供兼容证据；实现还会限制最大答案长度，并把最佳 span 与“无答案”分数比较。

生成式 QA 可以综合信息并用自然语言回答，却也可能加入证据中不存在的陈述。生产 QA 系统应保留证据来源，并区分“文档没有回答”与“模型可以生成一个貌似合理的句子”。

Python：选择有效抽取式 QA span 
tokens = ["Refunds", "are", "processed", "within", "five", "business", "days", "."]
start_prob = [0.01, 0.01, 0.03, 0.12, 0.70, 0.08, 0.03, 0.02]
end_prob =   [0.01, 0.01, 0.02, 0.03, 0.05, 0.20, 0.65, 0.03]

def best_span(tokens, start_prob, end_prob, max_answer_tokens=5):
    best = {"score": -1.0, "start": None, "end": None}

    # Step 1: enumerate only legal spans with start <= end.
    for start in range(len(tokens)):
        last_end = min(len(tokens), start + max_answer_tokens)
        for end in range(start, last_end):
            score = start_prob[start] * end_prob[end]

            # Step 2: retain the highest-scoring valid answer span.
            if score > best["score"]:
                best = {"score": score, "start": start, "end": end}

    # Step 3: convert inclusive token boundaries back into answer text.
    answer = " ".join(tokens[best["start"]:best["end"] + 1])
    return answer, best

answer, evidence = best_span(tokens, start_prob, end_prob)
print("answer:", answer)
print("span evidence:", evidence)

检索与 QA 解决知识访问的不同环节。检索询问应阅读哪些证据，QA 询问从证据可推出什么答案。只测答案质量会隐藏弱检索，只测检索又会隐藏无依据生成。

系统 需要检索？ 答案构造 适合场景
文档搜索 是 用户阅读结果 探索与高用户控制
抽取式 QA 有时 复制 span 答案明确出现在文本中
生成式 QA 通常 综合回答 需要组合或解释证据
RAG 助手 是 检索、生成并引用 知识变化且来源重要

生成任务

生成任务产生可变长度序列。常见形式对以输入 \(x\) 为条件的输出 \(y=(y_1,\ldots,y_M)\) 概率建模：

\[ p(y \mid x) = \prod_{t=1}^{M} p(y_t \mid y_{<t}, x). \]

\(M\) 是输出长度，\(y_t\) 是第 \(t\) 步生成的 token，\(y_{<t}\) 包含此前所有 token。该乘积表示自回归生成：每个下一 token 决策依赖源输入与部分输出。局部概率高的 token 可能导向较差完整序列，因此解码策略很重要。

流畅文本不自动等于正确文本。每种生成任务还施加意义保持、证据忠实、对话一致、风格、安全或术语等额外约束。

机器翻译

机器翻译（MT）把源语言序列转换成目标语言序列，同时保持含义并产生自然的目标语言文本。翻译不是逐词替换；词序、形态、习语、省略主语、礼貌、性别与文化惯例都可能要求显著重组。

神经机器翻译通常使用编码器－解码器。编码器表示源文本，解码器在关注相关源位置的同时生成目标 token。多语言模型跨多语言对共享参数，可以向低资源语言迁移模式，但共享容量与不平衡数据也可能偏向高资源语言。

训练通常使用平行句对 \((x,y)\) 并最小化 token 级负对数似然。推理时，贪心或束搜索产生候选译文。模型仍可能遗漏内容、误译名称、过度直译习语，或在异常源文本上产生幻觉。法律、医疗和技术领域仍需要术语约束与人工审核。

Python：使用明确模型运行翻译并进行质量检查 
from transformers import pipeline

# Step 1: pin a concrete model instead of relying on an unspecified default.
translator = pipeline(
    task="translation",
    model="Helsinki-NLP/opus-mt-en-de",
)

source = "The refund will be issued within five business days."

# Step 2: generate a bounded translation.
result = translator(source, max_new_tokens=80)[0]["translation_text"]
print("source:", source)
print("translation:", result)

# Step 3: preserve terms that require separate verification.
# Real systems use terminology lists, named-entity checks, and back-translation
# or bilingual human review for high-impact content.
required_concepts = ["refund", "five", "business days"]
print("concepts requiring QA:", required_concepts)

BLEU、chrF 与学习型语义指标适合在数据集层面比较系统，却不能认证单句翻译。人工评估应考虑充分性、流畅度、术语，以及错误的潜在后果。

文本摘要

文本摘要压缩源文本，同时保留最重要信息。抽取式摘要选择现有句子或 span；生成式摘要产生新措辞并可组合信息，却增加无依据细节的风险。

目标取决于用途。新闻标题、临床交接、会议行动清单与法律案例摘要需要不同内容选择。压缩程度可表示为：

\[ \text{compression ratio} = \frac{|y|}{|x|}, \]

其中 \(|x|\) 是源长度，\(|y|\) 是用相同单位（如 token）计算的摘要长度。比例越小表示压缩越强，却不表示摘要越好；过度压缩可能删除限定条件、不确定性或少数观点。

基于注意力的编码器－解码器在生成每个摘要 token 时学习哪些源位置相关。下图说明这种对齐：解码器使用对源隐藏状态进行注意力计算得到的上下文向量。

源词影响用于生成下一个摘要词的上下文向量。来源：See, Liu, and Manning, Get To The Point: Summarization with Pointer-Generator Networks。

现代 Transformer 摘要器用 self-attention 与 cross-attention 替代循环状态，但源文本到摘要的对齐问题仍然存在。摘要可以很流畅，却扭曲谁做了什么、改变数字，或把不确定性变成确定事实。

Python：构建可检查的抽取式摘要基线 
import re
from collections import Counter

document = (
    "The support team introduced a new refund workflow. "
    "Requests are now checked automatically for duplicate charges. "
    "High-value refunds still require manual approval. "
    "The change reduced average handling time by 18 percent."
)

def extractive_summary(text, sentence_count=2):
    sentences = re.split(r"(?<=[.!?])\s+", text.strip())
    words = re.findall(r"[a-z]+", text.lower())
    frequencies = Counter(words)

    scored = []
    for position, sentence in enumerate(sentences):
        sentence_words = re.findall(r"[a-z]+", sentence.lower())

        # Step 1: score a sentence by normalized content-word frequency.
        score = sum(frequencies[word] for word in sentence_words)
        score /= max(len(sentence_words), 1)
        scored.append((score, position, sentence))

    # Step 2: choose strong sentences, then restore source order.
    selected = sorted(scored, reverse=True)[:sentence_count]
    selected = sorted(selected, key=lambda item: item[1])
    return " ".join(sentence for _, _, sentence in selected)

summary = extractive_summary(document)
print(summary)

# Step 3: compare source and summary lengths as a diagnostic.
ratio = len(summary.split()) / len(document.split())
print(f"compression ratio: {ratio:.2f}")

抽取式基线灵活性较低，却能提供有价值的事实性参考，因为每个选中句子都来自源文本。强生成式系统应评估覆盖、相关性、连贯性和陈述级忠实度，而不只看 ROUGE。

对话与会话系统

对话系统跨多轮选择回答或行动。与孤立生成不同，当前输入的含义依赖会话状态：

User: I need to change it.

没有前文，就无法知道 it 指什么，也不知道希望修改什么。因此，对话系统要维护某种历史、实体、用户目标、工具结果与未解决问题表示。

任务导向对话旨在完成预订、故障排查或账户管理等目标；开放域对话优先考虑有吸引力且符合上下文的交流。许多部署助手结合两者：自由语言围绕受约束工作流展开。

经典任务导向管线包含：

user utterance
-> intent and slot extraction
-> dialogue state update
-> policy or action selection
-> tool execution
-> response generation

端到端语言模型可以在一次调用中执行多个步骤，但当行动具有真实后果时，系统仍需要显式状态与验证。

Python：执行行动前维护显式对话状态 
from dataclasses import dataclass

@dataclass
class RefundState:
    order_id: str | None = None
    reason: str | None = None
    confirmed: bool = False

def next_action(state: RefundState) -> str:
    # Step 1: request missing information rather than inventing it.
    if state.order_id is None:
        return "ask_for_order_id"
    if state.reason is None:
        return "ask_for_reason"

    # Step 2: require explicit confirmation before a consequential tool call.
    if not state.confirmed:
        return "ask_for_confirmation"

    # Step 3: only a complete, confirmed state may reach the refund tool.
    return "submit_refund_request"

state = RefundState(order_id="A-1042", reason="duplicate charge")
print(next_action(state))

state.confirmed = True
print(next_action(state))

对话质量是多维的。回答可以流畅却没有完成任务，可以完成任务却不礼貌，也可以符合当前一轮却与早期信息矛盾。因此，评估会结合任务成功、回答质量、状态准确率、安全性与用户结果。

生成任务 含义约束 典型失败 有用控制
翻译 保留源含义 遗漏或误译 术语检查与双语审核
摘要 保留重要且有依据的陈述 事实扭曲 源归因与陈述核验
对话 与状态和目标一致 虚构状态或不安全行动 显式状态、工具、确认与回退

情感计算与情感分析

情感计算研究能够识别、表示或回应情感倾向、情绪、心境、评价、立场与共情等情感现象的系统。文本只提供情感的间接证据，不是对一个人内部状态的直接测量。Fine, do whatever you want 可能表示无奈、愤怒、许可或其他含义，取决于说话人、历史与语气。

这一区分具有基础意义：

目标 问题 示例输出
情感倾向 评价是正面还是负面？ negative
情绪表达 文本表达了什么情绪？ frustration
体验情绪 说话人可能感受到什么？ uncertain, possibly frustration
立场 对目标持什么态度？ against policy change
共情 什么回答能承认并支持用户？ validation plus appropriate help

模型不应静默地从表达跳到诊断。检测到负面语言不能证明一个人的心理健康状况、意图或稳定人格。

表示情感

情感可用类别或维度表示。类别方案使用 joy、anger、sadness、fear 等标签，或更细粒度情绪；维度方案把情感放入连续空间，通常包括效价（愉悦到不愉悦）与唤醒度（平静到激活），有时加入支配度等第三维。

两种表示都不是普遍正确。类别便于路由与分析；维度更平滑地表示强度与相似性。细粒度类别造成标签稀疏与分歧，粗粒度类别又可能抹去失望与愤怒等重要差别。

GoEmotions 数据展示了标签不平衡与情绪间关系。一些标签频率远高于其他标签，相关情绪形成聚类。这提醒我们，情绪标签并不是相互独立、同样常见的盒子。

左图展示标签频率与标注者一致性，右图展示情绪间相关性与层次分组。来源：Demszky et al., GoEmotions: A Dataset of Fine-Grained Emotions。

情感分析

情感分析预测评价极性，通常为 positive、neutral 或 negative。文档级情感假设一个主导判断，句子级情感将其局部化。基于方面的情感分析同时识别目标方面及其对应情感：

The camera is excellent, but the battery is disappointing.

camera  -> positive
battery -> negative

方面形式对商品分析更可操作，因为能分离混合观点；它也更困难：系统要识别方面 span、把观点连接到正确方面、处理隐含目标，并理解否定与比较。

情感依赖领域。unpredictable 对汽车可能是负面，对惊悚片却可能是正面。星级评分提供方便的远程监督，但三星评论可能同时包含赞扬与严重批评。讽刺、礼貌、引用话语与语码转换进一步增加映射难度。

情绪识别

情绪识别常用多标签分类，因为一句话可以表达多种情绪。对每个情绪 \(k\)，模型预测独立 sigmoid 概率：

\[ p_k = \sigma(z_k) = \frac{1}{1+e^{-z_k}}. \]

\(z_k\) 是情绪 \(k\) 的 logit，\(e\) 是自然对数底，\(\sigma\) 把任意实数映射到 \((0,1)\)。与 softmax 不同，sigmoid 概率无需和为一，因此 sadness 与 disappointment 可以同时激活。

多标签二元交叉熵损失为：

\[ \mathcal{L} = -\frac{1}{K}\sum_{k=1}^{K} \left[y_k\log p_k + (1-y_k)\log(1-p_k)\right]. \]

\(K\) 是情绪标签数，\(y_k \in \{0,1\}\) 是标准指示值，\(p_k\) 是预测概率。第一项惩罚对存在情绪给出低概率，第二项惩罚对不存在情绪给出高概率。稀有情绪可能需要类别加权、采样或标签特定阈值。

Python：对情绪预测应用标签特定阈值 
probabilities = {
    "anger": 0.44,
    "disappointment": 0.72,
    "sadness": 0.58,
    "neutral": 0.08,
}

# Thresholds should be selected on validation data for the intended metric.
# A rarer or high-impact emotion may need a different operating point.
thresholds = {
    "anger": 0.40,
    "disappointment": 0.55,
    "sadness": 0.60,
    "neutral": 0.50,
}

# Step 1: retain every label that passes its own calibrated threshold.
predicted = [
    label
    for label, probability in probabilities.items()
    if probability >= thresholds[label]
]

# Step 2: preserve scores for review instead of exposing only hard labels.
ranked = sorted(probabilities.items(), key=lambda item: item[1], reverse=True)

print("predicted emotions:", predicted)
print("ranked evidence:", ranked)

标注者分歧不总是标注噪声。由于上下文缺失或情感解释具有主观性，读者可能合理地推断出不同情绪。保留标签分布或多个标注，可能比强制一个多数标签更有信息。

共情与情绪感知交互

对话中的共情不等于预测一个情绪，再插入同情短语。有用回答可能需要识别情境、不作无依据假设地确认用户感受，并采取恰当行动。

考虑：

User: I have explained this three times and the charge is still there.

较弱回答可能说 You sound angry.，这给用户贴标签并可能加剧交流。更强回答会承认经历并推进任务：I am sorry you have had to repeat this. I will check the duplicate charge using the case details already provided.

因此，情绪感知系统至少应分开三个决策：

affective evidence in the message
-> uncertainty-aware interpretation
-> response strategy appropriate to context and policy

最终策略可以是道歉、澄清、降温、庆祝、转介，或直接高效解决问题。在敏感场景中，情感预测应支持经过培训的人类，而不是诊断用户或触发不可逆行动。

情感任务 输出 强应用场景 重要限制
文档情感 极性标签 聚合反馈趋势 隐藏方面与混合观点
方面情感 方面加极性 商品或服务诊断 隐含方面很难
情绪分类 一个或多个情绪标签 会话分析 解释具有主观性与上下文依赖
维度情感 效价／唤醒度分数 跟踪渐进变化 尺度在业务上可能难解释
共情回答 回答策略或文本 支持与福祉界面 表面共情可能夸大理解

选择并限定 NLP 任务

最佳任务不一定是最时髦模型支持的任务，而是输出能直接支持合法用户或组织决策，且错误可测量、可管理的任务形式。

从期望行动出发：

user or operational need
-> decision to support
-> information required for that decision
-> task output
-> supervision and data
-> model family
-> evaluation and fallback

若目标是路由客服消息，多分类可能足够；若要精确展示涉及哪个商品和订单，再加入实体或槽位抽取；若答案依赖政策文档，就必须检索；若系统还要自然解释答案，可在检索证据后加入生成。每增加一个组件，都会增加价值与新失败模式。

端到端应用案例

考虑一个多语言客户反馈平台。产品需求不只是 analyze feedback，而是帮助团队识别紧急问题、了解受影响商品、找到支持政策并适当回应。

一种分解设计是：

incoming message
-> language and domain detection
-> intent and urgency classification
-> product, order, and issue span extraction
-> aspect-level sentiment and emotion signals
-> policy retrieval
-> grounded answer generation
-> human review for low-confidence or high-impact cases

每项输出有不同目标与指标：

组件 示例输出 重要失败
意图分类器 duplicate_charge 案例路由到错误团队
实体抽取器 order A-1042 行动应用到错误账户
情感模型 frustration probability 0.71 把中性措辞当成敌意
检索器 refund policy version 3 检索到过时政策
生成器 cited explanation 向用户作出无依据承诺
审核策略 escalate to billing specialist 高风险案例被自动处理

该案例说明，即使一个大型模型技术上能产生所有字段，任务边界仍然有用。显式契约支持组件测试、针对性数据、访问控制、可解释回退与失败归因。系统仍可共享一个编码器或使用一个生成模型，但必须针对它声称执行的不同任务分别评估行为。

本章可以归纳为四个问题：

  1. 系统必须产生什么精确信息？
  2. 应以什么粒度表示这些信息？
  3. 哪些证据与监督支持该目标？
  4. 输出将如何评估并用于下游？

回答这些问题，才能把有趣的语言问题转化为可辩护的 NLP 任务。学习路径后续章节再提供比较系统、理解风险，以及将任务集成进完整现代 NLP 应用所需的工具。
