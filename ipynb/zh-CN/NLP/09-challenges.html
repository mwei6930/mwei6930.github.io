挑战、风险、伦理与安全

NLP 系统并非运行在空白实验室中。它们读取人产生的语言，从被制度与历史塑造的数据中学习，再影响有关这些人的决策。因此，系统即使在基准上技术准确，仍可能在部署情境中不可靠、不公平、不安全或不合适。

本章核心不只是模型是否犯错。所有统计模型都会犯错，更重要的问题是：

what can fail
-> who can be affected
-> how serious is the impact
-> how can the risk be detected
-> what controls should be applied
-> who is responsible when the system fails

例如，错误的电影推荐通常影响较低；同类无依据生成若出现在医疗摘要中，就可能影响治疗并成为高影响安全故障。风险同时取决于模型行为与使用情境。

本章把负责任 NLP 视为系统属性。数据收集、标注、建模、评估、界面设计、部署策略、监控和人工监督都会影响最终结果。末端加入内容过滤器，无法修复管线更早阶段引入的所有问题。

层级 核心问题 示例失败
语言 系统是否理解语言？ 把讽刺按字面理解
统计 模型能否泛化？ 在新领域性能崩溃
事实 输出是否有依据且正确？ 摘要虚构诊断
社会 收益与错误是否公平分布？ 某种方言收到更多毒性误报
隐私 个人数据是否得到恰当处理？ 模型复现电子邮件地址
安全 攻击者能否操纵系统？ 注入指令覆盖预期任务
运行 故障能否被发现并处理？ 有害分布偏移后没有告警
治理 责任与补救是否明确？ 受影响用户无法申诉自动决策

本章重点不同于评估章节。评估解释如何测量模型质量；本章询问某些失败为什么重要、如何转化为伤害，以及技术与组织控制应如何应对。下一章再说明这些控制如何融入现代 RAG、工具调用与智能体系统。

理解 NLP 风险

风险是 NLP 系统促成不期望结果的可能性，结合了事件是否发生的不确定性与一旦发生的后果严重程度。伦理提供原则，用来判断哪些结果可接受、谁的利益应被考虑，以及开发者与部署方承担什么义务；安全则把原则转化为具体工程与运行控制。

这些概念相互关联，却不等同：

概念 主要焦点 典型问题
模型错误 预测与目标不同 标签或文本是否错误？
可靠性 在预期条件下保持可信行为 质量能否跨输入与时间稳定？
鲁棒性 在变化或攻击下保持稳定 小变化是否导致大故障？
安全 防止或控制不可接受伤害 故障能否伤害人或系统？
伦理 价值、权利、义务与收益／伤害分布 系统是否应该这样使用？
治理 权力、流程、文档与问责 谁决策、监控并响应？

技术故障与社会技术伤害

技术故障是模型或系统行为缺陷；伤害是个人、群体、组织或社会经历的负面后果。区分二者很重要，因为同一故障在不同情境中会造成不同伤害，系统即使按设计工作也可能产生有害结果。

考虑一个简历排序模型，它给包含与某社会群体相关词语的申请较低分。技术故障可能来自偏置训练数据或代理特征；资源分配伤害是合格申请者获得更少面试；组织伤害包括较差招聘决策与信任流失；若无人监控子群结果或提供申诉渠道，则还存在治理失败。

这种关系通常是一条链，而非一个事件：

historical practice
-> biased data
-> learned association
-> ranking decision
-> human reliance on ranking
-> unequal access to opportunity

NLP 特别具有社会技术性，因为语言承载社会身份、权力、礼貌、文化假设与上下文。毒性检测器不只是在识别句子的固定属性，而是在把政策定义应用到可能包含引用、反歧视言论、群体内重新使用的贬义词、幽默或社群规范的语言上。

有用分析应区分三个层级：

层级 示例 适当响应
组件故障 NER 漏掉一个地址 改进数据、模型或阈值
系统故障 脱敏管线暴露漏检地址 增加分层检测与验证
影响故障 地址暴露导致骚扰 提供事故响应、支持与补救

改进模型可以减少第一层故障，但预防最终伤害还需要产品设计、访问控制、日志、升级机制与问责。

利益相关者、情境与风险严重度

利益相关者包括构建、运行、使用系统，以及被系统表示或影响的任何人。直接用户只是其中一组。招聘经理使用排序模型，但求职者才是被评估者；临床医生使用摘要器，患者则是被摘要记录的主体；旁观者的消息、图像或个人详情进入模型输入时，也可能受影响。

测量风险前，至少识别以下角色：

利益相关者 示例 可能受到的影响
开发者 构建分类器的团队 正确性与可维护性
部署方 集成模型的组织 合规与运行可靠性
操作者 使用输出的审核员或分析师 工作负担与决策质量
直接用户 向聊天机器人提问的人 有用且安全的帮助
决策对象 被分类或排序的人 机会、尊严与正当程序
数据主体 在训练或输入数据中被提及的人 隐私与同意
受影响社群 承受聚合效应的群体 表征与公平待遇
审计者或监管者 独立监督机构 证据、可追踪性与问责

一种简单优先级模型为：

\[ R = L \times I \times E \]

其中 \(R\) 是相对风险分数，\(L\) 是故障发生的估计可能性，\(I\) 是影响严重度，\(E\) 是暴露量，即可能遇到该故障的人数或决策数。如果各因素取 1 到 5，结果范围为 1 到 125。低概率但灾难性事件仍可能优先级很高；小错误若重复数百万次，也会因暴露量而重要。

该公式只是优先级辅助，不是对人类伤害的客观测量。数字可能掩盖对“谁的影响被计算”、伤害能否逆转、受影响者是否同意承担风险的分歧，因此分数必须配有书面推理。

Python：构建小型 NLP 风险登记表 
risks = [
    {
        "name": "medical summary invents a medication",
        "likelihood": 2,
        "impact": 5,
        "exposure": 4,
        "owner": "clinical NLP lead",
        "control": "source-grounded generation plus clinician approval",
    },
    {
        "name": "sentiment model fails on code-mixed reviews",
        "likelihood": 4,
        "impact": 2,
        "exposure": 3,
        "owner": "model evaluation lead",
        "control": "language-slice tests and targeted data collection",
    },
    {
        "name": "support chatbot reveals an account identifier",
        "likelihood": 2,
        "impact": 4,
        "exposure": 3,
        "owner": "privacy engineer",
        "control": "input minimization, output DLP scan, and access logging",
    },
]

# Step 1: calculate a relative score for prioritization.
for risk in risks:
    risk["score"] = (
        risk["likelihood"] * risk["impact"] * risk["exposure"]
    )

# Step 2: review the highest-priority risks first.
for risk in sorted(risks, key=lambda item: item["score"], reverse=True):
    print(f"{risk['score']:>3} | {risk['name']}")
    print(f"      owner: {risk['owner']}")
    print(f"      control: {risk['control']}")

风险评估还应考虑可逆性、可检测性、受影响人群、法律或合同义务，以及申诉途径。若某类错误集中于脆弱群体，或一次错误难以逆转，较低平均错误率并不足够。

语言、多语言与领域挑战

语言具有歧义、依赖上下文、富有创造性且持续变化。NLP 系统把这一开放对象转成有限表示与统计预测。转换对许多常见模式有效，但困难案例会揭示模型真正学到了什么。

语言挑战不自动等同于伦理问题；当错误具有系统性、分布不均或被用于重要决策时，它们才成为安全或公平问题。音乐推荐中方言识别失败只是麻烦，同样失败发生在紧急呼叫转写中则可能危险。

歧义、上下文与语用

表达支持多种解释时就有歧义。人类通过语法、周围文本、共享知识、说话人目标与社会情境共同消解歧义；模型可能只依赖其中一部分。

常见形式包括：

歧义 示例 需要解决什么
词汇 bank 金融机构还是河岸？
句法 I saw the student with the telescope 谁持有望远镜？
指代 Maya told Priya that she won she 指谁？
作用域 Every reviewer did not agree 无人同意还是并非所有人同意？
语用 Can you open the window? 能力问题还是礼貌请求？
修辞 That update was a masterpiece 真诚称赞还是讽刺？

上下文不只是附近 token。在对话中，回答含义依赖先前轮次、说话人角色与会话目标；法律或临床文本中，文档前部定义可能支配后文含义；社交媒体中，图像、链接、话题标签或社群惯例可能不可或缺。

语用研究说话人意图，以及听者超越字面语义作出的推断。反讽、间接请求、预设、会话含义、礼貌与幽默很困难，因为相同词语可执行不同社会行动。若模型因 great 把 Great, another cancelled train 标为正面，它识别了词汇情感，却错过语用情感。

实际响应不只是扩大模型。系统可以保留更多会话上下文，在适当时加入说话人和领域元数据，测试对照样本，并允许表达不确定或拒答。敏感应用应避免把一句脱离上下文的话当作某人完整意图。

组合性与长距离推理

组合性表示较大表达的含义取决于组成部分及其组合方式。NLP 模型常学到有用词汇关联，却可能在熟悉词出现在新逻辑结构中时失败。

比较以下陈述：

The treatment was effective.
The treatment was not effective.
It is not true that the treatment was ineffective.
The treatment was effective for adults but not for children.

关键词重叠很高，结论却不同。否定、量词、条件句、合取、时间顺序与嵌套从句都会改变含义。可靠系统必须表示关系，而不只是统计正面或负面词。

长距离推理增加另一种困难。代词可能指向几段之前的实体；合同第 2 页的例外可能覆盖第 30 页的一般规则；科学答案可能需要结合多个章节证据。即使全文放得进上下文窗口，模型也未必能检索并整合正确部分。

有用测试包括最小对照，即只改变一个会改变含义的特征：

The patient has diabetes.      -> diagnosis present
The patient has no diabetes.   -> diagnosis absent

All claims were approved.      -> universal approval
Some claims were approved.     -> partial approval

最小对照可揭示预测是否因正确原因改变，比大规模随机测试集更具诊断性，因为后者多数样本并不包含目标语言现象。

领域与时间分布偏移

模型通常在一个数据分布上训练、在另一个分布部署。当以下关系成立时存在分布偏移：

\[ P_{\text{train}}(X, Y) \neq P_{\text{deploy}}(X, Y) \]

\(X\) 表示输入文本，\(Y\) 表示期望输出。该式说明训练期间观察到的关系不同于部署中遇到的关系。

区分三种形式很有用：

偏移 什么变化 NLP 示例
协变量偏移 \(P(X)\) 变化 正式新闻变成简短社交帖子
标签偏移 \(P(Y)\) 变化 欺诈报告频率增加
概念偏移 \(P(Y \mid X)\) 变化 某短语随时间获得新含义

领域偏移发生在新闻、医疗、法律、教育、客服或不同组织等来源之间。时间偏移来自语言与世界变化：新商品、公众人物、事件、俚语、政策与疾病名称不断出现；标注政策也会变化，例如去年允许的审核类别在政策修订后可能被禁止。

随机 train-test 划分通常低估问题，因为两者包含相同时期和来源的文本。更现实的评估可以留出组织、时间段、作者群、体裁或主题。部署监控还应把进入数据与切片级性能，同开发阶段记录的条件比较。

多语言、方言与语码转换

多语言 NLP 不是把英语 NLP 换一套词表。语言在形态、词序、书写系统、书写惯例、可用资源与文化假设上不同。在不平衡 Web 数据上训练的分词器和模型，可能为高资源语言分配好得多的表示。

方言是系统性的语言变体，不是被破坏的标准语。把方言特征当作拼写错误会抹去身份并造成质量不平等。审核模型可能把某社群使用的词汇过度关联到毒性；语音识别中的口音与方言错误，也会让下游助手对某些用户显得反应迟钝或能力较低。

语码转换是说话人在同一对话或句子中切换语言或语言变体：

The service was fast, pero la comida no estaba buena.

单语言情感系统可能只理解正面的英语从句，而错过负面的西班牙语从句。语码转换还可能包含转写、借词、混合文字系统与社群特定语法，因此文档级语言识别通常过于粗糙。

强多语言设计会使用语言与方言特定评估切片、母语者审核、适当分词，以及来自真实部署社群的任务数据。机器翻译可帮助系统起步，但翻译评估数据不能完全复现自然产生的语言。

低资源语言与文化表征

低资源语言相对于任务缺少数字文本、标注、工具、基准或计算投入。资源匮乏不是语言本身的属性，而常反映哪些内容被数字化、哪些研究获得资金的历史、经济与制度选择。

常见后果包括：

约束 模型后果 负责任响应
无标签文本很少 预训练表示较弱 经社群认可的数据收集与多语言迁移
标签很少 监督模型不稳定 主动学习、弱监督与谨慎的不确定性报告
没有基准 质量难以比较 与本地专家创建有代表性评估
书写标准有限 拼写与语法变化大 不把一种变体强制为普遍正确
引入外部标签 类别与本地概念不匹配 让社群参与重设计任务

文化表征超越翻译质量。情绪类别、礼貌、冒犯、身份词和会话预期在社群间不同。一个情境中开发的标签体系未必能迁移。例如在情感计算中，同一表达可依文化语境传达痛苦、尊重、幽默或间接反对。

Python：评估语言与领域切片 
from collections import defaultdict

examples = [
    {"slice": "standard", "gold": "positive", "pred": "positive"},
    {"slice": "standard", "gold": "negative", "pred": "negative"},
    {"slice": "negation", "gold": "negative", "pred": "positive"},
    {"slice": "negation", "gold": "positive", "pred": "positive"},
    {"slice": "code_switch", "gold": "negative", "pred": "positive"},
    {"slice": "code_switch", "gold": "negative", "pred": "negative"},
    {"slice": "new_domain", "gold": "neutral", "pred": "positive"},
    {"slice": "new_domain", "gold": "neutral", "pred": "neutral"},
]

# Step 1: count correct and total predictions within each meaningful slice.
stats = defaultdict(lambda: {"correct": 0, "total": 0})
for item in examples:
    group = stats[item["slice"]]
    group["total"] += 1
    group["correct"] += int(item["gold"] == item["pred"])

# Step 2: report slice performance instead of relying only on one average.
for slice_name, values in stats.items():
    accuracy = values["correct"] / values["total"]
    print(f"{slice_name:>12}: accuracy={accuracy:.2f}, n={values['total']}")

# Step 3: production tests should add confidence intervals and enough examples
# for every slice. A tiny slice is useful for diagnosis, not for a final claim.

总体结论是：语言覆盖必须被设计和测量。平均表现好的模型仍可能无法可靠处理否定、长文档、新领域、方言或低资源语言。当这些情况描述真实用户时，它们就不是边缘案例。

事实性、忠实性与幻觉

流畅语言不是事实证据。生成模型被训练来产生貌似合理的续写，因此即使没有可靠证据，也能生成语法精致的陈述。语言合理性与认识论支持之间的差距，是现代 NLP 最重要的限制之一。

应区分三个术语：

属性 用于判断的参照 问题
事实性 外部世界或权威知识 陈述是真的吗？
忠实性 提供的来源、数据、指令或证据 陈述是否由输入支持？
一致性 同一输出或对话的其他部分 输出是否自相矛盾？

一项陈述可以事实正确却不忠实。假设源文章讨论公司营收，但从未提及创立年份；摘要加入正确创立年份，可能符合现实，却没有得到源文本支持，因此作为摘要并不忠实。在源文本约束任务中，这种补充仍可能不可接受。

幻觉的类型与原因

幻觉是无依据、矛盾、虚构，或以其他方式脱离相关证据的生成内容。精确定义依赖任务，因为不同任务的相关证据不同。

在源文本约束生成中，两类传统划分很有用：

类型 定义 示例
内在幻觉 输出与提供来源矛盾 源文本说 approved in 2019，摘要说 approved in 2021
外在幻觉 输出增加无法从来源验证的陈述 摘要加入文章未提到的临床试验

开放域助手还会产生虚构实体、不存在的引用、错误日期、错误归因、无效推理，以及伪装成确定性的未知信息。这些形式可能重叠；假论文标题既是事实错误，也是虚构引用。

幻觉可以在多个阶段进入：

阶段 机制 示例
数据 来源有错或 source-target 对不一致 训练摘要包含原文章没有的事实
表示 模型压缩不完整或冲突知识 把相似实体混合
训练 目标奖励合理文本而非经验证真相 常见措辞获得高概率
对齐 偏好数据奖励自信与有帮助 模型猜测而不承认不确定
解码 采样选中无依据续写 温度放大低概率错误陈述
检索 无关或过时证据进入上下文 答案依据错误文档
编排 工具输出被省略、截断或误解 最终答案与计算器或数据库矛盾

因此，问题不能只归咎于解码。降低温度可以减少随机性，但确定性模型仍会自信地复现错误知识；检索可以提供证据，却不能保证证据相关、可信或被正确使用。

事实性与忠实性

事实性把输出与世界比较，忠实性把输出与指定来源或指令比较。这一区分决定正确评估方法。

考虑一份出院记录：

Source: The patient takes 5 mg of Drug A each morning.

Output A: The patient takes 10 mg of Drug A each morning.
Output B: The patient also takes Drug B in the evening.
Output C: The patient takes 5 mg of Drug A each morning.

输出 A 直接与来源矛盾，属于内在不忠实；输出 B 没有来源支持，现实中可能碰巧为真，但摘要器没有证据；输出 C 忠于来源，尽管若源记录本身过时，还会出现另一层问题。

这形成两层验证：

output vs supplied evidence -> faithfulness check
output vs reliable external evidence -> factuality check

摘要、数据到文本与检索约束 QA 通常首先要求忠实性；开放域问答则以外部事实性为核心。创意写作中虚构可能是预期行为，但仍需保持与用户约束一致。

任务 主要依据来源 主要失败
摘要 源文档 无依据或矛盾的摘要
数据到文本 表格或数据库 数值、关系或实体错误
机器翻译 源句子 增加、遗漏或改变含义
检索约束 QA 检索证据 答案无法由证据推出
开放域 QA 可靠世界知识 错误或虚构陈述
对话 会话状态与工具结果 人设、状态或行动不一致

依据与不确定性

依据把生成陈述连接到能支持或反驳它的证据。证据可来自输入文档、结构化数据库、检索段落、经过验证的工具结果或人类专家。基于依据的系统应保留来源，使证据可被检查。

不确定性描述系统不知道或无法可靠推断的内容。token 概率不等于事实置信度；模型可以给常见误解分配高概率，也可以给罕见但正确的技术词分配低概率。

概率分布的一种基本不确定性度量是熵：

\[ H(p) = -\sum_{i=1}^{K} p_i \log p_i \]

\(K\) 是可能输出或类别数，\(p_i\) 是选项 \(i\) 的概率。概率集中在一个选项时熵低，分散在多个选项时熵高。在分类中，若概率合理校准，它可以表示不确定性；在生成中，token 熵只表示对下一个 token 的不确定，而不是完整陈述是否真实。

实际不确定性机制包括：

机制 目的 限制
校准置信度 使报告置信度与观察正确率一致 校准可能随领域漂移
拒答 证据不足时不作答 拒答过多会降低可用性
保形预测 产生具有经验覆盖率的预测集合 分布偏移下假设可能减弱
证据引用 暴露依据来源 引用可能无关或被误读
多次采样 检测不稳定答案 重复模型可能共享同一错误
人工审核 升级有重要后果的不确定性 审核者时间有限且可能过度信任模型

安全系统应知道何时从直接回答切换到澄清、检索、工具调用或人工升级。界面应传达不确定性，而不能假装数字置信度比现有证据更精确。

检测与缓解

把段落拆成原子陈述逐一检查，比把整段压成一个分数更能检测幻觉。一条实用管线是：

generated response
-> split into checkable claims
-> retrieve or identify evidence for each claim
-> classify evidence as support, contradiction, or insufficient
-> aggregate claim results
-> revise, abstain, or escalate

不同工具回答不同问题：

方法 信号 最适合 主要限制
词汇重叠 共享词或短语 快速检查来源覆盖 漏掉改写与逻辑错误
NLI 模型 蕴含或矛盾 源文本约束陈述 继承 NLI 模型错误
基于 QA 的检查 答案一致性 摘要与长文档 问题生成可能漏掉关键陈述
检索加验证 外部证据 开放域事实性 验证受检索质量上限约束
知识库查询 结构化事实 实体、日期与关系 覆盖不完整
人工事实核查 专家判断 高影响或有歧义陈述 缓慢且昂贵

缓解可发生在生成前、中、后。数据过滤与纠正监督改善知识来源；检索与工具提供外部证据；约束生成与解码减少无依据变化；生成后验证可删除或标记陈述。高影响系统应结合多层控制。

Python：陈述级证据检查工作流 
import re

source = (
    "The trial enrolled 120 adults. Participants received Drug A for "
    "eight weeks. The report did not evaluate children."
)

generated_claims = [
    "The trial enrolled 120 adults.",
    "Participants received Drug A for eight weeks.",
    "The treatment was proven safe for children.",
]

def content_words(text):
    """A tiny lexical baseline, not a production fact checker."""
    tokens = re.findall(r"[a-z0-9]+", text.lower())
    stopwords = {"the", "a", "an", "for", "was", "were", "is", "of"}
    return {token for token in tokens if token not in stopwords}

def lexical_support(claim, evidence):
    # Step 1: compare the checkable words in the claim with source words.
    claim_terms = content_words(claim)
    evidence_terms = content_words(evidence)
    return len(claim_terms & evidence_terms) / max(len(claim_terms), 1)

review_queue = []

for claim in generated_claims:
    # Step 2: score each claim independently so one supported sentence
    # does not hide another unsupported sentence.
    score = lexical_support(claim, source)

    # Step 3: route weakly supported claims to a stronger NLI checker,
    # external retrieval, or a human reviewer.
    status = "provisionally supported" if score >= 0.75 else "needs review"
    print(f"{status:>23} | overlap={score:.2f} | {claim}")

    if status == "needs review":
        review_queue.append(claim)

print("review queue:", review_queue)

词汇分数有意用于演示流程，而不是完整方案。无依据的儿童安全陈述与来源共享一些词，可能骗过朴素重叠指标。生产检查器需要语义蕴含、矛盾检测、来源记录和领域专业知识。

检索与自验证的限制

检索增强生成可以减少对参数记忆的依赖，却把部分问题转移到检索与证据使用。系统可能检索错误段落、漏掉相关段落、使用过时内容、选择不可信来源，或生成无法由检索文本推出的陈述。

常见 RAG 失败模式包括：

失败 发生了什么 控制
检索漏失 正确证据从未进入上下文 混合检索、查询重写、召回测试
排序错误 相关证据排名过低 重排序与文档级评估
上下文过载 段落过多掩盖关键证据 上下文选择与压缩
来源冲突 检索文档彼此矛盾 来源、时效、权威排序与显式冲突报告
引用不匹配 引用存在却不支持陈述 陈述－引用蕴含检查
生成漂移 模型忽略或改变证据 依据约束提示、约束输出与后检查

自验证让同一模型或另一个模型批评答案。它可以发现算术错误、矛盾和不稳定推理，却不是独立证据；验证器可能与生成器共享训练数据、误解或盲点。重复表达自信不等于证明。

实用信任顺序是：

authoritative external evidence
> independently executed tool result
> independently trained verifier
> same-model critique
> unsupported model confidence

正确缓解取决于任务。创意生成可以容忍虚构；科学摘要应严格忠于来源；医疗、法律和金融帮助应结合权威证据、有限范围、显式不确定性与合格人工审核。

偏差、公平与包容

NLP 中的偏差指会扭曲表征、质量或结果的系统模式。并非所有统计差异都自动不公平，公平也不是一个通用数字。分析必须明确什么行为有害、伤害谁、发生在什么情境，以及依据什么规范原则。

语言模型从人类产生的数据学习。这些数据既包含宝贵文化知识，也包含刻板印象、排斥、不平等可见度、制度实践与标注判断。模型可能复现这些模式、放大它们，或在规模部署时创造新互动。

NLP 管线中的偏差来源

偏差可以在模型训练前进入，也可以在部署后产生。只关注模型参数会漏掉问题定义、数据收集、标注、指标选择、用户界面与反馈循环。

删除显式受保护属性不一定消除偏差。姓名、地点、学校、词汇与写作模式都可能成为代理。在某些场景，审计子群性能还需要受保护属性。负责任的问题是数据如何治理与使用，而不只是某列是否存在。

表征伤害与资源分配伤害

表征伤害关注个人和群体如何被描绘、识别或保持可见；资源分配伤害关注机会、资源或负担如何分配。

伤害类型 NLP 示例 潜在后果
刻板印象 职业与单一性别关联 强化社会刻板印象
贬损 身份语言与侮辱一同生成 尊严与心理伤害
抹除 某语言或身份持续被遗漏 用户对系统不可见
服务质量差异 某口音的 ASR 错误更高 不平等的服务可及性
资源分配伤害 简历排名随代理身份线索变化 就业机会不平等
监控负担 某社群更频繁被标记 不成比例的审核或执法

同一系统可产生多种伤害。过度标记方言的毒性分类器既造成质量差异、压制社群表达，也可能不均等地分配审核惩罚。只测平均准确率会隐藏三者。

情境也决定伤害。创意写作工具中的刻板印象，与招聘建议中的同一关联并不相同。这不表示前者无害，而表示两者的发生概率、暴露量和后果需要分别分析。

群体、个体与交叉公平

群体公平比较已定义群体之间的结果或错误率；个体公平要求相似的人得到相似待遇；交叉公平研究语言、性别、年龄与残障等属性组合，因为聚合类别会隐藏集中失败。

假设 \(A\) 是群体属性，\(Y\) 是真实标签，\(\hat{Y}\) 是模型决策。常见群体指标包括：

人口统计均等差异比较正向决策率：

\[ \Delta_{DP} = P(\hat{Y}=1 \mid A=a) - P(\hat{Y}=1 \mid A=b) \]

\(P(\hat{Y}=1 \mid A=a)\) 是群体 \(a\) 获得正向预测的比例。接近零表示选择率相近，但人口统计均等不考虑真实标签分布或标签质量是否不同。

机会均等差异比较真正率：

\[ \Delta_{EOpp} = P(\hat{Y}=1 \mid Y=1, A=a) - P(\hat{Y}=1 \mid Y=1, A=b) \]

它询问合格或真正的正例能否以相似比例被识别。在提供有益资源的场景，较低真正率意味着某群体错过更多应得正向结果。

均等赔率要求真正率与假正率都相近，同时考虑获得正向结果的机会与承受错误正向决策的风险。哪种错误更重要取决于应用。

公平定义可能冲突。若群体基础率不同且预测不完美，校准、均等赔率与相同正向率可能无法同时满足。因此，选择指标是伦理与政策决策，不只是数学便利。

交叉分析不可缺少，因为模型可能分别看起来在性别和语言上公平，却对使用某种低资源语言的女性表现很差。必须报告切片大小与不确定性，避免把噪声估计误认为均等证据。

测量与缓解偏差

偏差评估应结合定量切片、受控测试、定性审核与受影响社群反馈。基准可以显示差距但不能解释原因，访谈则可能揭示基准没有覆盖的伤害。

Python：计算子群错误与公平差距 
from collections import defaultdict

records = [
    # gold=1 means the message truly requires urgent support.
    {"group": "A", "gold": 1, "pred": 1},
    {"group": "A", "gold": 1, "pred": 1},
    {"group": "A", "gold": 0, "pred": 1},
    {"group": "A", "gold": 0, "pred": 0},
    {"group": "B", "gold": 1, "pred": 0},
    {"group": "B", "gold": 1, "pred": 1},
    {"group": "B", "gold": 0, "pred": 0},
    {"group": "B", "gold": 0, "pred": 0},
]

counts = defaultdict(lambda: {"tp": 0, "fp": 0, "tn": 0, "fn": 0})

# Step 1: build a confusion matrix for each group.
for row in records:
    if row["gold"] == 1 and row["pred"] == 1:
        counts[row["group"]]["tp"] += 1
    elif row["gold"] == 0 and row["pred"] == 1:
        counts[row["group"]]["fp"] += 1
    elif row["gold"] == 0 and row["pred"] == 0:
        counts[row["group"]]["tn"] += 1
    else:
        counts[row["group"]]["fn"] += 1

rates = {}
for group, c in counts.items():
    # Step 2: calculate rates tied to meaningful error types.
    tpr = c["tp"] / max(c["tp"] + c["fn"], 1)
    fpr = c["fp"] / max(c["fp"] + c["tn"], 1)
    selection = (c["tp"] + c["fp"]) / sum(c.values())
    rates[group] = {"tpr": tpr, "fpr": fpr, "selection": selection}
    print(group, rates[group], "n=", sum(c.values()))

# Step 3: report signed gaps and inspect the underlying rates.
equal_opportunity_gap = rates["A"]["tpr"] - rates["B"]["tpr"]
demographic_parity_gap = rates["A"]["selection"] - rates["B"]["selection"]

print("equal opportunity gap:", equal_opportunity_gap)
print("demographic parity gap:", demographic_parity_gap)

缓解可以发生在多个阶段：

阶段 技术 收益 风险或限制
问题设计 替换不当代理或减少自动化 处理决策根源 可能需要组织变革
数据 改善覆盖、文档与标签 减少表征差距 收集会增加隐私负担
训练 重加权、重采样、对抗目标 改变学习行为 可能权衡指标或过拟合群体标签
推理 在合法且合理时使用群体感知阈值 可针对错误率差距 政策与法律含义因情境而异

仅平衡数据不是完整方案。相同样本数不保证相同语言多样性、标签质量或社会含义；合成样本可能复现生成器刻板印象；在一个基准上去偏可能只压制可见信号，而不改变底层关联。

公平权衡与限制

公平工作包含不可避免的选择。提高某群体召回率可能增加假阳性；删除身份词可能减少测得刻板关联，却让系统无法讨论歧视；单一全局阈值可能产生不均等错误率，群体特定阈值在某些情境又可能不合适或被禁止。

负责任决策应记录：

the affected outcome
-> the groups and intersections examined
-> why a fairness definition was selected
-> uncertainty in each estimate
-> expected trade-offs
-> who participated in the decision
-> how affected people can contest outcomes

公平不是达到一次后永久冻结。语言、人群、政策与使用方式都会变化。开发时达到公平目标的模型，部署后仍可能漂移。因此，持续切片监控与反映真实体验的反馈渠道属于公平本身，而不是可选附加项。

隐私、版权与数据治理

NLP 系统处理的语言经常包含个人、机密、受版权保护或业务敏感信息。隐私不只是隐藏姓名；一段文本可通过细节组合暴露健康状况、政治观点、关系、位置、工作场所事件或身份。

数据治理规定数据如何收集、论证、记录、访问、保留、共享、纠正与删除。隐私控制保护生命周期中的人；版权与许可则处理使用和复制内容的权利问题。它们相互重叠，但满足其中一项不会自动满足其他项。

个人身份与敏感信息

个人身份信息（PII）是可以直接或结合其他信息识别个人的内容。直接标识包括姓名、账号、电子邮件与电话；年龄、郊区、职业、罕见疾病与事件日期等准标识符结合后也可能识别某人。

敏感信息可以包括：

类别 文本示例 潜在风险
身份 姓名、护照号、学生 ID 冒充或身份盗窃
联系方式 电子邮件、电话、地址 未经请求的联系或骚扰
健康 诊断、药物、治疗记录 歧视或个人伤害
金融 银行信息、债务、工资 欺诈或经济伤害
位置 精确活动轨迹或工作地点 跟踪或人身风险
信仰与组织关系 宗教、政治、工会成员 画像或歧视
私人通信 支持聊天、法律邮件、日记 违反保密

两种隐私故障容易混淆。披露是系统暴露被提供或存储的信息；敏感推断是系统从看似不敏感的信号推导私人属性。从档案删除疾病并不能阻止模型根据药物名称或社群成员关系推断它。

数据最小化是第一道防线：只收集任务真正需要的内容，只向模型发送必要字段，且只在合理时长内保留。脱敏有帮助但不完美；正则表达式能捕捉标准化标识符，而姓名、关系和上下文秘密需要实体模型、规则，有时还需人工审核。

记忆与训练数据抽取

记忆表示模型参数保留特定训练样本的信息；复现表示模型发出可识别的训练内容；抽取则是有意搜索记忆内容的对抗或调查过程。

三者相关但不同：

training example influences parameters
-> model memorizes some distinctive sequence
-> a prompt elicits the sequence
-> the output reveals private or copyrighted content

罕见、重复、高度独特或可预测字符串可能尤其脆弱。大规模训练不保证单个样本会消失在匿名平均值中。

控制措施包括训练数据去重、删除秘密与 PII、限制过拟合、隐私测试、访问限制、速率限制、输出扫描和隐私保护训练。没有单一控制能保证所有记忆内容都已移除。

同意、来源、许可与版权

同意询问人们是否知情并同意其数据的特定用途；来源记录数据来自何处及如何变换；许可规定合同权限与限制；版权涉及受保护表达的权利。数据集即使公开可访问，也仍可能受到隐私、许可或伦理约束。

这些问题应分别记录：

问题 示例证据
文本来自哪里？ URL、仓库、供应商、收集方法
谁创作或被表示？ 作者、说话人、数据主体、社群
适用什么权限？ 同意记录、许可证、合同、组织授权
发生了什么变换？ 过滤、翻译、标注、去重
排除哪些用途？ 商业用途、再分发、敏感推断
数据能否纠正或删除？ 删除流程与身份验证

训练使用、检索使用与输出复现带来不同问题。RAG 系统可以在授权内部许可下存储受版权保护文档，却仍向未授权用户暴露过多源文本；模型可能不逐字复现文档，却使用来源未知的数据训练。治理必须覆盖完整系统，而不只是模型权重。

法律要求随司法辖区、合同、行业与用例变化。因此，工程笔记应识别相关问题与证据，而不是给出一种普遍法律结论。高影响项目需要合格法律与隐私审核，与技术控制并行。

保留、删除与访问控制

数据通常不只存在于训练文件，还会出现在原始上传、预处理输出、缓存、向量索引、日志、提示追踪、模型检查点、备份、分析系统与人工审核工具中。若只删除其中一份，删除请求就未完成。

有用的数据清单会映射各类数据的整个生命周期：

collection
-> validation
-> preprocessing
-> training or indexing
-> inference
-> logging and review
-> archival or deletion

保留期限减少数据可能暴露的时间。访问控制应遵循最小权限：用户与服务只获得完成任务所需权限。加密保护传输中和静态数据，却不能阻止已授权应用向模型发送过量数据或把数据返回给错误用户。

从训练模型删除数据很困难。从源数据集删除一行，不会移除其对现有检查点的影响。选项包括重新训练、机器遗忘、替换模型，或屏蔽已知输出等补偿性控制。选择应匹配数据敏感度、记忆证据、可行性与所需保证。

隐私保护 NLP

隐私保护 NLP 结合组织与技术方法。匿名化试图让重新识别不现实；假名化用受控引用替换标识符。假名化数据仍可关联，因此仍需保护。

差分隐私提供形式化保证：当一个人的记录加入或删除时，随机机制的输出只发生有限变化。机制 \(M\) 在以下条件下近似满足差分隐私：

\[ P[M(D) \in S] \leq e^{\varepsilon} P[M(D') \in S] + \delta \]

\(D\) 与 \(D'\) 是只相差一个人记录的相邻数据集，\(M\) 是随机训练或分析机制，\(S\) 是任意可能输出集合。参数 \(\varepsilon\) 控制隐私损失：越小保证越强，但通常需要更多噪声；\(\delta\) 允许严格界限以很小概率不成立。

直觉是：无论某个个体是否参与，观察者看到的输出分布都应近似相同。差分隐私训练通常裁剪逐样本梯度并加入校准噪声。它可以降低记忆风险，却可能降低效用，尤其影响罕见模式与代表不足群体，因此隐私与公平效应应一起评估。

方法 防止什么 限制
最小化 不必要的收集与暴露 需要严格任务设计
脱敏 文本中的明显标识符 上下文仍可能重新识别个人
访问控制 未授权内部或外部使用 授权流程仍可能滥用数据
加密 截获与存储泄露 授权处理时数据仍可见
差分隐私 推断个人是否参与训练 效用与实现权衡
联邦学习 集中收集原始本地数据 若无额外保护，更新仍会泄漏信息
安全执行 基础设施级暴露 无法修复不当收集或输出
Python：分层 PII 检测与脱敏基线 
import re

text = (
    "Please contact Maya at maya.lee@example.org or +61 412 345 678. "
    "Her support ticket is TKT-48291."
)

patterns = {
    "EMAIL": re.compile(r"\b[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}\b"),
    "PHONE": re.compile(r"\+?\d[\d\s()-]{7,}\d"),
    "TICKET": re.compile(r"\bTKT-\d{4,}\b"),
}

findings = []
redacted = text

# Step 1: detect standardized identifiers with auditable rules.
for label, pattern in patterns.items():
    for match in pattern.finditer(text):
        findings.append(
            {"type": label, "value": match.group(), "span": match.span()}
        )

# Step 2: replace matches from right to left so character positions stay valid.
for item in sorted(findings, key=lambda value: value["span"][0], reverse=True):
    start, end = item["span"]
    redacted = redacted[:start] + f"[{item['type']}]" + redacted[end:]

print("redacted:", redacted)
print("audit findings:", findings)

# Step 3: a production pipeline should add named-entity recognition,
# domain-specific rules, confidence thresholds, and human review for
# high-sensitivity documents. Do not log raw values unnecessarily.

该代码是透明基线，不等于匿名化。它会漏掉人名，也会漏掉能识别她的上下文组合。后果严重时，必须结合分层检测、数据最小化、保留控制与审核。

鲁棒性与安全

鲁棒性询问 NLP 系统在输入或环境变化时能否保持可靠；安全询问攻击者能否故意利用系统、数据、接口或依赖。拼写错误通常是善意鲁棒性挑战；精心选择以强迫目标预测的触发器则是安全挑战。

两者都需要威胁模型。不能声明模型普遍鲁棒或安全；声明必须说明预期变化、攻击者能力、受保护资产、可接受故障率与部署环境。

噪声输入与分布偏移

真实输入不同于精选基准。文本可能包含拼写错误、OCR 伪影、ASR 错误、emoji、缩写、复制格式、异常 Unicode、不完整句子或混合语言。保持含义的改写也可能改变模型预测，即使人类看到相同意图。

鲁棒性评估应区分保持含义与改变含义的变化：

扰动 预期行为
标点或空白变化 预测通常应稳定
常见拼写错误 预测通常应稳定
同义词或改写 语义与预测应相近
插入否定 预测可能需要改变
改变实体或数字 事实输出可能需要改变
词的领域特定用法 系统应遵循领域含义

盲目不变性很危险。分类器应忽略无害空格，却应对 not、改变的药物剂量或新日期作出反应。鲁棒性测试必须编码哪些变换保持任务标签。

前文讨论的领域偏移是系统级鲁棒性问题。只监控输入统计并不足够，因为两个文本分布可以看似相近，而文本与标签关系已经改变。还需要定期带标签样本、用户反馈与领域专家审核。

对抗样本与规避

对抗样本是为导致模型失败而故意修改的输入，同时保留足够含义或合理性以不被注意。文本是离散的，因此攻击可以改变字符、词、句法、提示、格式或周围上下文。

通用对抗触发器是短输入序列，被优化来跨许多样本产生目标行为，而不只是攻击一个特定样本。

图片：用梯度引导搜索一个把正面评论推向负面预测的通用触发器。

来源：Wallace et al. - Universal Adversarial Triggers for Attacking and Analyzing NLP

攻击成功率通常报告为：

\[ ASR = \frac{N_{\text{successful attacks}}}{N_{\text{attempted attacks}}} \]

\(N_{\text{attempted attacks}}\) 是被攻击的合格样本数，\(N_{\text{successful attacks}}\) 是达到定义目标的数量。必须明确目标：任意预测改变、特定目标标签、有害生成，还是绕过某项控制。

ASR 应与干净准确率一起报告。通过拒绝所有输入来阻止攻击的防御，只在平凡意义上安全，而且没有效用。

防御包括对抗训练、归一化、集成检查、速率限制、异常检测、语义一致性测试与鲁棒系统设计。自适应评估不可缺少，因为攻击者看到防御后会改变策略。

数据投毒与后门

数据投毒修改训练、微调、偏好、检索或反馈数据，以影响后续行为。后门是一种由触发器激活的隐藏行为，而普通输入表现正常。

例如：

攻击面 示例
预训练数据 在 Web 文本中重复注入错误关联
微调数据 错误标签样本移动分类边界
偏好数据 有害行为反复被排序为更受偏好
检索语料 恶意文档被索引为权威证据
用户反馈 协同评分把系统推向目标回答
模型产物 被修改检查点包含触发行为

投毒难以检测，因为大型数据本就含噪声。有用控制包括来源记录、可信数据边界、去重、异常检测、签名产物、可复现构建、留出 canary、影响分析与训练后行为测试。

干净验证分数不能排除后门。模型可能在普通数据上正确，只在触发器出现时失败。安全测试必须包含触发器搜索、稀有模式切片与供应链审核。

提示注入与越狱

提示注入发生在不可信内容中包含指令，而模型把它当作权威控制。在 RAG 中，恶意指令可能藏在检索文档；工具调用系统中，它可能通过网页、邮件、文件或工具结果进入。这是间接提示注入，因为攻击者无需控制用户直接提示。

越狱试图绕过行为限制，常通过角色扮演、编码、多轮操纵或指令冲突。提示注入与越狱重叠，但提示注入本质上是完整性问题：数据被混淆为控制指令。

关键工程原则是：

natural-language instructions are not a security boundary

告诉模型忽略恶意指令是有用指导，但不是访问控制。外围应用必须验证工具参数、限制权限、分离可信与不可信内容、要求确认重要行动，并在执行前验证输出。

控制包括：

控制 目的
输入来源标签 区分用户、开发者、检索与工具内容
最小权限工具 限制受操纵模型能做什么
模式验证 拒绝格式错误或过度的工具参数
允许列表 限制目的地、命令、文件或行动
人工确认 批准不可逆或高影响行动
输出编码 防止生成内容成为可执行标记或代码
沙箱 限制工具执行与数据访问
审计日志 重建尝试与已完成行动

详细架构属于现代系统章节。这里的核心是：LLM 是更大安全设计中的不可信决策组件。

威胁建模与红队测试

威胁建模识别要保护什么、谁可能攻击、如何与系统交互，以及哪些控制降低风险。它应在部署前进行，并随系统获得新数据源、工具、用户或能力而更新。

实用 NLP 威胁模型记录：

assets -> private data, model behavior, tool permissions, service availability
actors -> ordinary users, malicious users, insiders, compromised suppliers
surfaces -> prompts, uploads, APIs, retrieval corpus, feedback, logs, checkpoints
goals -> extraction, manipulation, bypass, impersonation, disruption
controls -> prevention, detection, containment, recovery

红队测试是有组织地发现现实故障。参与者应包括领域专家与熟悉受影响社群的人，而不只有安全工程师。测试应覆盖滥用、有歧义边界、多语言行为、链式交互与完整应用攻击。

Python：保持含义的鲁棒性测试框架 
def perturbations(text):
    """Transformations expected to preserve sentiment for this test."""
    return {
        "original": text,
        "extra_spaces": text.replace(" ", "  "),
        "lowercase": text.lower(),
        "punctuation": text.rstrip(".!?") + "!!!",
        "common_typo": text.replace("excellent", "excelllent"),
    }

def mock_sentiment_model(text):
    # Placeholder for model.predict(text). This deliberately fragile rule
    # lets the test reveal sensitivity to a common typo.
    return "positive" if "excellent" in text.lower() else "neutral"

base_text = "The support team provided excellent service."
base_prediction = mock_sentiment_model(base_text)
failures = []

# Step 1: generate only transformations whose label should remain unchanged.
for name, candidate in perturbations(base_text).items():
    prediction = mock_sentiment_model(candidate)
    stable = prediction == base_prediction
    print(f"{name:>12} | {prediction:>8} | stable={stable}")

    # Step 2: retain failed cases as regression tests.
    if not stable:
        failures.append({"test": name, "text": candidate})

# Step 3: a real harness should measure accuracy and attack success rate,
# preserve seeds and model versions, and separate benign from adversarial tests.
print("robustness failures:", failures)

安全发现应按影响与可利用性确定优先级，再转化为回归测试。没有补救责任或复测的红队报告，只是一份已知问题清单。

对抗样本 精心构造的推理输入 预测完整性 对抗评估与分层检测

有害内容、错误信息与滥用

生成式与分析式 NLP 系统可以创建、排序、推荐、翻译或放大有害语言。伤害取决于内容、目标、意图、规模、受众与情境。关键词列表无法可靠区分骚扰，与引用骚扰内容的新闻、幸存者描述虐待，或谴责虐待的反驳言论。

因此，安全政策需要可操作定义：说明哪些行为禁止，哪些可谨慎允许，哪些需要年龄或领域限制，以及何时必须由人决策。do not generate harmful content 之类模糊指令难以一致评估与执行。

毒性、仇恨言论与骚扰

毒性是可能使互动敌对或不安全的宽泛语言标签；仇恨言论基于受保护或身份特征针对人；骚扰则向个人或群体实施侮辱或威胁。三者重叠，但不应视为同义词。

重要上下文区别包括：

情境 相同表面词语可能发挥的作用
直接攻击 针对性辱骂
引用 证据或报道
反驳言论 谴责虐待
群体内再使用 群体内部身份表达
教育讨论 分析有害词语
创意小说 叙事中的描写

审核模型会通过假阴性和假阳性造成伤害。假阴性让有害内容未被处理；假阳性压制合法表达，且错误可能集中于方言或身份讨论。评估应报告目标感知与上下文感知切片，而不只是一个毒性 F1。

生成系统需要输入与输出双重控制。看似无害的请求可能在多轮后产生有害内容，而含暴力词语的输入也可能是在寻求危机支持或学术分析。政策分类应使用会话上下文与预期变换。

错误信息与虚假信息

错误信息是被分享的错误或误导内容，不一定意图欺骗；虚假信息则被故意创造或传播来欺骗。只观察文本的模型通常无法判断意图，因此系统标签不应超出证据所能支持的范围。

NLP 系统以多种方式参与信息生态：

generate a claim
-> rewrite it persuasively
-> translate it across languages
-> personalize it for an audience
-> rank or recommend it
-> summarize reactions to it

规模与自动化会把普通模型错误转化为广泛暴露。反过来，当证据不完整或有争议时，自动事实核查也会制造虚假确定感。

有用控制包括来源记录、时效检查、陈述级检索、权威来源优先、不确定性、可见引用、速率限制与人工编辑审核。对时间敏感陈述，系统应记录证据检索时间；对有争议主题，应区分已验证事实、被报道的主张、专家共识、不确定性与观点。

错误信息检测不应简化为分类发布者或写作风格。可靠来源也会犯错，讽刺可能看起来虚假，低质量来源也可能引用真实事实。只要可能，验证单位应是陈述及其证据。

危险建议与双重用途能力

双重用途表示同一种 NLP 能力可服务有益或有害目标。翻译可以改善可及性，也可协调滥用；代码生成可以教授编程，也可帮助攻击系统；科学摘要可以支持研究，也可能加速有害实验。

风险取决于能力、意图、细节与可操作性：

回答层级 示例 典型处理
一般信息 网络安全高层解释 通常提供
防护指导 如何保护账户 提供具体防御步骤
有歧义的操作细节 流程既可能安全也可能有害 澄清情境并缩小范围
高风险可操作性 为造成伤害优化的指令 限制并引导至安全方向
紧迫人身危险 可信的自伤或暴力信号 支持性回应与适当升级路径

安全回答不总是拒绝。它可以提供高层教育背景、防御替代方案、紧急资源、不确定性，或建议咨询合格专业人士。回答不应把生成的医疗、法律或金融信息包装成个性化专业决策。

过度拒绝与拒绝不足

拒绝不足是系统提供了本应限制的内容；过度拒绝则是阻止无害、教育、创意或防护请求。两者都是安全故障。

过度拒绝的例子包括：拒绝历史学家分析极端主义宣传、阻止安全工程师询问防御，或拒绝翻译患者的症状描述。过度拒绝会降低可及性，也可能不成比例地影响语言形式与政策样本相似的用户。

拒绝不足包括：在表面改写后提供详细有害指令、通过变换请求泄露敏感内容，或允许长对话逐步拼接成不允许的计划。

评估需要平衡测试集，包含：

clearly allowed requests
clearly disallowed requests
allowed requests with sensitive vocabulary
ambiguous requests requiring clarification
multi-turn escalation attempts
multilingual and encoded variants

最佳行为可能是 comply、comply with boundaries、clarify、refuse with a safe alternative 或 escalate。二元 allow/block 标签通常过于粗糙。

安全与效用权衡

安全控制会改变精确率与召回率。降低审核阈值可捕捉更多有害内容，也会标记更多无害内容。合适阈值取决于错误成本、可逆性、审核能力与情境。

令 \(C_{FN}\) 为有害假阴性的成本，\(C_{FP}\) 为无害假阳性的成本，则简化期望成本为：

\[ C = C_{FN}N_{FN} + C_{FP}N_{FP} \]

\(N_{FN}\) 与 \(N_{FP}\) 是观察到的假阴性与假阳性计数。公式明确权衡，但成本赋值是政策判断，不应抹去权利、罕见严重结果或群体间不平等负担。

分层路由通常优于单一阈值：

low risk -> normal response
medium risk -> constrained response or clarification
high uncertainty -> human review
high risk -> block action and offer safe alternatives
immediate danger -> specialized escalation procedure

def route_request(harm_probability, uncertainty, high_impact_domain=False):
    """Return an action, not a final content judgment."""

    # Step 1: high-impact domains receive stricter review because an
    # incorrect answer can have larger consequences.
    review_threshold = 0.35 if high_impact_domain else 0.55
    restrict_threshold = 0.80

    # Step 2: high uncertainty is a reason to ask for review or context,
    # not a reason to confidently label the user as malicious.
    if uncertainty >= 0.40:
        return "clarify_or_human_review"

    # Step 3: route by risk tier. A production policy would also examine
    # category, target, conversation history, user permissions, and tools.
    if harm_probability >= restrict_threshold:
        return "restrict_and_offer_safe_alternative"
    if harm_probability >= review_threshold:
        return "constrained_response_or_review"
    return "normal_response"

    {"name": "general education", "risk": 0.08, "uncertainty": 0.05},
    {"name": "ambiguous medical request", "risk": 0.30, "uncertainty": 0.45,
     "high_impact": True},
    {"name": "highly actionable harm", "risk": 0.93, "uncertainty": 0.08},
]

for case in cases:
    action = route_request(
        case["risk"],
        case["uncertainty"],

透明、问责与人工监督

透明使需要信息的人能够获得系统相关资料；问责为决策与后果分配责任；人工监督则让人能实质性地审核、质疑、纠正、暂停或覆盖系统。

这些概念相互支持，但文档本身不会产生问责。一个记录完美的有害系统仍然有害；同样，如果审核者缺少信息、时间、权力或接受模型输出之外的现实选择，增加人工审核也无济于事。

可解释性与解释方法

可解释性关注模型行为或内部结构有多易理解；解释方法关注为某项行为产生原因或证据的方法。实践中术语常被宽泛使用，因此应明确目标受众与用途。

不同用户需要不同解释：

受众 有用解释
开发者 影响较大的 token、错误切片、内部诊断
领域专家 证据、不确定性与决策相关因素
决策对象 易懂原因与纠正或申诉路径
审计者 可复现日志、版本、测试与控制证据
管理者或监管者 预期用途、风险、责任人与性能边界

局部方法解释一次预测，全局方法描述更广泛模型行为。特征归因、反事实样本、原型、概念测试、探针与机制分析提供不同证据。注意力权重可用于诊断，但不应自动被呈现为完整因果解释。

解释质量有多个维度：

维度 问题
忠实度 解释是否反映真实决策过程？
可理解性 受众能否理解？
稳定性 相似输入是否得到相似解释？
可行动性 用户能否纠正或响应决策？
完整性 是否包含不确定性与限制？

流畅的自然语言理由可能听起来有说服力，却是在预测后生成且与因果过程无关。因此，解释应经过验证，而不能只因可读就被信任。

数据集、模型与系统文档

文档保存那些在团队、数据、模型或部署条件变化时容易消失的假设。不同产物描述不同对象：

产物 记录对象 重要内容
数据卡或 datasheet 数据集 来源、同意、人群、标签、缺口、变换
模型卡 训练模型 预期用途、评估、子群结果、限制
系统卡 部署应用 组件、交互、安全测试、访问、控制
决策日志 设计选择 替代方案、证据、责任人、日期、理由
风险登记表 已识别风险 可能性、影响、控制、状态、责任人
事故报告 观察到的故障 时间线、影响、根因、补救

模型卡最初用于报告预期用途及相关条件和子群上的性能。只有内容具体且版本化时它才最有用，而不是填入 may contain bias 等泛化陈述。

NLP 分类器的良好模型卡应说明标签定义、语言、领域、数据时间、阈值、切片指标、已知失败、校准、隐私考虑与范围外用途。RAG 系统还需要文档来源、索引版本、检索指标、引用检查与工具权限。

文档详尽程度应与影响成比例，但要尽早开始。部署后才写限制，会诱导团队为已经难以逆转的决策寻找理由。

可审计性与可复现性

可审计性表示授权审核者能够重建发生了什么，并判断控制是否得到遵循；可复现性表示过程或结果能被足够接近地重复，以验证声明。

现代 NLP 系统需要记录的不只是模型名称：

model and tokenizer version
-> code and configuration
-> data or index version
-> prompt and policy version
-> retrieval results and tool calls
-> decoding parameters and random seed where applicable
-> output filters and human actions
-> timestamp and deployment environment

生成输出会因采样、非确定性硬件、变化的托管模型、外部搜索结果或更新索引而变化。精确复现未必总能实现，但系统应保存足够证据解释执行路径。

日志会引入隐私与安全风险。保存每个提示可能捕捉秘密；保存原始工具输出可能暴露凭证或个人记录。审计日志应最小化内容、分离访问角色、保护完整性、定义保留期限，并记录必要来源，而不能成为第二个无人治理的数据集。

当评估者能检查假设、测试产物与已知事故时，独立评估更强。可审计性不等于公开所有模型权重或私有数据；访问可以受控，同时仍支持有意义监督。

人机协同决策

只有人具有明确定义角色时，人机协同才有意义。人可以标注数据、审核不确定案例、授权行动、监控模式、受理申诉或调查事故；这些职责需要不同技能与界面。

三种配置很有用：

配置 系统角色 人类角色
human-in-the-loop 模型提出，每项重要行动由人批准 主动决策者
human-on-the-loop 系统在限制内行动，人监控并可干预 监督者
human-out-of-the-loop 系统自动行动 治理依赖部署前控制与监控

重要决策应规定谁有权覆盖模型、展示什么证据、审核时间多长，以及审核者不同意时会发生什么。受影响者也应拥有申诉流程，而不只操作者。

人工审核有局限。审核者会疲劳、判断不一致、缺少领域知识、受到时间压力并产生自动化偏见。如果系统只把最难案例交给人，其工作负担会比平均案例更困难，基于普通案例的人类性能假设就会误导。

自动化偏见与人工监督限制

自动化偏见是过度依赖自动建议的倾向，尤其当系统通常显得很有能力时。人可能接受错误答案、不再寻找矛盾证据，或把自身判断改成与模型一致。

界面可能通过展示不带不确定性的精确分数、首先放置模型建议、隐藏来源证据，或让覆盖操作很麻烦而无意加强偏见。当吞吐目标只给每个案例几秒时，名义上的人工批准会变成盖章。

有用对策包括：

控制 为什么有帮助
在建议前显示源证据 鼓励独立判断
展示校准不确定性与已知限制 减少虚假精确
对高影响批准或覆盖要求理由 支持慎重审核与审计
抽样看似容易的案例 衡量隐藏自动化错误
轮换任务并管理工作量 减少疲劳
提供权限与升级渠道 使干预真实有效
测量人机组合性能 评估实际部署团队

负责任 NLP 生命周期

负责任 NLP 是持续生命周期，而非最终安全测试。风险可以在问题定义、数据收集、模型开发、集成、部署与用户交互期间进入，因此控制必须贯穿完整系统。

NIST AI 风险管理框架把工作组织为四项功能：治理（Govern）、映射（Map）、测量（Measure） 与管理（Manage）。治理贯穿各项工作，映射、测量和管理则随系统与情境变化反复进行。

开发前风险评估

第一个问题是，是否应该为拟议决策构建 NLP 系统。AI 方案可能没有必要、比简单规则更不可靠，或因目标无法从语言中有效推断而不适合。

开发前评估应定义：

项目 问题
目的 支持什么决策或用户需求？
非 AI 基线 规则、搜索、流程变革或人工服务能否更好解决？
利益相关者 谁使用、被表示并受影响？
预期用途 应在何处、由谁使用？
范围外用途 绝不能在哪里使用？
影响 假阳性或假阴性后会发生什么？
数据合理性 为什么每个数据源必要且获得许可？
成功标准 适用哪些质量、公平、隐私、安全与成本阈值？
补救 人如何纠正数据或质疑结果？

该阶段应识别以后可测试的假设。例如，项目可能假设客服消息包含足够证据推断紧急程度、标签政策稳定且用户用英语书写；部署违反的每项假设都会成为风险。

高影响项目适合在昂贵模型开发前进行影响评估与多学科审核。早期取消或缩小范围也可以是成功的风险管理结果。

部署前安全评估

部署前评估应在现实条件下测试完整系统。静态数据集的模型分数无法测试检索、提示、工具权限、用户界面、审核、人工复核或故障恢复。

发布关卡可以要求多个维度的证据：

task quality
+ slice and fairness evaluation
+ robustness and adversarial tests
+ privacy and extraction tests
+ harmful-content and misuse tests
+ human workflow evaluation
+ latency, availability, and rollback tests

测试集应包含正常案例、困难语言案例、高影响故障、范围外请求、恶意输入与多轮交互。人工评估者需要清楚量表与分歧分析；红队发现修复后必须复测。

发布决策不应依赖一个复合分数，使强准确率抵消关键隐私失败。有些控制是硬门槛：秘密暴露、未授权行动或不可接受的子群失败，无论平均效用如何都可能阻止部署。

部署后监控

部署改变可用证据。真实用户会产生新语言、以意外方式组合功能，并揭示基准中不存在的影响。监控应覆盖模型行为、系统行为与现实结果。

监控领域 示例信号
输入漂移 新词汇、语言、主题或文档长度
输出质量 抽样人工评分与纠正率
切片性能 子群假阴性率或方言错误
依据 无依据陈述与引用不匹配率
安全 有害补全、拒绝与升级率
隐私 PII 检测告警与异常重复查询
安全攻击 注入尝试与未授权工具请求
运行 延迟、失败、成本与回退率
影响 投诉、申诉、推翻决策与下游伤害

指标需要阈值、责任人和响应流程。没有责任人的告警只是一条通知。监控既要收集调查所需数据，也要遵守隐私与保留限制。

用户报告是重要信号，却不是代表性样本。权力较少或访问能力较低的人可能更难报告伤害，因此投诉渠道之外还需要主动审计与社群参与。

事故响应与持续审计

事故是系统造成或带来可信风险的不可接受伤害、政策违规、隐私暴露、安全入侵或重大可靠性故障。团队应在事故发生前定义事故类别与响应权限。

实用响应序列是：

detect
-> contain
-> preserve evidence
-> assess affected people and systems
-> communicate and provide remedy
-> identify root causes
-> remediate and validate
-> document lessons and update controls

控制措施可以禁用功能、撤销工具权限、回滚模型、隔离索引、收紧阈值，或把所有案例转人工。行动应减少伤害，同时保留调查所需证据。

根因分析不应只检查最终模型预测。有害结果可能还涉及政策含糊、来源缺失、界面设计薄弱、工作量压力、申诉不可达或监控缺口。纠正措施应处理每一个促成层级。

持续审计定期检查文档化控制是否仍在运行、部署是否仍在范围内，以及新能力是否创造新风险。团队往往有动机乐观解释自身结果，因此独立审核对高影响系统尤其重要。

实用风险缓解工作流

完整工作流把技术证据与责任、行动连接起来：

1. define purpose and boundaries
2. map stakeholders, data, threats, and possible harms
3. choose measurable requirements and hard safety gates
4. build the least risky system that can meet the need
5. evaluate components and the end-to-end workflow
6. document residual risk and obtain accountable approval
7. deploy gradually with monitoring, fallback, and rollback
8. investigate incidents and user feedback
9. update, restrict, or retire the system when assumptions fail
Python：负责任 NLP 系统的发布关卡 
release_evidence = {
    "task_macro_f1": 0.89,
    "worst_slice_f1": 0.82,
    "max_equal_opportunity_gap": 0.04,
    "unsupported_claim_rate": 0.015,
    "critical_privacy_findings": 0,
    "critical_security_findings": 0,
    "rollback_test_passed": True,
    "human_review_ready": True,
}

requirements = {
    "task_macro_f1": (">=", 0.85),
    "worst_slice_f1": (">=", 0.78),
    "max_equal_opportunity_gap": ("<=", 0.08),
    "unsupported_claim_rate": ("<=", 0.02),
}

def meets(value, operator, threshold):
    if operator == ">=":
        return value >= threshold
    if operator == "<=":
        return value <= threshold
    raise ValueError(f"unsupported operator: {operator}")

failures = []

# Step 1: evaluate quantitative requirements independently.
for metric, (operator, threshold) in requirements.items():
    value = release_evidence[metric]
    if not meets(value, operator, threshold):
        failures.append(f"{metric} is {value}; requires {operator} {threshold}")

# Step 2: enforce hard gates that cannot be averaged away by good accuracy.
hard_gates = {
    "critical_privacy_findings": release_evidence["critical_privacy_findings"] == 0,
    "critical_security_findings": release_evidence["critical_security_findings"] == 0,
    "rollback_test_passed": release_evidence["rollback_test_passed"],
    "human_review_ready": release_evidence["human_review_ready"],
}

for gate, passed in hard_gates.items():
    if not passed:
        failures.append(f"hard gate failed: {gate}")

# Step 3: produce an auditable decision and preserve the evidence version.
decision = "GO" if not failures else "NO-GO"
print("release decision:", decision)
