路由与互联网控制平面

转发回答“这个分组现在送到哪个端口”，路由则回答“这些转发规则从哪里来”。网络拓扑、链路状态、商业关系和安全事件都在变化，控制平面必须让分散设备在有限信息和故障条件下形成足够一致、稳定且符合策略的路径。

本章从两类经典算法开始：距离向量只向邻居交换目的距离，链路状态则向区域内传播拓扑并在本地运行最短路。随后把算法放入真实协议：RIP、OSPF 与 IS-IS 解决自治系统内部路由，BGP 在自治系统之间传播可达性与策略。最后讨论收敛、环路、路由泄漏、前缀劫持、RPKI、任播和组播。

警告

互联网路由不是单纯的“全局最短路”。AS 内可以优化度量，AS 间首先受商业与安全策略约束；路径长度只是决策属性之一。某条更长路径可能因为客户关系或本地策略而被有意优先选择。

路由问题

拓扑、度量、路径与策略

把网络建模为图 \(G=(V,E)\)：顶点是路由器或网络，边是链路，边权可表示配置成本、时延、带宽倒数或其他度量。路径是连接源与目的的一系列边；算法常尝试最小化路径代价

\[ C(P)=\sum_{e\in P}w(e), \]

但运营目标还可能要求避开某个提供商、优先客户链路、满足容量或安全约束。度量把工程偏好编码成可比较数字，策略则可以直接允许、拒绝或排序路径。

路由协议需要同时追求可达性、较好路径、无环、快速收敛、低开销和可扩展性，这些目标往往冲突。频繁追随瞬时最优可能造成振荡；过度抑制变化又会延长故障恢复。

集中式与分布式路由

集中控制器可以收集拓扑与策略，统一计算并下发规则，便于全局优化和验证，但控制器本身需要复制、分片与故障处理。分布式协议让每台路由器和邻居交换信息并独立计算，天然适应跨组织管理，却只能看到部分状态，收敛过程也可能产生暂态环路。现代网络经常混合两者：设备运行本地协议，控制器提供策略、自动化和跨域视图。

静态路由与动态路由

静态路由可预测、开销低，适合简单存根网络、默认出口、汇总和明确的黑洞策略；它不会自动感知故障，规模大时易发生配置漂移。动态路由自动发现变化并重新计算，但引入协议状态、收敛时间和错误传播风险。可靠设计通常让静态规则表达稳定意图，让动态协议处理变化，并为两者定义清楚的优先级。

收敛、稳定性与故障恢复

收敛是从拓扑/策略变化发生，到相关路由器形成一致可用转发状态的过程。在此期间可能丢包、环路、黑洞或路径绕行。恢复时间包括故障检测、信息传播、路径计算和 FIB 下装。检测越激进，越容易把短暂抖动误判为故障；抑制越强，真正故障恢复越慢。

稳定性要求一次变化最终停止引发新变化。等价路径、策略反馈、重分发和定时器不协调都可能造成 route flapping。评价路由方案时既要看稳态路径，也要观察整个过渡过程。

距离向量路由

Bellman–Ford 递推

节点 \(x\) 到目的 \(y\) 的最小距离满足

\[ D_x(y)=\min_{v\in N(x)}\{c(x,v)+D_v(y)\}, \]

其中 \(N(x)\) 是邻居集合，\(c(x,v)\) 是到邻居 \(v\) 的链路成本。含义很直观：询问每个邻居“你离目的还有多远”，再加上走到该邻居的成本，选择总和最小者。

每台路由器只需保存每个目的的当前代价与下一跳，不必知道完整拓扑。这降低状态和计算复杂度，却意味着信息是“听邻居转述”的，错误或陈旧距离会逐跳传播。

分布式路由通告

初始时，路由器知道自身为 0、直连邻居成本以及其他目的为无穷。收到邻居向量后，它对每个目的执行 Bellman–Ford 更新；若结果变化，再向邻居通告。正常条件下信息一跳一跳扩散，最终形成最短路径。

异步实现必须处理报文丢失、重复、乱序和邻居失效。定期更新可修复丢失状态，触发更新加快变化传播，超时让失联路由过期；但每种机制也会增加流量或不稳定性。

代码 
from copy import deepcopy
from math import inf


graph = {
    "A": {"B": 1, "C": 4},
    "B": {"A": 1, "C": 1, "D": 7},
    "C": {"A": 4, "B": 1, "D": 2, "E": 6},
    "D": {"B": 7, "C": 2, "E": 1},
    "E": {"C": 6, "D": 1},
}


def distance_vector_rounds(topology: dict[str, dict[str, int]]):
    """运行同步 Bellman–Ford 轮次，并保留每轮向量快照。"""

    nodes = sorted(topology)
    vectors = {
        node: {
            destination: (
                0 if destination == node
                else topology[node].get(destination, inf)
            )
            for destination in nodes
        }
        for node in nodes
    }
    history = [deepcopy(vectors)]

    while True:
        updated = deepcopy(vectors)
        for node in nodes:
            for destination in nodes:
                if node == destination:
                    updated[node][destination] = 0
                    continue
                updated[node][destination] = min(
                    link_cost + vectors[neighbor][destination]
                    for neighbor, link_cost in topology[node].items()
                )
        history.append(updated)
        if updated == vectors:
            return history
        vectors = updated


history = distance_vector_rounds(graph)
print("round | A->D | A->E | B->E")
for round_number, vectors in enumerate(history):
    print(
        f"{round_number:5} | {vectors['A']['D']:4} | "
        f"{vectors['A']['E']:4} | {vectors['B']['E']:4}"
    )
print("converged rounds:", len(history) - 1)

计数到无穷与路由环路

距离向量“好消息传播快，坏消息传播慢”。若目的从路由器 C 后方失效，而 A、B 互相以为对方还有路径，它们会交替通告越来越大的距离：A 经 B，B 又经 A，形成转发环路，直到度量达到协议定义的“无穷”。

环路期间分组不断循环直到 TTL 归零，浪费链路与缓冲。把无穷设为较小值能限制持续时间，却同时限制可表达的最大网络直径。根因是路由器只知道邻居声明的距离，不知道该路径是否又经过自己。

代码 
def count_to_infinity(rounds: int = 8, protocol_infinity: int = 16):
    """模拟 C 失去目的 X 后，A 与 B 相互强化陈旧路由。"""

    distance_a, distance_b = 2, 1
    timeline = [(0, distance_a, distance_b)]

    for round_number in range(1, rounds + 1):
        # 两台路由器都根据上一轮通告计算。
        new_a = min(protocol_infinity, 1 + distance_b)
        new_b = min(protocol_infinity, 1 + distance_a)
        distance_a, distance_b = new_a, new_b
        timeline.append((round_number, distance_a, distance_b))
    return timeline

水平分割、毒性逆转与抑制定时器

水平分割（split horizon）不把从某邻居学到的路由再通告回该邻居；毒性逆转（poison reverse）则明确向它通告无穷。这能消除常见两节点环路，但无法解决所有多节点环路。抑制定时器（hold-down）在路由失效后暂时拒绝可疑的较差替代，减少振荡，却可能延迟真实恢复。

这些都是局部启发式而非全局证明。更稳健的协议会携带更多拓扑/路径信息，或使用可行性条件、序列号等机制判断新路径是否可能形成环路。

链路状态路由

拓扑发现与链路状态泛洪

链路状态协议让每台路由器发现邻居和链路代价，生成链路状态通告（LSA/LSP），再可靠泛洪给同一区域的所有路由器。每台路由器最终拥有近似相同的链路状态数据库（LSDB），并独立计算以自己为根的最短路径树。

泛洪不是普通广播：设备通过序列号识别新旧实例，确认接收，向除来源外的邻居继续发送，并限制作用域。协议开销与拓扑变化频率和区域大小相关。

Dijkstra 最短路径算法

Dijkstra 在非负边权图上维护两组节点：已确定最短距离的集合 \(S\)，以及尚未确定的候选。每次选择候选距离最小的节点 \(u\) 加入 \(S\)，并松弛其邻边：

\[ D(v)\leftarrow\min\bigl(D(v),D(u)+w(u,v)\bigr). \]

记录前驱即可恢复路径；路由器只需从最短路径树提取每个目的的第一跳并下装到 FIB。使用优先队列时，典型复杂度为 \(O((V+E)\log V)\)。

算法正确并不保证网络立即无环：不同路由器可能在不同时间安装新旧路径，仍会产生微环。运营系统需要有序 FIB 更新、快速重路由或其他收敛机制处理过渡状态。

代码 
from heapq import heappop, heappush


def dijkstra(topology: dict[str, dict[str, int]], source: str):
    """返回加权图的距离、父节点与确定顺序。"""

    distances = {node: inf for node in topology}
    parents = {node: None for node in topology}
    distances[source] = 0
    queue = [(0, source)]
    settled_order = []

    while queue:
        distance_u, node_u = heappop(queue)
        if distance_u != distances[node_u]:
            continue                     # 忽略堆中过期的表项。
        settled_order.append((node_u, distance_u))

        for node_v, edge_cost in topology[node_u].items():
            candidate = distance_u + edge_cost
            if candidate < distances[node_v]:
                distances[node_v] = candidate
                parents[node_v] = node_u
                heappush(queue, (candidate, node_v))
    return distances, parents, settled_order


def reconstruct_path(parents: dict[str, str | None], destination: str):
    path = []
    current = destination
    while current is not None:
        path.append(current)
        current = parents[current]
    return list(reversed(path))


distances, parents, settled = dijkstra(graph, "A")
print("settlement order:", settled)
for destination in sorted(graph):
    print(
        f"A -> {destination}: cost={distances[destination]:2}, "
        f"path={'-'.join(reconstruct_path(parents, destination))}"
    )

序列号、老化与可靠泛洪

每份链路状态通告带有来源、序列号和寿命。更大序列号代表更新状态；老化清除已失效来源；确认与重传提高泛洪可靠性。路由器重启、序列号回绕和数据库同步都需要专门规则，否则旧信息可能覆盖新信息或长期残留。

两类协议都需要检测故障、传播变化并处理不一致，只是交换了信息量、计算位置和故障模式。

域内路由

路由信息协议

RIP 是经典距离向量协议，以跳数为度量，最大有效距离 15，16 表示不可达。它周期发送路由表并使用触发更新、水平分割和毒性逆转。实现简单，适合教学和小网络，但直径、收敛速度与度量表达能力使其不适合现代大型网络。

开放最短路径优先

OSPF 是链路状态 IGP。邻居建立邻接，交换并同步 LSDB，以接口成本为边权运行 SPF。OSPF 支持区域层次：Area 0 是骨干，区域边界路由器在区域间传播汇总信息。协议还定义网络类型、DR/BDR、不同 LSA 类型、认证及外部路由引入。

OSPF 成本通常与带宽相关但可配置；最短代价相同的路径可进行 ECMP。错误成本会导致次优或不对称路径，错误区域设计与过度重分发会扩大故障范围。

IS-IS 与运维差异

IS-IS 同样是链路状态 IGP，最初来自 OSI，直接运行在链路层，并以 TLV 扩展承载 IPv4/IPv6 等信息。Level 1 负责区域内，Level 2 负责区域间。大型服务商常选择 IS-IS，原因包括扩展方式与运维传统；OSPF 与 IS-IS 的核心算法相似，实际选择更多取决于生态、经验和设计一致性。

区域、汇总、ECMP 与重分发

区域限制拓扑变化传播与 SPF 规模；汇总减少路由状态并隐藏内部变化，但可能产生次优路径或黑洞。ECMP 把多个等价下一跳安装到 FIB，通常按流散列以避免乱序。重分发把一种协议/静态路由注入另一种协议，若缺少标签、过滤和明确优先级，容易形成反馈环路，因此应谨慎并保持边界清晰。

自治系统与互联网经济关系

转接、对等与客户—提供商关系

客户付费给提供商以获得更广可达性；对等体交换各自及客户流量，通常不为对方提供任意第三方转接。IXP 提供建立这些关系的共享设施，私有互联则适合流量很大的网络。

经济关系会直接变成路由策略：网络通常更愿意使用能带来收入的客户路径，其次是无结算对等，最后才是付费提供商路径。物理更短不代表商业上更优。

策略路由与最短路径路由

BGP 的目标是让每个 AS 在本地策略下选择可接受路径，而不是最小化全球统一度量。一个 AS 可按来源邻居设置 LOCAL_PREF、拒绝某些前缀、通过 prepend 影响外部选择，或用 MED 表达偏好入口。由于策略独立，互联网路径可能非对称并随商业关系变化。

无谷路径与导出策略

常见商业模型下，路径先沿客户→提供商方向“上坡”，可经过一次对等边，再沿提供商→客户方向“下坡”，不会下坡后再次上坡。典型导出规则是：客户学到的路由可通告给所有邻居；从提供商或对等体学到的路由只通告给客户。违反规则可能把一个 AS 意外变成免费转接，形成路由泄漏。

代码 
def is_valley_free(relationships: list[str]) -> bool:
    """检查简化的 c2p* p2p? p2c* 关系模式。"""

    phase = "up"
    for relationship in relationships:
        if phase == "up":
            if relationship == "c2p":
                continue
            if relationship == "p2p":
                phase = "peer"
                continue
            if relationship == "p2c":
                phase = "down"
                continue
        elif phase == "peer":
            if relationship == "p2c":
                phase = "down"
                continue
        elif phase == "down" and relationship == "p2c":
            continue
        return False
    return True


examples = {
    "customer -> provider -> peer -> customer": ["c2p", "p2p", "p2c"],
    "provider -> customer -> provider": ["p2c", "c2p"],
    "customer -> provider -> provider -> customer": ["c2p", "c2p", "p2c"],
    "peer -> peer": ["p2p", "p2p"],
}

for description, relationships in examples.items():
    print(f"{description:46} -> {is_valley_free(relationships)}")

边界网关协议

eBGP 与 iBGP 会话

eBGP 在不同 AS 的路由器之间交换路由，iBGP 在同一 AS 内分发外部可达性。BGP 运行在 TCP 之上，建立长期会话并以增量 UPDATE 通告或撤回前缀。TCP 提供可靠字节传输，但 BGP 仍要验证属性、维护 Adj-RIB-In/Out，并在会话失效时撤销路由。

BGP 路由通告与路径属性

一条 BGP 路由把前缀（NLRI）与属性绑定。重要属性包括 AS_PATH、NEXT_HOP、LOCAL_PREF、MED、ORIGIN 和 Communities。AS_PATH 同时提供路径选择信息和基本环路检测：若收到的路径已包含本 AS，通常拒绝。

Community 是附加策略标签，可表达“不要向某类邻居导出”“降低优先级”等运维意图；只有各方对语义达成一致时才有效。

路由选择与策略

BGP 决策首先受本地策略影响。实现细节不同，但常见顺序包括更高 LOCAL_PREF、更短 AS_PATH、更优 ORIGIN/MED、eBGP 优于 iBGP、较低 IGP 到 NEXT_HOP 成本及稳定决胜项。

因此不能只看 AS_PATH 最短判断“最佳”。选路过程是先过滤不可接受路线，再按本地商业和工程偏好排序，最后才用技术决胜条件稳定选择。

代码 
from dataclasses import dataclass, replace


@dataclass(frozen=True)
class BGPRoute:
    learned_from: str
    local_pref: int
    as_path: tuple[int, ...]
    origin: str
    ebgp: bool
    igp_cost_to_next_hop: int
    router_id: str


ORIGIN_RANK = {"IGP": 0, "EGP": 1, "INCOMPLETE": 2}


def bgp_selection_key(route: BGPRoute):
    """常见 BGP 决策过程的透明教学子集。"""

    return (
        -route.local_pref,                 # 优先选择更高的 LOCAL_PREF。
        len(route.as_path),                # 随后优先选择更短的 AS 路径。
        ORIGIN_RANK[route.origin],         # 起源类型按 IGP、EGP、incomplete 的顺序优先。
        0 if route.ebgp else 1,            # 在这个简化的平局条件下优先选择 eBGP。
        route.igp_cost_to_next_hop,        # 对剩余候选采用热土豆路由，选择最近出口。
        route.router_id,                   # 使用确定性的最终规则打破平局。
    )


candidates = [
    BGPRoute("customer", 200, (65100, 65210, 65300), "IGP", True, 30, "10.0.0.3"),
    BGPRoute("peer", 150, (65400, 65300), "IGP", True, 10, "10.0.0.2"),
    BGPRoute("provider", 100, (65500,), "IGP", True, 5, "10.0.0.1"),
]

best_policy_route = min(candidates, key=bgp_selection_key)
equal_local_pref = [replace(route, local_pref=100) for route in candidates]
best_short_path = min(equal_local_pref, key=bgp_selection_key)

print("normal policy winner:   ", best_policy_route.learned_from,
      best_policy_route.as_path)
print("if LOCAL_PREF is equal: ", best_short_path.learned_from,
      best_short_path.as_path)

导入策略、导出策略与 FIB

导入策略决定从邻居收到的路线能否进入本地决策，并可修改 LOCAL_PREF、Community 等；选出最佳路线后，还需确保 NEXT_HOP 可达并把结果递归解析为 FIB 下一跳。导出策略再决定把什么通告给每个邻居，可能修改 AS_PATH、MED 或 Community。RIB 中存在不代表一定转发，最佳本地路由也不代表会向所有邻居发布。

路由反射与 iBGP 扩展

传统 iBGP 要求全互连，会话数为 \(n(n-1)/2\)。路由反射器（RR）让客户端把路线交给 RR，再由 RR 反射给其他客户端/非客户端，显著降低会话数。

代价是 RR 的视图和决策可能隐藏其他可用路径，造成路径次优或控制平面单点。大型网络会部署冗余 RR、合理分层，并使用 Add-Paths 等机制增加路径可见性。

收敛与域间故障模式

路径探索与慢收敛

路线撤回后，BGP 邻居可能依次尝试多个后来才发现无效的替代 AS_PATH，这称为路径探索。MRAI、会话定时器、策略与庞大传播范围使域间收敛通常慢于 IGP。过度抑制 flap 可减少更新，却可能惩罚已经恢复的有效路线。

路由泄漏与前缀劫持

路由泄漏是把合法学到的路线通告给不应接收的邻居，违反预期商业作用域；前缀劫持是错误或恶意 AS 宣称自己起源某前缀。更具体前缀因 LPM 可能吸引流量，即使 BGP 策略并不偏好攻击者。结果可能是黑洞、监听、绕路或全球拥塞。

过滤、RPKI 与路由起源验证

运营者应基于客户授权、最大前缀长度、保留地址、IRR/RPKI 数据和合理 AS 路径进行过滤。RPKI 的 ROA 声明某 ASN 有权起源一个前缀及允许的最大长度；路由起源验证把通告分类为 Valid、Invalid 或 Not Found。

ROV 能阻止许多错误起源，却不验证完整 AS_PATH，也无法覆盖没有 ROA 的前缀。

路由安全的运维权衡

严格丢弃 Invalid 能提高安全，但错误 ROA 也可能使合法流量中断；宽松接受则无法阻止攻击。部署需要监控验证状态、分阶段执行、维护密钥与授权，并准备紧急修复。安全控制必须与可用性、全球采用率和变更流程共同设计。

代码 
from ipaddress import ip_network


@dataclass(frozen=True)
class ROA:
    prefix: object
    max_length: int
    origin_as: int


def origin_validation(announced_prefix: str, origin_as: int, roas: list[ROA]):
    """返回 RFC 6811 风格的 Valid、Invalid 或 Not Found 状态。"""

    announcement = ip_network(announced_prefix)
    covering = [roa for roa in roas if announcement.subnet_of(roa.prefix)]
    if not covering:
        return "Not Found"
    if any(
        origin_as == roa.origin_as
        and announcement.prefixlen <= roa.max_length
        for roa in covering
    ):
        return "Valid"
    return "Invalid"


validated_roas = [ROA(ip_network("203.0.113.0/24"), 24, 65001)]
announcements = [
    ("203.0.113.0/24", 65001),  # 已授权的精确前缀。
    ("203.0.113.0/24", 65009),  # 起源 AS 错误。
    ("203.0.113.0/25", 65001),  # 前缀比 maxLength 24 允许的范围更具体。
    ("198.51.100.0/24", 65008), # 不存在覆盖该前缀的 ROA。
]

for prefix, origin in announcements:
    print(f"{prefix:18} origin AS{origin} -> "
          f"{origin_validation(prefix, origin, validated_roas)}")

203.0.113.0/24     origin AS65009 -> Invalid
203.0.113.0/25     origin AS65001 -> Invalid
198.51.100.0/24    origin AS65008 -> Not Found

任播、组播与专用路由

IP 任播与服务复制

任播让多个地点通告同一前缀，路由系统把客户端带到按当前策略“最近”的实例。DNS 根服务器、CDN 与 DDoS 防护常用任播分散负载和故障。它并不保证地理最近或会话期间位置不变，长连接需要状态同步、连接迁移或稳定路由设计。

组播树与组成员管理概览

组播允许发送者向组地址发送一次，网络在分支点复制，避免源端为每个接收者发送独立副本。主机通过 IGMP/MLD 表达成员关系，路由协议构建源树或共享树。组播节省带宽，但状态、控制、跨域部署、安全和可靠性更复杂，因此互联网范围部署有限，而受控企业、运营商与媒体网络更常见。

模拟距离向量与链路状态路由

后面的代码在同一加权图上分别运行同步距离向量迭代与 Dijkstra。比较时不要只看最终距离，还要记录每轮变化、消息范围、故障后的暂态以及每个节点所需信息。两者最终可得到相同最短路径，却通过完全不同的知识分布和收敛过程达到结果。

可进一步实验：删除一条边，观察距离向量需要多少轮；改变权重，观察最短路径树与下一跳；人为延迟部分更新，检查暂态环路；为等价路径加入稳定决胜规则。

def remove_undirected_link(topology, node_a: str, node_b: str):
    changed = deepcopy(topology)
    del changed[node_a][node_b]
    del changed[node_b][node_a]
    return changed

跨自治系统追踪互联网路由

一次实用调查可以组合 tracert/traceroute、DNS、WHOIS/RDAP、公开 BGP 视图和 RPKI 验证。先记录目的 A/AAAA 地址和时间，再从多个地点探测路径，将可见路由器地址映射到前缀与 ASN，最后比较 BGP 起源、AS_PATH 和 ROV 状态。

必须承认观测限制：路由器接口地址不一定属于其转发流量的 AS；MPLS 可隐藏内部跳；负载均衡让连续探测走不同路径；反向 DNS 只是运营命名；正反向路径可能不同。不要从一条 traceroute 推断完整商业关系。

对比与总结

不要混淆 关键区别
数据平面与控制平面 执行已安装规则，与计算/分发规则
度量与策略 可累加的工程成本，与允许/拒绝/排序约束
距离向量与链路状态 邻居距离通告，与拓扑泛洪后本地 SPF
IGP 与 BGP 单一管理域内优化，与跨 AS 的策略可达性
eBGP 与 iBGP AS 之间交换，与 AS 内传播外部路线
最短 AS_PATH 与最佳 BGP 路径 路径长度只是本地策略之后的一项属性
路由泄漏与前缀劫持 错误导出合法路线，与错误声明起源
RPKI Valid 与“整条路径安全” 只验证起源授权，不证明完整路径可信

路由的核心挑战不是一次算出最短路径，而是在分布式、异步、分权和策略驱动的环境中持续维持可用路径。算法决定信息怎样传播，协议定义状态与作用域，经济关系决定哪些路径可接受，安全机制则限制错误通告的影响。
