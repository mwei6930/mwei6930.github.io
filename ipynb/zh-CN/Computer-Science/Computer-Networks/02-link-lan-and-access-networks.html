链路、局域网与接入网络

端到端通信最终必须落实为一系列相邻接口之间的传输。IP 数据报可能跨越整个互联网，但它每前进一跳，都要被重新封装进当前链路能够理解的帧，并受该链路的速率、介质、错误模式与共享规则约束。

本章聚焦网络的“第一跳”和“逐跳”基础：链路层提供什么服务，信号如何在铜缆、光纤与无线介质中传播，帧如何划分边界和发现错误，多台设备如何共享介质，以太网交换机如何学习位置，以及主机怎样通过 ARP 或 IPv6 邻居发现找到下一跳。理解这些机制后，诸如“有 Wi-Fi 信号却无法上网”“同一 VLAN 内为何能通信”“交换环路为何会拖垮整个 LAN”等问题就能被拆解为可验证步骤。

注记

链路层的作用域通常只有一跳。端到端 IP 地址一般保持不变，而源、目的 MAC 地址会在每次经过路由器后重新生成。交换机扩展同一个链路层广播域；路由器连接不同 IP 网络。

链路层的作用

节点、链路、帧与跳

节点（node）是连接到链路的设备接口，可以属于主机、交换机、路由器或接入点；链路（link）是在相邻节点间传输信号的通信信道；帧（frame）是链路层数据单元；分组从一个三层节点前进到下一个三层节点称为一跳（hop）。

发送端链路层把 IP 数据报封装进帧，加入本地交付所需的地址、类型和错误检测信息；接收端验证帧并把其中的数据报交给网际层。经过路由器后，入站帧被移除，数据报再用下一条链路的格式重新封装。因此，一条端到端路径可以先经过 Wi-Fi，再经过以太网、运营商光纤和点到点链路，而上层仍看到统一的 IP 服务。

链路层服务及其实现位置

链路层可能提供以下服务，但并非每种链路都全部提供：

服务 作用 典型实现
成帧 标识一段链路层数据的开始与结束 长度字段、分隔符、编码违规
介质访问 决定共享信道上谁可以发送 CSMA/CD、CSMA/CA、时隙或调度
本地寻址 在一个链路域内选择接口 Ethernet MAC 地址
差错检测 发现传输中改变的比特 FCS/CRC
局部可靠性 在一跳内确认与重传 802.11 ACK 与重试
链路管理 建立、维护和关闭连接 Wi-Fi 关联、速率协商

这些功能通常由网卡硬件、固件、设备驱动和操作系统共同实现。高速校验、DMA 与过滤适合硬件完成，策略、配置和异常处理则常由软件控制。实现位置影响性能，却不改变服务的逻辑作用域。

点到点链路与共享介质链路

点到点链路只有两个端点，发送权较简单；共享介质上多个节点使用同一信道，必须解决“谁在什么时候发送”。早期同轴以太网、无线 LAN 与共享无线电信道都面临竞争。现代交换式全双工以太网把每个端口变成独立点到点冲突域，基本消除了碰撞，但广播、未知单播和组播仍可能扩散到整个 VLAN。

物理传输基础

铜缆、光纤与无线介质

不同介质在容量、距离、成本、抗干扰能力和部署方式之间作出不同权衡：

介质 主要信号 优势 典型限制
双绞铜缆 电信号 便宜、易布线、可同时供电 距离与频率受衰减、串扰影响
同轴电缆 电信号 屏蔽较好、可共享频谱 接入拓扑与共享容量复杂
光纤 光脉冲 高带宽、长距离、抗电磁干扰 光模块和施工成本较高
无线 电磁波 支持移动与灵活部署 共享频谱、干扰、衰落和安全风险

“无线速率”不是固定管道容量。接收信噪比、调制编码方案、信道宽度、竞争设备、重传和空间流数量都会改变实际吞吐量。

比特率、带宽、噪声与衰减

比特率是每秒传输的比特数；物理层语境中的带宽常指信道可用频率范围，而网络性能语境中又常被用作链路容量。两者相关但不是同一个量。信号传播时会发生衰减，其他发送器和电子设备会引入噪声；接收方必须在噪声背景中判断符号。

香农容量给出带宽为 \(B\)、信噪比为 \(S/N\) 的理想信道上限：

\[ C=B\log_2(1+S/N). \]

它不是某条链路的实际速率公式，而是说明提高频谱或信噪比能够增加理论容量，并且信噪比收益呈对数递减。工程系统还受编码、硬件、法规和协议开销约束。

线路编码、调制与复用概览

线路编码把比特映射为基带信号变化，并处理时钟恢复、直流平衡等问题；调制把信息映射到载波的幅度、相位或频率；更高阶调制让每个符号携带更多比特，却需要更高信噪比。复用则让多个通信共享资源：TDM 划分时间，FDM/OFDMA 划分频率，WDM 在光纤中划分波长，空间复用利用多条独立空间路径。

链路宣称的“1 Gb/s”通常是物理层线速率。前导码、帧间隙、首部、确认、竞争和重传都会让应用层 goodput 更低。

成帧与差错处理

面向字节与面向比特的成帧

接收方看到的是连续信号或字节流，必须知道帧从哪里开始、在哪里结束。面向字节协议可以使用特殊分隔字节，并通过字节填充转义载荷中相同的值；面向比特协议可以使用特殊比特模式，并通过比特填充避免数据意外形成标志。另一种办法是在首部携带长度，但错误的长度字段可能让后续边界也失去同步，因此常与校验和重新同步机制配合。

奇偶校验、校验和与循环冗余校验

奇偶校验增加一个比特，使 1 的数量满足奇或偶约束，能发现任意奇数个翻转，却无法发现许多偶数错误。校验和把数据字累加并压缩成固定宽度，计算便宜，常用于软件实现。循环冗余校验（CRC）把比特串视为 \(GF(2)\) 上的多项式，用生成多项式 \(G(x)\) 做模二除法，并把余数附加到帧后：

\[ T(x)=M(x)x^r+R(x),\qquad T(x)\bmod G(x)=0. \]

接收方重新相除，非零余数说明检测到错误。合适的生成多项式能保证发现所有不超过一定长度的突发错误，并对更长错误保持很高检测概率。CRC 只能说明“检测到损坏”，不能单独恢复原始数据。

差错检测与差错纠正

检测后可以丢弃并请求重传；纠错码则增加足够冗余，让接收方在不重传的情况下定位并修复一定数量的错误。重传适合 RTT 较低且存在反向信道的链路；前向纠错适合卫星、广播、实时媒体或高时延链路。实际系统常混合两者：先用纠错处理常见错误，再用 CRC 拒绝无法可靠恢复的帧。

可靠链路协议

可靠链路通常组合序号、确认、定时器和重传。它能在高误码单跳上隐藏局部损失，例如 Wi-Fi 会在链路层快速重试。但局部可靠性不等于端到端可靠性：帧通过第一跳后，仍可能在后续队列、路由或接收主机处丢失。是否使用链路重试取决于其收益能否抵消额外时延、重复发送与队头阻塞。

def crc_remainder(data_bits: str, generator_bits: str) -> str:
    """使用 GF(2) 上的多项式长除法返回 CRC 余数。"""

    if generator_bits[0] != "1" or generator_bits[-1] != "1":
        raise ValueError("A generator must begin and end with 1")
    if set(data_bits + generator_bits) - {"0", "1"}:
        raise ValueError("Inputs must be bit strings")

    degree = len(generator_bits) - 1
    working = [int(bit) for bit in data_bits + "0" * degree]
    generator = [int(bit) for bit in generator_bits]

    # 当前最高系数为 1 时，把生成多项式异或到该位置。
    # 在二元域中，异或就是减法。
    for start in range(len(data_bits)):
        if working[start] == 1:
            for offset, generator_bit in enumerate(generator):
                working[start + offset] ^= generator_bit

    return "".join(str(bit) for bit in working[-degree:])


def crc_is_valid(codeword: str, generator_bits: str) -> bool:
    """在不补额外零比特的情况下检查接收码字。"""

    working = [int(bit) for bit in codeword]
    generator = [int(bit) for bit in generator_bits]
    for start in range(len(codeword) - len(generator_bits) + 1):
        if working[start] == 1:
            for offset, generator_bit in enumerate(generator):
                working[start + offset] ^= generator_bit
    return not any(working[-(len(generator_bits) - 1):])

多路访问协议

信道划分

共享信道可以按时间、频率或码字静态划分。TDMA 为每个站点分配时隙，FDMA 分配频带，CDMA 使用可区分码序列。优点是负载高时行为可预测、碰撞少；缺点是某个站点空闲时，其份额可能浪费，而且动态成员与突发流量很难提前分配。

ALOHA 与时隙 ALOHA

纯 ALOHA 允许节点随时发送，若未收到确认就在随机时间后重试；任何时间重叠都可能破坏帧。归一化负载为 \(G\) 时，理想吞吐量为 \(S=Ge^{-2G}\)，最大约 \(1/(2e)\approx18.4\%\)。时隙 ALOHA 要求只在帧时隙边界发送，将易受碰撞区间减半，\(S=Ge^{-G}\)，最大约 \(1/e\approx36.8\%\)。

这两个结果说明随机访问简单且低负载延迟小，但高负载下碰撞和重试会吞噬容量。

CSMA、CSMA/CD 与 CSMA/CA

载波侦听多路访问（CSMA）在发送前先监听信道。多个节点仍可能因传播时延同时判断“空闲”。共享半双工以太网使用 CSMA/CD：发送时继续监听，发现碰撞后停止并进行二进制指数退避。现代交换式全双工以太网没有共享冲突域，因此不再需要碰撞检测。

无线设备通常无法边发边可靠检测碰撞，而且还存在隐藏终端，所以 802.11 使用 CSMA/CA：监听、等待帧间间隔、选择随机退避计数，必要时用 RTS/CTS 预约，再发送数据并等待链路层 ACK。

碰撞检测、避免与公平性

“检测”在碰撞发生后尽快停止浪费，“避免”则降低碰撞概率，两者都不能保证绝对不碰撞。随机退避在多个竞争者之间提供概率公平，但短期可能很不均匀；持续高负载下还要考虑饥饿、捕获效应和不同速率设备占用信道时间的问题。

隐藏终端说明“我没有听到别人”并不等于“接收者处不会碰撞”；暴露终端则说明听到附近发送也不一定代表自己发送必然干扰目标接收者。RTS/CTS 能缓解部分隐藏终端问题，但额外控制开销使其更适合较大帧或高碰撞环境。

代码 
import math
import random


def simulate_slotted_aloha(
    stations: int,
    transmit_probability: float,
    slots: int = 200_000,
    seed: int = 7,
) -> tuple[float, float, float]:
    """返回提供负载、吞吐量和碰撞时隙比例。"""

    rng = random.Random(seed)
    attempts = 0
    successes = 0
    collisions = 0

    for _ in range(slots):
        contenders = sum(
            rng.random() < transmit_probability
            for _ in range(stations)
        )
        attempts += contenders
        if contenders == 1:
            successes += 1
        elif contenders > 1:
            collisions += 1

    offered_load = attempts / slots
    throughput = successes / slots
    collision_fraction = collisions / slots
    return offered_load, throughput, collision_fraction


print(" G(sim)  S(sim)  G*exp(-G)  collision slots")
for probability in (0.01, 0.025, 0.05, 0.10):
    offered, throughput, collisions = simulate_slotted_aloha(
        stations=20,
        transmit_probability=probability,
    )
    theoretical = offered * math.exp(-offered)
    print(
        f" {offered:5.3f}   {throughput:5.3f}"
        f"      {theoretical:5.3f}          {collisions:5.3f}"
    )

以太网与 MAC 寻址

以太网帧结构

Ethernet II 帧包含前导码/帧起始、目的与源 MAC、EtherType、载荷和帧校验序列（FCS）。EtherType 指明载荷通常是 IPv4、IPv6 或 ARP；载荷过短时需要填充，过长则超过 MTU。FCS 使用 CRC 检测链路传输错误，错误帧通常被静默丢弃。

MAC 地址与广播交付

典型 MAC 地址为 48 bit，以十六进制表示。单播地址选择一个接口，组播地址选择一组接收者，ff:ff:ff:ff:ff:ff 是广播地址。MAC 地址只在当前链路层域内有交付意义，并不会像 IP 前缀一样被全球路由。

交换机对未知目的单播、广播和部分组播执行泛洪，因此广播域越大，控制流量和故障影响范围也越大。VLAN 用逻辑方式把一套物理交换基础设施分割成多个广播域。

从共享以太网到交换式以太网

早期总线或集线器以太网让所有站共享一个冲突域，需要 CSMA/CD。交换机为每个端口建立独立全双工链路，可以同时转发多个无关帧，碰撞域缩小到单条端口链路。性能显著提升，但错误环路、广播风暴和错误 VLAN 配置仍可能影响整个二层域。

from dataclasses import dataclass


@dataclass(frozen=True)
class EthernetHeader:
    destination: str
    source: str
    ether_type: int


def format_mac(raw: bytes) -> str:
    return ":".join(f"{octet:02x}" for octet in raw)


def parse_ethernet_header(frame: bytes) -> EthernetHeader:
    """解析软件可见的 14 字节 Ethernet II 首部。

    物理前导码与 FCS 通常由网卡处理，操作系统抓包中可能不会出现。
    """

    if len(frame) < 14:
        raise ValueError("Frame is shorter than an Ethernet II header")

    return EthernetHeader(
        destination=format_mac(frame[0:6]),
        source=format_mac(frame[6:12]),
        ether_type=int.from_bytes(frame[12:14], byteorder="big"),
    )

    "00 00 00 00 00 00 c0 00 02 01"

学习型交换机与交换式 LAN

学习、过滤、泛洪与转发

透明交换机通过每个入站帧的源 MAC学习“该地址位于哪个端口”，并给表项设置老化时间。处理目的地址时：若目的端口已知且不同于入端口，就只向该端口转发；若已知且就在入端口，则过滤；若未知、广播或需要泛洪，则复制到 VLAN 内除入端口外的端口。

学习是数据驱动的软状态，因此主机移动后旧表项会老化，新的源帧会更新位置。它无需预先配置每台主机，却也会受到 MAC 泛洪、伪造与环路的影响。

冲突域与广播域

交换端口把冲突域分开，但同一 VLAN 仍属于一个广播域。路由器或三层接口通常是广播边界。排障时要明确问题是物理冲突、二层广播扩散，还是三层路由不可达；“都插在同一台交换机上”并不保证位于同一 VLAN。

环路与生成树协议

二层帧没有类似 IP TTL 的逐跳寿命字段。冗余链路形成环路时，广播或未知单播可被无限复制，导致广播风暴、重复帧和 MAC 表震荡。

生成树协议（STP）选举根桥，计算到根的最低代价路径，并把冗余端口置于不转发状态，从逻辑上得到无环树。链路故障后可重新收敛并启用备用路径。RSTP 改善收敛速度，但错误根桥、拓扑变化或边缘端口误配置仍可能造成中断。

VLAN 与 IEEE 802.1Q

VLAN 将端口划入逻辑广播域。接入口通常为终端收发无标签帧，干道在交换机之间携带多个 VLAN，并插入 IEEE 802.1Q 标签，其中包含 VLAN ID 与优先级信息。

不同 VLAN 间通信需要三层路由和相应安全策略。VLAN 提供流量分段与运维边界，但不是完整安全机制；错误 trunk、允许列表或原生 VLAN 配置都可能打破预期隔离。

链路聚合与冗余

链路聚合把多条物理链路组合为一个逻辑接口，提高总容量并容忍单链路故障。为了保持帧顺序，设备通常按流的地址/端口散列选择成员，而不是逐帧轮询；因此单个流一般仍受一条成员链路速率限制。冗余设计还必须考虑设备、电源、上行与控制平面的共同故障域。

代码 
from dataclasses import dataclass


@dataclass
class LearnedLocation:
    port: int
    last_seen: float


class LearningSwitch:
    """以太网交换机上单个 VLAN 的小型教学模型。"""

    BROADCAST = "ff:ff:ff:ff:ff:ff"

    def __init__(self, ports: set[int], aging_seconds: float = 300.0):
        self.ports = ports
        self.aging_seconds = aging_seconds
        self.fdb: dict[str, LearnedLocation] = {}

    def _expire(self, now: float) -> None:
        stale = [
            mac
            for mac, location in self.fdb.items()
            if now - location.last_seen > self.aging_seconds
        ]
        for mac in stale:
            del self.fdb[mac]

    def process(
        self,
        source: str,
        destination: str,
        incoming_port: int,
        now: float,
    ) -> tuple[str, list[int]]:
        self._expire(now)

        # 学习始终使用源地址与入端口。
        self.fdb[source] = LearnedLocation(incoming_port, now)

        if destination == self.BROADCAST or destination not in self.fdb:
            outputs = sorted(self.ports - {incoming_port})
            return "flood", outputs

        output = self.fdb[destination].port
        if output == incoming_port:
            return "filter", []
        return "forward", [output]


switch = LearningSwitch(ports={1, 2, 3}, aging_seconds=30)
frames = [
    ("A", "B", 1, 0),   # B 的位置未知，因此执行泛洪。
    ("B", "A", 2, 1),   # 学习 B 的位置；A 已知位于端口 1。
    ("A", "B", 1, 2),   # 此时 A 与 B 的位置都已知。
    ("C", "A", 3, 40),  # A 与 B 的表项均已老化，A 再次变为未知。
]

for source, destination, port, now in frames:
    action, outputs = switch.process(source, destination, port, now)
    print(
        f"t={now:>2}  {source}->{destination} on P{port}: "
        f"{action:<7} {outputs}"
    )

t= 1  B->A on P2: forward [1]

本地解析与主机接入

地址解析协议

IPv4 主机知道下一跳 IP 后，还需要其 MAC 地址才能构造本地以太网帧。ARP 先广播“谁拥有这个 IP”，目标主机以单播方式返回自己的 MAC。发送方将结果缓存一段时间，避免每个分组都广播查询。

ARP 只解析当前链路上的地址。访问远程服务器时，主机解析的是默认网关的 MAC，而不是远程服务器的 MAC；IP 目的地址仍是远程服务器。

ARP 缓存、免费 ARP 与故障模式

ARP 缓存是会过期的软状态。免费 ARP 在未被查询时主动通告映射，可用于地址冲突检测、主机迁移或高可用切换。ARP 没有内建认证，攻击者可伪造回复实施流量拦截或拒绝服务；交换机的 DHCP snooping、动态 ARP 检查和端口安全可降低风险，但依赖正确配置。

常见故障包括重复 IP、陈旧缓存、错误 VLAN、网关接口关闭与安全策略阻断。看到“不完整”邻居项时，重点检查请求是否发出、是否到达目标广播域，以及回复是否返回。

到默认网关的第一跳交付

主机先用最长前缀匹配判断目的 IP 是否同链路。若远程，选择默认路由的下一跳，解析网关 MAC，并构造“目的 MAC=网关、目的 IP=远程服务器”的帧。交换机只根据 MAC 把帧送到路由器；路由器移除帧后，再根据 IP 选择下一跳。这个过程清楚地区分了逐跳链路寻址与端到端网络寻址。

from ipaddress import ip_address, ip_interface


def choose_arp_target(
    local_interface: str,
    destination_ip: str,
    default_gateway: str,
) -> str:
    """在简化主机上选择需要解析 MAC 的 IPv4 地址。

    模型只含一个直连前缀和一条默认路由；真实路由表可包含许多更具体
    路由与策略决策。
    """

    interface = ip_interface(local_interface)
    destination = ip_address(destination_ip)

    if destination in interface.network:
        return str(destination)       # 解析目的主机自身的地址。
    return str(ip_address(default_gateway))  # 解析所选路由器的地址。


local = "192.0.2.24/24"
gateway = "192.0.2.1"

for destination in ("192.0.2.77", "203.0.113.80"):
    target = choose_arp_target(local, destination, gateway)
    scope = "on-link host" if target == destination else "default gateway"
    print(f"destination {destination:<13} -> ARP for {target:<12} ({scope})")

无线局域网

IEEE 802.11 体系结构与关联

站点（STA）与接入点（AP）构成基本服务集（BSS），多个 AP 可通过分布系统连接并使用同一 SSID。客户端扫描信道、发现网络、认证并关联到一个 AP，随后才能交换数据；企业网络还可能通过 802.1X/EAP 与后端身份服务认证。

无线是共享且半双工的：一个客户端的低速传输可能占用较长 airtime，影响其他客户端。信号强度只是因素之一，干扰、信道占用、重试率与速率选择同样重要。

隐藏终端与暴露终端问题

隐藏终端彼此听不到，却会在共同接收者处碰撞；暴露终端能够听到附近发送，但自身向另一个接收者发送其实不会造成有害干扰。它们说明仅凭本地载波侦听无法准确知道整个无线空间的冲突关系。RTS/CTS、功率控制和集中调度能缓解部分问题，但都有开销或部署限制。

确认、重传与速率自适应

802.11 单播帧通常需要短间隔后的 ACK，未收到就退避并重传。发送器还会根据成功率和信号状况选择调制编码速率。高物理速率并不总是最好：过于激进会增加重试，过于保守则占用更多 airtime。诊断时应同时观察协商速率、重试率、信道利用率和实际 goodput。

WLAN 内漫游与移动性

客户端在多个 AP 之间移动时，需要发现更合适的 AP、重新认证/关联，并更新交换网络中的位置。漫游决策通常由客户端发起，阈值和扫描行为因实现而异。802.11k/v/r 等机制能帮助发现邻居、引导选择和快速重新认证，但端到端会话是否中断还取决于 VLAN、IP 地址、网关与安全策略是否连续。

def wifi_exchange(
    payload_bytes: int,
    phy_rate_mbps: float,
    frame_overhead_bytes: int = 38,
    preamble_us: float = 40,
    contention_us: float = 80,
    sifs_us: float = 16,
    ack_us: float = 44,
    frame_error_probability: float = 0.0,
) -> tuple[float, float]:
    """估算一个 Wi-Fi 帧的期望空口时间与载荷有效吞吐量。

    数值仅作说明，不绑定某个具体 802.11 PHY。若帧失败相互独立，
    期望尝试次数为 1 / (1 - p)。
    """

    if not 0 <= frame_error_probability < 1:
        raise ValueError("Frame error probability must be in [0, 1)")

    transmitted_bits = (payload_bytes + frame_overhead_bytes) * 8
    data_us = transmitted_bits / phy_rate_mbps
    one_attempt_us = contention_us + preamble_us + data_us + sifs_us + ack_us
    expected_attempts = 1 / (1 - frame_error_probability)
    expected_airtime_us = one_attempt_us * expected_attempts

    goodput_mbps = (payload_bytes * 8) / expected_airtime_us
    return expected_airtime_us, goodput_mbps


print("PHY rate  error p  expected airtime  payload goodput")
for rate, error_probability in ((54, 0.02), (300, 0.02), (300, 0.20)):
    airtime, goodput = wifi_exchange(
        payload_bytes=1_500,
        phy_rate_mbps=rate,
        frame_error_probability=error_probability,
    )
    print(
        f"{rate:>7} Mb/s   {error_probability:>4.0%}"
        f"       {airtime:7.1f} us       {goodput:7.1f} Mb/s"
    )

接入网络技术

住宅宽带与光纤接入

住宅接入常见 DSL、有线宽带和光纤到户。DSL 在铜质电话线上使用频率划分，距离越远可用速率通常越低；有线网络由一组用户共享下行/上行信道；PON 则由光线路终端和无源分光器服务多个光网络单元。产品标称速率不等于持续应用吞吐量，上行不对称、共享汇聚、家庭 Wi-Fi 与缓冲队列都可能成为限制。

企业与校园接入网络

企业/校园通常组合交换以太网、集中管理 Wi-Fi、VLAN、802.1X、冗余汇聚与路由。设计不仅追求容量，还要处理身份、访客隔离、语音/实时业务、故障域和统一运维。接入端口、VLAN、地址分配、网关和访问控制之间必须保持一致。

蜂窝与卫星接入概览

蜂窝网络由无线接入网、移动核心和运营商策略共同提供连接，用户共享无线调度资源，并可能经历切换、NAT 与变化明显的 RTT。卫星覆盖广，但轨道高度、地面站路径和频谱共享影响时延与容量；低轨星座可降低传播时延，却需要频繁切换和庞大地面/空间基础设施。

比较接入技术时，应分别看下行、上行、基础 RTT、抖动、共享比例、覆盖、移动性、可靠性与成本，而不是只比较一个峰值速率。

跟踪分组穿越第一跳

假设笔记本通过 Wi-Fi 访问远程 HTTPS 服务器，第一跳可以拆成以下步骤：

  1. 客户端关联 AP 并取得 IP 前缀、默认网关与 DNS 配置；
  2. 路由表判断服务器不在本地前缀，选择默认网关；
  3. ARP 或 IPv6 邻居发现获得网关的链路层地址；
  4. 客户端等待无线信道、退避，发送含 IP 数据报的 802.11 帧并等待 ACK；
  5. AP 将无线帧桥接到对应 VLAN，以太网交换机依据学习表转发；
  6. 网关接收帧、移除二层封装并进入 IP 转发流程。

失败点也与层次对应：关联失败属于无线接入，邻居解析失败属于本地二层，错误 VLAN 会让请求与网关不在同一广播域，而网关之后的问题才进入三层路由。逐步验证比反复“重启路由器”更能定位根因。

推荐按以下顺序排查：确认接口物理启用和错误/丢弃计数；确认连接了预期 SSID、交换端口和 VLAN；检查本机地址与前缀；检查默认网关邻居项是否能解析；最后用抓包验证 ARP/ND 请求、回复以及链路重传。抓包位置决定能看到什么，无线网卡在普通客户端模式下通常看不到同信道的全部帧。

MAC 地址与 IP 地址 本地链路交付标识，与可路由的分层地址
交换机与路由器 在 VLAN 内学习/转发帧，与在前缀间转发数据报

标称链路速率与 goodput 物理/协议速率，与应用实际有用数据速率
ARP 目标与 IP 目标 下一跳 MAC，与最终目的 IP

链路层把统一的 IP 服务落实到不同物理介质上：成帧提供边界，CRC 发现损坏，多路访问协调共享信道，交换机通过源地址学习构建 LAN，VLAN 与 STP 控制广播域和环路，ARP/ND 把下一跳网络地址解析成本地交付地址。每一次路由跳都会重新执行这些局部工作，因此理解第一跳，也是理解整条路径的基础。
