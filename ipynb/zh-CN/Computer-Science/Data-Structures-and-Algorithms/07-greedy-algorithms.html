贪心算法

贪心算法（greedy algorithm）通过一连串不可撤销的选择构造解。每一步都按照某个局部规则，选择当前看起来最好且可行的选项，永久记录该选择，再解决剩余的更小问题。它类似旅行装包时反复拿走仍放得下且“最有用”的物品。这种方式快速、果断，但只有在早期选择不会阻塞更好的全局解时才正确。

因此，贪心设计并不等同于“每次取最大”或“每次取最小”，而是一项包含三部分的论断：

  1. 一个精确定义的局部规则能够确定下一选择；
  2. 该选择是安全的（safe），即至少有一个全局最优解包含它；
  3. 提交该选择后，剩余问题仍保持相同的有用结构。

本章从多个角度建立这一论断。区间调度展示排序如何产生简单可行前沿；Huffman 编码展示优先队列如何反复暴露下一对安全选择；最小生成树用切分性质证明安全边；反例则说明，一个看起来合理的局部规则并不能自动证明正确。

重要

贪心算法通常只探索一条解路径。它的速度来自丢弃其他选择，因此正确性证明必须准确解释为什么这些替代方案都不再需要。

贪心选择与最优子结构

贪心选择性质（greedy-choice property）表示：作出算法偏好的第一个局部选择后，仍然能够到达一个全局最优解。它不要求所有最优解都这样开始；只需证明至少一个最优解可以被重排，使其包含贪心选择且不变差。

最优子结构（optimal substructure）是另一个性质。固定第一个选择后，最优解的剩余部分必须是剩余问题的最优解。若 P 是原问题，g 是安全贪心选择，P_g 是选择 g 后的剩余问题，则可示意为

\[ \operatorname{OPT}(P)=\operatorname{combine}\!\left(g,\operatorname{OPT}(P_g)\right). \]

这里 \(\operatorname{OPT}(P)\) 表示最优解或目标值，\(g\) 是首次提交的选择，\(P_g\) 是缩小后的实例，combine 把该选择接到最优剩余答案上。这个等式表达依赖关系，而不是证明；动态规划同样依赖最优子结构。贪心算法的区别在于，还要证明某个特定 g 无需比较全部首选项就能安全选出。

通用控制流程很短：

GREEDY-SOLVE(problem P)
    solution <- empty
    while P is not complete
        candidates <- feasible choices in P
        g <- candidate preferred by the greedy rule
        add g to solution
        P <- residual problem after committing to g
    return solution

例：分数背包。 每件物品 \(i\) 有价值 \(v_i\)、重量 \(w_i\) 与价值密度

\[ \rho_i=\frac{v_i}{w_i}. \]

\(\rho_i\) 表示每单位容量获得的价值。由于物品可以拆分，从最高密度物品取可用重量是安全的：若某个方案使用了较低密度材料，同时仍有较高密度材料未用，交换等量重量不会破坏可行性，并会严格增加价值。交换后，未使用容量仍是一个更小的分数背包实例，因此两个必要性质都满足。

该证明依赖可分割性。0/1 背包中的物品不可拆分，等量交换可能无法进行，相同的比率规则可能失败。

Python 实现：分数背包 
from typing import Iterable


def fractional_knapsack(
    items: Iterable[tuple[str, float, float]], capacity: float
) -> tuple[float, list[tuple[str, float]]]:
    """返回最大价值以及每件所选物品取得的比例。"""
    if capacity < 0:
        raise ValueError("capacity must be non-negative")

    ranked = []
    for name, value, weight in items:
        if weight <= 0:
            raise ValueError("every item weight must be positive")
        ranked.append((value / weight, name, float(value), float(weight)))

    # 贪心规则只需这一顺序，之后不会撤销任何决定。
    ranked.sort(key=lambda item: item[0], reverse=True)

    total_value = 0.0
    remaining = float(capacity)
    taken: list[tuple[str, float]] = []

    for density, name, value, weight in ranked:
        if remaining == 0:
            break

        # 优先取得整件物品，最后一件可以只取一部分。
        fraction = min(1.0, remaining / weight)
        total_value += fraction * value
        remaining -= fraction * weight
        taken.append((name, fraction))

    return total_value, taken


example_items = [
    ("A", 60, 10),
    ("B", 100, 20),
    ("C", 120, 30),
]
value, selection = fractional_knapsack(example_items, capacity=50)
assert abs(value - 240.0) < 1e-9
print(value, selection)

排序 n 件物品需要 \(O(n\log n)\)，扫描为 \(O(n)\)。返回的选择占 \(O(n)\) 输出空间；排除输出后，排序完成的扫描只用 \(O(1)\) 状态。

练习： LeetCode 455 - 分发饼干要求识别安全顺序并完成匹配，不回访先前分配。

设计贪心策略

设计贪心算法首先要把问题变成可操作定义。“选择最好选项”过于模糊；候选集合、可行条件、目标、平局行为和维护状态都必须明确。

一个实用的设计顺序是：

  1. 描述部分解。 明确哪些选择已经提交，哪些仍未决定；
  2. 确定可行的下一选择。 选择必须保持全部硬约束，而不只是改善目标；
  3. 提出局部键。 例如最早结束时间、最小边权、最大价值密度或最远可达位置；
  4. 寻找前沿状态。 良好的贪心算法常把全部历史压缩为一个小不变量，如最后结束时间、当前可达边界或顶点所在连通分量；
  5. 证明选择安全。 使用交换、领先、切分或归纳论证；
  6. 寻找小反例。 在小实例上与精确算法穷举比较，可以在规则被精心实现前先证伪。
DESIGN-AND-RUN-GREEDY(instance)
    define candidates, feasibility, and objective
    define a local ordering or priority rule
    initialize a compact state describing the current frontier

    while the solution is incomplete
        expose the best currently feasible candidate
        commit to it
        update the frontier state

    prove that every commitment is safe
    test small instances against an exact oracle

例：固定路线上的最少加油次数。 假设加油站沿道路有序，车辆每次加油后最多行驶 \(R\) 距离。从当前位置看，在较早可达站停车不可能比最远可达站更有利：更远位置仍能到达早选方案可到达的所有后续站，还可能暴露更多站点。贪心状态只需当前站下标。

对路线 \([0,100,200,275,375,550]\) 和续航 \(R=200\)，车辆从 \(0\) 到 \(200\)，再到 \(375\)，最后到达 \(550\)，从不向后扫描。

MINIMUM-REFILLS(points, range R)
    current <- 0
    stops <- empty list
    while current is not the destination
        next <- current
        while the following point is within R of points[current]
            advance next
        if next = current
            return impossible
        if next is not the destination
            append points[next] to stops
        current <- next
    return stops
Python 实现：最远可达加油策略 
def minimum_refill_stops(
    points: list[int], max_distance: int
) -> list[int] | None:
    """返回加油位置；目的地不可达时返回 None。"""
    if not points or points[0] != 0:
        raise ValueError("points must start at position 0")
    if max_distance <= 0:
        raise ValueError("max_distance must be positive")
    if any(points[i] >= points[i + 1] for i in range(len(points) - 1)):
        raise ValueError("points must be strictly increasing")

    current = 0
    stops: list[int] = []

    while current < len(points) - 1:
        farthest = current

        # 一个共享指针只向前移动，直到当前最远可达点。
        while (
            farthest + 1 < len(points)
            and points[farthest + 1] - points[current] <= max_distance
        ):
            farthest += 1

        if farthest == current:
            return None  # 下一间隔超过续航。

        if farthest < len(points) - 1:
            stops.append(points[farthest])
        current = farthest

    return stops


route = [0, 100, 200, 275, 375, 550]
assert minimum_refill_stops(route, 200) == [200, 375]
assert minimum_refill_stops([0, 150, 400], 200) is None
print(minimum_refill_stops(route, 200))

最远指针只向前经过 n 个路线点，因此扫描为 \(O(n)\)。返回列表最坏占 \(O(n)\)；算法本身只保留 \(O(1)\) 状态。这个线性界来自单调前沿，而不是来自“贪心”这个词。

练习： LeetCode 55 - 跳跃游戏训练用一个最远可达前沿替代大量可能路径。

交换论证与始终领先证明

贪心算法的可行性通常直观，最优性则不明显。两种证明模板覆盖许多情况。

交换论证（exchange argument）从任意最优解 \(O\) 开始。若其第一选择不同于贪心选择 \(g\)，就用 \(g\) 替换 \(O\) 的一部分，并证明修改后的 \(O'\) 仍可行且不更差。因此存在一个与贪心选择一致的最优解，随后可对剩余问题重复相同推理。

始终领先证明（stays-ahead proof）比较前缀。令 \(G_i\) 表示前 i 个贪心选择后的进度，\(O_i\) 表示任意最优解前 i 个选择后的进度。对每个 i，证明最大化前沿满足 \(G_i\ge O_i\)，或成本/结束时间前沿满足 \(G_i\le O_i\)。若贪心在任何前缀都不落后，最终解不会更差。

EXCHANGE-PROOF(greedy solution G, optimal solution O)
    find the first position where G and O differ
    replace O's choice at that position with G's choice
    prove feasibility is preserved
    prove the objective value does not worsen
    repeat or invoke induction on the residual problem

STAYS-AHEAD-PROOF(G, O)
    define one comparable prefix measure M
    prove the base case M(G_1) is at least as good as M(O_1)
    assume the claim for prefix i - 1
    prove it for prefix i
    conclude the final greedy objective is optimal

例：容量限制下的两人配对。 排序全部体重，考虑当前最重者 \(h\)。若 \(h\) 不能与最轻者 \(l\) 同乘，则它不能与任何人同乘，必须独自出发；若 \(h+l\) 可行，把 \(h\) 与 \(l\) 配对是安全的：任何把 \(h\) 与更重者配对的方案，都可以把该伙伴换成 \(l\)，不破坏可行性，也不增加船数。每一步移除一个不可避免的最重者，并可能移除一个最轻伙伴。

Python 实现：交换安全的两人配对 
def minimum_two_person_boats(weights: list[int], limit: int) -> int:
    """返回每艘最多两人时所需的最少船数。"""
    if limit <= 0 or any(weight <= 0 for weight in weights):
        raise ValueError("weights and limit must be positive")
    if any(weight > limit for weight in weights):
        raise ValueError("every person must fit individually")

    ordered = sorted(weights)
    lightest = 0
    heaviest = len(ordered) - 1
    boats = 0

    while lightest <= heaviest:
        # 每个方案都必须为当前最重者分配一艘船。
        if lightest < heaviest and ordered[lightest] + ordered[heaviest] <= limit:
            lightest += 1  # 用最轻者利用原本会浪费的容量。
        heaviest -= 1
        boats += 1

    return boats


assert minimum_two_person_boats([3, 2, 2, 1], limit=3) == 3
assert minimum_two_person_boats([1, 2], limit=3) == 1
print(minimum_two_person_boats([3, 2, 2, 1], limit=3))

排序为 \(O(n\log n)\)，双指针最多向内移动 n 次，扫描为 \(O(n)\)。Python 的排序副本占 \(O(n)\)；原地排序可减少算法辅助状态。

证明必须与代码一致。代码总是移除最重项；论证解释为什么每个方案都必须为它分配容量，以及最轻的可行伙伴为何可以安全交换。证明另一条规则并不能证明当前实现正确。

练习： LeetCode 881 - 救生艇直接训练这一交换论证。

区间调度与区间合并

区间在内存中看起来相似，却支持不同目标。区间调度选择尽可能大的互相兼容子集；区间合并计算全部覆盖范围的并集。混淆二者会导致错误的排序键和不变量。

假设采用半开区间 \([s_i,f_i)\)，其中 \(s_i\) 是起点，\(f_i\) 是终点。相邻区间在下一起点满足 \(s_j\ge f_i\) 时兼容。若使用闭区间或特定端点规则，必须明确调整谓词。

为最大化区间数量，按结束时间递增排序，接受下一个兼容区间。最早结束会尽快释放共享资源，为后续区间留下不小于任何替代首选的空间。

INTERVAL-SCHEDULE(intervals)
    sort intervals by increasing finish time
    selected <- empty list
    last_finish <- negative infinity
    for interval (start, finish) in sorted order
        if start >= last_finish
            append interval to selected
            last_finish <- finish
    return selected

MERGE-INTERVALS(intervals)
    sort intervals by increasing start time
    merged <- empty list
    for interval (start, finish) in sorted order
        if merged is empty or start > merged.last.finish
            append a new interval
        else
            merged.last.finish <- max(merged.last.finish, finish)
    return merged

调度证明是交换论证。令 \(g\) 为最早结束区间，\(o\) 为某个最优调度的第一区间。用 \(g\) 替换 \(o\) 不会让任何后续已选区间失去兼容性，因为 \(f_g\le f_o\)。因此存在以 \(g\) 开始的最优调度，而从 \(f_g\) 之后开始的区间构成剩余实例。

合并维护不同不变量：处理前 i 个有序区间后，merged 精确表示它们的并集，且只有最后一个区间仍可能与未来输入重叠。按起点排序保证未来区间无法跨越已确定的空隙向后影响更早结果。

Python 实现：调度与合并 
from math import inf


def maximum_compatible_intervals(
    intervals: list[tuple[int, int]],
) -> list[tuple[int, int]]:
    """选择数量最大的半开兼容区间集合。"""
    if any(start > finish for start, finish in intervals):
        raise ValueError("every interval must satisfy start <= finish")

    selected: list[tuple[int, int]] = []
    last_finish = -inf

    # 对最大数量目标，最早结束是安全选择。
    for start, finish in sorted(intervals, key=lambda interval: (interval[1], interval[0])):
        if start >= last_finish:
            selected.append((start, finish))
            last_finish = finish

    return selected


def merge_intervals(
    intervals: list[tuple[int, int]],
) -> list[tuple[int, int]]:
    """将闭区间并集表示为互不相交的有序区间。"""
    if any(start > finish for start, finish in intervals):
        raise ValueError("every interval must satisfy start <= finish")
    if not intervals:
        return []

    ordered = sorted(intervals)
    merged: list[list[int]] = [[ordered[0][0], ordered[0][1]]]

    for start, finish in ordered[1:]:
        if start > merged[-1][1]:
            merged.append([start, finish])  # 真正空隙使旧范围最终确定。
        else:
            merged[-1][1] = max(merged[-1][1], finish)  # 扩展前沿。

    return [(start, finish) for start, finish in merged]


jobs = [(1, 4), (3, 5), (0, 6), (5, 7), (5, 9), (8, 9)]
assert maximum_compatible_intervals(jobs) == [(1, 4), (5, 7), (8, 9)]
assert merge_intervals([(1, 3), (2, 6), (8, 10), (9, 12)]) == [(1, 6), (8, 12)]
print(maximum_compatible_intervals(jobs))
print(merge_intervals([(1, 3), (2, 6), (8, 10), (9, 12)]))

两种算法都由排序主导，总时间为 \(O(n\log n)\)，随后扫描为 \(O(n)\)。输出最多包含 \(O(n)\) 个区间。调度扫描除输出外只保存一个前沿值；合并扫描只修改最后一个输出区间，因为排序使更早输出不可改变。

目标 排序键 提交条件 维护的前沿
最大兼容区间数量 结束时间 下一起点 \(\ge\) 最后结束 最后选中区间的结束时间
覆盖范围并集 起点 只有出现空隙才建立新范围 当前合并范围终点

练习： LeetCode 435 - 无重叠区间检验能否把最早结束调度转换为等价的最少删除目标。

Huffman 编码

Huffman 编码构建变长二进制编码，让高频符号获得短码字、低频符号获得长码字。该编码是前缀无歧义（prefix-free）的：任何符号码字都不是另一个码字的前缀。因此解码器可从左到右读取比特，到达叶节点就输出符号，无需在码字之间加入分隔符。

若符号 \(i\) 的概率为 \(p_i\)，码字长度为 \(\ell_i\)，每个符号的期望比特数为

\[ L=\sum_{i=1}^{k} p_i\ell_i. \]

k 是不同符号数，\(p_i\) 是相对频率，\(\ell_i\) 是符号在二叉编码树中的叶深度，\(L\) 是平均编码长度。Huffman 的目标是在二进制前缀码中最小化这一加权外部路径长度。

贪心选择反复合并频率最低的两棵树。最小优先队列支持所需操作：插入每棵单节点树，取出两个最低频树，在新父节点下合并并把频率设为二者之和，再把父节点插回。

HUFFMAN(frequencies)
    Q <- min-priority queue containing one leaf per symbol
    while size(Q) > 1
        left <- EXTRACT-MIN(Q)
        right <- EXTRACT-MIN(Q)
        parent.frequency <- left.frequency + right.frequency
        parent.left <- left
        parent.right <- right
        INSERT(Q, parent)
    return EXTRACT-MIN(Q) as the code tree

ASSIGN-CODES(node, prefix)
    if node is a leaf
        code[node.symbol] <- prefix
    else
        ASSIGN-CODES(node.left, prefix + "0")
        ASSIGN-CODES(node.right, prefix + "1")

正确性证明结合交换与归纳。在某棵最优满二叉编码树中，两个最低频符号可以放在最深的兄弟叶节点：把较低频符号向下、较高频符号向上交换，不会增加 \(\sum p_i\ell_i\)。把兄弟合并为频率相加的伪符号，对缩小字母表的最优编码展开后，就是原字母表的最优编码。重复该论证即可证明每次优先队列合并。

Python 实现：构建、编码与解码 Huffman 码 
from __future__ import annotations

from collections import Counter
from dataclasses import dataclass
from heapq import heapify, heappop, heappush
from itertools import count


@dataclass
class HuffmanNode:
    symbol: str | None = None
    left: HuffmanNode | None = None
    right: HuffmanNode | None = None


def build_huffman_codes(text: str) -> dict[str, str]:
    """为非空文本构建确定性的前缀码字典。"""
    if not text:
        raise ValueError("text must be non-empty")

    serial = count()  # 打破相同频率平局，避免比较树节点。
    heap = [
        (frequency, next(serial), HuffmanNode(symbol=symbol))
        for symbol, frequency in Counter(text).items()
    ]
    heapify(heap)

    if len(heap) == 1:
        only_symbol = heap[0][2].symbol
        return {only_symbol: "0"}

    while len(heap) > 1:
        left_frequency, _, left = heappop(heap)
        right_frequency, _, right = heappop(heap)

        # 父节点表示当前频率最低的两棵剩余子树。
        parent = HuffmanNode(left=left, right=right)
        heappush(
            heap,
            (left_frequency + right_frequency, next(serial), parent),
        )

    root = heap[0][2]
    codes: dict[str, str] = {}

    def visit(node: HuffmanNode, prefix: str) -> None:
        if node.symbol is not None:
            codes[node.symbol] = prefix
            return
        visit(node.left, prefix + "0")
        visit(node.right, prefix + "1")

    visit(root, "")
    return codes


def huffman_encode(text: str, codes: dict[str, str]) -> str:
    return "".join(codes[symbol] for symbol in text)


def huffman_decode(bits: str, codes: dict[str, str]) -> str:
    reverse = {code: symbol for symbol, code in codes.items()}
    decoded: list[str] = []
    prefix = ""

    for bit in bits:
        if bit not in "01":
            raise ValueError("encoded data must contain only 0 and 1")
        prefix += bit
        if prefix in reverse:
            decoded.append(reverse[prefix])
            prefix = ""

    if prefix:
        raise ValueError("bit string ends inside a codeword")
    return "".join(decoded)


message = "beep boop beer!"
dictionary = build_huffman_codes(message)
encoded = huffman_encode(message, dictionary)
assert huffman_decode(encoded, dictionary) == message
assert all(
    not b.startswith(a)
    for a in dictionary.values()
    for b in dictionary.values()
    if a != b
)
print(dictionary)
print(f"{len(message) * 8} raw bits -> {len(encoded)} encoded bits")

对于 k 种符号，建堆为 \(O(k)\)，k-1 次合并为 \(O(k\log k)\)。遍历树为 \(O(k)\)，编码长度为 m 的消息需要 \(O(m)\) 次字典查询。树、堆和码字典各占 \(O(k)\) 空间，编码比特串本身属于输出空间。

作为贪心算法的最小生成树

对连通、无向、加权图 \(G=(V,E)\)，最小生成树（MST）连接全部顶点、不含环、恰有 \(|V|-1\) 条边，并最小化总边权。Kruskal 和 Prim 在操作上不同，但二者都是贪心算法，因为它们每次都提交由某个切分证明安全的最轻边。

切分（cut）把顶点分为非空集合 \(S\) 与 \(V\setminus S\)。若一条边两个端点分别位于两侧，它就跨越该切分。切分性质指出：跨越一个尊重已选森林的切分的最小权边是安全的，至少有一棵 MST 同时包含已选边和该边。

LIGHTEST-CROSSING-EDGE(vertex set S, edges E)
    best <- none
    for each edge (u, v, weight) in E
        if exactly one of u and v belongs to S
            if best is none or weight < best.weight
                best <- (u, v, weight)
    return best

GREEDY-MST-SCHEME(graph)
    A <- empty set of selected edges
    while A has fewer than |V| - 1 edges
        choose a cut that respects A
        add a lightest edge crossing that cut
    return A

为什么跨越边安全？令 \(e\) 为所选轻边，\(T\) 为不包含它的 MST。把 \(e\) 加入 \(T\) 会形成一个环；该环必有另一条边 \(f\) 跨越同一切分。由于 \(e\) 最轻，\(w(e)\le w(f)\)。用 \(e\) 替换 \(f\) 恢复生成树且不增加总权重，从而得到包含 \(e\) 的 MST。

  • Kruskal 排序全部边，用并查集拒绝端点已经连通的边；其隐式切分把一个当前分量与其余部分分开。
  • Prim 扩展一棵连通树，用优先队列选择从树到外部顶点的最轻边；其切分是当前树与所有未访问顶点。

完整数据结构、步骤图与实现见第 05 章的最小生成树。本节聚焦共同的贪心证明，不重复全部实现。

Python 实现：暴露跨越切分的安全边 
from typing import Hashable


def lightest_crossing_edge(
    left_side: set[Hashable],
    edges: list[tuple[Hashable, Hashable, float]],
) -> tuple[Hashable, Hashable, float] | None:
    """返回恰有一个端点位于 left_side 的最轻边。"""
    best: tuple[Hashable, Hashable, float] | None = None

    for u, v, weight in edges:
        crosses = (u in left_side) != (v in left_side)  # 逻辑异或。
        if crosses and (best is None or weight < best[2]):
            best = (u, v, weight)

    return best


weighted_edges = [
    ("A", "B", 4),
    ("A", "C", 2),
    ("B", "C", 1),
    ("B", "D", 5),
    ("C", "D", 8),
]
cut = {"A", "C"}
assert lightest_crossing_edge(cut, weighted_edges) == ("B", "C", 1)
print(lightest_crossing_edge(cut, weighted_edges))

切分扫描需要 \(O(|E|)\) 时间和 \(O(1)\) 辅助空间，因为只保留当前最佳跨越边。完整 Kruskal 需要 \(O(|E|\log |E|)\) 排序时间，加上摊还近常数的 DSU 操作；邻接表和二叉堆 Prim 需要 \(O((|V|+|E|)\log |V|)\) 时间与 \(O(|V|+|E|)\) 图和堆空间。

贪心算法何时失败

当局部偏好的提交会破坏更好的全局组合时，贪心规则就会失败。仅有最优子结构不能挽救它：零钱兑换、0/1 背包与加权区间调度都有最优子问题，但自然的单路径规则仍可能选错剩余问题。

典型警告信号包括：

警告信号 为什么威胁贪心推理 可能替代方案
选择消耗不可分割资源 等量交换可能无法完成 动态规划
项目价值依赖后续组合 局部分数遗漏交互效应 DP 或搜索
更好的前缀可能导致更差的完成结果 不存在始终领先不变量 保留多个状态
负权重反转早期比较 已确定选择可能需要修改 Bellman-Ford 式松弛
所谓证明只给了一个例子 例子只说明可能性，不证明普遍安全 交换证明或反例搜索

攻击一条规则时，构造最小输入，使其第一选择与精确最优不同。下面两个算法展示零钱兑换失败：

GREEDY-COINS(coins, amount)
    sort coins from largest to smallest
    repeatedly take as many as possible of the current coin

OPTIMAL-COINS(coins, amount)
    dp[0] <- 0
    for value from 1 to amount
        dp[value] <- 1 + minimum dp[value - coin] over feasible coins
    return dp[amount]

使用硬币 \(\{1,3,4\}\) 凑 \(6\) 时，最大优先得到 \(4+1+1\)，使用三枚；最优是 \(3+3\)，只用两枚。0/1 背包中，密度顺序对可分割材料正确，却可能浪费不可分割容量。同样，最早结束最大化兼容区间的数量，却不能最大化任意区间权重；加权区间调度需要比较选择与跳过的状态。

Python 实现：比较贪心规则与精确 DP 预言机 
from math import inf


def greedy_coin_count(coins: list[int], amount: int) -> int | None:
    """使用最大优先规则；它并非对所有硬币系统都正确。"""
    if amount < 0 or any(coin <= 0 for coin in coins):
        raise ValueError("amount and coin values must be non-negative/positive")

    count = 0
    remaining = amount
    for coin in sorted(set(coins), reverse=True):
        used, remaining = divmod(remaining, coin)
        count += used
    return count if remaining == 0 else None


def optimal_coin_count(coins: list[int], amount: int) -> int | None:
    """用动态规划作为最少硬币数的精确预言机。"""
    if amount < 0 or any(coin <= 0 for coin in coins):
        raise ValueError("amount and coin values must be non-negative/positive")

    dp = [0] + [inf] * amount
    for value in range(1, amount + 1):
        for coin in coins:
            if coin <= value:
                dp[value] = min(dp[value], 1 + dp[value - coin])
    return None if dp[amount] == inf else int(dp[amount])


coins = [1, 3, 4]
assert greedy_coin_count(coins, 6) == 3
assert optimal_coin_count(coins, 6) == 2
print("greedy:", greedy_coin_count(coins, 6))
print("optimal:", optimal_coin_count(coins, 6))

对于 k 种面额，贪心排序需 \(O(k\log k)\)，额外状态为 \(O(1)\)。精确 DP 对目标金额 A 需要 \(O(kA)\) 时间和 \(O(A)\) 空间。正是这些额外状态让 DP 保留了贪心规则丢弃的替代方案。

对比与选择

当一个小前沿足以概括全部相关历史，且局部选择可以证明安全时，贪心算法最有吸引力。应从问题结构选择它，而不是因为某个看似合理的方案包含排序。

技术 保留的决策 常见正确性证据 常见成本 适用情况
贪心 一条已提交路径 交换、始终领先、切分性质 常为 \(O(n)\) 或 \(O(n\log n)\) 一个安全局部选择支配替代项
动态规划 多个摘要状态 递推式与归纳 状态数乘转移成本 选择相互作用且子问题重叠
分治 独立递归分支 分解与正确合并 如 \(T(n)=aT(n/b)+f(n)\) 子问题可独立解决
回溯 状态空间树中的显式替代项 穷尽覆盖与剪枝安全 最坏通常指数级 约束要求枚举兼容组合

采用贪心前应询问：

  1. 精确目标是什么？ 最大数量、最大权重、最小成本与最早完成，对同一组对象可能需要不同规则；
  2. 为什么下一选择安全？ 明确指出交换、前缀不等式、切分或其他结构事实；
  3. 留下什么剩余问题？ 它应保持证明所需的形式；
  4. 哪些状态真正足够？ 若一个前沿值无法总结过去，可能需要多个 DP 状态；
  5. 小型精确求解器是否会反对？ 差分测试很适合发现反例，尽管测试不能替代普遍证明。
Python 实现：寻找贪心假设的第一个反例 
from collections.abc import Callable, Iterable
from math import inf
from typing import TypeVar

T = TypeVar("T")


def first_counterexample(
    instances: Iterable[T],
    candidate: Callable[[T], int | None],
    oracle: Callable[[T], int | None],
) -> tuple[T, int | None, int | None] | None:
    """返回 candidate 与 oracle 首次产生不同结果的小实例。"""
    for instance in instances:
        candidate_value = candidate(instance)
        oracle_value = oracle(instance)
        if candidate_value != oracle_value:
            return instance, candidate_value, oracle_value
    return None


coins = (1, 3, 4)


def largest_first(amount: int) -> int:
    count = 0
    for coin in sorted(coins, reverse=True):
        used, amount = divmod(amount, coin)
        count += used
    return count


def exact_minimum(amount: int) -> int:
    dp = [0] + [inf] * amount
    for value in range(1, amount + 1):
        dp[value] = 1 + min(dp[value - coin] for coin in coins if coin <= value)
    return int(dp[amount])


failure = first_counterexample(range(1, 20), largest_first, exact_minimum)
assert failure == (6, 3, 2)
print(failure)

测试器对每个实例各调用一次候选算法与预言机，总成本是实例数乘两种求解器成本。当预言机昂贵时，只在有意限制的小输入上使用。一旦出现反例，应检查第一次分歧的提交，并修改规则或更换算法范式。
