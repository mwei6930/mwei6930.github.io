算法分析与正确性

编写代码只回答了一个问题：机器能否执行这些指令？ 算法设计还要回答三个更难的问题：应当得到什么结果，为什么这些步骤一定能得到该结果，以及当输入规模增大时，所需工作量会如何增长？

本章将建立回答这些问题所需的基本语言。学习目标并不是背诵一份复杂度类别列表，而是掌握一种可重复使用的分析方法：从非正式问题出发，形成精确的规格说明，选择合适的抽象，分析资源消耗，并在依赖测试结果之前论证算法的正确性。

核心流程如下：

  1. 准确说明输入假设和所需输出；
  2. 将算法表达为有限且无歧义的步骤；
  3. 确定输入规模参数，并计算占主导地位的工作量；
  4. 证明算法会终止，并且满足后置条件；
  5. 同时依据渐近代价和实际约束比较候选方案。

问题规格与算法思维

问题规格（problem specification） 是调用者与算法之间的一份契约。它说明哪些输入有效、需要产生什么输出，以及算法结束时必须满足哪些条件。可以把它类比为导航请求：“带我去一个不错的地方”过于模糊，无法验证；而“在避开收费道路的前提下，找出从 A 到 B 的最短驾车路线”则明确给出了输入、目标和约束。

这种精确性解决了一个重要问题：两个程序都可能正常运行、没有报错，却分别回答了同一请求的不同解释。在选择数据结构或编写循环之前，应当区分以下四个部分：

  • 输入（Input）： 提供给算法的值。
  • 前置条件（Precondition）： 算法可以依赖的假设，例如“数组已经排序”。
  • 输出（Output）： 算法返回的值或状态。
  • 后置条件（Postcondition）： 算法终止后必须成立的性质。

算法思维随后把这份契约转化为一系列受控的状态变化。例如，考虑一般任务：“返回目标值在序列中第一次出现的位置；如果不存在，则返回 -1。”扫描过程所依赖的不变式很简单：在检查位置 i 之前，任何更早的位置都不包含目标值。

伪代码。

FIRST-INDEX(values, target)
    for i from 0 to length(values) - 1
        if values[i] equals target
            return i
    return -1

提前返回不仅是一种性能优化。由于位置是从左向右检查的，第一个匹配位置必然是最小的有效下标。如果所有步骤都没有返回，就说明每个位置都已经检查过，因此 -1 满足契约中“目标不存在”的要求。

Python 实现：具有明确规格的顺序搜索 
from collections.abc import Sequence
from typing import TypeVar

T = TypeVar("T")


def first_index(values: Sequence[T], target: T) -> int:
    """返回 target 首次出现的下标；不存在时返回 -1。"""
    # 每次迭代开始时，target 都不在 values[:index] 中。
    for index, value in enumerate(values):
        if value == target:
            # 从左向右扫描保证这是第一个有效下标。
            return index

    # 执行到这里，说明所有位置都已经被排除。
    return -1


assert first_index([8, 3, 3, 5], 3) == 1
assert first_index([8, 3, 3, 5], 7) == -1

与一个含义模糊的“搜索”函数相比，这个实现更好，因为它明确规定了重复值和目标缺失时的行为。它的最坏运行时间是线性的，但正确性与速度是相互独立的：即使换用更快的实现，也仍然必须满足完全相同的契约。

练习。 LeetCode 1 - 两数之和 可以训练同样的“规格优先”习惯：先明确什么构成有效的数对，以及函数必须返回什么。

抽象数据类型、接口与实现

抽象数据类型（Abstract Data Type, ADT） 根据一个集合对外可观察的行为来描述它，而不是根据其物理存储方式来描述它。可以将 ADT 类比为电源插座：设备依赖的是电压和插头接口，而不关心电力来自太阳能、风力还是涡轮机。在软件中，这种分离让客户端代码依赖稳定的操作，同时允许底层实现发生变化。

需要清楚地区分三个层次：

  • ADT 定义值、操作及其行为规则；
  • 接口（interface） 为这些操作提供具体名称和函数签名；
  • 实现（implementation） 选择内存布局和实际算法。

例如，栈 ADT 承诺遵循后进先出（Last In, First Out, LIFO）。它的接口可能提供 push、pop、peek 和 is_empty。同一接口既可以由动态数组实现，也可以由链表实现，而两者具有不同的内存和性能权衡。

在内部，基于数组的栈把栈底元素存放在下标 0，把当前栈顶存放在最后一个已占用位置。push 在栈顶追加元素，pop 只删除栈顶元素。调用者不应直接访问内部列表，否则可能破坏栈的顺序规则。

栈 ADT 可以表示为一组操作契约。pop 和 peek 的前置条件也是抽象的一部分：实现必须拒绝对空栈调用这些操作，或者明确定义一个特殊的哨兵返回值。

ADT 操作 前置条件 必须产生的效果或结果
push(x) 无 将 x 设为新栈顶，并将大小增加一。
pop() 栈非空 删除并返回当前栈顶。
peek() 栈非空 返回当前栈顶，但不修改栈。
is_empty() 无 返回栈大小是否为零。
size() 无 返回当前存储的元素数量。

当栈中存储 n 个元素时，具体表示方式决定了操作代价：

操作 动态数组栈 链表栈
push 均摊 \(O(1)\)；扩容时最坏为 \(O(n)\) 最坏 \(O(1)\)
pop 从末尾删除时为 \(O(1)\) 在表头操作时为 \(O(1)\)
peek \(O(1)\) \(O(1)\)
is_empty / size \(O(1)\) 如果保存了大小，则为 \(O(1)\)
总存储空间 \(Theta(n)\)，外加未使用容量 \(Theta(n)\)，每个结点还需要一个链接字段

ADT 承诺的是 LIFO 行为，而不是某一种复杂度。复杂度属于所选实现：数组栈可能偶尔需要扩容，而链式栈则会为每个元素持续承担指针和内存分配开销。

Python 实现：基于数组的栈 ADT 
from typing import Generic, TypeVar

T = TypeVar("T")


class Stack(Generic[T]):
    """一个保持内部表示私有的小型 LIFO 栈。"""

    def __init__(self) -> None:
        # 列表末尾表示栈顶。
        self._items: list[T] = []

    def push(self, item: T) -> None:
        # list.append 的均摊复杂度为 O(1)。
        self._items.append(item)

    def pop(self) -> T:
        if self.is_empty():
            raise IndexError("pop from an empty stack")
        return self._items.pop()

    def peek(self) -> T:
        if self.is_empty():
            raise IndexError("peek at an empty stack")
        return self._items[-1]

    def is_empty(self) -> bool:
        return len(self._items) == 0

    def __len__(self) -> int:
        return len(self._items)


history = Stack[str]()
history.push("open")
history.push("edit")
assert history.peek() == "edit"
assert history.pop() == "edit"
assert history.pop() == "open"

当程序依赖 LIFO 行为时，ADT 比直接暴露普通列表更合适：它可以阻止无效操作、表达设计意图，并允许以后替换内部表示。但 ADT 并不会自动让程序更快；抽象和性能回答的是不同的设计问题。

练习。 LeetCode 155 - 最小栈 要求在保留栈接口的同时扩展其内部表示。

时间复杂度与空间复杂度

复杂度描述资源需求如何随输入规模增长。它更接近于估算旅程如何随距离变化，而不是测量某一次行程用了多久：秒表结果会受到硬件、语言、编译器和当前系统负载的影响，而增长模型解释的是输入扩大十倍或一千倍之后会发生什么。

令 n 表示某种输入规模。对于数组问题，n 通常是元素数量；对于图问题，可能需要同时使用顶点数 V 和边数 E。必须明确说明所选参数，因为“输入规模”并不是一个通用且唯一的量。

时间复杂度 \(T(n)\)

时间复杂度统计一种具有代表性的基本操作，例如比较、哈希表查询或边访问。假设重复元素检测会比较每一对元素：

HAS-DUPLICATE-BY-PAIRS(values)
    for i from 0 to n - 1
        for j from i + 1 to n - 1
            if values[i] equals values[j]
                return true
    return false

如果不存在重复元素，比较次数为

\[ (n-1) + (n-2) + \cdots + 1 = \frac{n(n-1)}{2}. \]

其中，n 是元素数量，这个表达式恰好把每一对无序元素统计一次。展开后得到 \(\frac{1}{2}n^2-\frac{1}{2}n\)；当 n 很大时，二次项占主导，因此运行时间为 \(\Theta(n^2)\)。

使用集合可以改变算法策略。每个元素只查询一次，在通常的哈希表假设下，预期时间为 \(\Theta(n)\)。

空间复杂度 \(S(n)\)

空间复杂度衡量随输入规模增长的内存。通常需要区分：

  • 输入空间（input space）： 调用者提供的数据所占用的空间；
  • 辅助空间（auxiliary space）： 算法额外创建的数据所占用的空间；
  • 调用栈空间（call-stack space）： 每个尚未返回的递归调用所占用的栈帧空间。

成对比较算法使用 \(O(1)\) 辅助空间，而基于集合的算法最多需要存储 n 个元素，因此使用 \(O(n)\) 辅助空间。这是一种有意识的时间与空间权衡：使用更多内存来消除重复比较。

Python 实现：比较不同的时间与内存策略 
from collections.abc import Iterable


def has_duplicate_by_pairs(values: list[int]) -> bool:
    """使用常数辅助空间，但时间可能达到平方级。"""
    for left in range(len(values)):
        for right in range(left + 1, len(values)):
            if values[left] == values[right]:
                return True
    return False


def has_duplicate_by_set(values: Iterable[int]) -> bool:
    """使用额外内存，将预期时间降低到线性。"""
    seen: set[int] = set()
    for value in values:
        if value in seen:
            return True
        # 这个状态记录已经处理过的所有元素。
        seen.add(value)
    return False


sample = [4, 8, 1, 8]
assert has_duplicate_by_pairs(sample)
assert has_duplicate_by_set(sample)

两种版本并不存在无条件的优劣。对于较大的内存内输入，集合版本通常更合适；但在输入极小或内存约束非常严格时，成对比较仍可能是合理选择。

练习。 LeetCode 217 - 存在重复元素 可以直接训练识别这种时间与空间权衡的能力。

最好、平均与最坏情况

输入规模本身并不总能唯一确定实际工作量。对 n 个元素进行线性搜索时，如果目标位于第一个位置，算法会立即停止；如果目标靠近中间，则需要进行若干次比较；如果目标位于末尾或根本不存在，就必须检查每个元素。

  • 最好情况（best case） 是所有规模为 n 的输入中的最小代价。
  • 最坏情况（worst case） 是所有规模为 n 的输入中的最大代价。
  • 平均情况（average case） 是在明确给定输入概率分布后得到的期望代价。

对于线性搜索，最好情况时间为 \(\Theta(1)\)，最坏情况时间为 \(\Theta(n)\)。如果目标以相同概率出现在 n 个位置中的任意一个位置，那么一次成功搜索的平均比较次数为

\[ \mathbb{E}[C] = \frac{1 + 2 + \cdots + n}{n} = \frac{n+1}{2} = \Theta(n). \]

\(C\) 是“比较次数”这一随机变量，\(\mathbb{E}[C]\) 是它的期望值。精确平均值大约是扫描一半元素，但其增长阶仍然是线性的。

伪代码。

LINEAR-SEARCH(values, target)
    comparisons <- 0
    for each value in values
        comparisons <- comparisons + 1
        if value equals target
            return found, comparisons
    return not-found, comparisons
Python 实现：让不同输入情况的代价可观察 
def measured_linear_search(values: list[int], target: int) -> tuple[int, int]:
    """返回 (下标, 比较次数)，从而观察不同输入情况。"""
    comparisons = 0

    for index, value in enumerate(values):
        comparisons += 1
        if value == target:
            return index, comparisons

    return -1, comparisons


values = [7, 2, 9, 4, 1]
assert measured_linear_search(values, 7) == (0, 1)   # 最好情况
assert measured_linear_search(values, 9) == (2, 3)   # 中间情况
assert measured_linear_search(values, 5) == (-1, 5)  # 最坏情况

最坏情况分析常被使用，是因为它无需假设输入会比较友好，就能提供明确保证。平均情况有时更贴近实际，但前提是所采用的概率假设确实合理。

练习。 LeetCode 35 - 搜索插入位置 展示了“输入已排序”这一前置条件如何让最坏情况从线性搜索改善为对数级二分搜索。

渐近记号与增长阶

渐近记号忽略依赖具体机器的常数和低阶项，用来比较输入充分大之后的增长速度。即使某个算法运行在更快的计算机上，当它具有更差的增长率且输入足够大时，仍可能失去优势。

  • \(T(n) \in O(g(n))\) 表示一个渐近上界：超过某个阈值后，\(T(n)\) 的增长速度不超过 \(g(n)\) 的某个常数倍。
  • \(T(n) \in \Omega(g(n))\) 表示一个渐近下界：超过某个阈值后，\(T(n)\) 的增长速度至少达到 \(g(n)\) 的某个常数倍。
  • \(T(n) \in \Theta(g(n))\) 表示一个渐近紧界：上界和下界同时成立。

形式化地，

\[ T(n) \in O(g(n)) \iff \exists c>0,\; \exists n_0\; \text{使得}\; 0 \le T(n) \le c\,g(n)\; \text{对所有 } n \ge n_0 \text{ 成立}. \]

符号 c 是一个固定的正数乘数，n_0 是该界开始成立的输入规模。因此，大 O 并不表示“完全相等”，它本身也不等同于“最坏情况”；它描述的是当前所分析情况的增长上界。

常见增长阶按照从慢到快排列如下：

增长阶 直观行为 常见来源
\(O(1)\) 工作量不随 n 增长 数组下标访问、平均情况下的哈希查询
\(O(\log n)\) 每一步丢弃固定比例的数据 二分搜索、平衡树查询
\(O(n)\) 每个元素被检查常数次 扫描、前缀结构构造
\(O(n\log n)\) 对数层级，每层完成线性工作 高效比较排序
\(O(n^2)\) 检查大量元素对 双层全对比较循环
\(O(2^n)\) 对许多二元选择进行分支 朴素子集搜索
\(O(n!)\) 枚举全部排列 暴力排序方案搜索
Python 实现：用数值比较不同增长速度 
import math


def growth_estimates(n: int) -> dict[str, float]:
    """返回常见增长阶对应的代表性操作次数。"""
    if n <= 0:
        raise ValueError("n must be positive")

    return {
        "constant": 1,
        "logarithmic": math.log2(n),
        "linear": n,
        "linearithmic": n * math.log2(n),
        "quadratic": n * n,
    }


for size in (10, 1_000, 1_000_000):
    costs = growth_estimates(size)
    print(size, {name: round(value, 2) for name, value in costs.items()})

渐近增长阶是一种筛选工具，而不是完整的基准测试。排除增长率不合适的算法后，仍然需要考虑常数因子、缓存行为、输入分布和实现开销。

练习。 LeetCode 121 - 买卖股票的最佳时机 要求把所有日期两两比较的二次方法改进为一次线性扫描。

循环与递归分析

循环和递归都用于表达重复。循环把状态保存在变量中，并在每轮结束后回到条件判断；递归为每个尚未结束的调用保存一份状态，并把问题缩减为规模更小的同类问题。应当选择更容易说明进度、终止性和代价的表达方式。

基于循环的分析

分析循环时，应确定控制变量变化的次数，以及每次迭代完成多少工作。一个把 i 从 0 增加到 n - 1 的循环共有 n 次迭代。如果每次把 i 加倍，直到达到 n，迭代次数大约为 \(\log_2 n\)，因为经过 k 步后有 \(i=2^k\)。

i <- 1
while i < n
    perform constant work
    i <- 2 * i

查看原始开放图像：Wikimedia Commons - While-loop diagram。

嵌套循环并不必然具有平方复杂度，关键在于循环边界。如果内层指针在整个执行过程中从不后退，那么两个在代码结构上嵌套的循环，其总工作量仍可能只有线性级别。

递归算法与递推关系

递归算法需要一个负责停止的基本情况（base case），以及一个不断接近基本情况的递归情况（recursive case）。递归算法的运行时间通常用递推关系表示。朴素 Fibonacci 算法满足

\[ T(n)=T(n-1)+T(n-2)+\Theta(1). \]

两个递归项分别代表两个子调用，\(\Theta(1)\) 代表当前调用中的加法和控制工作。调用树包含大量重叠子问题，因此总调用次数呈指数增长。

带记忆化的伪代码。

FIBONACCI(n, memo)
    if n <= 1
        return n
    if n is in memo
        return memo[n]
    memo[n] <- FIBONACCI(n - 1, memo) + FIBONACCI(n - 2, memo)
    return memo[n]

记忆化保证从 0 到 n 的每个整数只被求解一次，因此时间复杂度变为 \(\Theta(n)\)，记忆表与调用栈共同使用 \(\Theta(n)\) 空间。

Python 实现：迭代版本与记忆化递归版本 
def fibonacci_iterative(n: int) -> int:
    """以线性时间和常数辅助空间计算 F(n)。"""
    if n < 0:
        raise ValueError("n must be non-negative")

    previous, current = 0, 1
    for _ in range(n):
        # 经过 k 次迭代后：previous = F(k)，current = F(k + 1)。
        previous, current = current, previous + current
    return previous


def fibonacci_memoized(n: int, memo: dict[int, int] | None = None) -> int:
    """以递归方式计算 F(n)，同时避免重复求解子问题。"""
    if n < 0:
        raise ValueError("n must be non-negative")
    if n <= 1:
        return n

    if memo is None:
        memo = {}
    if n not in memo:
        memo[n] = (
            fibonacci_memoized(n - 1, memo)
            + fibonacci_memoized(n - 2, memo)
        )
    return memo[n]


assert fibonacci_iterative(10) == 55
assert fibonacci_memoized(10) == 55

迭代避免了调用栈开销，对于简单的线性状态转移通常更合适。递归则更适合树、分治算法和回溯等天然具有递归结构的问题。

练习。 LeetCode 70 - 爬楼梯 与 Fibonacci 具有相同的重叠子问题递推结构。

正确性证明：归纳法、反证法与循环不变式

测试只能说明算法在选定输入上有效；正确性证明则解释它为什么对所有满足前置条件的输入都有效。可以把这种区别类比为质量抽检与工程论证：检查几座桥梁可以提供有用证据，但不能替代对荷载、材料和全部允许条件的系统推理。

三种证明方法会反复出现：

  • 数学归纳法（mathematical induction） 先证明基本情况，再证明规模 k 时成立能够推出规模 k + 1 时也成立。它与递归算法天然对应。
  • 反证法（proof by contradiction） 假设目标命题不成立，并由此推出不可能的结果。它常用于证明贪心选择和复杂度下界。
  • 循环不变式（loop invariant） 是在每次迭代前后都保持成立的性质。它把局部更新与最终后置条件连接起来。

考虑一个返回非空序列最大元素的算法。

伪代码。

MAXIMUM(values)
    require length(values) > 0
    best <- values[0]
    for i from 1 to length(values) - 1
        if values[i] > best
            best <- values[i]
    return best

使用如下不变式：在迭代 i 开始之前，best 是 values[0:i] 中的最大值。

  1. 初始化（Initialization）： 在 i = 1 之前，已处理前缀只包含 values[0]，因此不变式成立。
  2. 保持（Maintenance）： 将 values[i] 与原来的前缀最大值比较后，best 成为扩展到位置 i 后的新前缀最大值。
  3. 终止（Termination）： 循环结束时，已处理前缀就是整个序列，因此 best 是所需的全局最大值。

还需要说明算法为什么会终止：i 每次增加一，并且受有限序列长度这一上界约束。

Python 实现：让代码结构与不变式保持一致 
from collections.abc import Sequence
from typing import TypeVar

T = TypeVar("T")


def maximum(values: Sequence[T]) -> T:
    """返回非空且元素可比较的序列中的最大值。"""
    if not values:
        raise ValueError("maximum requires a non-empty sequence")

    # 在处理下标 index 之前：
    # best 是 values[:index] 中的最大值。
    best = values[0]
    for index in range(1, len(values)):
        if values[index] > best:
            best = values[index]

    # 终止时，values[:len(values)] 就是全部输入。
    return best


assert maximum([-4, 7, 2, 7, 1]) == 7

优秀的实现往往能够映射其证明结构：变量具有清晰含义，每次更新都保持不变式，而退出条件则把不变式转化为后置条件。

练习。 LeetCode 283 - 移动零 很适合使用“已处理区域与未处理区域”上的循环不变式进行证明。

均摊分析

均摊分析（amortized analysis） 在不假设概率分布的前提下，对一个最坏操作序列中的平均单次操作代价给出上界。可以把它想象成每个月向维修基金存入一小笔钱：大多数月份花费很低，累积下来的余额足以支付偶尔发生的昂贵维修。

动态数组可以很好地说明这一思想。它把元素保存在一块容量固定的连续内存中。只要仍有空余容量，追加元素就很便宜；当存储块已满时，实现会分配一块容量加倍的新区域，复制已有元素，然后再追加新元素。

查看原始开放图像：Wikimedia Commons - Dynamic array。

伪代码。

APPEND(value)
    if size equals capacity
        new_storage <- array with 2 * capacity slots
        copy all size elements into new_storage
        storage <- new_storage
        capacity <- 2 * capacity
    storage[size] <- value
    size <- size + 1

作为一种序列型 ADT，动态数组通常不只提供 append：

ADT 操作 必须提供的行为 动态数组代价
get(i) 返回有效下标 i 处的元素。 \(O(1)\)
set(i, x) 将有效下标 i 处的元素替换为 x。 \(O(1)\)
append(x) 在当前最后一个元素之后添加 x。 均摊 \(O(1)\)；最坏 \(O(n)\)
pop_back() 删除并返回最后一个元素。 \(O(1)\)
insert(i, x) 在下标 i 插入 x 并保持原有顺序。 \(O(n)\)
delete(i) 删除下标 i 处的元素并填补空位。 \(O(n)\)

两个常数时间的下标操作来自连续存储。中间插入和删除是线性的，因为可能需要移动整个后缀。表格把 ADT 要求的行为与实现这些行为所采用的扩容策略区分开来。

一次扩容可能需要 \(\Theta(n)\) 时间，但扩容不会在每次追加时发生。当容量依次为 \(1,2,4,8,\ldots\) 时，在达到大小 n 之前，被复制的元素总数为

\[ 1+2+4+\cdots+2^k < 2n. \]

再加上 n 次普通写入，n 次追加中的基本移动总数少于 3n。用总代价除以操作数量，可以得到每次追加的均摊时间为 \(O(1)\)，尽管某一次追加的最坏时间仍然可能是线性的。

Python 实现：显式展示容量增长过程 
from typing import Generic, TypeVar, cast

T = TypeVar("T")


class DynamicArray(Generic[T]):
    """一个在存满时将容量加倍的最小动态数组实现。"""

    def __init__(self) -> None:
        self._capacity = 1
        self._size = 0
        self._storage: list[T | None] = [None] * self._capacity

    def _check_index(self, index: int) -> None:
        if index < 0 or index >= self._size:
            raise IndexError("dynamic-array index out of range")

    def get(self, index: int) -> T:
        self._check_index(index)
        return cast(T, self._storage[index])

    def set(self, index: int, value: T) -> None:
        self._check_index(index)
        self._storage[index] = value

    def append(self, value: T) -> None:
        if self._size == self._capacity:
            self._resize(self._capacity * 2)

        self._storage[self._size] = value
        self._size += 1

    def pop_back(self) -> T:
        if self._size == 0:
            raise IndexError("pop from an empty dynamic array")

        self._size -= 1
        value = cast(T, self._storage[self._size])
        self._storage[self._size] = None
        return value

    def _resize(self, new_capacity: int) -> None:
        new_storage: list[T | None] = [None] * new_capacity

        # 复制操作代价较高，但容量加倍使它不会频繁发生。
        for index in range(self._size):
            new_storage[index] = self._storage[index]

        self._storage = new_storage
        self._capacity = new_capacity

    def __len__(self) -> int:
        return self._size

    @property
    def capacity(self) -> int:
        return self._capacity


values = DynamicArray[int]()
for number in range(9):
    values.append(number)

assert len(values) == 9
assert values.capacity == 16
assert values.get(3) == 3
values.set(3, 30)
assert values.get(3) == 30
assert values.pop_back() == 8
assert len(values) == 8

均摊代价比“这个操作通常很快”更有力：它保证每个足够长的操作序列都具有受限的平均代价。不要把均摊分析与平均情况分析混淆，后者依赖某种输入概率模型。

实际复杂度选择

选择算法是一项受约束的工程决策，而不是脱离其他条件、只追求最小 Big-O 符号的竞赛。首先确保正确性，然后再比较预期输入规模、最坏情况保证、内存预算、更新频率、顺序要求、实现风险以及代码维护成本。

问题 为什么它会改变选择
输入是否已经排序？ 可能因此可以使用二分搜索或双指针方法。
是否需要对基本不变的数据执行大量查询？ 排序、前缀和等预处理可能抵消其初始代价。
内存是否受限？ 一个原地 \(O(n^2)\) 方法可能胜过需要大型辅助表的 \(O(n)\) 方法。
延迟是否必须可预测？ 最坏情况保证可能比预期性能更加重要。
n 是否始终很小？ 简单的二次方法可能更清晰，而且已经足够快。
数据表示是否符合访问模式？ 数组适合按下标访问；哈希表适合精确键查询；树可以保持顺序。

一个有纪律的选择流程如下：

  1. 排除所有不满足问题规格的候选方案；
  2. 估计现实的输入规模和各类操作的执行频率；
  3. 比较时间增长与辅助空间增长；
  4. 明确已排序、哈希查询预期为常数时间等假设；
  5. 在理解理论模型后，再使用具有代表性的输入进行基准测试；
  6. 记录所作权衡，使未来发生变化时能够用一致标准重新评估。

本章最重要的结论是：分析与证明相互支持。精确的不变式往往能揭示正确实现，而仔细的代价模型则能暴露哪些状态或重复工作需要重新设计。
