动态规划

动态规划（dynamic programming，DP）通过识别重复子问题、只求解每个不同子问题一次，并在相同状态再次出现时复用答案来解决问题。被保存的答案可以是最小成本、最大价值、构造数量、可行性判断、概率或一个实际解。因此，DP 本质上是组织依赖关系的方法，而不只是填表。

核心设计问题是：过去的哪些信息仍会影响未来？ 状态只保存这些信息。若两段不同决策历史产生相同的未来相关状态，它们就可以合并，因为一段历史可用的每种后续选择对另一段也同样可用。正是这种状态合并，把指数级递归树压缩为多项式大小的有向无环图。

动态规划位于相邻算法范式之间：

  • 贪心算法证明一个局部选择安全，并丢弃全部替代项；
  • 回溯保留不同选择历史，必要时逐一探索；
  • 动态规划保留替代方案，但合并通向同一状态的历史。

本章从识别问题和设计状态开始，再介绍常见状态形状：一维前缀、容量、两个前缀、网格与区间；最后区分计算最优值和重建实现该值的具体选择。

重要

不要先问“DP 数组里应该放什么”。应先写出完整句子：“状态 X 表示……”。递推式、基本情况、求值顺序和最终答案都应从这句话自然推导出来。

识别动态规划问题

当直接递归表述具有两个结构性质时，DP 往往是有力候选。

最优子结构（optimal substructure）表示最优答案可以由较小状态的最优答案组装。对于计数和判定问题，对应要求是当前答案能由较小答案完整组成。该性质说明为什么较小结果已经足够。

重叠子问题（overlapping subproblems）表示不同决策路径会请求同一状态。没有缓存时，该状态会被反复计算。分治也解决较小问题，但递归分支通常独立；当分支重新汇合时，DP 尤其有价值。

常见识别信号包括：

  • 问题要求从大量组合中求最小值、最大值、数量或存在性；
  • 一个选择把问题分成少量较小状态；
  • 相同后缀、前缀、容量、位置、掩码或区间在多种历史下重复出现；
  • 暴力递归容易描述，但调用大量重复；
  • 未来只依赖紧凑摘要，而不依赖完整构造历史。

通用自顶向下结构为：

SOLVE(state s)
    if s is a base state
        return its direct answer
    if s is already stored
        return stored[s]

    answer <- combine SOLVE(next_state) over every legal final/next decision
    stored[s] <- answer
    return answer

Fibonacci 是有意选择的小例子。朴素递归中的 \(F(n-1)\) 与 \(F(n-2)\) 都会继续请求 \(F(n-3)\) 等状态。记忆化把调用树变成每个整数状态只求值一次的图。相同转换也适用于 (row, column)、(item, capacity) 或 (left, right) 等更丰富状态。

Python 实现：暴露重复调用并用缓存消除 
from functools import cache


def compare_fibonacci_calls(n: int) -> tuple[int, int, int]:
    """返回 Fibonacci(n)、朴素函数体调用数和记忆化调用数。"""
    if n < 0:
        raise ValueError("n must be non-negative")

    naive_calls = 0

    def naive(k: int) -> int:
        nonlocal naive_calls
        naive_calls += 1
        if k < 2:
            return k
        return naive(k - 1) + naive(k - 2)

    memo_calls = 0

    @cache
    def memoized(k: int) -> int:
        nonlocal memo_calls
        memo_calls += 1  # 只有缓存未命中时才运行函数体。
        if k < 2:
            return k
        return memoized(k - 1) + memoized(k - 2)

    naive_value = naive(n)
    memoized_value = memoized(n)
    assert naive_value == memoized_value
    return naive_value, naive_calls, memo_calls


value, naive_count, memo_count = compare_fibonacci_calls(10)
assert (value, naive_count, memo_count) == (55, 177, 11)
print(value, naive_count, memo_count)

朴素递归需要 \(\Theta(\varphi^n)\) 时间，其中 \(\varphi\) 是黄金比例，因为调用树指数增长。记忆化只计算从 0 到 n 的 n+1 个状态，时间为 \(O(n)\)，缓存与递归栈空间为 \(O(n)\)。

识别只是第一步。低效或不完整状态仍可能产生指数数量的不同表项。后续各节关注如何让状态既充分又经济。

练习： LeetCode 70 - 爬楼梯是识别重复剩余步数并把递推转换为线性工作的紧凑练习。

状态、转移、基本情况与求值顺序

一个 DP 表述包含四个不可分离的部分：

  1. 状态含义：精确的子问题定义，包括下标约定；
  2. 转移：对所有合法最后选择或下一选择的完整划分；
  3. 基本情况：可以直接得知答案的最小状态；
  4. 求值顺序：使用某个依赖前，保证它已经可用的顺序。

以最大非相邻元素和为例。令非负值为 \(v_0,\ldots,v_{n-1}\)，定义 \(dp[i]\) 为从前 i 个值中选择且不选相邻位置时的最大和。前缀约定很重要：\(dp[0]\) 表示空前缀，\(v_{i-1}\) 是 \(dp[i]\) 中最后可用的值。

前 i 个值的任意最优解恰好采用两种最后选择之一：

  • 跳过 \(v_{i-1}\)，得到 \(dp[i-1]\)；
  • 选择 \(v_{i-1}\)，因此不能选 \(v_{i-2}\)，得到 \(v_{i-1}+dp[i-2]\)。

所以

\[ dp[i]=\max\left(dp[i-1],\;v_{i-1}+dp[i-2]\right),\qquad i\ge 2, \]

基本情况为 \(dp[0]=0\) 与 \(dp[1]=v_0\)。这里 i 是前缀长度，\(v_{i-1}\) 是最后可用值，max 两项分别代表互斥且穷尽的跳过/选择情况。状态 i 只依赖更小下标，因此递增 i 是有效拓扑顺序。

MAX-NON-ADJACENT(values v[0..n-1])
    if n = 0
        return 0
    dp[0] <- 0
    dp[1] <- v[0]
    for i <- 2 to n
        skip <- dp[i-1]
        take <- v[i-1] + dp[i-2]
        dp[i] <- max(skip, take)
    return dp[n]

正确性可对 i 归纳。假设所有较小前缀状态最优；每个可行解要么排除最后值，要么包含它，递推分别求出两个互斥情况的最优结果并取较大值，基本状态则锚定归纳。

Python 实现：使用显式状态表计算最大非相邻和 
def maximum_non_adjacent_sum(values: list[int]) -> int:
    """返回非相邻非负值的最大和。"""
    if any(value < 0 for value in values):
        raise ValueError("this state definition assumes non-negative values")
    if not values:
        return 0

    # dp[i] 表示使用 values[:i] 时的最佳答案。
    dp = [0] * (len(values) + 1)
    dp[1] = values[0]

    for i in range(2, len(values) + 1):
        skip = dp[i - 1]
        take = values[i - 1] + dp[i - 2]
        dp[i] = max(skip, take)

    return dp[-1]


assert maximum_non_adjacent_sum([2, 7, 9, 3, 1]) == 12
assert maximum_non_adjacent_sum([]) == 0
print(maximum_non_adjacent_sum([2, 7, 9, 3, 1]))

共有 n+1 个状态，每个状态工作为 \(O(1)\)，所以时间 \(O(n)\)、表空间 \(O(n)\)。依赖窗口宽度为二，若只需数值，之后可压缩为 \(O(1)\) 空间；应在完整状态和顺序正确后再做优化。

记忆化与制表法

记忆化（memoization）与制表法（tabulation）以不同方式求值同一状态图。

记忆化是自顶向下：从请求目标出发，沿递归依赖前进，并把每个完成答案存入缓存。它常直接对应数学递推，也可能跳过不可达状态；代价包括函数调用、递归深度与缓存键构造。

制表法是自底向上：显式选择满足依赖的顺序，从基本状态填到目标。它避免递归开销、内存访问可预测，也容易发现滚动数组优化，但可能计算目标永远不会到达的状态。

TOP-DOWN(state s)
    if s is a base state: return base value
    if s is cached: return cache[s]
    cache[s] <- combine TOP-DOWN(predecessor) over dependencies
    return cache[s]

BOTTOM-UP(all states)
    initialize every base state
    for state s in topological dependency order
        table[s] <- combine table[predecessor] over dependencies
    return table[target]

对最小爬楼成本，令 \(f(i)\) 为落在第 i 阶时支付的最小总成本。到达 i 的最后一步来自 i-1 或 i-2：

\[ f(i)=cost[i]+\min(f(i-1),f(i-2)). \]

楼顶位于最后一级之后，所以答案为 \(\min(f(n-1),f(n-2))\)。递归版只请求两个目标可达的状态；迭代版从左到右计算相同值。

Python 实现：同一递推的自顶向下与自底向上版本 
from functools import cache


def minimum_climbing_cost_top_down(cost: list[int]) -> int:
    """落到某阶时支付成本；可以从第 0 或第 1 阶开始。"""
    if len(cost) < 2 or any(value < 0 for value in cost):
        raise ValueError("provide at least two non-negative step costs")

    @cache
    def reach(i: int) -> int:
        if i < 2:
            return cost[i]
        return cost[i] + min(reach(i - 1), reach(i - 2))

    return min(reach(len(cost) - 1), reach(len(cost) - 2))


def minimum_climbing_cost_bottom_up(cost: list[int]) -> int:
    if len(cost) < 2 or any(value < 0 for value in cost):
        raise ValueError("provide at least two non-negative step costs")

    dp = cost.copy()
    for i in range(2, len(dp)):
        dp[i] += min(dp[i - 1], dp[i - 2])
    return min(dp[-1], dp[-2])


example = [10, 15, 20]
assert minimum_climbing_cost_top_down(example) == 15
assert minimum_climbing_cost_bottom_up(example) == 15
print(minimum_climbing_cost_top_down(example))
print(minimum_climbing_cost_bottom_up(example))

两者都有 n 个不同状态、每个 \(O(1)\) 工作，所以时间 \(O(n)\)。自顶向下使用 \(O(n)\) 缓存与递归栈；所示自底向上表使用 \(O(n)\)，可压缩为两个变量。稀疏状态图中记忆化可能计算更少状态；规则稠密表中制表法通常更简单、更快。

问题 记忆化 制表法
起点 请求目标 基本状态
顺序 递归产生 显式编写
不可达状态 通常跳过 可能被填充
栈溢出风险 有 无
空间压缩 较不直接 通常较直接

练习： LeetCode 746 - 使用最小花费爬楼梯可以在同一递推上实现两种求值方式。

一维动态规划

一维 DP 通常处理序列、金额或有序位置。常见状态 dp[i] 表示前 i 个元素或数值目标 i 的答案。当每次转移只依赖有限个较早位置或金额时，这种形状很有效。

关键不在数组维度，而在下标含义。前缀长度下标常简化基本情况，因为 dp[0] 自然表示空前缀。

考虑数字字符串解码，其中 1 到 26 映射为字母。定义 \(dp[i]\) 为前 i 个字符的有效解码数。空前缀有一种中性解码，因此 \(dp[0]=1\)。对每个 i：

  • 若单数字 s[i-1] 在 1 到 9 之间，可接到 \(dp[i-1]\) 中每种解码后；
  • 若双数字 s[i-2:i] 在 10 到 26 之间，可接到 \(dp[i-2]\) 中每种解码后。

所以

\[ dp[i]=\mathbf{1}_{1\le s[i-1]\le 9}\,dp[i-1] +\mathbf{1}_{10\le s[i-2:i]\le 26}\,dp[i-2]. \]

\(\mathbf{1}_{condition}\) 在条件为真时为 1，否则为 0。两项按照最后码字长度计算互斥构造。零不能独立解码，但可以属于 10 或 20。

COUNT-DECODINGS(string s)
    dp[0] <- 1
    for i <- 1 to length(s)
        dp[i] <- 0
        if s[i-1] is a valid one-digit code
            dp[i] <- dp[i] + dp[i-1]
        if i >= 2 and s[i-2:i] is a valid two-digit code
            dp[i] <- dp[i] + dp[i-2]
    return dp[length(s)]
Python 实现：统计有效解码数 
def count_decodings(digits: str) -> int:
    """返回映射 1..26 -> A..Z 下的解码数量。"""
    if not digits:
        return 0
    if not digits.isdigit():
        raise ValueError("digits must contain decimal characters only")

    dp = [0] * (len(digits) + 1)
    dp[0] = 1  # 空前缀有一种解码方式。

    for i in range(1, len(digits) + 1):
        if digits[i - 1] != "0":
            dp[i] += dp[i - 1]

        if i >= 2 and 10 <= int(digits[i - 2 : i]) <= 26:
            dp[i] += dp[i - 2]

    return dp[-1]


assert count_decodings("226") == 3
assert count_decodings("06") == 0
assert count_decodings("2101") == 1
print(count_decodings("226"))

共有 n+1 个前缀状态，每个最多两个转移，时间为 \(O(n)\)，所示表空间为 \(O(n)\)。因为状态 i 只依赖 i-1 和 i-2，正确性确定后可压缩至 \(O(1)\)。

其他一维模式包括到达位置的最小成本、组成金额的方法数、最长有效前缀与有限状态解析。共同技能是判断哪些早期状态可以合法转移到当前状态。

练习： LeetCode 91 - 解码方法直接训练前缀含义、零处理与多个前驱状态。

背包问题

背包 DP 建模消耗有限资源的决策。在 0/1 背包中，每件物品最多使用一次。物品 i 有重量 \(w_i\)、价值 \(v_i\)，所选总重量不超过容量 \(C\)。

定义 \(dp[i][c]\) 为使用前 i 件物品、容量上限为 c 时的最大价值。最后决定排除第 i 件，或在能放下时包含它：

\[ dp[i][c]= \begin{cases} dp[i-1][c], & w_i>c,\\ \max\left(dp[i-1][c],\;dp[i-1][c-w_i]+v_i\right), & w_i\le c. \end{cases} \]

i 是可用物品数，c 是当前容量上限。两种方案都使用第 i-1 行，因为第 i 件不能重复使用。基本状态 \(dp[0][c]=0\) 与 \(dp[i][0]=0\) 表示没有物品或没有容量。

物品维度可压缩为一维容量数组，但容量循环必须向下进行：处理物品 i 前，每个 dp[c-w] 必须仍代表上一物品层。向上循环会读取同一物品刚更新的值，悄悄把问题变成完全背包。

ZERO-ONE-KNAPSACK(items, capacity C)
    dp[0..C] <- 0
    for each item (weight w, value v)
        for c <- C down to w
            dp[c] <- max(dp[c], dp[c-w] + v)
    return dp[C]

Python 实现：空间优化的 0/1 背包价值 
def zero_one_knapsack_value(
    items: list[tuple[int, int]], capacity: int
) -> int:
    """每个（重量，价值）物品最多使用一次，返回最大价值。"""
    if capacity < 0:
        raise ValueError("capacity must be non-negative")
    if any(weight <= 0 or value < 0 for weight, value in items):
        raise ValueError("weights must be positive and values non-negative")

    dp = [0] * (capacity + 1)

    for weight, value in items:
        # 容量递减可保留上一物品层。
        for current_capacity in range(capacity, weight - 1, -1):
            dp[current_capacity] = max(
                dp[current_capacity],
                dp[current_capacity - weight] + value,
            )

    return dp[capacity]


example_items = [(10, 60), (20, 100), (30, 120)]
assert zero_one_knapsack_value(example_items, 50) == 220
print(zero_one_knapsack_value(example_items, 50))

对 n 件物品和容量 C，算法时间为 \(O(nC)\)、空间为 \(O(C)\)。这是伪多项式（pseudo-polynomial）复杂度：它对容量数值是多项式，而不是对编码 C 所需比特数。即使物品很少，十亿容量仍不可行。

变体 物品复用 一维容量循环方向 典型转移
0/1 背包 最多一次 递减 只使用上一层
完全背包 无限 递增 当前层可复用物品
多重背包 有限次数 拆分或次数状态 跟踪剩余数量
子集和 最多一次 递减 布尔可达性

子序列动态规划

子序列（subsequence）保持相对顺序，但允许删除元素；子串或子数组必须连续。子序列问题常比较一个或两个序列的前缀，因为末尾字符只产生少量且完整的情况。

对字符串 x 与 y，定义 \(dp[i][j]\) 为前缀 \(x[:i]\) 与 \(y[:j]\) 的最长公共子序列（LCS）长度。末字符相同时，可以扩展两个较短前缀的最优解；不同时，某个最优公共子序列至少排除其中一个末字符：

\[ dp[i][j]= \begin{cases} dp[i-1][j-1]+1, & x_{i-1}=y_{j-1},\\ \max(dp[i-1][j],dp[i][j-1]), & x_{i-1}\ne y_{j-1}. \end{cases} \]

i 和 j 是前缀长度。对角状态删除两个末字符，上方与左侧状态删除一个。第 0 行和第 0 列为零，因为空序列没有非空公共子序列。

LCS-LENGTH(x, y)
    initialize dp[0][j] and dp[i][0] to 0
    for i <- 1 to length(x)
        for j <- 1 to length(y)
            if x[i-1] = y[j-1]
                dp[i][j] <- dp[i-1][j-1] + 1
            else
                dp[i][j] <- max(dp[i-1][j], dp[i][j-1])
    return dp[length(x)][length(y)]

图片来源：Slowkow, Needleman-Wunsch pairwise sequence alignment，CC0。Needleman-Wunsch 使用匹配、失配与空位分数，但其前缀状态几何与 LCS、编辑距离属于同一类。

Python 实现：最长公共子序列长度 
def longest_common_subsequence_length(first: str, second: str) -> int:
    """使用完整前缀表返回 LCS 长度。"""
    rows = len(first) + 1
    columns = len(second) + 1
    dp = [[0] * columns for _ in range(rows)]

    for i in range(1, rows):
        for j in range(1, columns):
            if first[i - 1] == second[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])

    return dp[-1][-1]


assert longest_common_subsequence_length("abcde", "ace") == 3
assert longest_common_subsequence_length("abc", "def") == 0
print(longest_common_subsequence_length("abcde", "ace"))

长度分别为 m 与 n 时，表有 \((m+1)(n+1)\) 个状态，每个 \(O(1)\) 工作，因此时间和空间均为 \(O(mn)\)。若只需长度，可滚动一行为 \(O(\min(m,n))\) 空间；恢复实际子序列则需要额外决策或重算。

相关表述包括编辑距离、序列对齐、最短公共超序列与 \(O(n^2)\) 最长递增子序列。区别在转移语义，而不只是表维度。

网格与多维动态规划

网格 DP 用坐标作为状态维度。\(dp[r][c]\) 可以表示到达单元格 \((r,c)\) 的路径数、最小成本，或处理到该位置时的最佳分数。移动规则决定前驱单元格，从而决定有效求值顺序。

若只能向右和向下移动，进入 \((r,c)\) 的每条路径最后一步来自 \((r-1,c)\) 或 \((r,c-1)\)。路径计数递推为

\[ ways[r][c]=ways[r-1][c]+ways[r][c-1]. \]

r 与 c 标识行列。第一项计算最后向下的路径，第二项计算最后向右的路径；两组互斥且穷尽。障碍物把选定状态置零，而不改变依赖模式。

若单元格成本为 \(g[r][c]\)，求最小路径和时把计数相加替换为前驱成本取小：

\[ cost[r][c]=g[r][c]+\min(cost[r-1][c],cost[r][c-1]). \]

MINIMUM-GRID-PATH(grid g with R rows and C columns)
    dp[0] <- 0
    dp[1..C] <- infinity
    for r <- 0 to R-1
        for c <- 0 to C-1
            from_above <- dp[c]
            from_left <- dp[c-1] when c > 0, otherwise infinity
            dp[c] <- g[r][c] + min(from_above, from_left)
    return dp[C-1]

图片来源：Pascal’s triangle pathways，公有领域；同一依赖模式支持路径计数与最小路径成本。

Python 实现：用一行滚动数组求最小路径和 
from math import inf


def minimum_grid_path_sum(grid: list[list[int]]) -> int:
    """从左上到右下，只允许向右或向下。"""
    if not grid or not grid[0]:
        raise ValueError("grid must be non-empty")
    columns = len(grid[0])
    if any(len(row) != columns for row in grid):
        raise ValueError("grid must be rectangular")

    dp = [inf] * columns

    for row_index, row in enumerate(grid):
        for column_index, cell_cost in enumerate(row):
            if row_index == 0 and column_index == 0:
                dp[0] = cell_cost
                continue

            from_above = dp[column_index]
            from_left = dp[column_index - 1] if column_index > 0 else inf
            dp[column_index] = cell_cost + min(from_above, from_left)

    return int(dp[-1])


example_grid = [[1, 3, 1], [1, 5, 1], [4, 2, 1]]
assert minimum_grid_path_sum(example_grid) == 7
print(minimum_grid_path_sum(example_grid))

对于 R 行 C 列，每个单元格处理一次，时间 \(O(RC)\)。滚动行空间为 \(O(C)\)：当前状态只需仍保存在 dp[c] 的上方值和已经更新到 dp[c-1] 的左侧值。

额外维度可编码剩余资源、方向、奇偶性、访问掩码或时间。它们的乘积决定状态数，所以即使递推形式是“多项式”，若状态包含不必要信息仍可能不可行。

区间动态规划

区间 DP 使用 \(dp[i][j]\) 表示从下标 i 到 j 的连续范围。当最终操作会拆分、删除或包围一个区间，并留下可组合答案的更小区间时，它很合适。

与前缀 DP 不同，普通行优先顺序通常无效：\(dp[i][j]\) 可能依赖起点更大且终点更小的状态。安全顺序是按区间长度递增，先计算长度 1 的基本情况，再计算长度 2，以此类推。

矩阵链乘法是经典例子。矩阵 \(A_1,\ldots,A_n\) 的维度分别为 \(p_0\times p_1,p_1\times p_2,\ldots,p_{n-1}\times p_n\)。矩阵乘法满足结合律，但不同括号方式执行的标量乘法次数不同。

令 \(dp[i][j]\) 为计算 \(A_i\cdots A_j\) 的最小成本。若最后一次乘法在 \(A_k\) 后切分，左结果维度为 \(p_{i-1}\times p_k\)，右结果为 \(p_k\times p_j\)：

\[ dp[i][j]=\min_{i\le k<j}\left(dp[i][k]+dp[k+1][j]+p_{i-1}p_kp_j\right). \]

k 枚举每个可能的最终切分。前两项最优构造两个子乘积，\(p_{i-1}p_kp_j\) 是把结果矩阵相乘的标量成本。

MATRIX-CHAIN(dimensions p[0..n])
    dp[i][i] <- 0 for every matrix i
    for length <- 2 to n
        for each interval [i, j] of this length
            dp[i][j] <- infinity
            for k <- i to j-1
                candidate <- dp[i][k] + dp[k+1][j] + p[i-1]*p[k]*p[j]
                dp[i][j] <- min(dp[i][j], candidate)
    return dp[1][n]
Python 实现：矩阵链最小乘法成本 
from math import inf


def matrix_chain_minimum_cost(dimensions: list[int]) -> int:
    """返回给定矩阵链所需的最少标量乘法次数。"""
    if len(dimensions) < 2 or any(size <= 0 for size in dimensions):
        raise ValueError("dimensions must contain positive matrix dimensions")

    matrix_count = len(dimensions) - 1
    dp = [[0] * matrix_count for _ in range(matrix_count)]

    for length in range(2, matrix_count + 1):
        for left in range(0, matrix_count - length + 1):
            right = left + length - 1
            dp[left][right] = inf

            for split in range(left, right):
                combine_cost = (
                    dimensions[left]
                    * dimensions[split + 1]
                    * dimensions[right + 1]
                )
                candidate = (
                    dp[left][split]
                    + dp[split + 1][right]
                    + combine_cost
                )
                dp[left][right] = min(dp[left][right], candidate)

    return int(dp[0][matrix_count - 1]) if matrix_count else 0


assert matrix_chain_minimum_cost([10, 30, 5, 60]) == 4500
assert matrix_chain_minimum_cost([10, 20]) == 0
print(matrix_chain_minimum_cost([10, 30, 5, 60]))

共有 \(O(n^2)\) 个区间，每个区间最多 \(O(n)\) 个切分点，因此时间 \(O(n^3)\)、空间 \(O(n^2)\)。三次方来自 left、right 与 split 三个独立选择，而不是仅仅因为使用二维数组。

其他区间表述包括回文问题、最优二叉搜索树、多边形三角剖分，以及删除奖励取决于幸存邻居的元素问题。

解重建与空间优化

优化 DP 可能有两种不同输出契约：

  • 只返回最优目标值；
  • 返回一个见证（witness）：所选物品、路径、子序列、括号方式或编辑操作。

值表不一定唯一确定见证。重建通常为每个状态保存父决策，或在向后移动时比较相邻值。多个前驱并列时，一致的平局规则会返回某一个最优见证；枚举全部最优见证是另一个可能大得多的问题。

空间优化利用依赖窗口宽度。若第 i 行只依赖第 i-1 行，可以覆盖更早行；但这些行可能包含重建路径所需的前驱信息。正确优化取决于输出契约。

RECONSTRUCT-LCS(x, y, table dp)
    i <- length(x), j <- length(y), answer <- empty
    while i > 0 and j > 0
        if x[i-1] = y[j-1]
            append x[i-1] to answer
            i <- i-1, j <- j-1
        else if dp[i-1][j] >= dp[i][j-1]
            i <- i-1
        else
            j <- j-1
    reverse answer
    return answer
Python 实现：计算并重建一个最长公共子序列 
def longest_common_subsequence(first: str, second: str) -> str:
    """返回一个 LCS；平局时优先向上移动。"""
    rows = len(first) + 1
    columns = len(second) + 1
    dp = [[0] * columns for _ in range(rows)]

    for i in range(1, rows):
        for j in range(1, columns):
            if first[i - 1] == second[j - 1]:
                dp[i][j] = dp[i - 1][j - 1] + 1
            else:
                dp[i][j] = max(dp[i - 1][j], dp[i][j - 1])

    # 从目标状态沿某个最优前驱向后移动。
    i, j = len(first), len(second)
    reversed_answer: list[str] = []

    while i > 0 and j > 0:
        if first[i - 1] == second[j - 1]:
            reversed_answer.append(first[i - 1])
            i -= 1
            j -= 1
        elif dp[i - 1][j] >= dp[i][j - 1]:
            i -= 1
        else:
            j -= 1

    return "".join(reversed(reversed_answer))


def is_subsequence(candidate: str, sequence: str) -> bool:
    iterator = iter(sequence)
    return all(character in iterator for character in candidate)


answer = longest_common_subsequence("ABCBDAB", "BDCABA")
assert len(answer) == 4
assert is_subsequence(answer, "ABCBDAB")
assert is_subsequence(answer, "BDCABA")
print(answer)

完整 LCS 算法时间与空间均为 \(O(mn)\)，随后回溯为 \(O(m+n)\)。只需长度时，滚动行把空间降为 \(O(\min(m,n))\)。Hirschberg 算法结合滚动行和分治，可以在线性空间重建 LCS，但实现更复杂。

压缩内存前，应先问哪些值仍然存活、更新需要旧值还是新值、最终输出是否需要路径。空间优化是依赖分析，不是机械地把数组换成变量。

动态规划、贪心与回溯

这些技术可以从同一决策树出发，却保留不同信息。

贪心在证明每次提交安全后只走一条路径。回溯保留不同历史，因为它们未来的可行性可能不同。动态规划保留所有相关替代项，但合并拥有相同未来相关状态的历史，并为每个状态只保存最佳值、计数或可行性。

SELECT-A-STRATEGY(problem)
    if one local choice can be proved safe
        use greedy
    else if equivalent future states recur under many histories
        define and cache/tabulate those states with DP
    else if distinct histories must remain distinct
        use backtracking or another state-space search

使用面额 \(\{1,3,4\}\) 凑 6 是清晰比较。最大优先贪心得到 \(4+1+1\)，结果错误；回溯找到 \(3+3\)，但会通过多种顺序反复访问相同剩余金额；DP 保存每个金额的最佳结果并合并这些历史。

Python 实现：在同一状态空间比较贪心、回溯与 DP 
from math import inf


def greedy_coin_count(coins: list[int], amount: int) -> int | None:
    count = 0
    for coin in sorted(coins, reverse=True):
        used, amount = divmod(amount, coin)
        count += used
    return count if amount == 0 else None


def backtracking_coin_count(coins: list[int], amount: int) -> int | None:
    """精确但有意不缓存，只适合小例子。"""
    def search(remaining: int) -> int:
        if remaining == 0:
            return 0
        best = inf
        for coin in coins:
            if coin <= remaining:
                best = min(best, 1 + search(remaining - coin))
        return best

    result = search(amount)
    return None if result == inf else int(result)


def dynamic_programming_coin_count(coins: list[int], amount: int) -> int | None:
    dp = [0] + [inf] * amount
    for current in range(1, amount + 1):
        for coin in coins:
            if coin <= current:
                dp[current] = min(dp[current], 1 + dp[current - coin])
    return None if dp[amount] == inf else int(dp[amount])


coins = [1, 3, 4]
assert greedy_coin_count(coins, 6) == 3
assert backtracking_coin_count(coins, 6) == 2
assert dynamic_programming_coin_count(coins, 6) == 2
print("greedy:", greedy_coin_count(coins, 6))
print("backtracking:", backtracking_coin_count(coins, 6))
print("dynamic programming:", dynamic_programming_coin_count(coins, 6))

对 k 种硬币与目标 A，贪心为 \(O(k\log k)\)，但对任意面额不保证正确；无缓存回溯可能随 A 指数增长；DP 通过只求解每个剩余金额一次，使用 \(O(kA)\) 时间与 \(O(A)\) 空间。

结构问题 贪心 动态规划 回溯
是否保留替代项 安全证明后不保留 保留，但合并相同状态 保留不同历史
常见正确性工具 交换 / 始终领先 递推 + 归纳 穷尽覆盖 + 安全剪枝
重复等价状态 由证明丢弃 缓存或制表 未记忆化时常重复计算
常见最坏规模 线性或由排序主导 状态数乘转移数 指数搜索树

当你能明确说明“是什么让两个部分历史对所有未来延续都等价”时，选择 DP。若这种等价无法紧凑表达，可能需要回溯；若能证明某个替代项永久支配其他选择，贪心更简单且通常更快。
