数组、字符串与哈希

数组、字符串和哈希表之所以属于基础结构，是因为它们决定了信息如何排列以及如何被访问。许多起初看似毫无关联的问题，在识别出所需访问模式后都会变得简单：直接按位置访问提示使用数组，顺序处理文本提示把字符串视为序列，而快速判断成员关系或建立键值关联则提示使用哈希。

本章同时研究这些数据结构，以及建立在它们之上的算法模式。每个部分都会回答以下问题：

  1. 这种结构或模式解决什么问题，为什么它优于朴素方案？
  2. 对于数据结构，它承诺哪些 ADT 操作，各操作的前置条件和效果是什么？
  3. 它的内部状态如何组织或更新？
  4. 各项操作的时间和空间代价是什么，这些结论依赖哪些假设？
  5. 如何使用 Python 清晰地实现这种思想？

贯穿本章的主题是状态复用。前缀和复用之前的累计值，双指针复用顺序信息，滑动窗口复用相邻区间的重叠部分，而哈希则复用已经计算出的“键到桶”映射。

数组与动态数组

数组（array） 在连续内存中存储一系列大小相同的槽位。它类似一排带编号的储物柜：只要知道 0 号柜的位置和每个柜子的宽度，就能立即计算出任意柜子的地址。对于从零开始的下标 i，

\[ \operatorname{address}(A[i]) = \operatorname{base}(A) + i \cdot w, \]

其中，\(\operatorname{base}(A)\) 是第一个槽位的地址，w 是单个元素固定的字节宽度。正是这种地址运算让按下标访问具有 \(\Theta(1)\) 复杂度，因为算法无需扫描前面的元素。

数组适合需要有序存储、快速索引或缓存友好型顺序扫描的问题。它的主要限制是：在靠近开头的位置插入元素时，后续元素都需要移动。如果插入点之后还有 n 个元素，移动代价就是 \(\Theta(n)\)。

动态数组（dynamic array） 在固定容量数组之上提供“逻辑大小”这一抽象。它维护：

  • 一块包含 capacity 个槽位的存储区域；
  • 一个表示已占用槽位数量的逻辑 size；
  • 一条增长规则，通常在空间已满时把容量加倍。

查看原始开放图像：Wikimedia Commons - Dynamic array。

把数组或动态数组视为可变序列 ADT 时，它提供以下操作契约：

ADT 操作 必须提供的行为
length() 返回逻辑元素数量。
get(i) 返回有效下标 i 处的元素。
set(i, x) 将下标 i 处的元素替换为 x。
append(x) 在当前最后一个元素之后添加 x。
insert(i, x) 在 i 处插入 x，同时保持顺序。
delete(i) 删除 i 处的元素，并保持其余元素的顺序。
find(x) 返回匹配下标，或约定的“未找到”结果。

当逻辑元素数量为 n 时，各操作代价如下：

操作 固定数组 动态数组 原因
length \(O(1)\) \(O(1)\) 长度被显式保存。
get / set \(O(1)\) \(O(1)\) 地址运算直接定位一个槽位。
在无序数据中 find \(O(n)\) \(O(n)\) 可能需要扫描所有值。
append 有空槽时为 \(O(1)\) 均摊 \(O(1)\)；最坏 \(O(n)\) 扩容时需要复制已占用区域。
pop_back \(O(1)\) \(O(1)\) 不需要移动后缀。
中间 insert / delete \(O(n)\) \(O(n)\) 为保持顺序必须移动后缀。
遍历全部元素 \(\Theta(n)\) \(\Theta(n)\) 每个逻辑元素都要访问一次。

两种表示都使用 \(\Theta(n)\) 的逻辑存储空间。动态数组可能预留额外的未使用槽位；采用容量加倍策略后，数组增长过程中容量始终保持在 \(O(n)\)。

当最终长度未知时，动态数组优于固定数组：它既保留 \(O(1)\) 下标访问，又提供均摊 \(O(1)\) 的追加操作。链表在已知结点位置时可以不移动元素就完成插入，但它无法直接计算第 i 个元素的地址，缓存局部性也更弱。

Python 实现：显式展示插入和删除引起的移动 
from typing import TypeVar

T = TypeVar("T")


def insert_at(values: list[T], index: int, item: T) -> None:
    """插入 item，并显式展示数组元素的移动。"""
    if index < 0 or index > len(values):
        raise IndexError("insertion index out of range")

    # 必要时，Python 会扩展列表的底层存储空间。
    values.append(item)

    # 从末尾开始把后缀向右移动一位，避免覆盖尚未移动的值。
    for position in range(len(values) - 1, index, -1):
        values[position] = values[position - 1]

    values[index] = item


def delete_at(values: list[T], index: int) -> T:
    """删除一个元素，并填补删除后形成的空位。"""
    if index < 0 or index >= len(values):
        raise IndexError("deletion index out of range")

    removed = values[index]
    for position in range(index, len(values) - 1):
        values[position] = values[position + 1]

    values.pop()
    return removed


numbers = [10, 20, 40]
insert_at(numbers, 2, 30)
assert numbers == [10, 20, 30, 40]
assert delete_at(numbers, 1) == 20
assert numbers == [10, 30, 40]

生产代码应当使用 Python 内置的 list.insert 和 list.pop。上面的显式循环只是为了揭示这些便捷操作隐藏的结构性代价。

把字符串视为序列

字符串（string） 是有序的文本符号序列，但“一个符号”在不同层次上可能有不同含义。用户看到的是字符，Unicode 定义的是码点（code point），而 UTF-8 等编码再把码点存储为字节。这个区别很重要，因为一个可见字符不一定只占一个字节，有些可见的字素还由多个码点共同组成。

字符串用于解决文本搜索、解析、比较、规范化和转换问题。把它视为序列后，可以使用许多熟悉的数组模式，但需要特别注意两个性质：

  • Python 字符串是不可变的。看似修改字符串的操作实际上会创建一个新值。
  • Python 字符串下标访问的是 Unicode 码点，而编码后的 bytes 下标访问的是单个字节。

作为不可变序列 ADT，字符串支持观察和构造操作，但不支持原地 set(i, x)：

ADT 操作 必须提供的行为 长度为 n 时的代价
length() 返回可索引码点数量。 Python 中为 \(O(1)\)
char_at(i) 返回有效下标 i 处的码点。 Python 中为 \(O(1)\)
iterate() 按顺序访问所有可索引码点。 \(\Theta(n)\)
slice(left, right) 返回包含 k 个选中码点的新字符串。 \(\Theta(k)\) 时间和空间
concat(a, b) 返回依次包含两个操作数的新字符串。 \(\Theta(|a|+|b|)\)
equals(other) 检查长度和对应码点是否相同。 最坏 \(\Theta(n)\)
contains(character) 检查一个字符是否出现。 最坏 \(O(n)\)

字符串表示本身使用 \(\Theta(n)\) 的码元存储空间。由于 ADT 不可变，切片和连接都会分配新字符串；这个空间代价也解释了为什么在循环中反复执行 result = result + fragment 可能产生平方级总开销。

不可变性让字符串可以安全共享并用作哈希键，但循环中的重复连接会不断复制越来越长的前缀。通常更好的方式是先把片段追加到列表，最后只调用一次 join，使全部内容在最终的一次遍历中组装完成。

Python 实现：检查文本表示并高效构造字符串 
def inspect_text(text: str) -> list[dict[str, object]]:
    """显示每个 Python 字符、Unicode 码点和 UTF-8 字节。"""
    result: list[dict[str, object]] = []

    for character in text:
        result.append(
            {
                "character": character,
                "code_point": f"U+{ord(character):04X}",
                "utf8_bytes": list(character.encode("utf-8")),
            }
        )

    return result


def join_words(words: list[str]) -> str:
    """构造一个字符串，避免反复复制持续增长的前缀。"""
    fragments: list[str] = []
    for word in words:
        if fragments:
            fragments.append(" ")
        fragments.append(word)

    return "".join(fragments)


details = inspect_text("caf\N{LATIN SMALL LETTER E WITH ACUTE}")
assert len(details) == 4
assert details[-1]["utf8_bytes"] == [195, 169]
assert join_words(["data", "structures", "matter"]) == "data structures matter"

在只包含 ASCII 的面试题中，字符和字节推理通常一致。在真实的多语言系统中，则必须显式考虑 Unicode 规范化、大小写折叠、字素边界和区域规则。

哈希表、映射与集合

哈希表（hash table） 把键转换为桶下标，使查询可以直接跳到目标记录附近，而不必扫描全部记录。可以把它类比为根据图书标识符计算书架位置的图书馆：良好的规则会把图书均匀分散到不同书架，但两本书仍可能被分配到同一个书架。

对于包含 m 个桶的表，一种常见的下标计算方式是

\[ \operatorname{index}(k)=\operatorname{hash}(k) \bmod m. \]

哈希函数把键 k 转换为整数，模 m 运算再把该整数映射到 0 至 m-1 的有效桶下标。在键的生命周期内，相等的键必须产生相等的哈希值。

当不同的键选择了同一个桶时，就发生了冲突（collision）。拉链法（separate chaining）在每个桶中保存一个较小的键值对集合；开放寻址法（open addressing）则根据探测规则继续搜索其他表位置。

查看原始开放图像：Wikimedia Commons - Hash table。

负载因子（load factor） 定义为

\[ \alpha = \frac{n}{m}, \]

其中 n 是已存储记录数，m 是桶数。随着 \(\alpha\) 增大，冲突链会变长。实际哈希表会通过扩容控制负载因子，从而支持预期 \(O(1)\) 的查询、插入和删除。如果大量键发生冲突，最坏查询时间仍然是 \(O(n)\)。

映射（map） 把每个唯一键关联到一个值；集合（set） 只存储唯一键。两者可以使用相同的哈希表机制。当程序频繁询问“我是否见过这个键？”或“这个键对应什么值？”，并且不要求有序时，它们优于重复扫描数组。

哈希表通常实现两个相关 ADT：

ADT 操作 必须提供的效果或结果
Map set(key, value) 插入新关联，或替换相等键的原值。
Map get(key) 返回关联值；键缺失时失败或返回定义好的哨兵。
Map delete(key) 删除 key 的关联。
Map contains(key) 报告关联是否存在。
Set add(value) 保存 value 的一个副本。
Set remove(value) 在契约允许调用时删除 value。
Set contains(value) 报告成员关系。

对于包含 n 条记录且负载因子受到控制的拉链哈希表，其代价如下：

操作 预期时间 最坏时间 说明
get / contains \(O(1)\) \(O(n)\) 搜索一条短链；最坏时所有键冲突。
set / add 均摊预期 \(O(1)\) \(O(n)\) 可能需要搜索冲突链或扩容。
delete / remove 预期 \(O(1)\) \(O(n)\) 定位并移除一条链记录。
遍历全部记录 \(O(n+m)\) \(O(n+m)\) 检查 m 个桶并输出 n 条记录。
存储空间 \(O(n+m)\) \(O(n+m)\) 桶和已存储记录。

“预期”这一说法依赖分布良好的哈希函数，以及把 \(\alpha=n/m\) 控制在常数范围内的扩容策略。下面的固定容量教学实现可以展示冲突，但不会扩容，因此如果记录数量无限增长，冲突链也会不断变长。

Python 实现：一个小型拉链哈希映射 
from collections.abc import Hashable
from typing import Generic, TypeVar

K = TypeVar("K", bound=Hashable)
V = TypeVar("V")


class ChainedHashMap(Generic[K, V]):
    """使用拉链法的教学实现。"""

    def __init__(self, bucket_count: int = 8) -> None:
        if bucket_count <= 0:
            raise ValueError("bucket_count must be positive")
        self._buckets: list[list[tuple[K, V]]] = [
            [] for _ in range(bucket_count)
        ]
        self._size = 0

    def _bucket(self, key: K) -> list[tuple[K, V]]:
        index = hash(key) % len(self._buckets)
        return self._buckets[index]

    def set(self, key: K, value: V) -> None:
        bucket = self._bucket(key)

        # 只搜索被选中的冲突链。
        for position, (stored_key, _) in enumerate(bucket):
            if stored_key == key:
                bucket[position] = (key, value)
                return

        bucket.append((key, value))
        self._size += 1

    def get(self, key: K) -> V:
        for stored_key, stored_value in self._bucket(key):
            if stored_key == key:
                return stored_value
        raise KeyError(key)

    def contains(self, key: K) -> bool:
        return any(stored_key == key for stored_key, _ in self._bucket(key))

    def delete(self, key: K) -> V:
        bucket = self._bucket(key)
        for position, (stored_key, stored_value) in enumerate(bucket):
            if stored_key == key:
                bucket.pop(position)
                self._size -= 1
                return stored_value
        raise KeyError(key)

    def __len__(self) -> int:
        return self._size


scores = ChainedHashMap[str, int]()
scores.set("Ada", 91)
scores.set("Grace", 95)
scores.set("Ada", 93)
assert scores.get("Ada") == 93
assert scores.contains("Grace")
assert len(scores) == 2
assert scores.delete("Grace") == 95
assert not scores.contains("Grace")
assert len(scores) == 1

实际代码应当使用经过高度优化的 Python dict 和 set，而不是上面的教学实现。

Map ADT：有序、无序与哈希实现

Map ADT 存储唯一键，并让每个键最多关联一个值。它并不要求必须使用哈希实现。其操作契约为：

ADT 操作 前置条件 必须提供的效果或结果
set(key, value) 键有效 插入关联，或替换相等键的旧值。
get(key) 通常要求键存在 返回关联值，或遵循文档规定的缺失键策略。
delete(key) 通常要求键存在 删除键及其值。
contains(key) 无 返回键是否存在。
items() 无 恰好遍历每个键值关联一次。
range(low, high) 键可排序 返回键位于指定区间内的关联。

应根据应用最常执行哪些操作来选择表示方式。

无序序列映射以任意顺序存储键值记录。如果已经知道键不存在，追加记录可以是 \(O(1)\)；但通用 set 必须先搜索相等键，因此是 \(O(n)\)。有序数组映射保持键有序，使二分查询达到 \(O(\log n)\)；但插入和删除仍为 \(O(n)\)，因为后续记录需要移动。哈希映射提供预期 \(O(1)\) 的精确键操作，却无法自然支持有序遍历或区间查询。后续介绍的平衡搜索树则能同时提供 \(O(\log n)\) 更新和有序操作。

实现 get / contains set delete 有序区间查询
无序序列 \(O(n)\) \(O(n)\) \(O(n)\) \(O(n)\) 扫描
有序数组 \(O(\log n)\) \(O(n)\) \(O(n)\) \(O(\log n + k)\)
哈希表 预期 \(O(1)\) 预期 \(O(1)\) 预期 \(O(1)\) \(O(n)\) 扫描
平衡树 \(O(\log n)\) \(O(\log n)\) \(O(\log n)\) \(O(\log n + k)\)

区间查询代价中的 k 是返回记录数量。这个输出项无法消除，因为仅产生 k 个答案就需要 \(\Omega(k)\) 工作。

Python 实现：有序数组映射 
from bisect import bisect_left, bisect_right


class SortedArrayMap:
    """在保持键有序的同时，把整数键映射到值。"""

    def __init__(self) -> None:
        self._keys: list[int] = []
        self._values: list[str] = []

    def set(self, key: int, value: str) -> None:
        # 二分搜索以 O(log n) 找到键或它的插入位置。
        index = bisect_left(self._keys, key)

        if index < len(self._keys) and self._keys[index] == key:
            self._values[index] = value
            return

        # 列表插入会移动后缀，因此这一步是 O(n)。
        self._keys.insert(index, key)
        self._values.insert(index, value)

    def get(self, key: int) -> str:
        index = bisect_left(self._keys, key)
        if index == len(self._keys) or self._keys[index] != key:
            raise KeyError(key)
        return self._values[index]

    def contains(self, key: int) -> bool:
        index = bisect_left(self._keys, key)
        return index < len(self._keys) and self._keys[index] == key

    def delete(self, key: int) -> str:
        index = bisect_left(self._keys, key)
        if index == len(self._keys) or self._keys[index] != key:
            raise KeyError(key)

        self._keys.pop(index)
        return self._values.pop(index)

    def items(self) -> list[tuple[int, str]]:
        return list(zip(self._keys, self._values))

    def range_items(self, low: int, high: int) -> list[tuple[int, str]]:
        """返回满足 low <= key <= high 的记录。"""
        start = bisect_left(self._keys, low)
        stop = bisect_right(self._keys, high)
        return list(zip(self._keys[start:stop], self._values[start:stop]))


map_by_id = SortedArrayMap()
map_by_id.set(30, "thirty")
map_by_id.set(10, "ten")
map_by_id.set(20, "twenty")
assert map_by_id.get(20) == "twenty"
assert map_by_id.contains(30)
assert map_by_id.range_items(15, 30) == [(20, "twenty"), (30, "thirty")]
assert map_by_id.delete(20) == "twenty"
assert map_by_id.items() == [(10, "ten"), (30, "thirty")]

频繁进行精确键访问时，哈希更合适；需要顺序、前驱/后继或区间访问时，有序存储更合适。接口本身并不能决定正确的底层实现。

练习。 LeetCode 128 - 最长连续序列 展示了哈希集合如何把一个看似需要排序的 \(O(n\log n)\) 问题改进为预期 \(O(n)\)。

前缀和

前缀和（prefix sum） 是一种累计记账方式。可以把它类比为记录设备安装以来总用电量的电表：某个月的用电量可以由较晚读数减去较早读数得到，无需重新累加每一分钟。

对于长度为 n 的数组 \(A\)，定义长度为 n + 1 的前缀数组 \(P\)：

\[ P[0]=0, \qquad P[i+1]=P[i]+A[i]. \]

P[i] 表示前 i 个元素的和，不包括 A[i]。采用这种左闭右开的约定后，从下标 left 开始、到 right 之前结束的区间和为

\[ \sum_{j=left}^{right-1} A[j] = P[right]-P[left]. \]

left 之前的所有元素同时出现在两个前缀总和中，因此相减后会被抵消。

伪代码。

BUILD-PREFIX(A)
    P <- array of length n + 1 filled with 0
    for i from 0 to n - 1
        P[i + 1] <- P[i] + A[i]
    return P

RANGE-SUM(P, left, right)
    return P[right] - P[left]

构建过程需要 \(O(n)\) 时间和 \(O(n)\) 额外空间，之后每次区间查询只需 \(O(1)\)。因此，当数组基本静态且预计有大量区间查询时，前缀和优于重复扫描。若元素频繁更新，它就不够方便，因为一次修改会影响之后的所有前缀值。

Python 实现：不可变数组上的区间和查询 
class PrefixSum:
    """预处理数值序列，以 O(1) 回答左闭右开区间和。"""

    def __init__(self, values: list[int]) -> None:
        self._prefix = [0]

        # 每个新前缀恰好比上一个多包含一个输入值。
        for value in values:
            self._prefix.append(self._prefix[-1] + value)

    def range_sum(self, left: int, right: int) -> int:
        """返回 sum(values[left:right])。"""
        if left < 0 or right < left or right >= len(self._prefix):
            raise IndexError("invalid half-open range")

        return self._prefix[right] - self._prefix[left]


totals = PrefixSum([3, -1, 4, 2, 5])
assert totals.range_sum(1, 4) == 5   # -1 + 4 + 2
assert totals.range_sum(0, 5) == 13
assert totals.range_sum(3, 3) == 0   # 空区间

同样的相减思想还可以扩展到二维前缀和、频率前缀、奇偶前缀和前缀异或。

双指针

双指针（two pointers） 技术在同一序列中维护两个具有明确含义的位置。它不枚举所有元素对，而是让每次比较利用结构性质排除大量候选。可以把它类比为从有序书架两端搜索：如果当前两个数之和过大，向内移动较大的一端是唯一可能让总和变小的操作。

对于有序数组和目标和：

PAIR-SUM-SORTED(values, target)
    left <- 0
    right <- length(values) - 1

    while left < right
        total <- values[left] + values[right]
        if total equals target
            return (left, right)
        if total < target
            left <- left + 1
        else
            right <- right - 1

    return not-found

为什么这些移动是安全的？如果当前和过小，那么把当前左端值与 right 左侧任意元素配对，只会得到相同或更小的和，因此当前左端值不可能参与答案。当总和过大时，可以用对称论证说明移动 right 是安全的。每个指针只向内移动，最多发生 n - 1 次移动，所以算法使用 \(O(n)\) 时间和 \(O(1)\) 辅助空间。

双指针特别适合有序数对问题、回文检查、划分、合并，以及“快慢指针”遍历。只有当指针移动确实能安全排除候选时，它才优于嵌套枚举全部数对。

Python 实现：在有序序列中寻找目标和数对 
def pair_sum_sorted(values: list[int], target: int) -> tuple[int, int] | None:
    """返回有序列表中一个目标和数对的下标。"""
    left = 0
    right = len(values) - 1

    while left < right:
        total = values[left] + values[right]

        if total == target:
            return left, right
        if total < target:
            # 使用当前左值的所有剩余数对都过小。
            left += 1
        else:
            # 使用当前右值的所有剩余数对都过大。
            right -= 1

    return None


assert pair_sum_sorted([1, 2, 4, 7, 11], 9) == (1, 3)
assert pair_sum_sorted([1, 2, 4, 7, 11], 20) is None

练习。 LeetCode 11 - 盛最多水的容器 需要另一种排除证明：宽度必然缩小，而较短一侧限制当前面积，因此应当移动较短边界。

滑动窗口

滑动窗口（sliding window） 使用左右边界表示一个连续区间。相邻区间高度重叠，因此算法只更新新进入或刚离开的元素，而不重新计算整个区间。可以把它类比为移动的相机画框：大部分画面保持不变，一条区域消失，同时出现一条新区域。

常见形式有两种：

  • 固定大小窗口在移动过程中保持长度不变；
  • 可变大小窗口先扩张以收集候选，再不断收缩，直到约束重新满足。

对于无重复字符的最长子串，应维护“不包含重复字符”这一窗口不变式。

LONGEST-DISTINCT-WINDOW(text)
    left <- 0
    last_seen <- empty map
    best <- 0

    for right from 0 to length(text) - 1
        character <- text[right]
        if character was seen at or after left
            left <- last_seen[character] + 1
        last_seen[character] <- right
        best <- max(best, right - left + 1)

    return best

当 left 移动时，无需清空映射。旧位置仍然无害，因为条件会检查此前下标是否还位于当前窗口内。两个边界都只向前移动，因此即使收缩在概念上发生于扩张循环内部，总工作量仍是 \(O(n)\)。

当目标性质可以随边界移动增量更新时，滑动窗口优于枚举全部子串。如果移除最左元素后无法高效更新状态，或者该性质缺少决定移动哪个边界所需的单调性，它就不适用。

Python 实现：字符互异的可变窗口 
def longest_distinct_window(text: str) -> tuple[int, str]:
    """返回无重复字符最长子串的长度和一个对应子串。"""
    last_seen: dict[str, int] = {}
    left = 0
    best_left = 0
    best_length = 0

    for right, character in enumerate(text):
        previous = last_seen.get(character)

        if previous is not None and previous >= left:
            # 一次跳过此前副本以及它之前的所有内容。
            left = previous + 1

        last_seen[character] = right
        current_length = right - left + 1

        if current_length > best_length:
            best_length = current_length
            best_left = left

    return best_length, text[best_left : best_left + best_length]


length, window = longest_distinct_window("abcabcbb")
assert length == 3
assert len(set(window)) == len(window)

子数组与子串模式

子数组（subarray）或子串（substring）必须连续；子序列（subsequence）保持相对顺序但可以跳过元素；子集（subset）则不关心位置和顺序。这个词汇区别直接决定哪些算法有效。滑动窗口和前缀差自然描述连续区间，而子序列问题通常需要动态规划。

对于最大子数组和，枚举每一对边界并重新计算区间和会重复大量工作。Kadane 算法在每个位置只询问一个更小的问题：必须在当前位置结束的子数组，其最大和是多少？

令 current 表示在当前值 x 处结束的最佳和。只有两种可能：扩展此前的结尾子数组，或者从 x 开始一个新子数组。

\[ \operatorname{current}_i = \max(A[i],\; \operatorname{current}_{i-1}+A[i]). \]

第一项表示重新开始，第二项表示继续扩展。另一个变量 best 保存所有位置上出现过的最大 current。

伪代码。

MAXIMUM-SUBARRAY-SUM(values)
    current <- values[0]
    best <- values[0]

    for each value x after the first
        current <- max(x, current + x)
        best <- max(best, current)

    return best

算法使用 \(O(n)\) 时间和 \(O(1)\) 辅助空间。它优于 \(O(n^2)\) 的边界数对方案，是因为此前位置所需的全部信息都被总结为一个数。通过用第一个元素而不是零初始化，它还能正确处理全负数组，而不会擅自允许空子数组。

Python 实现：恢复边界的 Kadane 算法 
def maximum_subarray(values: list[int]) -> tuple[int, int, int]:
    """对非空列表返回 (最佳和, 起点, 右侧开区间终点)。"""
    if not values:
        raise ValueError("maximum_subarray requires a non-empty list")

    current_sum = best_sum = values[0]
    current_start = best_start = 0
    best_end = 1

    for index in range(1, len(values)):
        value = values[index]

        if value > current_sum + value:
            # 旧前缀会降低结果，因此从当前位置开始新候选。
            current_sum = value
            current_start = index
        else:
            current_sum += value

        if current_sum > best_sum:
            best_sum = current_sum
            best_start = current_start
            best_end = index + 1

    return best_sum, best_start, best_end


values = [-2, 1, -3, 4, -1, 2, 1, -5, 4]
best_sum, left, right = maximum_subarray(values)
assert best_sum == 6
assert values[left:right] == [4, -1, 2, 1]

矩阵遍历与模拟

矩阵通常表示为“行的列表”，第 r 行、第 c 列的元素通过 matrix[r][c] 访问。矩阵算法的难点往往不在元素值本身，而在于如何让边界、方向和已访问区域始终保持一致。

模拟（simulation）会把这些状态变量显式表示出来。在螺旋遍历中，四条边界描述尚未访问的矩形：

  • top：第一条未访问行；
  • bottom：最后一条未访问行；
  • left：第一列未访问列；
  • right：最后一列未访问列。

每一轮依次消耗顶行、右列、底行和左列，然后把对应边界向内移动。

SPIRAL(matrix)
    top <- 0, bottom <- row_count - 1
    left <- 0, right <- column_count - 1

    while top <= bottom and left <= right
        visit top row from left to right; top <- top + 1
        visit right column from top to bottom; right <- right - 1

        if top <= bottom
            visit bottom row from right to left; bottom <- bottom - 1
        if left <= right
            visit left column from bottom to top; left <- left + 1

遍历底边和左边之前的两个条件可以避免只剩一行或一列时发生重复访问。每个矩阵元素恰好输出一次，因此时间复杂度为 \(O(rows \cdot columns)\)。输出本身就包含这么多元素；如果不计输出存储，算法只使用 \(O(1)\) 辅助状态。

Python 实现：由边界控制的螺旋遍历 
def spiral_order(matrix: list[list[int]]) -> list[int]:
    """按顺时针螺旋顺序返回矩阵元素。"""
    if not matrix or not matrix[0]:
        return []

    top = 0
    bottom = len(matrix) - 1
    left = 0
    right = len(matrix[0]) - 1
    result: list[int] = []

    while top <= bottom and left <= right:
        # 从左向右消耗顶边。
        for column in range(left, right + 1):
            result.append(matrix[top][column])
        top += 1

        # 从上向下消耗右边。
        for row in range(top, bottom + 1):
            result.append(matrix[row][right])
        right -= 1

        # 这些检查可以安全处理只剩一行或一列的情况。
        if top <= bottom:
            for column in range(right, left - 1, -1):
                result.append(matrix[bottom][column])
            bottom -= 1

        if left <= right:
            for row in range(bottom, top - 1, -1):
                result.append(matrix[row][left])
            left += 1

    return result


grid = [[1, 2, 3], [4, 5, 6], [7, 8, 9]]
assert spiral_order(grid) == [1, 2, 3, 6, 9, 8, 7, 4, 5]

比较与选择

本章技术彼此相关，但不能相互替代。应根据问题提供的信息和反复执行的操作进行选择。

需求或线索 首选候选 被复用的状态 典型代价
按位置直接访问 数组 基地址与下标 \(O(1)\) 访问
有序文本处理 字符串序列 相邻符号与下标 通常 \(O(n)\) 扫描
精确成员关系或关联 哈希集合 / 映射 键到桶的映射 预期 \(O(1)\) 操作
大量静态区间总和 前缀和 累计总值 \(O(n)\) 构建，\(O(1)\) 查询
有序候选可以被排除 双指针 左右可行区域 通常 \(O(n)\)
性质属于连续区间 滑动窗口 上一个窗口的状态 通常 \(O(n)\)
最佳连续累计得分 Kadane 算法 在当前位置结束的最佳和 \(O(n)\)
按方向访问网格 边界模拟 不断缩小的未访问区域 \(O(rc)\)

一个实用的决策流程是：

  1. 判断顺序、连续性、成员关系或重复区间查询是否为核心；
  2. 写出最简单的正确基线，并找出其中的重复工作；
  3. 询问映射、前缀状态、指针边界或滚动状态能否总结这些工作；
  4. 明确说明每次更新安全所依赖的不变式；
  5. 检查空输入、重复值、全负数组、单行矩阵和 Unicode 文本等边界情况；
  6. 在明确假设下确认时间和辅助空间代价。

这些模式组合使用时最为强大。滑动窗口常携带频率哈希表；子数组计数方法会把前缀和与哈希结合；双指针往往依赖排序。真正的设计能力在于识别哪些状态可以复用此前工作，同时不牺牲正确性。
