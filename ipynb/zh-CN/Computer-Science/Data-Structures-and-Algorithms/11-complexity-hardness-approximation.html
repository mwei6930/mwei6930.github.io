计算复杂性、困难性与近似算法

算法分析通常从一个已经选定的问题出发：给定某种算法，它会消耗多少时间和内存？计算复杂性理论（computational complexity theory）追问的是更早一步的问题：在给定计算模型下，无论采用哪一种算法，解决这个问题本身究竟需要多少计算资源？

当直接搜索包含指数级候选解，而长期研究仍未找到多项式时间精确算法时，这种视角尤其重要。复杂性理论提供了一套严格语言，用来区分几个经常被混为一谈的陈述：

  • 某个具体实现很慢；
  • 目前还不知道该问题的多项式时间算法；
  • 已经通过某种明确的归约证明该问题是 NP-hard；
  • 放宽输出形式或质量保证后，可以得到实用算法。

本章以顶点覆盖（Vertex Cover）为贯穿示例。对于无向图 \(G=(V,E)\)，若集合 \(C\subseteq V\) 使每条边至少有一个端点属于 \(C\)，则 \(C\) 是一个顶点覆盖。优化版本要求找到最小顶点覆盖；判定版本询问是否存在大小不超过 \(k\) 的顶点覆盖。验证一个给定集合是否满足要求非常容易，但在一般图上寻找最小顶点覆盖是 NP-hard 的。

困难性结论并不意味着应当停止设计算法。它只是把工程问题从“我是不是漏掉了某个精确的多项式算法”，转变为“可以利用哪些假设、参数、结构、近似保证或计算资源”。精确指数算法、近似算法、随机算法、参数化算法和启发式方法，分别回答了这一问题的不同版本。

重要

NP-hard 并不等于“不可能求解”或“所有输入都很慢”。它是关于一族输入的最坏情况陈述。规模较小、结构特殊或参数较小的实例，仍可能被快速而精确地求解。

判定问题与优化问题

判定问题（decision problem）只返回一位信息：YES 或 NO。P、NP 等复杂性类在形式上都针对判定问题定义，因为二值接口使归约与验证能够被精确表述。搜索问题（search problem）要求返回一个具体证据，而优化问题（optimization problem）要求返回最佳目标值或最佳证据。

对于顶点覆盖，三种表述分别是：

  • 判定：图 \(G\) 中是否存在满足 \(|C|\le k\) 的顶点覆盖 \(C\)？
  • 搜索：如果存在，返回这样一个集合 \(C\)。
  • 优化：返回基数最小的覆盖，其大小记为 \(OPT(G)\)。

它们是不同的接口，但通常可以通过多项式次数的调用相互联系。顶点覆盖的判定谓词关于 \(k\) 单调：一旦存在大小为 \(k\) 的覆盖，也必然存在大小上界更大的覆盖。因此，可以对 \(0,1,\ldots,|V|\) 进行二分搜索，并借助判定预言机找到最优值。

若还要恢复具体解，则需要进行自归约（self-reduction）。得到最优大小 \(k\) 后，逐个尝试排除或强制选择某个顶点，并询问剩余问题是否仍有最优解。重复判定查询即可重建一个具体覆盖。这种关系需要针对具体问题证明，不能仅凭三种问题名称相近就直接假设。

Python 实现：精确的顶点覆盖判定与优化 
from itertools import combinations


def is_vertex_cover(
    edges: list[tuple[str, str]], candidate: set[str]
) -> bool:
    return all(u in candidate or v in candidate for u, v in edges)


def has_vertex_cover(
    vertices: list[str], edges: list[tuple[str, str]], limit: int
) -> bool:
    """判定版本：只返回是否存在足够小的覆盖。"""
    for size in range(min(limit, len(vertices)) + 1):
        for chosen in combinations(vertices, size):
            if is_vertex_cover(edges, set(chosen)):
                return True
    return False


def minimum_vertex_cover(
    vertices: list[str], edges: list[tuple[str, str]]
) -> set[str]:
    """优化版本：返回一个最优证据。"""
    for size in range(len(vertices) + 1):
        for chosen in combinations(vertices, size):
            candidate = set(chosen)
            if is_vertex_cover(edges, candidate):
                return candidate
    raise AssertionError("全部顶点始终构成一个覆盖")


vertices = ["a", "b", "c", "d"]
edges = [("a", "b"), ("b", "c"), ("c", "d"), ("d", "a")]
cover = minimum_vertex_cover(vertices, edges)
assert len(cover) == 2
assert has_vertex_cover(vertices, edges, 1) is False
assert has_vertex_cover(vertices, edges, 2) is True
print(cover)

穷举实现最多检查 \(2^{|V|}\) 个子集，并对每个子集检查 \(|E|\) 条边，因此最坏时间复杂度为 \(O(2^{|V|}|E|)\)，候选集合占用 \(O(|V|)\) 空间。这里的重点并不是“优化问题一定比判定问题更难”，而是在讨论复杂性之前，必须先明确要求算法返回什么。

练习：LeetCode 698 - Partition to K Equal Sum Subsets 可以自然表述为判定问题，也展示了即使输出只有 YES/NO，内部仍可能需要大量组合搜索。

可处理性与计算资源

若一个问题存在最坏资源消耗关于编码后输入长度为多项式的算法，通常称其是可处理的（tractable）。若输入占用 \(n\) 个比特或符号，多项式上界形如 \(O(n^c)\)，其中常数 \(c\) 与具体实例无关。

这个定义依赖编码方式。整数 \(W\) 的二进制表示只占 \(\Theta(\log W)\) 位。一个 \(O(nW)\) 的动态规划虽然关于数值 \(W\) 是多项式的，但关于表示 \(W\) 所需的比特数可能是指数级的，因此它是伪多项式（pseudopolynomial）算法，而不是标准比特模型下的多项式算法。

常见的资源度量包括：

  • 时间：通常以基本计算步骤数衡量；
  • 空间：算法运行时使用的最大额外内存；
  • 在专门模型中使用的随机位、预言机查询次数、通信量或并行深度；
  • 参数依赖：例如把结构参数 \(k\) 与总输入规模分开后得到的 \(f(k)n^c\)。

多项式时间是一项理论上的稳健性标准，并不保证实际速度。\(O(n^{100})\) 虽然属于多项式，却几乎没有实用价值；相反，当 \(n\le 40\) 时，精心设计的指数算法可能十分有效。复杂性类描述的是增长趋势和最坏情况边界，常数、输入分布、预处理和实例结构仍然会影响实际性能。

        for total from target down to x

    return reachable[target]

时间：O(n * target)。当 target 采用二进制编码时，这是伪多项式复杂度。
Python 实现：伪多项式 Subset Sum 
def subset_sum(values: list[int], target: int) -> bool:
    if target < 0 or any(value < 0 for value in values):
        raise ValueError("该实现只接受非负整数")

    reachable = [False] * (target + 1)
    reachable[0] = True

    for value in values:
        # 逆序更新，防止同一个输入值被重复使用。
        for total in range(target, value - 1, -1):
            reachable[total] = reachable[total] or reachable[total - value]

    return reachable[target]


assert subset_sum([3, 7, 11, 15], 18) is True
assert subset_sum([3, 7, 11, 15], 10) is True
assert subset_sum([6, 10], 7) is False
print(subset_sum([3, 7, 11, 15], 18))

状态表包含 target + 1 个状态，\(n\) 个数中的每一个都可能更新整张表，因此时间复杂度为 \(O(n\cdot target)\)，辅助空间为 \(O(target)\)。如果 target 的数值相对于其二进制编码长度呈指数增长，这些上界就不是关于输入比特数的多项式。

练习：LeetCode 416 - Partition Equal Subset Sum 是伪多项式 Subset Sum 动态规划的直接应用。

P、NP 与高效验证

在形式化定义中，一个判定问题被表示为一种语言（language），即所有正确答案为 YES 的编码实例所组成的集合。

P 包含能由确定性算法在多项式时间内求解的判定问题。NP 包含这样的判定问题：每个 YES 实例都存在一个多项式长度的证书（certificate），并且确定性验证器能在多项式时间内检查该证书。

等价地，当存在多项式时间验证器 \(V\) 和多项式 \(p\)，使得

\[ x\in L \iff \text{存在证书 }y, \ |y|\le p(|x|), \text{ 且 }V(x,y)=1, \]

语言 \(L\) 属于 NP。其中 \(x\) 是编码后的实例，\(y\) 是证据，\(|x|\) 与 \(|y|\) 是编码长度，\(V(x,y)=1\) 表示验证器接受。定义中的“存在”至关重要：NP 的定义并不要求 NO 实例也具有同样简短的证书。

对于顶点覆盖，证书就是候选集合 \(C\)。验证器检查 \(|C|\le k\)，再扫描每条边，确认至少一个端点属于 \(C\)。验证给定集合是多项式时间的，即使寻找这样的集合可能需要指数级搜索。

每个 P 中的问题也属于 NP，因为一个多项式时间求解器可以忽略证书，直接算出答案。因此

\[ P\subseteq NP. \]

\(P=NP\) 是否成立仍是开放问题。NP 的全称是非确定性多项式时间（nondeterministic polynomial time），而不是“非多项式”。目前没有无条件证明允许把“NP-complete”直接表述为“绝不存在多项式算法”。

Python 实现：多项式时间顶点覆盖验证器 
def verify_vertex_cover(
    vertices: set[str],
    edges: list[tuple[str, str]],
    limit: int,
    certificate: set[str],
) -> bool:
    # 证据只能使用已知顶点，并且大小不能超过给定上界。
    if not certificate <= vertices or len(certificate) > limit:
        return False

    # 每条边只需检查一次。
    return all(
        u in certificate or v in certificate
        for u, v in edges
    )


vertices = {"a", "b", "c", "d"}
edges = [("a", "b"), ("b", "c"), ("c", "d"), ("d", "a")]
assert verify_vertex_cover(vertices, edges, 2, {"a", "c"}) is True
assert verify_vertex_cover(vertices, edges, 1, {"a"}) is False
assert verify_vertex_cover(vertices, edges, 2, {"a", "x"}) is False
print(verify_vertex_cover(vertices, edges, 2, {"a", "c"}))

若使用哈希集合成员查询，包含证据合法性检查在内的验证过程需要期望 \(O(|V|+|E|)\) 时间，证书本身占用 \(O(|C|)\) 空间。这个快速验证器证明问题属于 NP，却不能证明它是 NP-hard。

多项式时间归约

从判定问题 \(A\) 到判定问题 \(B\) 的多项式时间多一归约（polynomial-time many-one reduction）写作

\[ A\le_p B, \]

它是一个可在多项式时间内计算的变换 \(f\)，满足

\[ x\in A \iff f(x)\in B. \]

变换处理的是任意问题实例，而不只是某个已经知道答案的样例。“当且仅当”同时保持 YES 与 NO 实例。若存在 \(B\) 的多项式时间求解器，那么先计算 \(f(x)\)、再求解 \(f(x)\)、最后返回相同答案，就能在多项式时间内求解 \(A\)。因此，在这种归约关系下，\(B\) 至少与 \(A\) 一样困难。

归约方向是最常见的错误来源。为了证明一个新的目标问题 \(B\) 很难，必须把已知困难的源问题 \(A\) 归约到 \(B\)。证明 \(B\le_p A\) 只表示 \(B\) 可以借助 \(A\) 的求解器，并没有把 \(A\) 的困难性传递给 \(B\)。

归约具有传递性：若 \(A\le_p B\) 且 \(B\le_p C\)，组合两个多项式时间变换即可得到 \(A\le_p C\)。因此，从最初的 NP-complete 问题出发，可以建立庞大的困难性归约网络。

顶点覆盖与独立集之间存在简单的图归约。集合 \(C\) 是顶点覆盖，当且仅当其补集 \(V\setminus C\) 是独立集。因此

\[ (G,k)\in VertexCover \iff (G,|V|-k)\in IndependentSet. \]

def vertex_cover_to_independent_set(
    vertices: set[str],
    edges: list[tuple[str, str]],
    cover_limit: int,
) -> tuple[set[str], list[tuple[str, str]], int]:
    return vertices.copy(), edges.copy(), len(vertices) - cover_limit


def is_independent_set(
    edges: list[tuple[str, str]], candidate: set[str]
) -> bool:
    return all(not (u in candidate and v in candidate) for u, v in edges)

NP-hard 与 NP-complete

若 NP 中的每个问题 \(L\) 都能在多项式时间内归约到问题 \(H\)，则 \(H\) 是 NP-hard 的：

\[ \forall L\in NP,\quad L\le_p H. \]

NP-hard 问题本身不一定属于 NP。它可能是优化问题而非判定问题，甚至可能不存在可在多项式时间内验证的证书。NP-complete 问题则同时属于 NP 且为 NP-hard：

\[ NPC = NP\cap NP\text{-hard}. \]

要证明判定问题 \(B\) 是 NP-complete，必须分别完成两项义务：

  1. 成员关系：给出多项式长度的证书与多项式时间验证器，证明 \(B\in NP\)。
  2. 困难性：选择一个已知 NP-complete 问题 \(A\)，证明 \(A\le_p B\)。

困难性归约把所有 NP 问题通过 \(A\) 传递到目标问题；成员关系则保证目标仍处于可高效验证的判定问题集合中。只完成第二项最多能证明 NP-hard，不能得出 NP-complete。

如果任意一个 NP-complete 问题存在多项式时间算法，那么所有 NP 问题都可在多项式时间内求解，于是 \(P=NP\)。反过来，在普遍采用但尚未证明的 \(P\ne NP\) 假设下，没有 NP-complete 问题属于 P。

PROVE-NP-COMPLETE(target B)
    成员关系：
        为 YES 实例定义多项式长度的证书
        给出多项式时间验证器

    困难性：
        选择已知 NP-complete 源问题 A
        在多项式时间内构造 f(x)
        证明 x 在 A 中为 YES 当且仅当 f(x) 在 B 中为 YES

Python 实现：SAT 验证与穷举搜索 
from itertools import product


def verify_cnf(
    clauses: list[list[tuple[str, bool]]],
    assignment: dict[str, bool],
) -> bool:
    """每个文字表示为 (变量, 是否为正文字)。"""
    return all(
        any(assignment[variable] == is_positive for variable, is_positive in clause)
        for clause in clauses
    )


def solve_cnf_bruteforce(
    clauses: list[list[tuple[str, bool]]]
) -> dict[str, bool] | None:
    variables = sorted({variable for clause in clauses for variable, _ in clause})

    for values in product((False, True), repeat=len(variables)):
        assignment = dict(zip(variables, values))
        if verify_cnf(clauses, assignment):
            return assignment
    return None


# (x OR not y) AND (y OR z) AND (not x OR z)
formula = [
    [("x", True), ("y", False)],
    [("y", True), ("z", True)],
    [("x", False), ("z", True)],
]
assignment = solve_cnf_bruteforce(formula)
assert assignment is not None
assert verify_cnf(formula, assignment)
print(assignment)

对于已经给定的赋值，验证只需扫描所有文字出现位置，若编码后公式长度为 \(L\)，时间复杂度为 \(O(L)\)。穷举求解对 \(n\) 个变量最多尝试 \(2^n\) 种赋值，耗时 \(O(2^nL)\)。这种差异说明了 NP 成员关系；而 SAT 是 NP-complete 的结论还需要额外的归约定理。

练习：LeetCode 691 - Stickers to Spell Word 是受限覆盖问题，它的一般化亲属属于 NP-hard；较短的目标字符串使精确状态压缩仍然可行。

经典 NP-complete 问题与归约链

NP-complete 问题构成的是一张网络，而不是彼此孤立的清单。掌握一组结构不同的经典问题，可以在证明新问题困难性时选择合适的源问题：

问题 判定问题 典型证书
SAT / 3SAT 是否存在满足公式的真值赋值？ 变量赋值
Clique 是否存在大小至少为 \(k\) 的完全子图？ 所选顶点
Independent Set 是否存在大小至少为 \(k\)、两两不相邻的集合？ 所选顶点
Vertex Cover 是否存在大小至多为 \(k\) 的覆盖？ 所选顶点
Hamiltonian Cycle 是否存在恰好访问每个顶点一次的环？ 有序环
Subset Sum 是否存在子集使元素之和恰好为 \(T\)？ 所选元素下标
Set Cover 是否能用至多 \(k\) 个集合覆盖全集？ 所选集合
3-Coloring 是否能用三种颜色为顶点合法着色？ 每个顶点的颜色

选择归约源时，应尽量让源问题的约束结构与目标问题相似。逻辑约束型目标通常从 3SAT 出发；选择型问题常从 Independent Set、Vertex Cover 或 Set Cover 出发；路径和访问型问题可能从 Hamiltonian Cycle 出发。

三个图问题之间存在特别简单的转换。设图 \(G\) 有 \(n\) 个顶点：

  • \(S\) 在 \(G\) 中是独立集，当且仅当 \(V\setminus S\) 是 \(G\) 中的顶点覆盖；
  • \(S\) 在 \(G\) 中是独立集，当且仅当 \(S\) 在补图 \(\overline{G}\) 中是团；
  • 因此 Independent Set 的参数 \(k\) 在 Vertex Cover 中变为 \(n-k\)，在 Clique 中仍为 \(k\)。

from itertools import combinations


def normalize(edge: tuple[str, str]) -> frozenset[str]:
    return frozenset(edge)


def independent_set_to_clique(
    vertices: set[str],
    edges: list[tuple[str, str]],
    target_size: int,
) -> tuple[set[str], list[tuple[str, str]], int]:
    original = {normalize(edge) for edge in edges}
    complement = [
        (u, v)
        for u, v in combinations(sorted(vertices), 2)
        if frozenset((u, v)) not in original
    ]
    return vertices.copy(), complement, target_size


def independent_set_to_vertex_cover(
    vertices: set[str],
    edges: list[tuple[str, str]],
    target_size: int,
) -> tuple[set[str], list[tuple[str, str]], int]:
    return vertices.copy(), edges.copy(), len(vertices) - target_size

构造归约证明

一个归约图“看起来等价”并不足以完成证明。完整归约必须明确履行四项义务：

  1. 源问题：指出一个在相同归约类型下已知困难的问题。
  2. 构造：把每个源实例映射成定义精确的目标实例。
  3. 正确性：证明 YES 实例等价关系的两个方向。
  4. 复杂度：证明构造在多项式时间内运行，并只产生多项式大小的输出。

考虑从 Independent Set 到 Vertex Cover 的归约。输入 \((G=(V,E),k)\)，输出 \((G,|V|-k)\)。

正向。假设 \(S\) 是满足 \(|S|\ge k\) 的独立集。没有任何边的两个端点都在 \(S\) 中，所以每条边至少有一个端点属于 \(V\setminus S\)。因此 \(V\setminus S\) 是大小至多为 \(|V|-k\) 的顶点覆盖。

反向。假设 \(C\) 是满足 \(|C|\le |V|-k\) 的顶点覆盖。如果 \(V\setminus C\) 中两个顶点相邻，那么这条边的两个端点都不属于 \(C\)，与 \(C\) 覆盖每条边矛盾。因此 \(V\setminus C\) 是独立集，且大小至少为 \(k\)。

图可以直接复用或复制，新参数可在线性时间内计算，整个转换耗时 \(O(|V|+|E|)\)。由于 Vertex Cover 还具有前文给出的多项式验证器，这个归约可以参与 NP-completeness 证明。

from itertools import combinations


def exists_independent_set(
    vertices: list[int], edges: list[tuple[int, int]], size: int
) -> bool:
    edge_set = {frozenset(edge) for edge in edges}
    return any(
        all(frozenset(pair) not in edge_set for pair in combinations(chosen, 2))
        for chosen in combinations(vertices, size)
    )


def exists_vertex_cover(
    vertices: list[int], edges: list[tuple[int, int]], limit: int
) -> bool:
    return any(
        all(u in chosen or v in chosen for u, v in edges)
        for size in range(limit + 1)
        for chosen in map(set, combinations(vertices, size))
    )


def reduction_equivalence_holds(
    vertices: list[int], edges: list[tuple[int, int]], k: int
) -> bool:
    return exists_independent_set(vertices, edges, k) == exists_vertex_cover(
        vertices, edges, len(vertices) - k
    )

近似算法

近似算法（approximation algorithm）在多项式时间内返回一个可行解，并保证对每个合法输入，其目标值都与最优值足够接近。这个可证明的最坏情况质量界，把近似算法与启发式方法区分开来：启发式算法可能在实验中表现很好，却没有必须满足的通用质量保证。

对于最小顶点覆盖，一个简单的 2-近似算法先构造任意极大匹配（maximal matching） \(M\)：其中边两两不共享端点，并且再也无法加入任何一条边。然后把 \(M\) 中每条边的两个端点都加入覆盖 \(C\)。

所得集合一定可行。若仍存在未覆盖边，则它的两个端点都没有被匹配，于是可以把该边加入 \(M\)，这与 \(M\) 已经极大矛盾。

近似比证明利用一个下界。匹配中的边不共享端点，因此任何顶点覆盖都必须为每条匹配边选择至少一个不同端点，于是

\[ OPT\ge |M|. \]

算法恰好为每条匹配边选择两个端点：

\[ |C|=2|M|\le 2OPT. \]

极大（maximal）与最大（maximum）并不相同。极大匹配只是无法再局部扩展，不一定包含尽可能多的边；但仅凭极大性，已经足以证明覆盖可行和 2 倍近似界。

    for each edge (u,v)
        if u and v are both unmatched
            add u and v to matched_vertices

    return cover

def approximate_vertex_cover(
    edges: list[tuple[str, str]],
) -> set[str]:
    matched_vertices: set[str] = set()
    cover: set[str] = set()

    for u, v in edges:
        if u not in matched_vertices and v not in matched_vertices:
            # 向极大匹配加入一条边，并选择它的两个端点。
            matched_vertices.update((u, v))
            cover.update((u, v))

    return cover


def is_cover(edges: list[tuple[str, str]], chosen: set[str]) -> bool:
    return all(u in chosen or v in chosen for u, v in edges)

近似比与性能保证

令 \(ALG(I)\) 表示算法在实例 \(I\) 上返回的目标值，\(OPT(I)\) 表示最优目标值。

对于最小化问题，\(\rho\)-近似算法满足

\[ OPT(I)\le ALG(I)\le \rho\,OPT(I), \qquad \rho\ge 1. \]

对于最大化问题，不等式方向相反：

\[ \frac{OPT(I)}{\rho}\le ALG(I)\le OPT(I). \]

当分母为正时，也可以写为：最小化问题要求 \(ALG/OPT\le\rho\)，最大化问题要求 \(OPT/ALG\le\rho\)。该比例是对所有合法实例成立的最坏情况乘法保证，而不是在某个基准数据集上观测到的平均表现。

某些问题采用加法保证（additive guarantee），例如 \(|ALG-OPT|\le c\)，因为当 \(OPT=0\) 时乘法比值没有意义。随机近似算法还必须明确说明该界是在期望意义下成立，还是以高概率成立。

近似方案允许用户指定精度参数 \(\varepsilon>0\)：

  • PTAS 对每个固定的 \(\varepsilon\)，在多项式时间内为最小化问题返回 \((1+\varepsilon)\)-近似解；
  • FPTAS 的运行时间同时关于输入长度和 \(1/\varepsilon\) 为多项式。

二者的区别在于对 \(1/\varepsilon\) 的依赖。例如 \(n^{1/\varepsilon}\) 对固定 \(\varepsilon\) 是多项式，因此可构成 PTAS，但它不是 FPTAS。

from itertools import combinations
from random import Random


def exact_vertex_cover_size(
    vertices: list[int], edges: list[tuple[int, int]]
) -> int:
    for size in range(len(vertices) + 1):
        for chosen_tuple in combinations(vertices, size):
            chosen = set(chosen_tuple)
            if all(u in chosen or v in chosen for u, v in edges):
                return size
    raise AssertionError


def approximate_cover_size(edges: list[tuple[int, int]]) -> int:
    matched: set[int] = set()
    for u, v in edges:
        if u not in matched and v not in matched:
            matched.update((u, v))
    return len(matched)

随机算法与不确定性

随机算法（randomized algorithm）把随机位作为计算的一部分。对于固定输入，不同随机选择会形成关于运行时间、输出或两者的概率分布。这里的概率来自算法内部随机性，并不要求输入本身随机生成。

Las Vegas 与 Monte Carlo 算法

Las Vegas 算法总会返回正确答案，但运行时间是随机变量。随机化快速排序是标准例子：无论枢轴选择序列如何，结果始终正确；随机选择枢轴使任意固定输入上的期望比较次数为 \(O(n\log n)\)，尽管最坏情况仍为 \(O(n^2)\)。

Monte Carlo 算法具有确定的运行时间上界，但可能以受控概率返回错误答案。Freivalds 算法每轮用 \(O(n^2)\) 时间检查 \(AB=C\)，避免直接执行 \(O(n^3)\) 的矩阵乘法。当 \(AB\ne C\) 时，一个随机二进制向量以至少 \(1/2\) 的概率检测到错误；若乘积正确，则算法始终接受。

独立重复可以放大置信度。如果单轮失败概率至多为 \(p\)，连续进行 \(r\) 轮并且全部通过才接受，则总失败概率至多为

\[ p^r. \]

对于 Freivalds 算法，\(p\le 1/2\)，所以 \(r\) 轮把错误接受概率降至不超过 \(2^{-r}\)。

期望运行时间分析

若 \(\Omega\) 是所有随机执行结果的集合，\(T(\omega)\) 是结果 \(\omega\) 对应的运行时间，则

\[ \mathbb{E}[T] = \sum_{\omega\in\Omega}\Pr[\omega]T(\omega). \]

期望时间表示：对一个固定输入，在算法自身的随机选择上取平均。期望的线性性经常简化分析，因为即使指示变量 \(X_i\) 相互依赖，仍有 \(\mathbb{E}[\sum_i X_i]=\sum_i\mathbb{E}[X_i]\)。

from random import Random


def randomized_quicksort(values: list[int], rng: Random) -> list[int]:
    if len(values) <= 1:
        return values.copy()

    pivot = rng.choice(values)
    lower = [value for value in values if value < pivot]
    equal = [value for value in values if value == pivot]
    upper = [value for value in values if value > pivot]
    return (
        randomized_quicksort(lower, rng)
        + equal
        + randomized_quicksort(upper, rng)
    )


def matrix_vector(matrix: list[list[int]], vector: list[int]) -> list[int]:
    return [
        sum(value * vector[column] for column, value in enumerate(row))
        for row in matrix
    ]


def freivalds(
    a: list[list[int]],
    b: list[list[int]],
    c: list[list[int]],
    rounds: int,
    rng: Random,
) -> bool:
    size = len(a)
    for _ in range(rounds):
        vector = [rng.randrange(2) for _ in range(size)]
        b_vector = matrix_vector(b, vector)
        if matrix_vector(a, b_vector) != matrix_vector(c, vector):
            return False
    return True

精确、启发式与参数化方法

确认困难性之后，仍有多种算法契约可供选择。

精确算法（exact algorithm）始终返回最优解，但可能需要指数时间。分支限界、子集动态规划、SAT 求解器和整数规划在实践中可能非常有效，因为剪枝和现代求解器工程能在结构化实例上避免探索大部分理论候选状态。

启发式算法（heuristic）追求快速获得较好解，但不提供通用近似保证。局部搜索、贪心修复、元启发式和领域专用构造规则都属于这一类。评估启发式方法时，应把结果与可证明下界、小规模实例的精确解以及有代表性的工作负载比较。

参数化复杂性（parameterized complexity）把参数 \(k\) 与总输入规模 \(n\) 分开。若一个问题的运行时间可以写成

\[ f(k)n^c, \]

其中常数 \(c\) 与 \(k\) 无关，则称其为固定参数可处理（fixed-parameter tractable, FPT）。这与 \(n^{f(k)}\) 不同：后者对固定 \(k\) 也是多项式，但属于更宽泛的 XP 形式，当参数稍大时就可能迅速失去可扩展性。

以解大小 \(k\) 为参数的 Vertex Cover 是 FPT 的。任取一条尚未覆盖的边 \((u,v)\)，任何顶点覆盖都必须包含 \(u\) 或 \(v\)。因此，可以分别对选择 \(u\) 和选择 \(v\) 两种必要情况分支，并把剩余预算减一。搜索树深度至多为 \(k\)，分支因子为 2。

VERTEX-COVER-FPT(edges E, budget k)
    if E is empty: return empty cover
    if k = 0: return failure
    choose any edge (u,v)

    result <- 选择 u、删除其关联边后递归
    if result succeeds: return result union {u}

    result <- 选择 v、删除其关联边后递归
    if result succeeds: return result union {v}
    return failure
Python 实现：参数化 Vertex Cover 分支算法 
def vertex_cover_fpt(
    edges: list[tuple[str, str]], budget: int
) -> set[str] | None:
    normalized = frozenset(frozenset(edge) for edge in edges)

    def search(
        remaining: frozenset[frozenset[str]], k: int
    ) -> set[str] | None:
        if not remaining:
            return set()
        if k == 0:
            return None

        u, v = tuple(next(iter(remaining)))
        for chosen in (u, v):
            # 选择 chosen 会覆盖并删除所有与它关联的边。
            reduced = frozenset(edge for edge in remaining if chosen not in edge)
            suffix = search(reduced, k - 1)
            if suffix is not None:
                return suffix | {chosen}
        return None

    return search(normalized, budget)


edges = [("a", "b"), ("b", "c"), ("c", "d"), ("d", "a")]
assert vertex_cover_fpt(edges, 1) is None
cover = vertex_cover_fpt(edges, 2)
assert cover is not None and len(cover) <= 2
assert all(u in cover or v in cover for u, v in edges)
print(cover)

搜索树最多有 \(2^k\) 个叶节点。若每个节点以 \(O(|E|)\) 时间筛选边，这个直接实现的时间复杂度为 \(O(2^k|E|)\)；沿一条递归路径复制的状态占用 \(O(k|E|)\) 空间。更仔细的数据表示和核化（kernelization）可以改善常数与状态规模，同时保持固定参数可处理性。

面对困难性时如何选择实用方法

困难性结果标出了边界，但实现仍需要明确的算法契约。首先应形式化真正需要解决的问题，而不是只看它的非正式名称：

  1. 输出应是判定结果、证据、计数还是最优值？
  2. 答案必须精确，还是可以接受有证书的误差范围？
  3. 实际的 \(n\)、数值权重和结构参数规模是多少？
  4. 实例是否属于二分图、区间图、平面图、有界树宽或小全集等更容易的特殊类别？
  5. 能否在不改变答案的前提下通过预处理缩小实例？

随后，根据实际需求选择具有相应保证的方法：

情况 首选方法 应报告的信息
实例较小且必须精确 穷举、子集 DP、分支限界 最坏情况限制与可解规模
参数 \(k\) 较小 FPT 分支或核化 \(f(k)n^c\) 的依赖关系与参数定义
实例很大且需要质量保证 近似算法或松弛方法 已证明的近似比或最优性间隙
实例很大且需要快速可行解 启发式或局部搜索 基准质量与结果方差

混合型的随时算法（anytime algorithm）往往最实用：对于最小化问题，持续保存目前最佳可行解作为上界，同时使用松弛或匹配维护下界；当时间耗尽时，返回当前解及可量化的最优性间隙。这比只给出一个缺乏上下文的启发式数值更有信息量。

Python 实现：一个小型混合顶点覆盖策略 
from itertools import combinations


def hybrid_vertex_cover(
    vertices: list[str],
    edges: list[tuple[str, str]],
    exact_vertex_limit: int = 20,
) -> tuple[str, set[str], int]:
    """返回所用方法、覆盖集合和可证明的下界。"""
    if len(vertices) <= exact_vertex_limit:
        for size in range(len(vertices) + 1):
            for chosen_tuple in combinations(vertices, size):
                chosen = set(chosen_tuple)
                if all(u in chosen or v in chosen for u, v in edges):
                    return "exact enumeration", chosen, size

    # 对较大图，极大匹配同时给出一个下界和一个覆盖。
    matched: set[str] = set()
    matching_size = 0
    for u, v in edges:
        if u not in matched and v not in matched:
            matched.update((u, v))
            matching_size += 1

    return "2-approximation", matched, matching_size


vertices = ["a", "b", "c", "d", "e"]
edges = [("a", "b"), ("b", "c"), ("c", "d"), ("d", "e"), ("e", "a")]
method, cover, lower_bound = hybrid_vertex_cover(vertices, edges)
assert method == "exact enumeration"
assert len(cover) == lower_bound == 3
assert all(u in cover or v in cover for u, v in edges)

method, cover, lower_bound = hybrid_vertex_cover(
    vertices, edges, exact_vertex_limit=3
)
assert method == "2-approximation"
assert all(u in cover or v in cover for u, v in edges)
assert lower_bound <= 3 <= len(cover)
print(method, cover, lower_bound)

精确分支具有指数复杂度，因此只在用户配置的小规模阈值内运行。大规模分支在哈希集合期望常数时间操作下耗时 \(O(|E|)\)，同时返回由匹配得到的下界，以及大小不超过该下界两倍的覆盖。生产环境中的混合求解器还应强制设置实际时间与内存预算。
