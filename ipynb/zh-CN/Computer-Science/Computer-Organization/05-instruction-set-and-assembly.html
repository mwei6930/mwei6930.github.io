指令集体系结构与汇编

前几章建立了计算所需的物理概念：数值、组合函数、存储状态与时序。软件通常不会直接控制这些门和触发器，而是使用指令集体系结构（ISA）。ISA 是一份稳定契约，规定机器提供哪些操作，以及这些操作如何改变程序员可见状态。

本章以 32 位 RISC-V 基础整数 ISA RV32I 为贯穿示例。它足够小，可以手工编码和模拟，同时又足以作为编译器目标。重点不是背诵每个操作码，而是把每条指令读成精确的状态变换，理解汇编如何用符号表达这种变换，并区分 ISA 规则、ABI 约定与微体系结构选择。

什么是指令集体系结构

ISA 定义处理器向软件承诺的行为，通常包括：

  • 程序员可见寄存器及其位宽；
  • 指令编码与操作语义；
  • 内存寻址方式和可传输的数据宽度；
  • 控制流、异常与特权行为；
  • 通信所需的原子性与顺序规则；
  • 可选扩展及其组合规则。

如果两个处理器正确实现相同 ISA 与执行环境，同一机器码程序应观察到相同体系结构结果，即使其中一个是小型多周期核，另一个是深流水、乱序执行处理器。时钟频率、缓存大小、内部寄存器、推测策略和执行单元数量属于组成（organization），而不是 ISA。

层次 定义内容 RISC-V 示例
ISA 已编码操作与体系结构状态转移 add x5, x6, x7 对两个寄存器求和
汇编语言 汇编器接受的可读记法 助记符 add、标签、指令
ABI 让独立编译代码协作的二进制约定 a0-a7 传参、sp 对齐、保存寄存器
微体系结构 实现 ISA 的具体硬件组织 单周期、流水线或乱序核心

汇编并不等于 ISA。一条机器指令可以有多个文本别名，一个伪指令也可能展开成多条机器指令。同样，ISA 把整数寄存器称为 x0-x31；ra、sp 和 a0 等名称由软件调用约定分配。

一条指令可以表示成体系结构转移

\[ A_{k+1}=I(A_k,M_k), \]

其中 \(A_k\) 是指令 \(k\) 执行前的可见体系结构状态，\(M_k\) 是相关内存状态，\(I\) 是译码后的指令语义，\(A_{k+1}\) 是提交后的可见状态。推测执行处理器内部可能执行许多操作并丢弃一部分，但退休指令时必须表现得仿佛遵循了这份契约。

因此，ISA 同时提供兼容性与抽象：软件获得稳定目标，硬件设计者则可在边界之下自由改进实现。

程序员可见机器状态

程序员可见状态是指令按照 ISA 可以读取或修改的信息。RV32I 向非特权代码公开 32 个整数寄存器和程序计数器，并允许指令通过加载和存储访问按字节寻址的内存空间。更完整的 RISC-V 系统还存在特权控制与状态寄存器，但不属于本章讨论的基础 RV32I 状态。

寄存器

RV32I 中 XLEN=32，每个整数寄存器保存 32 位。x0 很特殊：读取永远得到零，写入一律被丢弃。x1-x31 是普通比特容器。具体指令决定一个模式被解释为有符号补码、无符号值、地址还是布尔字段。

常见三寄存器算术形式是

operation rd, rs1, rs2

rs1 与 rs2 是源寄存器，rd 是目的寄存器。例如

add x5, x6, x7

表示

\[ x[5]\leftarrow(x[6]+x[7])\bmod 2^{32}. \]

方括号表示“寄存器内容”。模 \(2^{32}\) 保留低 32 位并丢弃 XLEN 之外的进位。与某些 ISA 不同，基础 RISC-V 整数运算不会更新条件码寄存器，比较和分支会显式命名操作数。

不可变零寄存器让普通指令兼任常用操作：addi rd, x0, imm 生成小常量，add rd, rs, x0 复制寄存器，把 rd 写成 x0 则无需新编码即可丢弃结果。

Python 模型：RV32 寄存器状态与硬连线零寄存器 
class RV32Registers:
    def __init__(self) -> None:
        self._x = [0] * 32
        self.mask = (1 << 32) - 1

    def read(self, index: int) -> int:
        if not 0 <= index < 32:
            raise IndexError("寄存器索引必须位于 x0-x31")
        return 0 if index == 0 else self._x[index]

    def write(self, index: int, value: int) -> None:
        if not 0 <= index < 32:
            raise IndexError("寄存器索引必须位于 x0-x31")
        if index != 0:
            self._x[index] = value & self.mask


registers = RV32Registers()
registers.write(6, 0xFFFF_FFFF)
registers.write(7, 2)
registers.write(5, registers.read(6) + registers.read(7))
assert registers.read(5) == 1       # 算术按模 2^32 回绕。

registers.write(0, 12345)
assert registers.read(0) == 0       # x0 永远不变。

程序计数器

程序计数器（pc）保存当前指令地址，决定从哪里取指，但普通 RV32I 指令不能像访问 x0-x31 那样直接命名 pc。

对正常顺序执行的 32 位指令，

\[ pc_{next}=pc+4. \]

4 是指令的字节长度，不是比特长度。可选压缩扩展引入 16 位指令，因此支持该扩展的核心可能为压缩指令加 2，为普通指令加 4。

控制流指令会替换顺序前进：

  • 条件分支在 pc+4 与 PC 相对目标之间选择；
  • JAL 跳到 PC 相对目标，并可保存返回地址；
  • JALR 用寄存器加立即数形成目标；
  • 异常或中断按特权体系结构规则转移控制。

“程序计数器”一词会隐藏实现细节。流水线可为不同阶段的指令保存多个内部 PC，乱序核心也可预测未来 PC；但提交时体系结构效果必须符合 ISA。

PC 相对寻址让代码可以在内存中移动，而无需改写每个内部绝对地址。汇编标签最终会变成偏移；若最终地址尚未知，还会生成重定位记录。

内存与地址空间

RV32I 拥有 32 位按字节寻址的地址空间，一个地址标识一个字节，因此最多有 \(2^{32}\) 个字节地址。这不保证机器一定安装 4 GiB 物理 RAM：某些区域可能未映射、受保护、保留或连接到内存映射设备。

多字节值占用连续地址。在小端执行环境中，一个字的最低有效字节放在最低地址。若 0x12345678 从地址 A 开始存放：

地址 存储字节
A 0x78
A+1 0x56
A+2 0x34
A+3 0x12

字节序改变内存中的字节顺序，而不是寄存器内的比特编号。从地址 A 加载一个字节，仍会得到实际存于 A 的字节。

当地址是访问大小的倍数时，访问为自然对齐，例如四字节字在能被 4 整除的地址上自然对齐。未对齐加载和存储如何处理由执行环境决定：可以直接完成、产生可见陷阱，或由不可见机制支持。可移植且高效的程序通常保持标量对象自然对齐。

地址空间还是接口边界。普通 RAM 地址存放数据，而内存映射设备地址可能触发 I/O 行为。两者使用同样的加载/存储语法，但缓存、顺序、权限和副作用取决于平台与特权体系结构。

RISC-V 指令格式与编码

指令字不只是数值编号，它的比特字段告诉译码器执行什么操作以及操作数在哪里。基础 RV32I 使用固定 32 位指令和 R、I、S、U 四种核心布局；分支和跳转使用由相同字段位置构成的 B、J 立即数变体。

图片来源：RISC-V 非特权 ISA 规范，RV32I 基础指令格式，RISC-V International，CC BY 4.0。

字段 位宽 用途
opcode 7 位 选择指令大类与格式
rd 5 位 选择 32 个目的寄存器之一
funct3 3 位 区分同一 opcode 类内的操作
rs1 5 位 第一源寄存器
rs2 5 位 第二源寄存器
funct7 7 位 为 R 型提供额外操作选择
immediate 依格式而定 嵌入常量、地址偏移或控制流位移

只要字段存在，RISC-V 都让 rd、rs1、rs2 保持在相同位置。这种规则性简化并加速寄存器译码，代价是 S、B 与 J 型立即数必须被拆分或重新排列。

  • R 型：寄存器-寄存器算术，例如 add、sub；
  • I 型：寄存器-立即数算术、加载和 JALR；
  • S 型：存储，需要两个源但没有目的寄存器；
  • B 型：带有符号 PC 相对偏移的条件分支；
  • U 型：LUI 与 AUIPC，提供高位立即数；
  • J 型：JAL，具有更宽的有符号 PC 相对偏移。

大多数立即数会做符号扩展。对 \(n\) 位编码值 \(u\)，

\[ sext_n(u)= \begin{cases} u,&u<2^{n-1},\\ u-2^n,&u\ge2^{n-1}. \end{cases} \]

\(2^{n-1}\) 是符号位权重。小于它的值非负，大于等于它的模式符号位为 1，减去 \(2^n\) 后得到负补码值。RISC-V 把常规立即数的符号来源放在指令第 31 位，使符号扩展可与译码并行开始。

add x5, x6, x7 的字段为：

funct7  rs2    rs1    funct3  rd     opcode
0000000 00111  00110  000     00101  0110011

拼接后得到 0x007302B3。这个十六进制值不是另行分配的编号，而只是所有字段打包后的结果。

Python 编码器：构造并检查 RV32I 的 R 型与 I 型指令字 
def check_register(index: int) -> None:
    if not 0 <= index < 32:
        raise ValueError("寄存器索引必须能放入 5 位")


def encode_r(funct7: int, rs2: int, rs1: int,
             funct3: int, rd: int, opcode: int) -> int:
    for register in (rd, rs1, rs2):
        check_register(register)
    if not 0 <= funct7 < 128 or not 0 <= funct3 < 8 or not 0 <= opcode < 128:
        raise ValueError("function 或 opcode 字段越界")
    return (
        (funct7 << 25)
        | (rs2 << 20)
        | (rs1 << 15)
        | (funct3 << 12)
        | (rd << 7)
        | opcode
    )


def encode_i(immediate: int, rs1: int, funct3: int,
             rd: int, opcode: int) -> int:
    check_register(rd)
    check_register(rs1)
    if not -2048 <= immediate <= 2047:
        raise ValueError("I 型立即数必须能放入有符号 12 位")
    imm12 = immediate & 0xFFF
    return (imm12 << 20) | (rs1 << 15) | (funct3 << 12) | (rd << 7) | opcode


add_x5_x6_x7 = encode_r(0b0000000, 7, 6, 0b000, 5, 0b0110011)
addi_x5_x6_minus12 = encode_i(-12, 6, 0b000, 5, 0b0010011)

assert add_x5_x6_x7 == 0x007302B3
assert addi_x5_x6_minus12 == 0xFF430293

# 可从固定位置恢复公共字段。
assert (add_x5_x6_x7 >> 7) & 0x1F == 5   # rd
assert (add_x5_x6_x7 >> 15) & 0x1F == 6  # rs1
assert (add_x5_x6_x7 >> 20) & 0x1F == 7  # rs2

算术与逻辑指令

RV32I 算术指令变换寄存器值并写入一个寄存器结果。寄存器-寄存器操作使用 R 型编码，常量操作数版本使用 I 型编码，两者通常都显式命名目的寄存器。

类别 示例 体系结构效果
加减 add、sub、addi 算术结果的低 XLEN 位
比较 slt、sltu、slti、sltiu 条件为真写 1，否则写 0
布尔逻辑 and、or、xor 及立即数形式 按位运算
左移 sll、slli 左移并在低位补零
逻辑右移 srl、srli 右移并在高位补零
算术右移 sra、srai 右移并复制符号位

寄存器算术满足

\[ x[rd]\leftarrow f(x[rs1],x[rs2])\bmod2^{XLEN}. \]

\(f\) 是选定 ALU 操作。RV32I 的 XLEN 为 32，RV64I 为 64。加法、减法与左移可能有高位离开寄存器，因此模运算不可忽略。

有符号与无符号比较使用相同存储模式，却采用不同解释。若 x5=0xFFFFFFFF，有符号比较把它解释为 \(-1\)，无符号比较则是 \(2^{32}-1\)；因此 slt 与 sltu 可以在不改变操作数的情况下得到不同答案。

移位指令只使用寄存器移位量的低 \(\log_2(XLEN)\) 位。RV32I 使用五位，因为 \(\log_2(32)=5\)。逻辑右移与算术右移的唯一区别是高位补入内容，后者保留补码符号模式。

基础 RV32I 不含整数乘除，它们属于标准 M 扩展。没有 M 的实现可以调用软件例程，支持它的处理器则在模块化 ISA 框架下公开额外指令。

RISC-V 基础整数加法不会触发专门的有符号溢出异常，而是写入回绕结果。需要检测溢出的软件要显式比较。这使有符号与无符号模式的算术语义保持一致。

Python 模型：执行代表性的 RV32I ALU 操作 
MASK32 = (1 << 32) - 1


def signed32(value: int) -> int:
    value &= MASK32
    return value - (1 << 32) if value & (1 << 31) else value


def rv32_alu(operation: str, left: int, right: int) -> int:
    left &= MASK32
    right &= MASK32
    shift = right & 0x1F  # RV32 只使用低 5 位移位量。

    if operation == "add":
        result = left + right
    elif operation == "sub":
        result = left - right
    elif operation == "and":
        result = left & right
    elif operation == "or":
        result = left | right
    elif operation == "xor":
        result = left ^ right
    elif operation == "sll":
        result = left << shift
    elif operation == "srl":
        result = left >> shift
    elif operation == "sra":
        result = signed32(left) >> shift
    elif operation == "slt":
        result = int(signed32(left) < signed32(right))
    elif operation == "sltu":
        result = int(left < right)
    else:
        raise ValueError(f"不支持的操作：{operation}")

    return result & MASK32


assert rv32_alu("add", 0xFFFF_FFFF, 2) == 1
assert rv32_alu("slt", 0xFFFF_FFFF, 1) == 1    # 有符号 -1 < 1
assert rv32_alu("sltu", 0xFFFF_FFFF, 1) == 0  # 无符号最大值 > 1
assert rv32_alu("sra", 0x8000_0000, 4) == 0xF800_0000
assert rv32_alu("srl", 0x8000_0000, 4) == 0x0800_0000

加载、存储与寻址

RISC-V 是加载-存储体系结构。算术与逻辑指令只操作寄存器，只有加载和存储在寄存器与内存之间传输值。把访存分离出来，为数据通路建立规则边界，也让地址生成变得明确。

加载和存储都使用基址加偏移寻址：

\[ EA=(x[rs1]+sext_{12}(imm))\bmod2^{XLEN}. \]

  • \(EA\) 是有效字节地址；
  • \(x[rs1]\) 是源寄存器保存的基址；
  • \(imm\) 是指令中的有符号 12 位偏移；
  • \(sext_{12}\) 把偏移扩展到 XLEN；
  • 模 \(2^{XLEN}\) 使地址算术保持在体系结构位宽内。

汇编把这种模式写作 offset(base)：

lw t0, 12(sp)    # t0 <- 地址 sp + 12 处的 32 位字
sw t1, 8(sp)     # 地址 sp + 8 处的内存字 <- t1 的低 32 位

加载有目的寄存器，因为数据进入寄存器文件；存储没有 rd，第二源寄存器负责提供数据。这就是存储立即数会占据 R 型中部分 rd 位位置的原因。

指令 字节数 加载扩展或存储数据
lb 1 字节符号扩展到 XLEN
lbu 1 字节零扩展
lh 2 半字符号扩展
lhu 2 半字零扩展
lw 4 加载一个 32 位 RV32 字
sb 1 存储寄存器低 8 位
sh 2 存储低 16 位
sw 4 存储低 32 位

加载较小有符号整数时，符号扩展很关键。字节 0xFF 经 lb 得到 0xFFFFFFFF，经 lbu 则得到 0x000000FF。内存字节完全相同，只有寄存器解释不同。

数组使用基址加缩放索引。RV32I 访存指令没有通用缩放字段，所以软件显式计算字节位移。四字节整数数组的索引 \(i\) 对应 base + 4*i，常用 slli index, index, 2 再加基址。

Python 内存模型：小端加载、存储与符号扩展 
class LittleEndianMemory:
    def __init__(self, byte_count: int) -> None:
        self.data = bytearray(byte_count)

    def _check(self, address: int, width: int) -> None:
        if address < 0 or address + width > len(self.data):
            raise IndexError("内存访问越界")

    def store(self, address: int, value: int, width: int) -> None:
        self._check(address, width)
        for byte_index in range(width):
            self.data[address + byte_index] = (value >> (8 * byte_index)) & 0xFF

    def load(self, address: int, width: int, *, signed: bool = False) -> int:
        self._check(address, width)
        value = sum(
            self.data[address + byte_index] << (8 * byte_index)
            for byte_index in range(width)
        )

        # 把选定访问宽度符号扩展到 32 位寄存器。
        if signed and value & (1 << (8 * width - 1)):
            value -= 1 << (8 * width)
        return value & 0xFFFF_FFFF


memory = LittleEndianMemory(64)
memory.store(16, 0x12345678, width=4)
assert list(memory.data[16:20]) == [0x78, 0x56, 0x34, 0x12]
assert memory.load(16, 4) == 0x12345678

memory.store(24, 0xFF, width=1)
assert memory.load(24, 1, signed=True) == 0xFFFF_FFFF  # lb
assert memory.load(24, 1, signed=False) == 0x0000_00FF # lbu

分支、跳转与控制流

控制流指令决定哪个指令地址成为下一个 pc。条件分支实现判断和循环，跳转则实现无条件转移、过程调用与返回。

\[ pc_{next}= \begin{cases} pc+sext(offset),&\text{条件为真},\\ pc+4,&\text{条件为假}. \end{cases} \]

分支直接比较两个寄存器。beq、bne 检查相等关系；blt、bge 使用有符号顺序；bltu、bgeu 使用无符号顺序。它不依赖先前算术指令留下的隐藏标志寄存器。

分支偏移采用 PC 相对方式，并按两字节倍数编码，所以目标最低位隐含为零。即使基础 RV32I 指令长四字节，这一选择仍支持与 16 位压缩指令共存。

JAL 同时完成两个体系结构动作：

\[ x[rd]\leftarrow pc+4, \]

\[ pc_{next}\leftarrow pc+sext(jump\ offset). \]

保存 pc+4 会生成返回链接。惯用 jal ra, function 把它写入 x1（ra），jal x0, label 则丢弃链接并作为普通跳转。

JALR 使用寄存器相对目标：

\[ t=(x[rs1]+sext_{12}(imm)), \]

\[ pc_{next}=t\mathbin{\&}\sim1. \]

清除目标第 0 位可保证偶数指令地址，并让某些软件约定把指针低位用于辅助信息。jalr x0, 0(ra) 跳回保存链接并丢弃新链接，从而实现返回。

分支带来的硬件挑战将在第 07 章讨论：条件与目标尚未确定时，流水线可能已经取了多条后续指令。预测会改变性能，却不改变上述体系结构语义。

Python 模型：计算分支、JAL 与 JALR 的效果 
MASK32 = (1 << 32) - 1


def branch(pc: int, left: int, right: int, offset: int, condition: str) -> int:
    comparisons = {
        "eq": left == right,
        "ne": left != right,
        "ltu": (left & MASK32) < (right & MASK32),
    }
    if condition not in comparisons:
        raise ValueError("不支持的分支条件")
    return (pc + (offset if comparisons[condition] else 4)) & MASK32


def jal(pc: int, offset: int) -> tuple[int, int]:
    link = (pc + 4) & MASK32
    target = (pc + offset) & MASK32
    return target, link


def jalr(pc: int, base: int, immediate: int) -> tuple[int, int]:
    link = (pc + 4) & MASK32
    target = (base + immediate) & MASK32
    return target & ~1, link


assert branch(0x1000, 5, 5, 24, "eq") == 0x1018
assert branch(0x1000, 5, 7, 24, "eq") == 0x1004
assert jal(0x2000, -16) == (0x1FF0, 0x2004)
assert jalr(0x3000, 0x4123, 4) == (0x4126, 0x3004)

汇编语言

汇编语言是机器指令和工具链功能的符号接口。它用助记符与寄存器名替代二进制字段，用标签替代手工计算地址，用指示符描述节与数据。它依赖具体体系结构并接近 ISA 行为，但并非始终与机器码一一对应。

典型语句由可选标签、一条指令或指示符、操作数以及可选注释组成：

loop:   addi t0, t0, -1    # 递减循环计数器
        bne  t0, zero, loop

汇编器确定寄存器编号、选择编码、展开伪指令并记录尚未解析的符号引用。空格与注释语法属于汇编方言，操作语义则来自 ISA。

标签与指示符

标签把符号名与当前位置关联。它不执行，也不一定分配存储；之后可作为分支目标、数据地址或重定位表达式。

汇编器指示符以点号开头，告诉汇编器如何构造目标文件，不会被处理器取作指令。

指示符 常见用途
.text 选择可执行代码节
.data 选择已初始化可写数据节
.bss 选择零初始化存储节
.globl name 让符号对链接器可见
.align n 按汇编器规则对齐后续内容
.byte、.half、.word 发出定宽数据
.asciz 发出零结尾字符串 
    .section .rodata
message:
    .asciz "hello"

    .text
    .globl read_first
read_first:
    la   t0, message
    lbu  a0, 0(t0)
    ret

message 命名数据，read_first 命名代码。la 与 ret 是伪指令，最终机器序列取决于上下文；字符串字节属于目标文件数据，而不是指令字。

对齐指示符尤其要注意，因为不同汇编器和目标的语法不同。GNU RISC-V 的 .align n 使用二次幂字节边界，可移植源码应遵循所选工具链文档，而不能假定所有汇编器解释一致。

伪指令

伪指令是会展开成一条或多条真实指令的汇编记法。它提高可读性，但不会扩大硬件 ISA。

伪指令 典型基础展开 含义
nop addi x0, x0, 0 不改变体系结构数据
mv rd, rs addi rd, rs, 0 复制寄存器
not rd, rs xori rd, rs, -1 逐位取反
neg rd, rs sub rd, x0, rs 补码取负
j label jal x0, label 不保存链接的跳转
ret jalr x0, 0(ra) 返回 ra 中链接
li rd, constant 一条或多条指令 构造常量
la rd, symbol PC 相对指令序列 形成符号地址

“典型展开”很重要。汇编器和链接器会根据代码模型、符号位置、扩展、位置无关性与松弛优化选择不同合法序列。

加载常量说明展开并不简单。有符号 12 位值可直接放入 addi rd, x0, imm。更宽的 32 位常量可用 lui 提供高位，再由 addi 提供有符号低位。由于 addi 会符号扩展 12 位立即数，通常按

\[ hi20=(C+0x800)\gg12, \]

\[ lo12=C-(hi20\ll12) \]

拆分。\(C\) 是目标 32 位常量；加 0x800 会在低位第 11 位为 1 时把高位向上修正；右移选出调整后的高 20 位；\(lo12\) 最终位于 -2048 到 2047；lui 提供 hi20 << 12，addi 提供有符号余量。

Python 展开辅助函数：为 LUI 加 ADDI 拆分 32 位常量 
def split_lui_addi(constant: int) -> tuple[int, int]:
    """返回 20 位 LUI 字段与有符号 12 位 ADDI 立即数。"""
    constant &= 0xFFFF_FFFF
    signed_constant = constant - (1 << 32) if constant & (1 << 31) else constant

    hi20 = (signed_constant + 0x800) >> 12
    lo12 = signed_constant - (hi20 << 12)
    if not -2048 <= lo12 <= 2047:
        raise AssertionError("调整后的低立即数必须能放入有符号 12 位")
    return hi20 & 0xFFFFF, lo12


def reconstruct(hi20: int, lo12: int) -> int:
    return ((hi20 << 12) + lo12) & 0xFFFF_FFFF


for constant in (0x0000_07FF, 0x0000_0800, 0x1234_5ABC, 0xFFFF_FFFF):
    high, low = split_lui_addi(constant)
    assert reconstruct(high, low) == constant

assert split_lui_addi(0x1234_5ABC) == (0x12346, -0x544)

阅读反汇编时，应先判断工具显示的是规范机器指令，还是重新构造的伪指令。不同助记符显示可能描述完全相同的字节。

从汇编到机器码

汇编源码要经历多个阶段才能成为可执行代码。汇编器可以立即编码已知数值操作数和局部关系，但最终地址往往取决于其他文件与节布局。

主要产物依次为：

  1. 源文件：助记符、标签、指示符与表达式；
  2. 可重定位目标文件：已编码字节、节、符号和重定位记录；
  3. 已链接可执行文件或库：尽可能解析符号，并为各节分配最终关系；
  4. 已加载映像：把段映射到地址空间、建立权限并准备入口状态。

符号表记录名称与当前节相对值。重定位说明某些比特在符号最终地址确定后必须调整。RISC-V 的 PC 相对地址序列可能使用成对的高低重定位，因为一条指令无法保存任意 32 位地址。

链接器还可进行松弛（relaxation）：最终距离确定后，把通用序列替换为更短或更简单的等价序列。因此源码行数、目标文件指令数和链接后指令数不一定相同。

两遍汇编器很好地说明标签解析。第一遍确定每条指令地址并记录标签，第二遍用标签偏移替换符号并编码最终指令字。真实汇编器还会处理节、宏、表达式、符号可见性、重定位和更多指令格式。

Python 小型示例：解析标签并编码一段 ADDI/BEQ 程序 
def encode_addi(rd: int, rs1: int, immediate: int) -> int:
    if not -2048 <= immediate <= 2047:
        raise ValueError("ADDI 立即数越界")
    return ((immediate & 0xFFF) << 20) | (rs1 << 15) | (rd << 7) | 0x13


def encode_beq(rs1: int, rs2: int, offset: int) -> int:
    if offset % 2 or not -4096 <= offset <= 4094:
        raise ValueError("BEQ 偏移必须是偶数且能放入有符号 13 位")
    imm = offset & 0x1FFF
    return (
        (((imm >> 12) & 1) << 31)
        | (((imm >> 5) & 0x3F) << 25)
        | (rs2 << 20)
        | (rs1 << 15)
        | (((imm >> 1) & 0xF) << 8)
        | (((imm >> 11) & 1) << 7)
        | 0x63
    )


program = [
    ("start", "addi", (5, 0, 3)),
    (None, "addi", (5, 5, -1)),
    (None, "beq", (5, 0, "done")),
    (None, "beq", (0, 0, "start")),
    ("done", "addi", (10, 5, 0)),
]

# 第一遍：基础指令均为 4 字节，因此可以为标签分配地址。
labels = {}
pc = 0
for label, _, _ in program:
    if label is not None:
        labels[label] = pc
    pc += 4

# 第二遍：编码，并把符号分支目标替换为 PC 相对偏移。
machine_words = []
pc = 0
for _, mnemonic, operands in program:
    if mnemonic == "addi":
        machine_words.append(encode_addi(*operands))
    elif mnemonic == "beq":
        rs1, rs2, target = operands
        machine_words.append(encode_beq(rs1, rs2, labels[target] - pc))
    pc += 4

assert labels == {"start": 0, "done": 16}
assert machine_words[2] == 0x00028463  # beq x5, x0, +8
assert machine_words[3] == 0xFE000AE3  # beq x0, x0, -12

过程与调用约定

过程调用必须转移控制并在之后返回。独立编译的函数还必须就参数、结果、寄存器所有权、栈布局和对齐达成一致。RISC-V 清晰地分离两层：

  • JAL 与 JALR 提供 ISA 层的控制转移与链接；
  • 处理器特定 ABI 中的过程调用约定为寄存器和栈分配软件角色。

ISA 允许私有程序把 x20 当作链接寄存器并让栈向上增长，这仍是合法指令，但除非在边界遵循相同 ABI，否则无法安全调用标准库。

惯用调用是

jal ra, function

它把 pc+4 保存到 ra（x1）。返回使用 ret 伪指令，通常展开为

jalr x0, 0(ra)

叶过程不调用其他过程，可以把 ra 留在输入寄存器；非叶过程在继续调用时会覆盖 ra，所以通常先保存调用者的返回地址。

栈帧

栈是由 sp（x2）管理的内存区域。标准 RISC-V ABI 中，栈向低地址增长，过程入口的 sp 按 128 位即 16 字节对齐。过程从 sp 减去空间以分配帧，返回前再加回相同大小。

调用约定依据：RISC-V ABI 规范，RISC-V International，CC BY 4.0。

典型非叶过程序言与尾声：

example:
    addi sp, sp, -16     # 分配一个对齐栈帧
    sw   ra, 12(sp)      # 保存调用者返回地址
    sw   s0, 8(sp)       # 修改被调用者保存寄存器前先保存
    addi s0, sp, 16      # 可选帧指针指向入口 sp

    # 函数体可用 0(sp)、4(sp) 保存局部变量或溢出值
    # 函数体可能调用另一个函数

    lw   s0, 8(sp)       # 恢复被保存值
    lw   ra, 12(sp)
    addi sp, sp, 16      # 精确释放已分配栈帧
    ret

栈帧可包含返回地址与被调用者保存寄存器、需要取地址的局部变量、活跃值超过寄存器时的溢出槽、传给被调用函数的栈参数以及对齐填充。

帧指针可选。使用时位于 s0（x8），仍属于被调用者保存寄存器。稳定帧指针在 sp 于函数内移动时有利于调试和访问，但优化代码常省略它，直接相对 sp 寻址。

标准 ABI 不保留当前栈指针以下的数据。与某些 ABI 不同，代码不能假设 sp 下方存在受保护的 red zone。

参数与返回值

整数调用约定用 a0-a7（x10-x17）传递前八个整数参数槽，a0 与 a1 也用于返回值。参数寄存器用尽后，其余值按 ABI 布局放在栈上。

RV32 中，不宽于 XLEN 的标量通常占一个参数寄存器。64 位标量需要两个 XLEN 大小片段，并可能按类型和寄存器余量要求对齐寄存器对或放到栈上。聚合体可拆成寄存器大小字段、经寄存器对传递，或通过地址间接传递。精确规则取决于类型大小与 ABI，而不只是 ISA。

int affine(int x, int scale, int bias) {
    return x * scale + bias;
}

具备 M 扩展时，参数/结果映射可为：

# a0 = x, a1 = scale, a2 = bias
affine:
    mul a0, a0, a1
    add a0, a0, a2
    ret
# 结果在 a0 中返回

该函数是叶过程，不需要栈帧：只使用调用者保存的参数寄存器，在 a0 返回，且不进行其他调用。栈帧由实际存储与保存需求产生，并不是每个过程的固定仪式。

指针按 ABI 数据模型以整数寄存器宽度传递。指针只标识内存，调用者仍要用加载/存储访问对象；传地址并不等于复制地址指向的数据。

可变参数函数、浮点 ABI、向量和大型聚合体会增加规则。与编译代码互操作时，应查阅所选 psABI，而不是只凭寄存器昵称推断。

保存寄存器与临时寄存器

调用把寄存器保存责任分给调用者与被调用者。“保存”不表示硬件自动存储，而是规定必要时谁负责保留原值。

寄存器组 ABI 名称 跨调用保留？ 责任
零 x0/zero 不可变 不存在需保存值
返回地址 x1/ra 否 若后续调用后仍需要，调用者保存
栈指针 x2/sp 是 被调用者返回前恢复
全局/线程指针 x3/gp、x4/tp 固定/不可分配 普通过程不改作他用
临时 t0-t6 否 调用者保存仍活跃值
参数/结果 a0-a7 否 调用者保存仍活跃值
保存寄存器 s0-s11 是 被调用者保存并恢复其修改项

被调用函数可以自由覆盖调用者保存寄存器；调用者若在调用后还需要旧值，就必须提前复制或溢出。被调用者保存寄存器让调用者可以假定值会保留，任何修改它的被调用函数都必须先保存输入值并在返回前恢复。

这种分工减少不必要的内存传输：只跨一次调用的短期值适合调用者保存寄存器，跨越多次调用的长期值适合被调用者保存寄存器。编译器会根据活跃性和调用结构选择。

Python 契约检查器：检测未恢复保存寄存器的被调用函数 
CALLER_SAVED = {"ra", *(f"a{i}" for i in range(8)), *(f"t{i}" for i in range(7))}
CALLEE_SAVED = {"sp", *(f"s{i}" for i in range(12))}


def checked_call(registers: dict[str, int], callee) -> dict[str, int]:
    before = registers.copy()
    after = callee(registers.copy())

    changed_saved = {
        name for name in CALLEE_SAVED
        if after.get(name) != before.get(name)
    }
    if changed_saved:
        raise AssertionError(f"被调用者没有恢复：{sorted(changed_saved)}")
    return after


initial = {"sp": 0x8000, "s0": 99, "a0": 4, "t0": 7, "ra": 0x1004}


def valid_leaf(regs: dict[str, int]) -> dict[str, int]:
    regs["a0"] *= 2          # 返回值可以覆盖 a0。
    regs["t0"] = 123         # 临时寄存器可以被破坏。
    return regs


result = checked_call(initial, valid_leaf)
assert result["a0"] == 8 and result["s0"] == 99 and result["sp"] == 0x8000


def broken_callee(regs: dict[str, int]) -> dict[str, int]:

该检查器只模拟保存约定，并非完整 ABI。真实正确性还需要栈对齐、参数布局、返回值规则和合法内存行为。

RISC 与 CISC 设计理念

RISC 与 CISC 描述一组常见 ISA 设计取向，而不是处理器质量的二元评分。RISC-V 通过规则寄存器字段、加载-存储基础与大多固定 32 位指令体现 RISC 倾向；x86 则通过变长编码、更丰富寻址与可组合访存和计算的指令体现 CISC 倾向。

维度 RISC 倾向 CISC 倾向
编码 规则字段，基础长度常固定 变长且有更密集的特殊情况
内存操作数 明确加载/存储边界 某些运算直接命名内存
操作粒度 简单、显式步骤 较丰富操作可合并步骤
译码 易确定边界与提取字段 找长度和操作数工作更多
代码密度 可能需要更多指令 常用操作往往字节更少
实现 规则前端更方便 常见做法是转换为内部微操作

“每个 RISC 指令一个周期”是历史口号，不是现代定义。加载未命中可能等待数百周期，乱序处理器也可能每周期完成多条指令；复杂体系结构指令同样可以译成多个规则微操作并高效执行。

边界已经模糊：RISC-V 具有提高代码密度的压缩扩展和语义丰富的向量/密码扩展；现代 x86 核心把指令转换为内部微操作并深度流水、推测执行；两者都可使用缓存、分支预测、乱序调度、SIMD/向量单元和微码；编译器质量与工作负载行为通常比标签更重要。

ISA 设计需要平衡编码空间、代码大小、编译器便利、实现成本、兼容性和未来扩展。规则 ISA 可简化小型核心和验证，却不意味着所有高性能实现都简单；密集 ISA 可降低取指带宽，却需要更复杂前端译码。

公平比较应分开体系结构表达与微体系结构实现。性能必须在真实实现和工作负载上测量，不能从缩写推断。

阅读编译器生成的汇编

阅读编译器汇编时，应重建数据流与控制流，而不是逐条把助记符翻成自然语言。先确定 ABI 接口，再找循环携带值，最后把分支和访存映射回源代码结构。

int sum_positive(const int *a, int n) {
    int total = 0;
    for (int i = 0; i < n; ++i) {
        if (a[i] > 0) total += a[i];
    }
    return total;
}

一种可能的优化 RV32I 序列如下：

sum_positive 的示意性优化 RV32I 汇编 
# a0 = 数组指针 a，a1 = 元素数量 n
sum_positive:
    addi a2, x0, 0          # total = 0
    bge  x0, a1, .Ldone     # 若 n <= 0，跳过循环

.Lloop:
    lw   a3, 0(a0)          # 读取当前 a[i]
    addi a0, a0, 4          # 指针前进 sizeof(int)
    bge  x0, a3, .Lskip     # value <= 0 时跳过加法
    add  a2, a2, a3         # total += value

.Lskip:
    addi a1, a1, -1         # 剩余数量减一
    bne  a1, x0, .Lloop

.Ldone:
    addi a0, a2, 0          # 在 a0 返回 total（mv 伪指令）
    jalr x0, 0(ra)          # 返回（ret 伪指令）

分层阅读：

  1. 接口：a0 初始是数组指针，a1 是 \(n\)，最终 a0 必须保存返回值；
  2. 活跃状态：a2 是运行总和，a0 变成移动指针，a1 变成剩余元素计数；
  3. 内存：lw a3, 0(a0) 读取四字节元素，指针加 4 实现数组遍历；
  4. 控制：.Lloop、.Lskip、.Ldone 定义循环和条件路径；
  5. 有符号含义：bge x0, a3, .Lskip 在零大于等于有符号元素时跳过，即 a[i] <= 0；
  6. 过程形态：它是叶过程，只用调用者保存寄存器，因此无需栈帧。

编译器转换了源变量。不存在显式保存 i 的寄存器；移动指针和递减计数以更低成本编码同样的循环进度。这是正常优化，并非语义丢失。

编译选项会改变结果：-O0 常把值溢出到栈并保留明显源码结构；-O2 会传播常量、删除死代码、用寄存器运行循环并可能内联；ISA 扩展可用乘法、位操作、压缩、浮点或向量指令替代序列；调试、sanitizer、位置无关代码和安全选项也会增加指令与元数据。

检查真实输出时，应记录目标 ISA 字符串、ABI、编译器版本、优化级别、代码模型，以及看到的是链接前汇编还是最终反汇编。缺少这些上下文时，两份正确输出也可能看起来完全不同。

Python 辅助：按体系结构角色分类示例中的指令 
assembly = """
addi a2, x0, 0
bge x0, a1, .Ldone
lw a3, 0(a0)
addi a0, a0, 4
bge x0, a3, .Lskip
add a2, a2, a3
addi a1, a1, -1
bne a1, x0, .Lloop
addi a0, a2, 0
jalr x0, 0(ra)
"""

categories = {
    "add": "ALU", "addi": "ALU",
    "lw": "memory",
    "bge": "conditional control", "bne": "conditional control",
    "jalr": "indirect control",
}

counts: dict[str, int] = {}
for line in assembly.strip().splitlines():
    mnemonic = line.split()[0]
    category = categories[mnemonic]
    counts[category] = counts.get(category, 0) + 1

assert counts == {
    "ALU": 5,
    "conditional control": 3,
    "memory": 1,
    "indirect control": 1,
}

本章小结。ISA 是编码指令与体系结构状态的可见契约，汇编、ABI 和微体系结构位于它周围不同层次。RV32I 公开 32 个整数寄存器、程序计数器和按字节寻址内存。规则的 32 位格式固定寄存器字段，并针对算术、存储、分支和跳转重新组织立即数。算术只操作寄存器并回绕到 XLEN；只有加载和存储经基址加偏移地址访问内存；分支、JAL 和 JALR 选择下一 PC 并支持过程控制流。汇编加入标签、指示符和伪指令，随后汇编器、链接器与加载器把符号源码转为可执行字节。调用约定分配参数、返回值、临时、保存、栈与链接责任，使独立编译的过程可以协作。RISC 与 CISC 描述设计权衡，而不是速度排名。阅读编译器输出时，要沿 ABI 接口、寄存器数据流、访存和控制流边恢复语义。第 06 章会把这些 ISA 层状态转移映射到具体数据通路部件与控制信号。
