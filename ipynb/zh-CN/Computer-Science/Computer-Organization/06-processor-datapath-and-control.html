处理器数据通路与控制

第 05 章把指令描述成体系结构承诺：add 改变一个寄存器，sw 改变内存，beq 可能改变下一程序计数器，jal 同时改变链接寄存器与 PC。这些语句规定软件必须观察到什么，处理器还要决定门、状态元件、存储器和导线如何精确地产生这些变化。

本章用一个刻意精简的 RV32I 子集搭起这座实现桥梁，支持代表性的寄存器算术、加载、存储、条件分支与 jal。它是一种教学微体系结构，而不是唯一实现。小型单周期核、多周期控制器、顺序流水线核和推测乱序核都可以实现同一 ISA，却以完全不同方式组织硬件。

从 ISA 语义到处理器

一条指令最好理解为状态转移。设指令执行前程序员可见状态为

\[ S=(PC,R,M), \]

其中 \(PC\) 是当前指令地址，\(R\) 是寄存器文件，\(M\) 是内存。执行指令 \(I\) 必须产生

\[ S^{+}=F_I(S). \]

\(S^{+}\) 是指令提交后的体系结构状态，\(F_I\) 是指令 \(I\) 要求的转移。下标 \(I\) 很重要，因为 add、lw、sw、beq 与 jal 更新的状态部分不同。

对 add x5, x6, x7，RV32I 要求

\[ R^{+}[5]=(R[6]+R[7])\bmod2^{32},\qquad PC^{+}=PC+4, \]

其他寄存器和内存保持不变。模运算使 32 位结果自然回绕，所得模式之后可由其他指令按有符号或无符号解释。

实现分为两个协作部分：

  • 数据通路（datapath）包含状态元件和数值变换硬件：PC、寄存器文件、存储器、ALU、加法器、比较器与多路选择器；
  • 控制单元（control unit）解释指令比特和当前条件，产生使能与选择值，告诉数据通路哪一种操作有效。

可以把数据通路类比为铁路的轨道、车站与道岔，控制则负责选路。数值像列车一样沿线路移动，而控制信号决定它最终到达 ALU、数据存储器、寄存器文件还是下一 PC 输入。

ISA 要求 数据通路责任 控制决定
读取 rs1 与 rs2 提供两个寄存器读端口 选择编码的寄存器索引
计算 ALU 结果 把操作数送往 ALU 选择寄存器或立即数，并选择操作
加载或存储 向数据存储器提供有效地址 启用访存并选择写回来源
分支或跳转 计算候选下一地址 选择顺序 PC 或目标 PC
只提交一种合法结果 为边沿触发状态提供输入 只断言允许的写使能

这项分离是核心设计纪律。许多导线上可以同时存在候选值，但只有得到使能的状态元件才会让它们成为体系结构可见结果。

核心数据通路部件

处理器把状态与组合变换结合起来。状态跨时钟边沿记忆数值，组合模块在周期内计算候选值，输入改变后不保留信息。存储器接口的时序取决于实现：教学模型可以把读取视为组合过程，真实缓存和外部内存则使用可变延迟的请求/响应协议。

这解释了为什么数据通路图中箭头很多，而体系结构更新很少。一个周期内，PC+4、分支目标、ALU 和与内存输出可能都在计算；多路选择器挑选候选值，写使能决定哪些候选在边沿被捕获。

部件类型 典型示例 跨周期存储？ 回答的问题
体系结构状态 PC、整数寄存器、内存 是 软件可以观察什么？
内部状态 指令寄存器、ALUOut、内存数据寄存器 是 多周期实现需要记住什么？
组合变换 ALU、比较器、立即数生成器、加法器 否 应计算哪个候选值？
引导 MUX、译码器、使能逻辑 否 选择哪个候选或动作？

程序计数器

程序计数器是保存取指地址的寄存器。直线代码通常按指令长度递增，所以称为计数器；更准确地说，它是“下一指令地址寄存器”，因为分支、跳转、陷阱和返回都可替换普通计数。

对本章使用的基础 32 位指令，顺序候选为

\[ PC_{seq}=PC+4. \]

4 的单位是字节，因为内存按字节寻址，每条基础指令占四字节。简化下一 PC 规则为

\[ PC^{+}=\begin{cases} PC+Imm,&\text{分支被采用或执行 jal},\\ PC+4,&\text{其他情况}. \end{cases} \]

\(Imm\) 是经过符号扩展、格式相关的 PC 相对偏移。条件分支由比较结果决定是否选择目标，jal 则无条件选择目标。

jalr 还需要候选 \((R[rs1]+Imm)\mathbin{\&}\sim1\)，陷阱需要陷阱向量地址，因此完整处理器的下一 PC MUX 会比这个二选一方程拥有更多输入。

jal 中旧 PC 同时参与目标 \(PC+Imm\) 与链接 \(PC+4\) 的计算。两者必须来自同一个边沿前 PC。同步硬件会从稳定当前值并行计算候选，再统一提交，而不会像错误的软件顺序那样提前覆盖 PC。

指令存储器

指令存储器把指令地址映射为编码比特：

\[ Instr=IMem[PC]. \]

教学数据通路把它画成组合读取：PC 稳定后，经过存储器延迟出现 32 位指令。各字段随后并行扇出：instr[6:0] 送主译码器；instr[19:15]、instr[24:20]、instr[11:7] 在适用格式中选择 rs1、rs2、rd；功能字段细化 ALU 或分支操作；分散的立即数位送往立即数生成器。

IMem 并不要求物理上独立的 ROM，而代表取指接口。Harvard 风格教学模型分开指令与数据接口，使单周期加载能在同一周期取指并读数据。统一存储实现必须提供双端口、两个缓存、仲裁或多周期，才能避免结构冲突。

不支持压缩指令的 RV32I 有 \(IALIGN=32\)，合法指令地址按四字节对齐，因此 PC 低两位通常为零。加入压缩扩展后允许两字节对齐，取指单元还要处理 16 与 32 位混合边界。

真实指令缓存包含标签、命中检查、未命中、权限与响应握手，通常不是简单组合盒。这里的抽象是为了先揭示数据通路逻辑，再引入缓存和流水线时序。

寄存器文件

整数寄存器文件保存 32 个体系结构寄存器。典型标量 RV32I 数据通路提供双读单写端口，因为 add、sw 和 beq 可能需要两个源，但每条指令至多退休一个整数目的。

组合读取为

\[ A=R[rs1],\qquad B=R[rs2], \]

边沿触发写入为

\[ R^{+}[rd]=\begin{cases} WD,&RegWrite=1\ \text{且}\ rd\ne0,\\ R[rd],&\text{其他情况}. \end{cases} \]

\(WD\) 是写回 MUX 选出的值；RegWrite 是写使能；\(rd\ne0\) 保持 RISC-V 的硬连线 x0=0。

执行 add x5, x5, x6 时，周期内读取旧 x5、x6，新 x5 只在边沿捕获。真实寄存器阵列仍需定义或旁路同地址读写，确保电路实现这种先读后提交语义。

寄存器文件不只是存储阵列，端口数量强烈影响面积、布线和延迟。多发射处理器需要更多读写端口或分 bank，这也是宽超标量设计的寄存器文件与旁路网络很昂贵的原因。

ALU

ALU 变换来自寄存器文件、立即数生成器或 PC 的操作数，并被复用于多种任务：

指令目的 ALU 输入 操作 结果用途
寄存器算术 \(R[rs1]\)、\(R[rs2]\) 加减、逻辑、比较 寄存器写回
立即数算术 \(R[rs1]\)、\(Imm\) 由 funct3 选择 寄存器写回
访存地址 \(R[rs1]\)、\(Imm\) 加法 数据存储器地址
分支比较 两个源值 减法或专用比较 是否采用分支
PC 相对目标 \(PC\)、\(Imm\) 加法 下一 PC 候选

某些数据通路复用主 ALU 计算分支目标和比较，另一些增加专用硬件使它们并行。ISA 不规定这项选择。

\[ Y=(A+B)\bmod2^{XLEN}. \]

RV32I 的 \(XLEN=32\)，没有体系结构溢出标志；软件在需要时自行检测有符号溢出或无符号进位。

Python 模型：小型 RV32I 风格 ALU 
MASK32 = (1 << 32) - 1


def to_signed32(value: int) -> int:
    """把 32 位模式解释为有符号补码整数。"""
    value &= MASK32
    return value if value < (1 << 31) else value - (1 << 32)


def alu(a: int, b: int, control: str) -> int:
    """返回 ALU 控制字选择的 32 位结果。"""
    a &= MASK32
    b &= MASK32

    if control == "ADD":
        result = a + b
    elif control == "SUB":
        result = a - b
    elif control == "AND":
        result = a & b
    elif control == "OR":
        result = a | b
    elif control == "SLT":
        result = int(to_signed32(a) < to_signed32(b))
    else:
        raise ValueError(f"不支持的 ALU 操作：{control}")

    # 物理 RV32I 输出只携带低 32 位。
    return result & MASK32


assert alu(11, 7, "ADD") == 18
assert alu(0, 1, "SUB") == 0xFFFFFFFF
assert alu(0xFFFFFFFF, 0, "SLT") == 1  # 有符号解释下 -1 < 0

ALUControl 是局部控制，而不是 ISA 字段。不同实现可以用不同内部编码表示 ADD，只要各自译码器与 ALU 一致即可。

数据存储器

加载-存储 ISA 中只有加载与存储访问数据内存。ALU 先产生有效地址：

\[ EA=(R[rs1]+Imm)\bmod2^{32}. \]

加载时，内存提供 \(EA\) 处字节，加载单元在写回前扩展或拼装；存储时，\(R[rs2]\) 提供写数据，字节使能指明哪些 lane 可改变。

操作 地址输入 数据方向 体系结构更新
lw rd, imm(rs1) ALU 结果 内存到处理器 向 rd 写 32 位字
lb/lbu ALU 结果 内存到处理器 字节符号/零扩展
sw rs2, imm(rs1) ALU 结果 处理器到内存 写四个选中字节
sb ALU 结果 处理器到内存 写一个选中字节

简化数据通路假定一次成功对齐访问在周期内结束。真实接口还要报告访问错误、页错误、对齐行为、缓存未命中与设备副作用。精确异常要求：若指令将陷入，存储不能已经对外可见，加载也不能写入目的寄存器。

小端序只控制字节与多字节值之间的对应，不改变 ALU 计算哪个数字地址。

寄存器传输级描述

寄存器传输级（RTL）描述组合逻辑计算哪些值，以及时钟边沿由哪些寄存器捕获。它位于 ISA 文字与单个逻辑门之间。

  • \(Y=F(X)\) 表示随输入变化并在传播延迟后稳定的组合关系；
  • \(Q^{+}\leftarrow D\) 表示下一边沿发生的使能状态更新。

对 add x5, x6, x7：

\[ A=R[6],\quad B=R[7],\quad ALUResult=(A+B)\bmod2^{32}, \]

随后在边沿

\[ R^{+}[5]\leftarrow ALUResult,\qquad PC^{+}\leftarrow PC+4. \]

箭头不表示寄存器写先于 PC 更新；两者都从旧状态输入在同一边沿提交。存储则有

\[ EA=R[rs1]+Imm_S,\qquad M^{+}[EA:EA+3]\leftarrow R[rs2]_{31:0}, \]

且 RegWrite=0。不采用的分支不改寄存器和内存，只提交 \(PC^{+}\leftarrow PC+4\)。

Python 模型：不破坏当前状态地计算下一状态 
from dataclasses import dataclass

MASK32 = (1 << 32) - 1


@dataclass(frozen=True)
class ArchitecturalState:
    pc: int
    registers: tuple[int, ...]


def add_transition(
    state: ArchitecturalState, rd: int, rs1: int, rs2: int
) -> ArchitecturalState:
    """模拟一条 RV32I ADD 的同步 RTL 更新。"""
    result = (state.registers[rs1] + state.registers[rs2]) & MASK32

    next_registers = list(state.registers)
    if rd != 0:
        next_registers[rd] = result
    next_registers[0] = 0

    return ArchitecturalState(
        pc=(state.pc + 4) & MASK32,
        registers=tuple(next_registers),
    )


registers = [0] * 32
registers[5], registers[6] = 10, 8
before = ArchitecturalState(pc=0x100, registers=tuple(registers))
after = add_transition(before, rd=5, rs1=5, rs2=6)

assert before.registers[5] == 10
assert after.registers[5] == 18
assert after.pc == 0x104

该模型不模拟门或时间，价值在于用不可变当前状态明确表达同时提交，避免错误的软件顺序推理。

单周期数据通路

单周期处理器在相邻有效边沿之间完成一条体系结构指令。取指、译码、寄存器读取、执行、可选数据访存、写回选择和下一 PC 选择都是同一个长组合区间内的逻辑阶段，中间没有流水线寄存器。

数据通路通过共享硬件，并在不同指令类别需要不同源或目的处插入 MUX：

  1. PC 提供取指地址，也输入 PC+4 与 PC 相对目标加法器；
  2. 指令字段并行驱动寄存器文件、立即数生成器与控制单元；
  3. 第一 ALU 操作数通常来自 rs1，第二个在 rs2 与立即数间选择；
  4. ALU 结果既可以是算术答案，也可以是数据内存地址；
  5. 写回 MUX 在 ALU、内存数据与 jal 的 PC+4 间选择；
  6. 分支比较与跳转控制选择顺序或目标 PC。

“单周期”不是说每个模块各花一个周期，而是完整寄存器到寄存器路径位于同一周期。组合模块并发反应，例如寄存器文件读取期间，立即数生成器和控制译码器也在工作。

\[ \begin{aligned} PC^{+}&\leftarrow NextPC,\\ R^{+}[rd]&\leftarrow Result&&\text{若 }RegWrite,\\ M^{+}[EA]&\leftarrow WriteData&&\text{若 }MemWrite. \end{aligned} \]

只有使能线路提交。存储会在结果总线上算出值却不写寄存器；add 也会把值呈现在内存地址线上，但不使能内存写。防止意外副作用与算出正确答案同样重要。

Python 模型：执行五类教学指令 
from dataclasses import dataclass

MASK32 = (1 << 32) - 1


@dataclass
class Machine:
    pc: int
    registers: list[int]
    words: dict[int, int]


def execute(machine: Machine, instruction: tuple) -> None:
    """提交一条抽象的 add/lw/sw/beq/jal 指令。"""
    op, *args = instruction
    old_pc = machine.pc
    next_pc = (old_pc + 4) & MASK32

    # 像组合数据通路一样，先计算候选效果。
    register_write: tuple[int, int] | None = None
    memory_write: tuple[int, int] | None = None

    if op == "add":
        rd, rs1, rs2 = args
        value = (machine.registers[rs1] + machine.registers[rs2]) & MASK32
        register_write = (rd, value)
    elif op == "lw":
        rd, offset, rs1 = args
        address = (machine.registers[rs1] + offset) & MASK32
        register_write = (rd, machine.words[address])
    elif op == "sw":
        rs2, offset, rs1 = args
        address = (machine.registers[rs1] + offset) & MASK32
        memory_write = (address, machine.registers[rs2])
    elif op == "beq":
        rs1, rs2, offset = args
        if machine.registers[rs1] == machine.registers[rs2]:
            next_pc = (old_pc + offset) & MASK32
    elif op == "jal":
        rd, offset = args
        register_write = (rd, (old_pc + 4) & MASK32)
        next_pc = (old_pc + offset) & MASK32
    else:
        raise ValueError(f"不支持的指令：{op}")

    # 统一提交被选中的状态变化。
    if memory_write is not None:
        address, value = memory_write
        machine.words[address] = value & MASK32
    if register_write is not None:
        rd, value = register_write
        if rd != 0:
            machine.registers[rd] = value & MASK32
    machine.registers[0] = 0
    machine.pc = next_pc


cpu = Machine(pc=0x100, registers=[0] * 32, words={0x200C: 37})
cpu.registers[6], cpu.registers[7] = 0x2000, 7
execute(cpu, ("lw", 5, 12, 6))
assert (cpu.pc, cpu.registers[5]) == (0x104, 37)

模型表达体系结构效果而非物理时序，但“先候选、后提交”的结构与数据通路纪律一致，也便于之后表达异常抑制。

控制信号生成

控制把编码含义转换为控制字：当前周期施加的一组布尔使能与多位选择值。单周期译码器本身是组合逻辑，不会依次“执行命令”，所有输出都由同一指令比特稳定产生。

把主控制与 ALU 控制分开可减少重复。加载与存储的体系结构效果不同，但都需要 ALU 把基址与立即数相加，主控制只需共同请求 ADD。这里的信号名仅用于教学，并非标准 RISC-V 名称。

主控制

主译码器主要检查 7 位 opcode。opcode 标识大类，从而决定立即数格式、操作数来源、写目的、内存动作与下一 PC 行为。

指令 Opcode RegWrite ImmSrc ALUSrc MemWrite ResultSrc Branch Jump ALUOp
R 型 ALU 0110011 1 X 寄存器 0 ALU 0 0 译码 funct
lw 0000011 1 I 立即数 0 内存 0 0 ADD
sw 0100011 0 S 立即数 1 X 0 0 ADD
beq 1100011 0 B 寄存器 0 X 1 0 比较
jal 1101111 1 J X 0 PC+4 0 1 X

X 表示无关项：后续使能或 MUX 选择排除了该路径，所以输出不可能影响体系结构状态。它给综合更多自由，但只有门控论证正确时才安全，例如 sw 中 RegWrite=0，因此 ResultSrc 无关。

简单组合内存可以持续输出读数据，所以图中可能只有 MemWrite。真实缓存还需要请求类型、大小、valid、ready、fault 与字节使能，控制契约复杂得多。

Python 模型：把 RV32I opcode 译成主控制信号 
from dataclasses import dataclass


@dataclass(frozen=True)
class MainControl:
    reg_write: bool
    imm_src: str | None
    alu_src: str
    mem_write: bool
    result_src: str | None
    branch: bool
    jump: bool
    alu_op: str


CONTROL_BY_OPCODE = {
    0b0110011: MainControl(True,  None, "REG", False, "ALU", False, False, "FUNCT"),
    0b0000011: MainControl(True,  "I", "IMM", False, "MEM", False, False, "ADD"),
    0b0100011: MainControl(False, "S", "IMM", True,  None,  False, False, "ADD"),
    0b1100011: MainControl(False, "B", "REG", False, None,  True,  False, "COMPARE"),
    0b1101111: MainControl(True,  "J", "NA",  False, "PC4", False, True,  "NA"),
}


def decode_main(instruction: int) -> MainControl:
    opcode = instruction & 0x7F
    try:
        return CONTROL_BY_OPCODE[opcode]
    except KeyError as error:
        raise ValueError(f"不支持的 opcode 0b{opcode:07b}") from error


assert decode_main(0x007302B3).result_src == "ALU"
assert decode_main(0x00C32283).result_src == "MEM"
assert decode_main(0x00732623).mem_write

ALU 控制

主译码器知道加载需要加法、分支需要比较，但 R 型 opcode 本身不能区分 add、sub、and、or 与 slt。ALU 译码器把宽泛 ALUOp 与 funct3、相关 funct7 位组合。

ALUOp funct3 instr[30] ALU 动作 示例
ADD X X ADD lw/sw 地址
FUNCT 000 0 ADD add
FUNCT 000 1 SUB sub
FUNCT 111 X AND and
FUNCT 110 X OR or
FUNCT 010 X 有符号 SLT slt

只有 opcode 与 funct3 已确定相关家族后，instr[30] 才足以区分 add 与 sub；单独检查它会误译其他格式。分支也可复用 ALU 标志或用专用比较器，后者能与目标加法器并行，缩短下一 PC 路径。

Python 模型：分层 ALU 译码 
def decode_alu(alu_op: str, funct3: int = 0, bit30: int = 0) -> str:
    """把主控制类别和功能位转换为局部 ALU 动作。"""
    if alu_op == "ADD":
        return "ADD"
    if alu_op == "COMPARE":
        return "COMPARE"
    if alu_op != "FUNCT":
        raise ValueError(f"ALU 不用于 ALUOp={alu_op}")

    if funct3 == 0b000:
        return "SUB" if bit30 else "ADD"
    if funct3 == 0b111:
        return "AND"
    if funct3 == 0b110:
        return "OR"
    if funct3 == 0b010:
        return "SLT"
    raise ValueError(f"不支持 funct3={funct3:03b}")


assert decode_alu("ADD") == "ADD"
assert decode_alu("FUNCT", 0b000, 0) == "ADD"
assert decode_alu("FUNCT", 0b000, 1) == "SUB"
assert decode_alu("FUNCT", 0b111, 0) == "AND"

分层译码是实现优化；综合可能再次展平逻辑，但这种层次让设计者先按指令类别、再按具体操作推理。

立即数生成

为保持寄存器字段位置固定，RISC-V 立即数并不总连续存放。立即数生成器负责重排编码位，为分支与跳转插入隐含低零，并把结果符号扩展到 XLEN。

\[ \begin{aligned} Imm_I&=sext(\{instr[31:20]\}),\\ Imm_S&=sext(\{instr[31:25],instr[11:7]\}),\\ Imm_B&=sext(\{instr[31],instr[7],instr[30:25],instr[11:8],0\}),\\ Imm_J&=sext(\{instr[31],instr[19:12],instr[20],instr[30:21],0\}). \end{aligned} \]

花括号表示从高到低拼接。sext 把符号位复制到所有更高位。B 与 J 末尾的零使字节偏移为偶数，并未显式存储。所有格式都以 instr[31] 为符号源，使扩展可与低位路由并行。

\[ sext_n(x)=\begin{cases} x,&x<2^{n-1},\\ x-2^n,&x\ge2^{n-1}. \end{cases} \]

Python 模型：译码 I、S、B 与 J 立即数 
def bits(value: int, high: int, low: int) -> int:
    """提取闭区间 [high:low]。"""
    width = high - low + 1
    return (value >> low) & ((1 << width) - 1)


def sign_extend(value: int, width: int) -> int:
    sign = 1 << (width - 1)
    return (value ^ sign) - sign


def decode_immediate(instruction: int, kind: str) -> int:
    if kind == "I":
        raw, width = bits(instruction, 31, 20), 12
    elif kind == "S":
        raw = (bits(instruction, 31, 25) << 5) | bits(instruction, 11, 7)
        width = 12
    elif kind == "B":
        raw = (
            (bits(instruction, 31, 31) << 12)
            | (bits(instruction, 7, 7) << 11)
            | (bits(instruction, 30, 25) << 5)
            | (bits(instruction, 11, 8) << 1)
        )
        width = 13
    elif kind == "J":
        raw = (
            (bits(instruction, 31, 31) << 20)
            | (bits(instruction, 19, 12) << 12)
            | (bits(instruction, 20, 20) << 11)
            | (bits(instruction, 30, 21) << 1)
        )
        width = 21
    else:
        raise ValueError(f"未知立即数类型：{kind}")
    return sign_extend(raw, width)


assert decode_immediate(0xFFF00093, "I") == -1
assert decode_immediate(0x00732623, "S") == 12

立即数生成本质上是布线与符号扩展逻辑，不是软件算术译码，但其延迟仍影响加载和存储何时能开始地址计算。

追踪指令类别

追踪一条指令，就是从编码字段一路跟随所有可能影响体系结构状态的值与控制信号。可靠追踪要回答：读取哪些旧状态；计算哪些组合候选；哪些控制使路径有效；哪些状态元件在边沿提交。

R 型指令

考虑 PC=0x100 时的 add x5, x6, x7，其中 R[6]=11、R[7]=7。

opcode 选择 R 型，funct3=000 与相关 funct7 位选择 ADD。ALUSrc=register 让两个寄存器输出进入 ALU。数据存储器可能看到地址线上的 ALU 结果，但 MemWrite=0，所以不改内存。ResultSrc=ALU、RegWrite=1 把 18 写入 x5。

阶段 数值或决定
取指 IMem[0x100] 中的指令比特
译码 rd=5、rs1=6、rs2=7、R 型控制
读操作数 \(A=11\)、\(B=7\)
执行 \(ALUResult=18\)
写回 \(R^{+}[5]=18\)
下一 PC \(PC^{+}=0x104\)

该顺序是推理顺序。物理硬件中，输入一旦可用，寄存器读取、控制译码、目标计算和无关候选路径会重叠进行。

加载与存储

加载与存储共享地址生成，却有相反数据方向与不同提交目标。若 R[6]=0x2000、偏移为 12，则

\[ EA=0x2000+12=0x200C. \]

对 lw x5, 12(x6)，ImmSrc=I 重建 12，ALU 相加，内存读取 0x200C，ResultSrc=memory 选返回字，RegWrite=1 提交到 x5。

对 sw x7, 12(x6)，ImmSrc=S 从不同位置重建同一偏移，ALU 计算同一地址；R[7] 直接到内存写端口；MemWrite=1 提交字，RegWrite=0 阻止寄存器更新。

Python 模型：小端字加载与存储路径 
MASK32 = (1 << 32) - 1


def store_word(memory: bytearray, address: int, value: int) -> None:
    """模拟对齐小端 SW 的四条有效字节 lane。"""
    if address % 4 != 0:
        raise ValueError("教学模型要求字对齐")
    memory[address:address + 4] = (value & MASK32).to_bytes(4, "little")


def load_word(memory: bytearray, address: int) -> int:
    """模拟数据内存读取与 LW 拼装路径。"""
    if address % 4 != 0:
        raise ValueError("教学模型要求字对齐")
    return int.from_bytes(memory[address:address + 4], "little")


registers = [0] * 32
registers[6] = 0x20
registers[7] = 0x12345678

assert memory[0x2C:0x30] == bytes([0x78, 0x56, 0x34, 0x12])
assert registers[5] == 0x12345678

加载通常形成单周期关键路径，因为它包含取指、寄存器读取、地址计算、数据访存与寄存器写回。存储省去写回，ALU 指令省去数据访存。

分支与跳转

控制流指令计算目标并决定是否替换 PC+4。不能简单归纳为“改变 PC”：beq 需要条件但不需要链接，jal 需要链接却不需要条件。

在 PC=0x100 执行 beq x5, x6, +16：

\[ Target=PC+Imm_B=0x110, \]

\[ PC^{+}=\begin{cases} Target,&Branch\land BrEq,\\ PC+4,&\text{其他情况}. \end{cases} \]

Branch 说明当前指令是条件分支，BrEq 说明本次条件为真。分开两者可防止其他指令的相等结果错误重定向。

对 jal x1, +32：

\[ R^{+}[1]=PC+4=0x104,\qquad PC^{+}=PC+Imm_J=0x120. \]

ResultSrc=PC+4 与 RegWrite=1 提交链接，Jump=1 选择目标。

Python 模型：下一 PC 与链接决定 
MASK32 = (1 << 32) - 1


def beq_transition(pc: int, left: int, right: int, offset: int) -> int:
    """只有相等条件成立时才选择分支目标。"""
    target = (pc + offset) & MASK32
    sequential = (pc + 4) & MASK32
    return target if (left & MASK32) == (right & MASK32) else sequential


def jal_transition(pc: int, offset: int) -> tuple[int, int]:
    """返回由同一个旧 PC 算出的 (next_pc, link_value)。"""
    return (pc + offset) & MASK32, (pc + 4) & MASK32


assert beq_transition(0x100, 9, 9, 16) == 0x110
assert beq_transition(0x100, 9, 8, 16) == 0x104
assert jal_transition(0x100, 32) == (0x120, 0x104)

基础 ISA 中，采用的分支或跳转若目标未合法对齐，会产生异常而不提交正常转移。这把下一 PC 逻辑与章末异常路径连接起来。

关键路径与时钟周期限制

时钟周期必须容纳最坏工艺、电压、温度、布线与时钟条件下最慢的有效寄存器到寄存器路径：

\[ T_{clk}\ge t_{clk\rightarrow q}+t_{comb,max}+t_{setup}+t_{skew}+t_{uncertainty}. \]

各项分别是周期、发射寄存器时钟到输出延迟、最大组合延迟、目的寄存器建立时间，以及偏斜与变化裕量。

单周期 lw 的长路径通常穿过 PC、指令内存、寄存器文件、立即数/操作数选择、ALU、数据内存、写回 MUX 和目的寄存器建立时间。

\[ T_{lw}=30+200+120+150+250+30+20=800\text{ ps}. \]

即使 add 在 550 ps 后稳定，也不能提前开始下一条；所有指令共享 800 ps 周期。因此

\[ T_{program}=N\times1\times T_{clk}. \]

CPI=1 并不保证执行时间短，周期可能很长。

Python 模型：比较指令路径延迟与全局时钟 
path_ps = {
    "add": 30 + 200 + 120 + 150 + 30 + 20,
    "lw":  30 + 200 + 120 + 150 + 250 + 30 + 20,
    "sw":  30 + 200 + 120 + 150 + 250,
    "beq": 30 + 200 + 120 + 150 + 30,
    "jal": 30 + 200 + 80 + 30,
}

clock_ps = max(path_ps.values())
unused_ps = {name: clock_ps - delay for name, delay in path_ps.items()}

assert clock_ps == 800
assert unused_ps["add"] == 250
assert unused_ps["lw"] == 0

assert program_time_ns == 800

复制加法器可让 PC+4、目标与主 ALU 并行，更快的内存与寄存器文件也有帮助。但单周期内存和导线延迟最终会限制扩展。多周期通过在操作间加寄存器缩短时钟，流水线再让不同指令的操作重叠。

多周期数据通路

多周期处理器把一条指令分成多个时钟状态转移。单周期中同时发生的操作现在位于不同周期，硬件因而可以复用：同一个 ALU 可在取指时递增 PC，之后计算有效地址，再在另一状态执行算术。

输入变化后中间值会消失，所以必须保存。常见内部寄存器包括：IR 保存当前指令，A/B 保存读出的寄存器值，ALUOut 保存算术、目标或地址，MDR 保存内存返回数据，oldPC 在 PC 已推进后支持相对计算。它们属于微体系结构状态，不是程序员可见寄存器。

指令类别 周期序列 近似 CPI
R 型/立即数 ALU IF、ID、EX-ALU、WB-ALU 4
加载 IF、ID、EX-ADDR、MEM-READ、WB-LOAD 5
存储 IF、ID、EX-ADDR、MEM-WRITE 4
分支 IF、ID、EX-BRANCH 3
jal IF、ID、EX-JUMP 3

时钟周期现在由最慢阶段加内部寄存器开销决定，而不是完整加载路径。程序时间仍为

\[ T_{program}=N\times CPI_{avg}\times T_{clk},\qquad CPI_{avg}=\sum_i f_iCPI_i. \]

\(f_i\) 是动态指令类别比例且总和为 1。更短 \(T_{clk}\) 与更大平均 CPI 相互竞争，多周期不自动更快。

Python 模型：指令混合与多周期执行时间 
cpi = {"alu": 4, "load": 5, "store": 4, "branch": 3, "jal": 3}
mix = {"alu": 0.45, "load": 0.25, "store": 0.10, "branch": 0.15, "jal": 0.05}

assert abs(sum(mix.values()) - 1.0) < 1e-12
average_cpi = sum(mix[name] * cpi[name] for name in mix)

single_cycle_ps = 800
multi_cycle_ps = 250
average_multi_instruction_ps = average_cpi * multi_cycle_ps

assert abs(average_cpi - 4.05) < 1e-12
assert average_multi_instruction_ps == 1012.5
assert average_multi_instruction_ps > single_cycle_ps

该数值例中，多周期虽然时钟短得多，每条指令反而更慢。优势在于资源复用、更现实的内存时序，以及支持可变延迟操作的顺序基础。流水线会保留短阶段并重叠不同指令，以提高吞吐量。

硬连线控制与微程序控制

单周期译码天然属于硬连线控制。多周期设计还需要状态机，可用两类方式实现。

硬连线控制用门、可编程逻辑阵列或综合 RTL 表示状态转移和输出，延迟通常较低，适合规则指令集，但修改复杂序列需要改动并重新验证逻辑。

微程序控制把微指令存入控制存储器。微程序计数器选出一条微指令，其比特驱动数据通路使能并选择下一微地址；一条体系结构指令可展开成多个内部微操作。

维度 硬连线控制 微程序控制
表示 布尔逻辑与 FSM 控制存储器加微序列器
控制延迟 通常较低 含控制存储与顺序访问
复杂序列 修改可能困难 自然表达为微指令序列
更新 改硬件/RTL 可能更新控制存储
常见用途 规则快速路径 复杂、少见、兼容或修正序列

两类并不互斥。现代核心可以硬连线常见指令，而以微码处理复杂操作、辅助、初始化或流片后修复。RISC-V 也不禁止微码实现。

Python 模型：小型微程序随时间发出控制字 
MICROCODE = {
    "IF": {
        "signals": {"MemRead": 1, "IRWrite": 1, "PCWrite": 1, "ALU": "PC+4"},
        "next": "ID",
    },
    "ID": {
        "signals": {"ReadRegs": 1, "ImmGen": 1},
        "dispatch": {"lw": "EX_ADDR", "add": "EX_ALU"},
    },
    "EX_ADDR": {
        "signals": {"ALUSrc": "IMM", "ALU": "ADD", "ALUOutWrite": 1},
        "next": "MEM_READ",
    },
    "MEM_READ": {
        "signals": {"MemRead": 1, "MDRWrite": 1},
        "next": "WB_LOAD",
    },
    "WB_LOAD": {
        "signals": {"ResultSrc": "MDR", "RegWrite": 1},
        "next": "IF",
    },
}


def control_sequence(opcode_name: str) -> list[dict]:
    state = "IF"
    emitted = []
    while True:
        microinstruction = MICROCODE[state]
        emitted.append(microinstruction["signals"])
        if state == "ID":
            state = microinstruction["dispatch"][opcode_name]
        else:
            state = microinstruction["next"]
        if state == "IF":
            return emitted

assert len(lw_sequence) == 5
assert lw_sequence[-1]["RegWrite"] == 1

微码低于体系结构指令层。软件仍只观察到一条 lw，内部控制序列是实现细节，除非时序或侧信道泄露它。

异常与精确体系结构状态

异常是当前指令引起的同步事件，例如非法编码、目标未对齐、环境调用或访存错误；中断是来自指令流外部的异步请求，例如定时器或设备事件。RISC-V 用陷阱（trap）统称两者引起的特权软件控制转移。

精确陷阱让软件观察到干净的指令边界：

  1. 所有更老指令的体系结构效果已完成；
  2. 需要重试或报告时，出错指令没有普通体系结构变化；
  3. 没有更年轻指令改变体系结构状态；
  4. 陷阱状态标明原因与控制转移位置。
CSR 机器级陷阱用途
mepc 定义处理或恢复位置的指令地址
mcause 中断标志及异常/中断原因编码
mtval 可选原因相关值，常为错误地址或指令位
mtvec 选择处理入口的基址与模式
mstatus 记录并改变特权/中断使能状态

同步错误的 mepc 通常指向出错指令；两条指令之间接收的中断则指向尚未执行、可恢复的下一点。具体规则由特权架构规定。

单周期核心中精确性较直接：边沿前检测陷阱、按优先级选原因并门控普通副作用。

\[ RegWrite_{final}=RegWrite_{decode}\land\neg Trap, \]

\[ MemWrite_{final}=MemWrite_{decode}\land\neg Trap, \]

\[ PC^{+}=\begin{cases} TrapVector,&Trap=1,\\ NormalNextPC,&Trap=0. \end{cases} \]

内存系统必须在加载写回或存储对外可见之前返回错误。若检测到多个条件，优先编码器选择体系结构规定的原因。陷阱后内部组合候选可能毫无意义，但没有普通写使能会捕获它们。

Python 模型：选择精确陷阱时抑制普通效果 
from dataclasses import dataclass


@dataclass(frozen=True)
class CommitDecision:
    next_pc: int
    register_write: tuple[int, int] | None
    memory_write: tuple[int, int] | None
    mepc: int | None
    mcause: str | None
    mtval: int | None


def finalize_load(
    pc: int,
    rd: int,
    loaded_value: int,
    address: int,
    access_fault: bool,
    mtvec: int,
) -> CommitDecision:
    """在正常加载提交与原子陷阱状态更新之间选择。"""
    if access_fault:
        return CommitDecision(
            next_pc=mtvec,
            register_write=None,
            memory_write=None,
            mepc=pc,
            mcause="load access fault",
            mtval=address,
        )
    return CommitDecision(
        next_pc=pc + 4,
        register_write=(rd, loaded_value),
        memory_write=None,
        mepc=None,
        mcause=None,
        mtval=None,
    )


fault = finalize_load(0x108, 5, 0, 0xDEAD0000, True, mtvec=0x80000000)
assert fault.next_pc == 0x80000000
assert fault.register_write is None
assert fault.mepc == 0x108
assert fault.mtval == 0xDEAD0000

多周期硬件可能在发现错误前改变内部寄存器，但它们不是体系结构状态，可以丢弃。流水线中多条指令并存，年轻指令还可能推测执行，精确性更难；第 07 章会加入排序、冲刷和提交规则来维持同一个干净边界。

本章小结。ISA 定义体系结构状态转移；数据通路提供候选值，控制单元只使能当前指令允许的变化。PC、寄存器文件、指令接口、ALU 与数据内存接口构成核心路径。RTL 区分持续计算的候选与边沿同步提交。单周期实现用 MUX 共享部件，在一个长周期完成 add、lw、sw、beq 或 jal。主控制译码指令类别，ALU 控制细化操作，立即数生成器重建分散字段。加载路径常限制单周期时钟；多周期控制以更高 CPI 换取短阶段与硬件复用，可采用硬连线或微程序顺序。精确陷阱最终抑制普通写入、记录原因与恢复状态，并在干净体系结构边界重定向执行。第 07 章将重叠不同指令的这些阶段，并处理由重叠产生的冒险。
