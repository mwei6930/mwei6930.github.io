虚拟内存与地址转换

第 08 章从物理地址出发，跟踪了它在缓存层次中的查找过程。真实程序通常不会直接产生物理地址：取指、load 或 store 首先生成虚拟地址，由内存管理单元（Memory-Management Unit, MMU）完成转换并检查访问权限，随后缓存与主存系统才可以服务该请求。

因此，虚拟内存不只是“RAM 不够时借用磁盘”的技术，而是处理器和操作系统共同实现的一项体系结构契约。硬件负责快速转换与权限检查；操作系统负责创建页表、决定哪些映射存在，并处理异常情况。本章重点就在这条软硬件边界上。

为什么需要虚拟内存

若没有虚拟内存，程序必须知道自己的字节实际位于哪些物理位置。装入多个程序时需要寻找互不重叠的物理区间；移动程序会使已保存的指针全部失效；一个程序还可能意外命名另一个程序的数据。物理碎片和不断变化的内存需求都会泄漏到普通应用逻辑中。

虚拟内存插入了一层间接映射。进程看到的是稳定且大体连续的地址空间，而页表可把其页面放到任意可用物理页框。这种间接性支持四个密切相关的目标：

  • 隔离： 私有映射阻止一个进程访问另一个进程的页框。
  • 重定位： 即使物理放置改变，虚拟地址也保持不变。
  • 按需分配： 未使用或暂时不活跃的虚拟页无需立即占用 RAM。
  • 受控共享： 不同进程可按指定权限映射到同一物理页框。

很大的虚拟地址空间并不代表可用内存无限。页面活跃时仍需要物理存储，页表、RAM、后备存储与操作系统策略也都存在实际限制。虚拟内存的价值在于以页面为单位管理分配和保护，而不是把固定物理地址暴露给程序。

Python 模型：同一虚拟地址可表示不同的物理字节 
PAGE_SIZE = 4096

# 每个进程拥有独立的虚拟页映射。
page_tables = {
    "A": {0x1: 12, 0x2: 27},
    "B": {0x1: 52, 0x2: 27},  # VPN 0x2 有意共享 PFN 27
}


def translate(process, virtual_address):
    vpn, offset = divmod(virtual_address, PAGE_SIZE)
    if vpn not in page_tables[process]:
        raise MemoryError("virtual page is not mapped")
    pfn = page_tables[process][vpn]
    return pfn * PAGE_SIZE + offset


same_va = 0x1008
assert translate("A", same_va) != translate("B", same_va)

shared_va = 0x2008
assert translate("A", shared_va) == translate("B", shared_va)
print(hex(translate("A", same_va)), hex(translate("B", same_va)))

虚拟地址空间与物理地址空间

虚拟地址空间是在某一个转换上下文中解释的一组地址。对用户进程而言，这个上下文通常由页表根与 ASID 或 PCID 等地址空间标识符共同确定。物理地址空间则是缓存层次、互连和内存控制器能够接受的地址集合。二者可以具有不同位宽和完全不同的布局。

单独的虚拟地址数值并不是全局唯一的内存位置。进程 A 和进程 B 都可以使用虚拟地址 0x12345ABC，但各自页表可能把它映射到不同页框；反过来，两个无关的虚拟地址也可有意映射到同一物理页框，以实现共享库、共享内存或内存映射文件。

上下文切换会改变当前转换上下文。简单处理器可能在页表根改变时清空进程专属 TLB 项；支持 ASID 标记的 TLB 则可同时保留多个进程的转换，并使用 (ASID, VPN) 而不是仅用 VPN 区分它们，从而在保持隔离的同时减少不必要的重新填充。

属性 虚拟地址空间 物理地址空间
由谁解释 进程与 MMU 转换上下文 缓存层次、互连和内存控制器
布局 私有、稀疏，由页表决定 有限且实际安装或体系结构可寻址的存储
两个进程中的相同数值 可以指向不同数据 指向同一个物理位置
空洞 未映射范围很常见 未实现或保留范围由平台决定
共享 多个虚拟映射可别名到同一页框 一个页框保存共享字节

页面、页框与地址转换

分页把虚拟空间划分为固定大小的页面（page），把物理内存划分为同样大小的页框（frame），二者都按页面大小对齐。转换用物理页号或页框号（PPN/PFN）替换虚拟页号（VPN），而页面内的字节偏移保持不变。

对页面大小 \(P\) 和虚拟地址 \(VA\)，

\[ VPN=\left\lfloor\frac{VA}{P}\right\rfloor,\qquad offset=VA\bmod P. \]

若页表把该 VPN 映射到物理页号 \(PPN\)，则

\[ PA=PPN\times P+offset. \]

其中，\(VA\) 是虚拟字节地址，\(PA\) 是物理字节地址，\(P\) 是每个页面/页框的字节数，offset 在转换前后指向相同的页内位置。正是页面对齐使这个偏移可以直接复用。

当 \(P=2^p\) 时，地址最低的 \(p\) 位就是偏移。4 KiB 页面有 \(4096=2^{12}\) 字节，所以 32 位虚拟地址可拆成 20 位 VPN 与 12 位页内偏移。

在这个例子中，0x12345ABC 得到 VPN 0x12345 和偏移 0xABC，映射 0x12345 -> 0x2BEEF 形成物理地址 0x2BEEFABC。硬件并不是对页号和偏移做普通加法；由于页框和页面均对齐，字段拼接即可得到同一结果。

Python 示例：拆分虚拟地址并构造物理地址 
def split_address(address, page_size):
    # divmod 同时返回页号和字节偏移。
    return divmod(address, page_size)


def make_physical_address(ppn, offset, page_size):
    if not 0 <= offset < page_size:
        raise ValueError("offset must remain inside one page")
    return ppn * page_size + offset


virtual_address = 0x12345ABC
page_size = 4 * 1024
vpn, offset = split_address(virtual_address, page_size)
physical_address = make_physical_address(0x2BEEF, offset, page_size)

assert vpn == 0x12345
assert offset == 0xABC
assert physical_address == 0x2BEEFABC
print(hex(vpn), hex(offset), hex(physical_address))

页面大小也存在权衡。大页面可提高 TLB 覆盖范围、减少页表项数量，但可能浪费分配末页中的未使用字节，缺页时搬运更多数据，并要求更大的连续对齐物理区域。因此，许多体系结构同时支持普通页面和一种或多种大页面。

页表

页表（page table）是驻留在内存中的数据结构，用来描述一个虚拟地址空间。特权寄存器保存其根地址；每个索引项可能指向下一层页表、提供最终物理页号，或表示当前映射无法使用。

页表遍历本身属于存储系统操作：页表项位于内存中，其读取也会经过缓存。四级遍历不一定产生四次 DRAM 访问，因为页表遍历缓存或普通数据缓存可能保存上层页表项；但它仍是一串相互依赖的查找，这正是处理器使用 TLB 缓存已完成转换的原因。

单级页表

单级页表把整个 VPN 作为一个数组索引。若虚拟地址有 \(v\) 位、页内偏移有 \(p\) 位，则页表需要

\[ N_{PTE}=2^{v-p} \]

个表项。每项占 \(E\) 字节时，内存成本为

\[ M_{flat}=2^{v-p}\times E. \]

\(N_{PTE}\) 是可能虚拟页的数量，\(v-p\) 是 VPN 位数，\(E\) 是 PTE 大小，\(M_{flat}\) 是平坦页表预留的内存。对于 32 位虚拟地址、4 KiB 页面和 4 字节 PTE，结果为 \(2^{20}\times4=4\) MiB/进程，即使该进程只映射了少量页面。

Python 示例：计算平坦页表的存储开销 
def flat_page_table_bytes(virtual_bits, page_size, pte_bytes):
    # 2 的幂页面会把 log2(page_size) 位留给偏移。
    offset_bits = page_size.bit_length() - 1
    if page_size != 1 << offset_bits:
        raise ValueError("page size must be a power of two")
    vpn_bits = virtual_bits - offset_bits
    return (1 << vpn_bits) * pte_bytes


size = flat_page_table_bytes(32, 4096, 4)
assert size == 4 * 1024 * 1024
print(f"{size / 1024**2:.0f} MiB per process")

平坦页表可直接索引，硬件概念简单，但其固定成本与巨大、稀疏的地址空间并不匹配。

多级页表

多级页表把 VPN 拆成多个索引。只有某个虚拟子区域中确实存在映射时，上层表项才指向下层表；因此，大段空洞可由一个无效的上层项表示，而无需保留成千上万个无效叶项。

同样在 32 位示例中，两级设计可以把地址拆为 10 位 L1 索引 | 10 位 L2 索引 | 12 位偏移。每项 4 字节时，每张表包含 \(2^{10}=1024\) 项，大小恰好为 4 KiB，因此每张表本身占一个页面。

对于 VA = 0x12345ABC，上层索引是 72，下层索引是 837，偏移为 0xABC。硬件先读取 root[72] 找到对应叶表，再读取 leaf[837] 获得最终 PPN 与权限。

Python 模型：遍历两级页表 
PAGE_SIZE = 4096
INDEX_MASK = 0x3FF  # 十个 1 位可选择 1024 个表项之一

# 这个小例子只分配了一张下级页表。
root = {
    72: {837: {"ppn": 0x2BEEF, "read": True, "write": True}},
}


def walk_two_levels(virtual_address):
    l1_index = (virtual_address >> 22) & INDEX_MASK
    l2_index = (virtual_address >> 12) & INDEX_MASK
    offset = virtual_address & 0xFFF

    leaf_table = root.get(l1_index)
    if leaf_table is None:
        raise MemoryError("no lower-level table for this virtual region")
    pte = leaf_table.get(l2_index)
    if pte is None:
        raise MemoryError("virtual page is not mapped")
    return pte["ppn"] * PAGE_SIZE + offset, (l1_index, l2_index)


pa, indices = walk_two_levels(0x12345ABC)
assert indices == (72, 837)
assert pa == 0x2BEEFABC
print(indices, hex(pa))

权衡很明确：层次结构在虚拟空间稀疏时节省内存，但 TLB 未命中可能需要多次相互依赖的 PTE 读取。若大型对齐映射适用，大页叶项可在较高层终止遍历，同时减少页表深度与 TLB 压力。

页表项

页表项（Page-Table Entry, PTE）不只保存页框号。它还记录表项是否可用、哪些特权级可使用、允许哪些操作，以及页面是否被访问或修改。不同体系结构中的位名和位置不尽相同，因此应理解字段职责，而不应假设一种通用二进制布局。

概念字段 用途 典型后果
有效/在内存 当前表项能否完成转换 清除时可能触发缺页，或表示未使用的子树
PPN/PFN 标识映射页框或下一层页表 叶映射中与偏移拼接
用户/监督者 限制当前特权模式 用户访问仅监督者页面会产生异常
读/写/执行 限制请求操作 支持只读代码、不可执行数据和保护页
已访问/引用 记录近期使用 帮助软件选择替换候选
脏/已修改 记录成功写入 告诉软件淘汰页面时是否需要写回
软件状态 保存操作系统自定义元数据 可标识写时复制、交换位置或记账状态

非叶 PTE 指向另一张页表页，叶 PTE 描述已映射页面。权限不仅要在页表遍历时检查，也必须在 TLB 命中时检查，因此 TLB 项会把保护信息与 PPN 一起缓存。

Python 模型：执行 PTE 权限检查 
from dataclasses import dataclass


@dataclass
class PTE:
    ppn: int
    present: bool
    user: bool
    read: bool
    write: bool
    execute: bool
    accessed: bool = False
    dirty: bool = False


def authorize(pte, mode, operation):
    if not pte.present:
        return "page-fault:not-present"
    if mode == "user" and not pte.user:
        return "page-fault:privilege"
    allowed = {"read": pte.read, "write": pte.write, "execute": pte.execute}
    if not allowed[operation]:
        return f"page-fault:{operation}-denied"

    # 成功访问会更新使用状态。
    pte.accessed = True
    if operation == "write":
        pte.dirty = True
    return "allowed"


data_page = PTE(0x2BEEF, True, True, True, True, False)
assert authorize(data_page, "user", "write") == "allowed"
assert data_page.accessed and data_page.dirty
assert authorize(data_page, "user", "execute") == "page-fault:execute-denied"
print(data_page)

转换后备缓冲区

转换后备缓冲区（Translation Lookaside Buffer, TLB）是一种小型相联缓存，保存最近使用的页地址转换。其键在概念上是 (ASID, VPN)，值包含 PPN、权限与状态信息。TLB 缓存的是页面映射到哪里，并不缓存请求的指令字节或数据字节。

TLB 命中时，MMU 无需遍历页表即可取得 PPN；TLB 未命中时，由硬件或特权软件处理程序查找页表。若找到有效叶 PTE，就填充 TLB 并继续原访问；只有映射缺失、无效或权限不允许时才产生缺页异常。因此，TLB miss 与 page fault 不是同义词。

图片来源：Arilou, Wikimedia Commons，采用 CC BY-SA 4.0 许可。原图用“page table miss”表示简化的页面不驻留路径；真实缺页还包括权限失败、延迟分配和写时复制。

TLB 能同时表示的虚拟内存范围称为 TLB 覆盖范围（TLB reach）：

\[ R_{TLB}=N_{entries}\times P. \]

若各表项映射不同页面，\(R_{TLB}\) 是可覆盖字节数，\(N_{entries}\) 是缓存转换数量，\(P\) 是页面大小。64 项 TLB 配合 4 KiB 页面可覆盖 256 KiB；同样 64 项若映射 2 MiB 大页，则可覆盖 128 MiB。大页面提高覆盖范围，但仍具有前述分配和碎片权衡。

处理器通常在流水线附近分别设置指令 TLB 和数据 TLB，有些还提供更大的共享二级 TLB。替换、相联度、ASID 容量、页面大小支持以及独立的读写执行权限都会影响行为。

Python 模型：支持 ASID 的 LRU TLB 
from collections import OrderedDict


class TLB:
    def __init__(self, entries):
        self.entries = entries
        self.lines = OrderedDict()

    def lookup(self, asid, vpn):
        key = (asid, vpn)
        if key not in self.lines:
            return None
        value = self.lines.pop(key)
        self.lines[key] = value  # 标记为最近使用
        return value

    def insert(self, asid, vpn, ppn):
        key = (asid, vpn)
        self.lines.pop(key, None)
        self.lines[key] = ppn
        if len(self.lines) > self.entries:
            self.lines.popitem(last=False)  # 淘汰最久未使用项


tlb = TLB(entries=2)
tlb.insert(asid=7, vpn=0x12345, ppn=0x2BEEF)
tlb.insert(asid=12, vpn=0x12345, ppn=0x01020)
assert tlb.lookup(7, 0x12345) == 0x2BEEF
assert tlb.lookup(12, 0x12345) == 0x01020
print(tlb.lines)

缺页异常与需求分页

缺页异常（page fault）是一种精确异常：当前地址转换或保护状态无法完成内存访问时，处理器记录足够的体系结构状态并把控制权交给操作系统。操作系统检查原因，修复映射或报告错误；若成功修复，故障指令会重新执行，从程序视角看就像该指令只是花了很长时间。

需求分页会有意让某些有效虚拟区域开始时处于不驻留状态。第一次访问触发缺页后，操作系统获取页框、准备内容、更新 PTE 与相关 TLB 状态，再重启指令。准备页面可能需要读取文件或交换区，也可能只是为新的匿名页填零，或为写时复制创建副本。因此，并不是每次缺页都会进行存储 I/O。

故障情形 映射含义 典型处理
匿名内存延迟分配 虚拟区域有效，但尚无页框 分配页框并填零
文件支持的需求页 文件映射有效，页面不驻留 读取所需文件页
已换出页面 原内容保存在 RAM 之外 从交换区或存储设备读回
写时复制 store 共享只读映射被标记为 COW 复制页框并安装私有可写 PTE
保护违规 操作与 R/W/X 或特权位冲突 拒绝访问或向进程发信号
未映射地址 不属于任何有效虚拟区域 拒绝访问，常表现为段错误

若没有空闲页框，还需要选择替换页面。脏页面在页框复用前必须保存其当前内容；干净的文件支持页可直接丢弃，因为之后能够再次读取。这些操作系统策略建立在体系结构提供的访问位与脏位之上。

Python 模型：分类并处理简化的缺页情形 
regions = {
    0x10: {"kind": "anonymous", "write": True, "present": False},
    0x20: {"kind": "file", "write": False, "present": False},
    0x30: {"kind": "cow", "write": False, "present": True},
}
next_free_ppn = iter([100, 101, 102])


def handle_access(vpn, operation):
    region = regions.get(vpn)
    if region is None:
        return "fatal:unmapped"

    if operation == "write" and not region["write"]:
        if region["kind"] != "cow":
            return "fatal:write-protection"
        # 写时复制建立私有可写页面。
        region.update(kind="anonymous", write=True, ppn=next(next_free_ppn))
        return "resolved:copy-on-write"

    if not region["present"]:
        region.update(present=True, ppn=next(next_free_ppn))
        return f"resolved:fill-{region['kind']}"
    return "hit:resident"


assert handle_access(0x10, "write") == "resolved:fill-anonymous"
assert handle_access(0x20, "read") == "resolved:fill-file"
assert handle_access(0x30, "write") == "resolved:copy-on-write"
assert handle_access(0x99, "read") == "fatal:unmapped"
print(regions)

保护、特权与共享

每次取指、load 与 store 都必须经过 MMU，因此地址转换也是执行保护检查的自然位置。一个页面可以只读、不可执行、仅监督者模式可访问，或作为保护区域完全不可访问；这些规则必须在请求获准影响体系结构状态前完成检查。

页面粒度也让共享具有选择性。两个进程可在不同虚拟地址映射同一个只读可执行页框，同时保持可写数据私有；若程序有意同步，共享内存页也可在双方进程中均为可写。写时复制则先把同一页框以只读方式映射到多个进程，第一次写入者触发异常并获得私有副本。

同一个物理页框可在不同虚拟映射中具有不同权限。权限属于“映射关系”，而不是 RAM 单元本身。这使共享库能在用户态可执行，内核别名具有不同特权，或同一文件在一个进程中只读、在另一个进程中采用私有写时复制。

安全性要求所有转换缓存与页表修改保持一致。撤销访问或重新映射页面后，特权软件必须使所有受影响处理器中的旧 TLB 项失效；否则，过期转换可能在 PTE 已改变后继续授权访问。

Python 模型：第一次 store 使一个共享页框发生写时复制 
frames = {27: bytearray(b"shared page")}
mappings = {
    "A": {"pfn": 27, "writable": False, "cow": True},
    "B": {"pfn": 27, "writable": False, "cow": True},
}


def write_first_byte(process, value):
    mapping = mappings[process]
    if not mapping["writable"]:
        if not mapping["cow"]:
            raise PermissionError("read-only mapping")
        # 故障处理程序先分配并复制，再授予写权限。
        new_pfn = max(frames) + 1
        frames[new_pfn] = bytearray(frames[mapping["pfn"]])
        mapping.update(pfn=new_pfn, writable=True, cow=False)
    frames[mapping["pfn"]][0] = value


write_first_byte("A", ord("S"))
assert mappings["A"]["pfn"] != mappings["B"]["pfn"]
assert frames[mappings["A"]["pfn"]] == bytearray(b"Shared page")
assert frames[mappings["B"]["pfn"]] == bytearray(b"shared page")
print(mappings)

完整的 TLB—缓存—内存访问路径

完整访问路径把本章的地址转换机制与第 08 章的缓存层次连接起来。对于典型的物理标记缓存，概念流程如下：

  1. 指令产生虚拟地址和操作类型。
  2. 从虚拟地址中分离页内偏移与 VPN。
  3. TLB 查询 (ASID, VPN) 并检查权限。
  4. TLB 未命中时，MMU 遍历页表；有效叶项填充 TLB，不可用映射则产生缺页异常。
  5. PPN 与保持不变的页内偏移组成物理地址。
  6. 缓存检查物理数据块；缓存未命中继续前往更低级缓存，必要时访问 DRAM。

这些步骤会产生相互独立的结果。TLB 未命中后，页表遍历可以给出有效物理地址，而目标块恰好在缓存中；TLB 命中后，目标数据块也可能不在缓存。缺页则会在请求的数据访问完成前停止它，尽管页表遍历本身可能已经产生了缓存流量。

现代 L1 常使用虚拟索引、物理标记（Virtually Indexed, Physically Tagged, VIPT）组织，让一部分地址转换与缓存索引并行。由于转换不改变页内偏移，只要索引位全部取自偏移，TLB 返回 PPN 前就可以选择集合。常用设计条件为

\[ S\times B\le P, \]

其中 \(S\) 是集合数，\(B\) 是缓存块大小，\(P\) 是页面大小。\(S\times B\) 等于每一路的缓存容量；它不超过一页时，所有集合索引位都位于不变的页内偏移中，于是缓存读取集合的同时，物理标记可从 TLB 到达。更激进的设计需要额外处理虚拟别名。

转换结果 缓存结果 含义
TLB 命中 缓存命中 常见快速路径：转换与数据均已缓存
TLB 未命中，有效 PTE 缓存命中 需要重建转换，但数据块已驻留
TLB 命中 缓存未命中 转换可用，数据需从下层缓存或 DRAM 取得
缺页异常 请求的数据查找未完成 软件必须先修复或拒绝该映射
Python 模型：区分 TLB、缓存与缺页结果 
class TranslationCachePath:
    def __init__(self, page_table, page_size=4096, block_size=64):
        self.page_table = page_table
        self.page_size = page_size
        self.block_size = block_size
        self.tlb = {}
        self.cache_blocks = set()

    def access(self, virtual_address):
        vpn, offset = divmod(virtual_address, self.page_size)
        tlb_hit = vpn in self.tlb

        if tlb_hit:
            ppn = self.tlb[vpn]
        else:
            ppn = self.page_table.get(vpn)
            if ppn is None:
                return {"page_fault": True, "tlb_hit": False, "cache_hit": None}
            self.tlb[vpn] = ppn  # 成功页表遍历会填充 TLB

        physical_address = ppn * self.page_size + offset
        block = physical_address // self.block_size
        cache_hit = block in self.cache_blocks
        self.cache_blocks.add(block)  # 对每次未命中模拟一次填充
        return {
            "page_fault": False,
            "tlb_hit": tlb_hit,
            "cache_hit": cache_hit,
            "physical_address": physical_address,
        }


system = TranslationCachePath({0x12345: 0x2BEEF, 0x22222: 0x2BEEF})
results = [
    system.access(0x12345000),  # TLB 未命中，缓存未命中
    system.access(0x12345004),  # TLB 命中，同一缓存块命中
    system.access(0x22222000),  # TLB 未命中，别名物理块命中
    system.access(0x22222080),  # TLB 命中，不同缓存块未命中
    system.access(0x33333000),  # 无映射：缺页异常
]

assert [(r["page_fault"], r["tlb_hit"], r["cache_hit"]) for r in results] == [
    (False, False, False),
    (False, True, True),
    (False, False, True),
    (False, True, False),
    (True, False, None),
]
print(results)

转换性能与内存开销

地址转换从三个尺度影响性能：页表占用内存，TLB 未命中增加普通访问延迟，缺页则较少发生却可能带来极大延迟。把三个尺度分开分析，可以避免误导性的平均值。

对于不发生缺页的访问，一个简化平均模型是

\[ EAT_{normal}=hT_{hit}+(1-h)T_{miss}. \]

\(EAT_{normal}\) 是普通驻留访问的有效时间，\(h\) 是 TLB 命中率，\(T_{hit}\) 是完整 TLB 命中路径，\(T_{miss}\) 包括页表遍历、TLB 填充和请求缓存访问。该公式刻意保持抽象，因为每次 PTE 读取可能命中不同缓存层级，处理器也可能重叠部分遍历。

加入缺页概率 \(p\) 后可另写为

\[ EAT=(1-p)T_{normal}+pT_{fault}. \]

\(T_{normal}\) 是驻留路径，\(T_{fault}\) 则包含陷阱处理以及解决故障所需的一切工作。若 \(T_{normal}=100\) ns，而一次需要存储设备的缺页耗时 8 ms，要使平均值低于 200 ns，必须近似满足

\[ p\le\frac{200-100}{8{,}000{,}000-100}\approx1.25\times10^{-5}. \]

也就是说，大约每 80,000 次内存访问最多发生一次这种故障。具体数值随系统而异，但数量级差距说明持续换页足以支配整个执行时间。

页表内存也必须计入成本。平坦页表为所有可能 VPN 付费；多级页表只为根和已经分配的下层页付费。大页面减少叶项数量、提高 TLB 覆盖范围，却可能增加内部碎片，并使连续分配更困难。

机制 主要收益 主要成本或限制
更大或更高相联的 TLB 减少替换与冲突未命中 面积、能量和查找复杂度增加
ASID/PCID 标记 上下文切换后仍可保留转换 标识符数量有限，失效处理更复杂
页表遍历缓存 避免反复读取上层 PTE 不像 TLB 那样缓存所有叶转换
多级页表 只为已使用区域分配元数据 未缓存遍历需要更多依赖读取
大页面 增加 TLB 覆盖并缩短遍历 碎片、对齐以及升降级成本
需求分页 不装入从未使用的页面 首次使用触发异常，可能需要慢速 I/O
Python 示例：比较 TLB 覆盖范围与缺页敏感度 
def tlb_reach(entries, page_bytes):
    return entries * page_bytes


def effective_access_time(normal_ns, fault_ns, fault_probability):
    return (1 - fault_probability) * normal_ns + fault_probability * fault_ns


small_page_reach = tlb_reach(64, 4 * 1024)
huge_page_reach = tlb_reach(64, 2 * 1024 * 1024)
assert small_page_reach == 256 * 1024
assert huge_page_reach == 128 * 1024 * 1024

normal_ns = 100
fault_ns = 8_000_000
target_ns = 200
max_fault_probability = (target_ns - normal_ns) / (fault_ns - normal_ns)

assert effective_access_time(normal_ns, fault_ns, max_fault_probability) == target_ns
print(f"4 KiB reach: {small_page_reach / 1024:.0f} KiB")
print(f"2 MiB reach: {huge_page_reach / 1024**2:.0f} MiB")
print(f"maximum storage-backed fault probability: {max_fault_probability:.3e}")

本章总结。 虚拟内存为每个进程提供受保护的地址空间，其中页面可重定位、按需分配并有意共享。MMU 把虚拟地址拆为 VPN 与页内偏移，通过页表或 TLB 缓存项转换 VPN，执行特权与 R/W/X 权限检查，再把 PPN 与不变偏移组成物理地址。平坦页表可以直接索引但固定占用空间；多级页表利用地址空间的稀疏性，代价是相互依赖的遍历。TLB 未命中请求重新查找“转换”，缓存未命中请求“数据块”，缺页则因当前映射无法完成访问而把控制交给软件。性能取决于页表内存、TLB 覆盖、遍历延迟，以及数量级更大的存储型缺页成本。第 10 章将继续讨论设备搬运数据所需的 I/O、中断、DMA 与存储机制，它们也会最终服务某些缺页路径。
