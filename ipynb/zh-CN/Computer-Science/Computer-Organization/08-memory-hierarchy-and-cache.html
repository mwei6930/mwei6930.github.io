存储层次与缓存

第 07 章把取指和访存阶段简化为：一条指令或一个数据字通常能在一个周期内到达。这个假设是理想五级流水线成立的基础，但容量很大的主存通常无法满足处理器最短的时钟周期。若每次 IF 请求和每条 load 都直接等待 DRAM，流水线停顿的时间将远多于真正执行指令的时间。

缓存（cache）是一种小而快的结构，用来保存部分内存块的副本。它对普通程序语义透明：无论一次 load 命中 L1、命中更低级缓存，还是最终访问 DRAM，都必须返回相同的体系结构值。缓存改变的是“从哪里、何时找到数据”，而不是软件有权观察到的数据内容。

本章讨论缓存的物理组织及其性能影响。地址转换、页表与 TLB 留到第 09 章介绍；在此之前，示例都使用物理地址，或者等价地假设地址转换已经给出了缓存查找所需的地址。

为什么计算机需要存储层次

存储系统同时面对相互冲突的目标。处理器希望延迟低，使依赖指令尽快继续；带宽高，使多条指令能够同时取得数据；容量大，容纳活跃程序；同时还要求能耗低、单位比特成本低。没有一种存储技术能够把这些属性同时做到最好。

存储层次能够工作，是因为上层无需保存全部内存，只需保存近期很可能使用的工作集（working set）。寄存器保存当前操作数；分离的 L1 指令缓存和数据缓存分别服务流水线的两类请求；更低级缓存保留更大的近期工作集；DRAM 提供大得多的容量。完整系统中，持久存储位于主存下方，但它不是每次 load 的普通缓存命中路径。

层级 首要设计目标 未命中的典型后果
寄存器 立即取得操作数 指令必须移动或重新计算该值
L1I / L1D 最短的常见命中路径与高局部带宽 请求继续前往下一级缓存
L2 / 末级缓存 减少昂贵的主存流量 更长的片上查找，或发起 DRAM 请求
DRAM 大容量易失性工作空间 若页面不在内存，可能需要操作系统与存储设备参与

因此，存储层次优化的是常见情况：大多数访问应在靠近处理器的位置结束，少数未命中才承担更长路径。命中时间很短但命中率很低的缓存仍可能性能很差；容量很大但拖慢处理器时钟的缓存，也可能得不偿失。容量、相联度、块大小、替换策略和写策略会共同决定结果。

时间局部性与空间局部性

引用局部性（locality of reference）是程序在短时间内倾向于使用有限范围内指令和数据的经验规律，而不是 ISA 提供的保证。循环、过程调用、栈操作、顺序取指、数组遍历以及对活跃对象的反复访问都会产生局部性。

时间局部性表示最近访问过的对象很可能再次被访问。例如，循环会重复执行同一段指令并更新同一个计数器；只要缓存保留这些块，后续访问就能命中。空间局部性表示程序很可能访问近期地址附近的位置。一次传入对齐的数据块，会在程序逐个请求之前就带来相邻指令或数组元素。

缓存真正管理的是块，而不是源代码中的变量。若一个 64 字节块可容纳八个 8 字节整数，顺序遍历只需一次下层传输便能使用八个元素；若步长为 64 字节，则每个元素都落在不同块中，传回块内其余字节都未被利用。一个从不复用、但邻近字节都被使用的块仍体现空间局部性；同一块被反复访问则体现时间局部性。

复用距离（reuse distance）是两次访问同一块之间出现过的不同块数量。复用距离较小，意味着规模不大的缓存也可能保留该块；当复用距离超过目标集合可容纳的有效行数，或超过整个缓存的有效工作容量时，块很可能在再次使用前被淘汰。

Python 示例：比较顺序访问与跨步访问的块足迹 
def block_trace(addresses, block_size):
    """把字节地址转换为缓存实际观察到的内存块编号。"""
    return [address // block_size for address in addresses]


base = 0x1000
element_size = 8
block_size = 64

# 八个相邻的 64 位值都位于同一个 64 字节块中。
sequential = [base + i * element_size for i in range(8)]

# 八个彼此相隔一个完整块的值会占用八个不同块。
strided = [base + i * block_size for i in range(8)]

sequential_blocks = block_trace(sequential, block_size)
strided_blocks = block_trace(strided, block_size)

assert len(set(sequential_blocks)) == 1
assert len(set(strided_blocks)) == 8
print("sequential blocks:", sequential_blocks)
print("strided blocks:   ", strided_blocks)

局部性解释了缓存为什么有效，也解释了它何时失效。流式扫描远大于缓存的数据集具有空间局部性，却几乎没有时间复用；在被强制映射到同一集合的地址之间交替访问，即使缓存总体仍有空闲空间，也会因为冲突破坏局部性。

缓存块与地址分解

缓存将内存区域划分为固定大小的块（block），也称缓存行（cache line）。一个块表示连续且自然对齐的地址范围，其大小通常是 2 的幂。如果块大小为 \(B\) 字节，字节地址 \(A\) 属于

\[ BlockNumber=\left\lfloor\frac{A}{B}\right\rfloor, \qquad BlockOffset=A\bmod B. \]

  • \(A\) 是请求的字节地址。
  • \(B\) 是作为一个整体复制和管理的字节数。
  • BlockNumber 标识对齐的内存区域。
  • BlockOffset 标识该区域中的目标字节。

组相联缓存把数据容量划分为若干集合（set）和路（way）。设数据容量为 \(C\) 字节、块大小为 \(B\)、每组相联度为 \(E\) 路，则集合数为

\[ S=\frac{C}{B\times E}. \]

当各尺寸均为 2 的幂，且地址宽度为 \(m\) 位时，

\[ b=\log_2 B,\qquad s=\log_2 S,\qquad t=m-s-b, \]

其中 \(b\)、\(s\)、\(t\) 分别是块内偏移、集合索引和标记的位数。本章持续使用的例子为 \(C=32\) KiB、\(B=64\) 字节、\(E=4\)、\(m=32\)，因此共有 128 个集合，偏移 6 位、索引 7 位、标记 19 位。

Python 示例：计算缓存几何参数并分解地址 
from math import log2


def cache_fields(address, address_bits, capacity_bytes, block_bytes, ways):
    """返回 2 的幂缓存的几何参数与 tag/index/offset 数值。"""
    sets = capacity_bytes // (block_bytes * ways)
    offset_bits = int(log2(block_bytes))
    index_bits = int(log2(sets))
    tag_bits = address_bits - index_bits - offset_bits

    offset = address & (block_bytes - 1)
    index = (address >> offset_bits) & (sets - 1)
    tag = address >> (offset_bits + index_bits)

    return {
        "sets": sets,
        "tag_bits": tag_bits,
        "index_bits": index_bits,
        "offset_bits": offset_bits,
        "tag": tag,
        "index": index,
        "offset": offset,
    }


fields = cache_fields(
    address=0x1234ABCD,
    address_bits=32,
    capacity_bytes=32 * 1024,
    block_bytes=64,
    ways=4,
)

assert fields == {
    "sets": 128,
    "tag_bits": 19,
    "index_bits": 7,
    "offset_bits": 6,
    "tag": 0x91A5,
    "index": 47,
    "offset": 13,
}
print(fields)

产品所标注的缓存容量通常只统计数据字节，不包括标记、有效位、脏位、纠错位与替换元数据。这些附加结构仍会占用面积和能量，因此提高相联度并不是免费的。

标记

标记（tag）保存当前占据某一路的内存块高位身份。索引只能选中一个集合，而许多不同内存块都可能映射到该集合；标记用来区分其中究竟保存了哪一个块。

对于第 \(w\) 路，一次读命中在概念上表示为

\[ Hit_w=Valid_w\land(Tag_w=RequestedTag). \]

  • 复位或失效后，\(Valid_w\) 为假，表示该行不包含可用数据块。
  • \(Tag_w\) 是与第 \(w\) 路数据块一起保存的身份。
  • RequestedTag 来自请求地址的高位。
  • 组相联缓存的命中是各路命中信号的 OR；正常情况下最多只有一个有效路匹配。

有效位不可省略，因为 SRAM 上电后的任意内容可能碰巧等于请求标记。脏位承担的是另一种职责：它表示写回缓存行中是否含有尚未向下传播的修改。脏状态影响淘汰过程，但不决定目标块是否存在。

地址更宽或块更小时，标记存储通常会增加；路数更多时，也要并行读取和比较更多标记。设计者可能通过分级比较或预测保护命中延迟，但基本的身份检查不变。

索引

索引（index）精确选择一个缓存集合。在 2 的幂缓存中，它是紧邻块内偏移上方的一段连续位。等价地，

\[ SetIndex=BlockNumber\bmod S. \]

在本章示例中，\(S=128\)，所以索引 47 会选中集合 47 中的四个标记/数据项；请求块只能位于这四路之一。其他集合无需激活，相比把请求标记与全部缓存行比较，这减少了查找工作。

索引同时带来了放置限制。块编号相差 \(S\) 的整数倍时，它们拥有相同索引；若这些块同时活跃，就会争用同一集合的 \(E\) 路，即使其他集合仍为空。这种碰撞会造成冲突未命中。

索引查找类似数组选择，因此速度很快；但选中的集合必须足够早地就绪，使标记比较和数据选择能装入缓存命中关键路径。第 09 章将解释地址转换如何与该时序交互，本章则有意使用已经确定的缓存地址。

块内偏移

块内偏移（block offset）由最低的 \(b=\log_2B\) 个地址位构成，用来选择匹配块中的某个字节或字，并不决定缓存的是哪一个块。块大小为 64 字节时，偏移为 6 位，范围是 0 到 63。

地址 0x1234ABCD 的偏移为 13，因此它请求的是以下对齐块起始地址后的第 13 个字节：

\[ BlockBase=A-(A\bmod B)=\texttt{0x1234ABC0}. \]

缓存可以在标记比较时读取整路数据块或一个存储体，再根据偏移和访问大小选择所需字节。若一条 load 跨越块边界，其字节属于不同标记，甚至不同集合，因而可能需要两次缓存行访问。

块大小本身存在权衡。更大的块可利用更多空间局部性，并在容量固定时减少标记项数量；但它也会延长传输、在未命中时占用更多带宽、减少能独立保留的块数量，并可能取回永远不会使用的字节。

缓存映射

映射（mapping）规定一个内存块允许放在缓存的哪些位置。具有 \(S\) 个集合、每组 \(E\) 路的缓存共有 \(S\times E\) 条数据行。每个块先映射到一个集合，再选择该集合中的任意一路。因此，直接映射、组相联和全相联是同一连续设计空间中的不同点，而不是互不相关的结构。

组织方式 集合数 每组路数 选中集合内的标记比较次数 替换选择
直接映射 行数 1 1 无选择，必须使用索引行
\(E\) 路组相联 行数 / \(E\) \(E\) \(E\) 在集合内选择一路
全相联 1 总行数 每一行 可选择任意一行

提高相联度通常能减少放置冲突，但会增加标记比较、路选择逻辑、替换元数据与能耗。最佳选择取决于访问模式以及该级缓存可接受的延迟预算。

直接映射缓存

直接映射缓存每个集合只有一路。内存块 \(n\) 必须使用

\[ line=n\bmod L, \qquad tag=\left\lfloor\frac{n}{L}\right\rfloor, \]

其中 \(L\) 是缓存行数。它只需一次标记比较，不需要替换策略，因此命中路径短而简单。

严格放置也会导致来回抖动。在四行缓存中，块 0 与块 4 都映射到行 0；访问序列 0, 4, 0, 4 每次都会未命中，因为每次访问都淘汰下一次所需的块，而第 1 到第 3 行始终闲置。

Python 模型：跟踪直接映射缓存 
def direct_mapped_trace(blocks, line_count):
    """返回每次访问的命中/未命中决策以及最终标记状态。"""
    tags = [None] * line_count
    events = []

    for block in blocks:
        line = block % line_count
        tag = block // line_count
        hit = tags[line] == tag
        events.append((block, line, tag, "hit" if hit else "miss"))
        if not hit:
            tags[line] = tag

    return events, tags


events, tags = direct_mapped_trace([0, 4, 0, 4], line_count=4)
assert [event[-1] for event in events] == ["miss"] * 4
assert tags == [1, None, None, None]  # 块 4 最终留在行 0
print(*events, sep="\n")

当短命中时间的收益大于冲突成本时，直接映射仍然很有效，尤其适合容量小、延迟关键的结构或放置行为温和的工作负载。

组相联缓存

\(E\) 路组相联缓存允许一个块占据其索引集合中的任意 \(E\) 路。两路缓存可以让两个发生索引碰撞的块共存，四路缓存则可以保留四个。集合仍由 \(BlockNumber\bmod S\) 选择，所以只需搜索该集合中的路。

命中时通常并行比较所有路的标记，再由多路选择器选出匹配数据。未命中时优先使用无效路；若所有路均有效，则由替换策略选择牺牲者。本章的 32 KiB 缓存共有 128 个集合、每组四路，因此同样拥有七位索引的四个块可以同时驻留。

组相联是直接映射的短查找路径与全相联的放置自由之间最常见的折中。相联度越高，冲突未命中通常越少，但收益会递减，而比较器、多路选择器和替换网络的成本持续增加。

全相联缓存

全相联缓存只有一个集合，其中包含全部缓存行，因此不存在索引字段，整个块身份都作为标记。任意新块可放入任意行，所以放置限制不会造成冲突未命中；容量未命中和强制未命中仍然存在。

代价是必须在所有有效标记中进行关联搜索，并在整个结构中选择替换行。因此，全相联更适合小型结构或特殊缓冲区，而不适合大型一级数据阵列。

Python 模型：比较单路、两路与四路放置 
class SetAssociativeCache:
    """使用块编号而非字节地址的小型 LRU 缓存模型。"""

    def __init__(self, line_count, ways):
        if line_count % ways != 0:
            raise ValueError("ways must divide line_count")
        self.ways = ways
        self.sets = [[] for _ in range(line_count // ways)]

    def access(self, block):
        entries = self.sets[block % len(self.sets)]
        if block in entries:
            entries.remove(block)
            entries.insert(0, block)  # 最近使用的块放在最前
            return True
        if len(entries) == self.ways:
            entries.pop()            # 淘汰最久未使用的块
        entries.insert(0, block)
        return False


trace = [0, 4, 0, 4]
misses = {}

for ways, label in [(1, "direct"), (2, "two-way"), (4, "fully")]:
    cache = SetAssociativeCache(line_count=4, ways=ways)
    misses[label] = sum(not cache.access(block) for block in trace)

assert misses == {"direct": 4, "two-way": 2, "fully": 2}
print(misses)

无论采用哪种组织，两块所表示的数据完全相同。相联度只改变它们能否同时驻留，以及查找这些副本需要多少硬件。

替换策略

当一次未命中选中了已经填满的集合时，替换策略（replacement policy）决定淘汰哪条有效缓存行。直接映射缓存没有选择，索引行就是唯一牺牲者；相联缓存若存在无效路，会首先使用它，因为填充空闲位置不会丢失任何已缓存数据。

策略 使用的状态 直觉 局限
LRU 最近使用顺序 最近使用的块可能很快再次使用 路数较多时，精确维护成本高
伪 LRU 压缩的方向位或状态位 用较少硬件近似 LRU 可能选择并非最久未使用的牺牲者
FIFO 插入顺序 移除最早进入的驻留块 命中时不考虑复用
随机 伪随机路号 避免顺序元数据和系统性模式 可能淘汰热点行
最优/Belady 未来访问序列 淘汰未来最晚才会使用的块 在线实现不可能，只能用作理论上界
Python 示例：在同一集合访问序列上比较 LRU 与 FIFO 
from collections import deque


def replacement_trace(accesses, capacity, policy):
    """返回每次访问后的驻留顺序和被淘汰块。"""
    resident = deque()
    events = []

    for block in accesses:
        evicted = None
        hit = block in resident

        if hit and policy == "LRU":
            resident.remove(block)
            resident.appendleft(block)
        elif not hit:
            if len(resident) == capacity:
                evicted = resident.pop()
            resident.appendleft(block)

        events.append((block, hit, evicted, tuple(resident)))

    return events


trace = list("ABCAD")
lru = replacement_trace(trace, capacity=3, policy="LRU")
fifo = replacement_trace(trace, capacity=3, policy="FIFO")

assert lru[-1][2] == "B"
assert fifo[-1][2] == "A"
print("LRU final:", lru[-1])
print("FIFO final:", fifo[-1])

替换本质上是一项预测任务：控制器试图保留那些在下一次淘汰机会到来前仍有价值的块。没有任何在线策略能在所有访问模式中占优，所以实现成本和工作负载行为与策略名称同样重要。

写策略

load 只需找到当前数据副本；store 则带来另一项责任：存储层次必须决定现在修改哪个副本、何时把新值送到下层，以及目标块缺失时如何处理。两个相互独立的策略维度分别回答这些问题。

即使 store 只改变一个字节，策略仍按数据块管理。字节使能信号负责更新缓存行中的选定字节；写回缓存必须保留其余字节，并最终把整个块或硬件支持的部分更新传送到下一级。

写直达与写回

采用写直达（write-through）时，每次 store 命中都会同时更新当前缓存和下一级，因此下层能及时收到修改，缓存行也不会仅因为这次 store 而需要在淘汰时写回。代价是每条 store 都会产生下层流量。写缓冲区可以让流水线与一部分写延迟解耦，但缓冲区一旦填满，仍会迫使流水线停顿。

采用写回（write-back）时，store 命中只更新当前缓存行并设置脏位，下层内存可暂时保留旧值。当脏行被淘汰时，缓存先把它写到下一级，再安装替换块。因此，对同一驻留行的多次 store 可以合并为一次写回传输。

\[ EvictionCost= \begin{cases} WriteBlock+ReadReplacement, & dirty=1,\\ ReadReplacement, & dirty=0. \end{cases} \]

这些项表示传输操作，而不是通用的固定周期数；实际延迟取决于下层队列、带宽以及写操作能否与读操作重叠。

Python 模型：比较写直达与写回处理重复 store 的流量 
def repeated_store_traffic(store_count, policy, evict_after=True):
    """统计对同一驻留行重复命中时产生的下层写次数。"""
    dirty = False
    lower_writes = 0

    for _ in range(store_count):
        if policy == "write-through":
            lower_writes += 1
        elif policy == "write-back":
            dirty = True
        else:
            raise ValueError("unknown policy")

    if policy == "write-back" and dirty and evict_after:
        lower_writes += 1
        dirty = False

    return lower_writes, dirty


assert repeated_store_traffic(3, "write-through") == (3, False)
assert repeated_store_traffic(3, "write-back") == (1, False)
print("three stores: 3 lower writes versus 1 write-back on eviction")

写回减少了流量，却也让脏行状态成为正确性的一部分。故障、冲刷、一致性请求或缓存块管理操作都不能悄悄丢弃系统中唯一的最新副本。

写分配与非写分配

store 未命中时，写分配（write-allocate）会读取包含目标地址的数据块，将其安装到缓存，再执行 store。它需要支付类似“读以获得所有权”的未命中成本，但之后对同一块或邻近字节的访问很可能命中。当 store 具有局部性时，它自然适合与写回组合。

非写分配（no-write-allocate）也称写绕过（write-around），会把 store 直接发送到下一级，而不把缺失块装入当前缓存。对于只写一次的流式输出，这能避免缓存被无复用价值的数据污染；但之后对同一地址的 load 仍会未命中，除非其他机制已经把块带入。

未命中后的预期行为 更适合的倾向
重复 store 或读取邻近字节 写分配保留该块
单次流式输出 非写分配避免缓存污染
写回缓存中的部分字节 store 先分配，以正确保留未修改字节
写缓冲带宽充足 写直达/非写分配更容易承受

写直达配合非写分配、写回配合写分配是常见组合，但不是体系结构定律。不同缓存层级可以采用不同策略，专门的非临时操作也可请求面向流式数据的行为。

缓存未命中

当选中集合中存在有效且标记匹配的缓存行时，访问命中（hit）；若请求块不在该缓存中，则发生未命中（miss），请求必须继续向下。未命中惩罚可能包括下层查找、写回脏牺牲行、传输新块、安装缓存行，以及重新启动等待中的访问。

经典的 3C 模型通过把目标缓存与若干理想参考缓存比较，将未命中按原因分类。不同类别对应不同原因，也提示不同的改进方法。

这个分类是一种分析概念，不是普通缓存硬件为每次访问保存的字段。性能工具或模拟器会记录首次访问，并比较不同组织方式，从而对访问序列分类。

强制未命中

强制未命中（compulsory miss）也称冷未命中，是测量期间第一次访问某个块。任何初始为空的缓存都不可能预先包含它。块被取回后，只要放置与替换策略没有过早淘汰它，后续访问就可能命中。

如果程序很快访问邻近字节，更大的块可使一次强制传输覆盖多个后续请求，从而减少需求未命中次数；代价是更多带宽、更长填充时间与更少的独立缓存行。硬件或软件预取能让传输早于实际需求发生，把可见延迟转化为推测流量，但并未让第一次传输凭空消失。

强制未命中还取决于测量边界。热缓存可能保留先前执行留下的块，而冷缓存实验会有意从空状态开始；有意义的比较必须说明采用哪一种初始条件。

容量未命中

当总活跃工作集超过缓存容量时，就产生容量未命中（capacity miss）。在行数、块大小和参考替换策略相同的全相联缓存中，它仍然会发生；增加放置自由也无济于事，因为有价值的不同块数量超过了总行数。

访问序列 A, B, C, D, A 在三行全相联缓存中，最后一次访问 A 就是容量未命中：复用前已有四个不同块进入活跃集合。只增加相联度而不增加缓存行，无法让四个块同时容纳。

增大数据容量、缩短复用距离，或每次只处理更小工作集，都能减少容量未命中。循环分块是典型的软件方法：先在一块适合缓存的区域上完成更多工作，再移动到下一块区域。

冲突未命中

冲突未命中（conflict miss）源于目标缓存的集合放置限制：一个仍有价值的块被迫淘汰，而在总容量相同的全相联缓存中它本可继续保留。直接映射序列 0, 4, 0, 4 主要由冲突导致，因为两个块都坚持使用行 0，而其他行保持空闲。

更高相联度、牺牲缓存、替代索引方式或改变数据对齐都可以减少冲突。增加总容量有时也会改变索引位，顺带分离碰撞地址，但冲突未命中的定义性原因是放置限制，而不是总行数不足。

Python 模型：使用 3C 方法分类访问序列 
class LRUBlockCache:
    def __init__(self, line_count, ways):
        self.ways = ways
        self.sets = [[] for _ in range(line_count // ways)]

    def access(self, block):
        entries = self.sets[block % len(self.sets)]
        hit = block in entries
        if hit:
            entries.remove(block)
        elif len(entries) == self.ways:
            entries.pop()
        entries.insert(0, block)
        return hit


def classify_3c(trace, line_count, target_ways):
    """把目标缓存与同容量全相联 LRU 缓存进行比较。"""
    target = LRUBlockCache(line_count, target_ways)
    fully_associative = LRUBlockCache(line_count, line_count)
    seen = set()
    counts = {"compulsory": 0, "capacity": 0, "conflict": 0}

    for block in trace:
        target_hit = target.access(block)
        full_hit = fully_associative.access(block)

        if not target_hit:
            if block not in seen:
                counts["compulsory"] += 1
            elif not full_hit:
                counts["capacity"] += 1
            else:
                counts["conflict"] += 1
        seen.add(block)

    return counts


trace = [0, 4, 0, 1, 2, 3, 4, 0]
counts = classify_3c(trace, line_count=4, target_ways=1)
assert counts == {"compulsory": 5, "capacity": 2, "conflict": 1}
print(counts)

在多核系统中，另一个核心使缓存行失效还会产生一致性未命中，这个第四类原因将在第 11 章讨论。本章的 3C 模型只描述没有一致性失效的单一请求流。

平均存储访问时间

平均存储访问时间（Average Memory Access Time, AMAT）把快速命中路径与较慢未命中路径合并为一个期望值。当“未命中惩罚”表示完成缓存命中检查后新增的时间时，

\[ AMAT=T_{hit}+r_m\times P_m. \]

  • \(T_{hit}\) 是每次访问都要支付的时间，包括选择集合、比较标记以及命中后返回数据。
  • \(r_m\) 是未命中率，即在当前缓存未命中的访问比例。
  • \(P_m\) 是确认未命中后额外支付的平均惩罚。

若命中时间为 1 ns、未命中率为 5%、额外惩罚为 60 ns，则

\[ AMAT=1+0.05\times60=4\text{ ns}. \]

即使 95% 的访问只需 1 ns，少量长路径仍为平均值增加了 3 ns。这说明，当未命中惩罚很大时，未命中率的微小变化也可能非常重要。

另一种约定把 \(T_{miss,total}\) 定义为一次未命中的完整时间，其中包含最初的缓存检查：

\[ AMAT=(1-r_m)T_{hit}+r_mT_{miss,total}. \]

只要定义一致，两种公式完全等价；若把完整未命中时间代入第一个公式，就会重复计算或遗漏一部分工作。

Python 示例：把 AMAT 与流水线 CPI 联系起来 
def amat(hit_time, miss_rate, additional_miss_penalty):
    return hit_time + miss_rate * additional_miss_penalty


def memory_stall_cpi(
    base_cpi,
    instruction_miss_rate,
    instruction_penalty_cycles,
    data_accesses_per_instruction,
    data_miss_rate,
    data_penalty_cycles,
):
    """假设各类未命中惩罚不重叠的一阶 CPI 模型。"""
    instruction_stalls = instruction_miss_rate * instruction_penalty_cycles
    data_stalls = data_accesses_per_instruction * data_miss_rate * data_penalty_cycles
    return base_cpi + instruction_stalls + data_stalls


assert amat(1.0, 0.05, 60.0) == 4.0

cpi = memory_stall_cpi(
    base_cpi=1.0,
    instruction_miss_rate=0.01,
    instruction_penalty_cycles=40,
    data_accesses_per_instruction=0.30,
    data_miss_rate=0.04,
    data_penalty_cycles=50,
)

assert round(cpi, 2) == 2.00
print(f"AMAT = {amat(1.0, 0.05, 60.0):.2f} ns; CPI = {cpi:.2f}")

CPI 公式直接连接到第 07 章：指令缓存未命中会使 IF 断粮，load 未命中则会延迟依赖指令所需的数据。现代处理器可以重叠多个未命中并继续独立工作，因此这个加法模型是一阶估计，而不是周期精确描述。

多级缓存

单个缓存难以同时兼顾短命中时间与低未命中率。多级缓存层次使用较小的 L1 保护最短常见路径，再用容量更大的下层缓存拦截未命中，避免它们直接到达 DRAM。L1 通常分为指令和数据缓存，使 IF 与 MEM 能并发访问不同阵列，也消除了第 07 章介绍的结构冲突。

对于两级缓存，若 L2 未命中率采用只在 L1 未命中请求中统计的局部未命中率，则

\[ AMAT=T_{L1}+MR_{L1}\left(T_{L2}+MR_{L2|L1miss}\times P_{mem}\right). \]

  • 每个请求都要支付 \(T_{L1}\)。
  • \(MR_{L1}\) 是所有请求中到达 L2 的比例。
  • \(T_{L2}\) 是 L1 未命中后额外的 L2 查找时间。
  • \(MR_{L2|L1miss}\) 是所有 L2 查找中仍然未命中的比例。
  • \(P_{mem}\) 是 L2 未命中后额外的下层存储惩罚。

所有请求中最终到达主存的全局比例为

\[ MR_{L2,global}=MR_{L1}\times MR_{L2|L1miss}. \]

混淆局部未命中率和全局未命中率，是 AMAT 计算中非常常见的错误。

Python 示例：递归计算多级 AMAT 
def multilevel_amat(l1_time, l1_miss_rate, l2_time, local_l2_miss_rate, memory_penalty):
    """每一级下层时间都表示确认上一级未命中后的额外时间。"""
    l1_miss_service = l2_time + local_l2_miss_rate * memory_penalty
    average = l1_time + l1_miss_rate * l1_miss_service
    global_memory_rate = l1_miss_rate * local_l2_miss_rate
    return average, global_memory_rate


average, memory_rate = multilevel_amat(
    l1_time=1.0,
    l1_miss_rate=0.08,
    l2_time=4.0,
    local_l2_miss_rate=0.15,
    memory_penalty=80.0,
)

assert round(average, 2) == 2.28
assert round(memory_rate, 3) == 0.012
print(f"AMAT={average:.2f} ns, requests reaching memory={memory_rate:.1%}")

多个层级还要规定副本之间的关系。包容式层次保证上层块也存在于下层；排他式层次让不同级保存互不重叠的数据，以扩大总容量；非包容非排他设计则不提供简单保证。这些选择会影响淘汰、一致性与可用容量，但不会改变逐级查找的基本依赖关系。

未命中填充时，可以优先返回请求所需的关键字节，使流水线在整块传完前恢复。非阻塞缓存还能跟踪尚未完成的未命中，并继续服务彼此独立的命中。它们通过重叠工作降低有效惩罚，但不会把未命中变成命中。

缓存感知的程序行为

缓存对普通软件通常透明，但软件决定了地址访问序列。两个算术复杂度相同的实现，可能产生截然不同的数据块复用行为。缓存感知编程的目标是改善局部性，而不是依赖某一时刻缓存中恰好保存的内容。

常见变换包括：

变换 对局部性的影响 重要注意事项
按存储顺序遍历 使用每个块中的相邻元素 连续维度由语言和数据布局决定
循环分块 在小区域内完成工作，缩短复用距离 分块仍要与其他活跃数据共享缓存容量
紧凑存放相关字段 共同使用的字节落入更少块 不使用的字段可能浪费带宽
数组结构（SoA） 向量化操作只流式读取所需字段 对需要完整记录的代码可能不利
对齐或填充对象 可消除病态的集合冲突 额外填充会消耗容量
预取 重叠可预测的强制传输 过早或无用预取浪费容量与带宽
Python 模型：统计逐行、逐列和分块遍历的未命中次数 
class DirectMappedByteCache:
    def __init__(self, capacity_bytes, block_bytes):
        self.block_bytes = block_bytes
        self.tags = [None] * (capacity_bytes // block_bytes)
        self.misses = 0

    def access(self, address):
        block = address // self.block_bytes
        line = block % len(self.tags)
        tag = block // len(self.tags)
        if self.tags[line] != tag:
            self.misses += 1
            self.tags[line] = tag


def matrix_addresses(n, order, tile=8, element_bytes=8):
    def address(i, j):
        return (i * n + j) * element_bytes  # 按行存储

    if order == "row":
        for i in range(n):
            for j in range(n):
                yield address(i, j)
    elif order == "column":
        for j in range(n):
            for i in range(n):
                yield address(i, j)
    elif order == "tiled-column":
        # 保留按列处理的工作顺序，但一次完成一个小分块。
        for jj in range(0, n, tile):
            for ii in range(0, n, tile):
                for j in range(jj, min(jj + tile, n)):
                    for i in range(ii, min(ii + tile, n)):
                        yield address(i, j)
    else:
        raise ValueError("unknown order")


def miss_count(order):
    cache = DirectMappedByteCache(capacity_bytes=4 * 1024, block_bytes=64)
    for address in matrix_addresses(64, order):
        cache.access(address)
    return cache.misses


misses = {order: miss_count(order) for order in ["row", "column", "tiled-column"]}
assert misses == {"row": 512, "column": 4096, "tiled-column": 512}
print(misses)

该模型有意省略相联度、预取、多级缓存与访问重叠，让地址顺序的影响更加清晰。真实测量应使用有代表性的输入规模和硬件性能计数器，而不能假设所有机器具有相同缓存几何结构。

缓存优化首先必须保持程序正确性和可维护性。测量后再优化热点循环，通常比在没有证据时全局复杂化数据布局更有价值。最持久的思维方式是从数据块、工作集、复用距离和访问顺序出发分析程序。

本章总结。 存储层次把小而快的上层与大而慢的下层组合起来，因为没有单一技术可以同时提供最低延迟、最大容量、最高带宽与最低成本。时间局部性奖励保留近期使用的数据块，空间局部性则奖励一次传输邻近字节。缓存把地址分解为标记、集合索引和块内偏移：有效且匹配的标记决定命中，索引限制放置位置，偏移选择块内字节。直接映射最小化查找硬件，组相联平衡冲突和成本，全相联提供最大放置自由。替换策略预测哪个驻留块最不值得保留；写直达与写回决定更新何时向下传播，写分配与非写分配决定 store 未命中时是否装入缓存。3C 模型区分强制、容量和冲突未命中。AMAT 按概率加权命中时间与未命中惩罚，而存储停顿把层次结构直接连接到流水线 CPI。多级缓存保护 L1 命中路径并过滤 DRAM 流量；遍历顺序、分块、布局、对齐和预取则能在不改变数学结果的前提下改善局部性。第 09 章将加入虚拟地址、页表和 TLB，并把地址转换与本章的缓存查找路径连接起来。
