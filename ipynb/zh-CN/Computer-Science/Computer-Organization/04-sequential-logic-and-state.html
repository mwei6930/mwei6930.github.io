时序逻辑与状态

第 03 章构造了组合电路：输入稳定后，输出只由当前输入决定。加法器可以算出一个和，却无法在操作数消失后记住结果。处理器还必须记住当前指令地址、中间结果、条件标志、尚未完成的控制决定，以及数百万乃至数十亿个数据比特。

时序逻辑（sequential logic）加入了这种记忆能力。它把存储元件与组合逻辑结合起来，使系统能够依次经历一系列状态。时钟本身不执行计算；它只是建立所有存储元件共同认可的时刻，用来接收前一时间区间内计算出的结果。这种分离把持续变化的电气网络转化为一台能够按周期推理的机器。

数字系统为什么需要状态

状态（state）是决定未来行为所需的最小记忆信息，并不一定等于完整历史。交通灯控制器无需保存每辆经过车辆的日志，只需知道当前阶段、计时条件以及是否有行人请求。处理器同样通过程序计数器和寄存器等值，紧凑地表示其体系结构历史。

纯组合系统满足

\[ Y=F(X), \]

其中 \(X\) 是当前输入向量，\(F\) 是布尔或算术函数，\(Y\) 是结果输出。相同的 \(X\) 出现两次，所得 \(Y\) 也相同。

时序系统则遵循状态转移模型：

\[ S[k+1]=F(S[k],X[k]), \]

\[ Y[k]=G(S[k],X[k]). \]

  • \(k\) 表示当前离散步骤或时钟周期；
  • \(S[k]\) 是周期 \(k\) 中保存的状态；
  • \(X[k]\) 是该周期观察到的外部输入；
  • \(F\) 是下一状态函数，决定接下来记住什么；
  • \(S[k+1]\) 是下一周期捕获的状态；
  • \(G\) 是输出函数，可以只依赖状态，也可以同时依赖状态与当前输入。

因此，存储状态不同时，相同输入也可能产生不同输出。播放/暂停按钮就是简单类比：按钮事件相同，但下一动作取决于播放器当前处于播放还是暂停状态。

需求 保留的状态 示例
继续一项计算 部分结果与进度 迭代乘法或除法
保存一个值 一个 \(n\) 位字 处理器寄存器
选择下一动作 控制状态 指令控制器
统计事件 二进制计数 定时器或性能计数器
记住地址 当前位置 程序计数器
缓冲通信 排队数据与指针 部件之间的 FIFO

状态也带来新的义务：系统需要已知初始条件、明确的状态改变规则，以及防止存储元件采样不稳定数据的时序保证。组合逻辑错误会产生错误函数，而时序逻辑错误可能只在某段特定历史后出现，因此状态设计必须严谨。

Python 类比：保留状态后，相同输入会产生不同结果 
class Accumulator:
    """一个记住运行总和的微型状态机。"""

    def __init__(self) -> None:
        self.state = 0

    def clock(self, value: int, enable: bool = True) -> int:
        # 先由当前状态和输入计算下一状态。
        next_state = self.state + value if enable else self.state

        # 赋值模拟时钟边沿的捕获。
        self.state = next_state
        return self.state


acc = Accumulator()
assert acc.clock(5) == 5
assert acc.clock(5) == 10       # 输入相同，但当前状态不同。
assert acc.clock(100, False) == 10
assert acc.clock(-3) == 7

时钟与同步设计

时钟（clock）是用于协调状态更新的周期信号，重要事件通常是上升沿、下降沿或两者。在正边沿触发设计中，寄存器在每个上升沿观察输入并保存捕获值，直到下一个上升沿。

若时钟周期为 \(T_{clk}\)，标称频率为

\[ f_{clk}=\frac{1}{T_{clk}}. \]

\(T_{clk}\) 的单位是每周期秒数，\(f_{clk}\) 的单位是每秒周期数，即赫兹。2 ns 周期对应 \(1/(2\times10^{-9})=500\) MHz。更高频率每秒提供更多状态更新机会，但也让组合逻辑稳定的时间更短，通常还会增加时钟分发功耗。

最常见的同步数据通路包含三个概念部分：

  1. 发射寄存器给出上一边沿捕获的状态；
  2. 组合逻辑转换该状态与当前输入；
  3. 捕获寄存器在下一边沿保存已经稳定的结果。

所有寄存器在逻辑上同时更新，尽管物理时钟边沿到达各处的时间会略有差异。关键是，寄存器的新输出不可能穿过整个设计又在同一个理想边沿被捕获：输出要经过时钟到 Q 延迟才变化，而接收寄存器已经在该边沿完成采样。这建立了清晰的周期边界。

时钟负责协调而非引发计算。组合门在输入变化时一直作出反应，时钟只决定何时把结果固化为状态。给每个门加时钟既浪费又没有必要；设计者只在有意义的阶段边界放置寄存器，让中间逻辑在两个边沿之间运行。

同步设计的优势是时序可化为局部的寄存器到寄存器检查。另一种异步设计不依赖全局节拍，而通过握手和局部完成信号通信。它可能减少无谓等待与时钟功耗，但控制和验证更专业。现代处理器主要是同步系统，同时仍包含异步接口与多个时钟域。

复位建立已知初态。同步复位只在有效时钟边沿改变状态；异步复位能够立即强制存储元件。时钟不可用时，异步断言很有帮助，但释放复位必须同步，避免不同寄存器在不一致的边沿恢复工作。

设计规则 重要原因
每个时钟域只使用一个明确的有效边沿 避免模糊的采样关系
普通数据信号不要接到时钟引脚 数据毛刺不能变成额外时钟事件
有意识地处理跨时钟域 无关时钟之间没有共同的建立/保持保证
定义复位值与释放方式 防止未知启动状态
同时分析最大与最小路径延迟 建立时间与保持时间是不同约束

锁存器与触发器

锁存器和触发器通过反馈保存一个比特。外部行为是数字的，但存储机制是物理的：交叉耦合增益会强化两种稳定电压状态中的一种。输出通常记为 \(Q\) 和 \(\overline Q\)；在有效操作中，上横线表示逻辑互补。

核心区别是输入在什么时间可以影响存储状态：

  • 锁存器是电平敏感的，在使能区间内可以一直透明；
  • 触发器是边沿触发的，只在某个时钟跳变附近采样。

SR 锁存器

置位-复位锁存器（SR latch）是最简单的显式存储元件。两个交叉耦合 NOR 门形成反馈：每个输出都会参与决定另一个门的输入。一旦某个输出变为 1，即使引发变化的输入恢复为 0，反馈仍会保持该状态。

对于图中的高有效 NOR 实现：

\(S\) \(R\) \(Q_{next}\) 含义
0 0 \(Q\) 保持先前状态
1 0 1 置位
0 1 0 复位
1 1 非法 两个输出都被强制为低

当 \(S=R=0\) 时，没有输入请求变化，反馈会重现先前的 \(Q\)。当 \(S=1\) 时，下方 NOR 输出变为 0，使上方输出 \(Q\) 可以变为 1；复位过程与之对称。

\(S=R=1\) 不只是真值表中“不方便”的一行。两个输出都会变成 0，违背 \(Q\) 与 \(\overline Q\) 互补的预期。若随后两个输入几乎同时恢复为 0，微小的物理延迟差异会决定哪个稳定状态获胜。允许这种情况等于放弃确定性的数字行为。

NAND 型 SR 锁存器也很常见，但外部输入为低有效。真值表必须结合电路极性理解，不能脱离上下文死记。原理图中的圆圈或上横线表示把控制驱动到 0 才是“断言”。

SR 锁存器很好地解释了记忆从何而来，但两个独立数据命令不便于普通同步存储。D 锁存器从一个数据输入派生置位和复位，从而消除非法命令。

Python 状态模型：测试 SR 锁存器的有效与非法命令 
class SRLatch:
    def __init__(self, initial_q: int = 0) -> None:
        self.q = int(bool(initial_q))

    def apply(self, set_input: int, reset_input: int) -> int:
        set_input = int(bool(set_input))
        reset_input = int(bool(reset_input))

        if set_input and reset_input:
            # 真实硬件在两个输入释放时可能失去确定状态。
            raise ValueError("对高有效 NOR 锁存器，S=R=1 非法")
        if set_input:
            self.q = 1
        elif reset_input:
            self.q = 0
        # S=R=0 不进行赋值，因此保持状态。
        return self.q


latch = SRLatch()
assert latch.apply(1, 0) == 1
assert latch.apply(0, 0) == 1
assert latch.apply(0, 1) == 0

D 锁存器

D 锁存器具有数据输入 \(D\) 与使能输入 \(E\)。当 \(E=1\) 时，锁存器透明，\(Q\) 在门延迟后跟随 \(D\)；当 \(E=0\) 时，反馈路径保存最后一个值。下一状态方程为

\[ Q^{+}=ED+\overline E\,Q. \]

  • \(Q^{+}\) 表示锁存器响应后的值；
  • \(D\) 是候选新数据；
  • \(E\) 是使能电平；
  • \(ED\) 在 \(E=1\) 时传递 \(D\)；
  • \(\overline E\,Q\) 在 \(E=0\) 时反馈旧状态。

两个乘积项不会同时有效，因为 \(E\) 与 \(\overline E\) 互补。因此，该方程等价于一个以 \(E\) 为选择信号的 2 选 1 多路选择器，两个输入分别是新数据和当前状态。

图片来源：D-Type Transparent Latch.svg，Inductiveload，公有领域。

透明性很有用，但必须谨慎。如果多个高有效锁存器共享同一使能，变化可能在该区间穿过多个级，形成直通竞争（race-through）。两相锁存系统用不重叠的交替相位规避它：一组透明时另一组保持。它还能支持时间借用，让较慢模块使用相邻相位的一部分时间，但验证比简单边沿到边沿时序更复杂。

锁存器更小，在定制高性能设计中可能很高效。入门级寄存器传输推理更常使用边沿触发器，因为采样时刻更容易界定。

使能 \(E\) 数据 \(D\) 锁存器响应
0 任意 保持 \(Q\)
1 0 驱动 \(Q\) 向 0 变化
1 1 驱动 \(Q\) 向 1 变化

“透明”不等于零延迟，而是表示使能期间允许变化传播。真实门延迟仍决定 \(Q\) 何时变化，以及较晚的数据跳变能否满足关闭边沿的时序要求。

边沿触发器

边沿触发 D 触发器只在有效时钟边沿附近捕获 \(D\)。两个边沿之间，\(D\) 的变化不会改变 \(Q\)。理想正边沿器件满足

\[ Q[k+1]=D\big|_{\text{上升沿 }k+1}. \]

即下一周期输出等于第 \(k+1\) 个上升沿采样到的数据。它并不表示输出立即变化：真实 \(Q\) 要经过时钟到 Q 延迟才出现。

图片来源：Edge triggered D flip flop.svg，Nolanjshettle，CC BY-SA 3.0。

一种概念实现使用两个透明相位相反的锁存器，通常称为主锁存器与从锁存器。有效边沿前，前者跟随输入、后者保持输出；到达边沿时，两者交换角色：前者关闭并锁定最后输入，后者打开并发布捕获值。实际标准单元可能采用脉冲触发或优化晶体管结构，但外部时序契约仍是边沿采样。

触发器数据手册或时序库规定的不只是真值表：

  • 建立时间：边沿前 \(D\) 必须稳定多久；
  • 保持时间：边沿后 \(D\) 必须继续稳定多久；
  • 时钟到 Q 传播延迟：新 \(Q\) 最晚何时保证出现；
  • 时钟到 Q 污染延迟：\(Q\) 最早何时可能开始变化；
  • 若存在，异步复位或置位行为。

这些值取决于电压、温度、制造工艺、输入跳变速度和输出负载。把触发器视为瞬时赋值的仿真适合检查功能，却不能证明物理时序正确。

存储元件 敏感区间 主要优势 主要问题

D 锁存器 整个使能电平 紧凑，可借用时间 透明性与直通竞争

寄存器、计数器与移位寄存器

一个 \(n\) 位寄存器把 \(n\) 个触发器并排放置并共享时钟。每个触发器保存一位，所以一个字的所有位会在同一个逻辑边沿被捕获。寄存器可保存处理器操作数、指令字段、地址、状态标志与流水线边界。

寄存器通常需要装载使能。与其用普通逻辑门控时钟，不如让多路选择器为每一位选择新数据或反馈：

\[ D_i=Load\cdot X_i+\overline{Load}\cdot Q_i. \]

\(i\) 表示一个比特位置，\(X_i\) 是输入数据，\(Q_i\) 是当前存储位。Load=1 时 \(D_i=X_i\)；Load=0 时 \(D_i=Q_i\)，所以下一边沿重新捕获相同值。专用时钟门控单元可以节省动态功耗，但它们经过防毛刺设计，必须按受控规则插入。

计数器（counter）是下一状态逻辑执行固定进程的寄存器。无符号模 \(2^n\) 加计数器满足

\[ Q[k+1]=(Q[k]+1)\bmod 2^n. \]

\(n\) 是寄存器位宽，模 \(2^n\) 会丢弃最高位外的进位。因此 3 位计数器按 000, 001, …, 111, 000 循环。行波计数器用一个触发器的输出作为下一个触发器的时钟，结构小，但跳变在不同时间传播并产生临时编码；同步计数器让所有触发器共享同一时钟，并以组合逻辑计算所有下一位，时序更容易控制。

移位寄存器（shift register）把每一级的下一输入连接到邻级。它可以把串行数据转换为并行字、延迟比特流、完成串行通信或构造紧凑模式生成器。常见模式包括保持、并行装载、左移与右移。

图片来源：3 bit bi-directional shift register circuit.svg，Dizquierdol，CC0 1.0。

对 \(n\) 位寄存器逻辑右移时，第 \(i\) 级接收旧的第 \(i+1\) 位，最高有效级接收串行输入，通常是 0。由于所有级同时捕获，每一级使用的是邻居的旧值。若软件从左到右原地修改列表，就无法正确模拟这种并行行为；必须先算出完整下一状态，再替换当前状态。

结构 下一状态操作 常见用途

计数器 加一、减一或重装 定时、地址、事件统计
移位寄存器 移动邻接比特 串并转换与延迟
环形计数器 循环移动独热状态 简单相位排序

Python 模型：并行寄存器、模计数器与双向移位寄存器 
class SequentialWord:
    def __init__(self, width: int, initial: int = 0) -> None:
        if width <= 0:
            raise ValueError("width 必须为正")
        self.width = width
        self.mask = (1 << width) - 1
        self.q = initial & self.mask

    def load(self, value: int, enable: bool = True) -> int:
        # 先计算 D 输入，再模拟一次同时发生的边沿。
        next_q = value & self.mask if enable else self.q
        self.q = next_q
        return self.q

    def count_up(self, enable: bool = True) -> int:
        next_q = (self.q + 1) & self.mask if enable else self.q
        self.q = next_q
        return self.q

    def shift(self, direction: str, serial_in: int = 0) -> int:
        serial_in &= 1
        old_q = self.q

        if direction == "right":
            next_q = (old_q >> 1) | (serial_in << (self.width - 1))
        elif direction == "left":
            next_q = ((old_q << 1) & self.mask) | serial_in
        else:
            raise ValueError("direction 必须是 left 或 right")

        self.q = next_q
        return self.q


counter = SequentialWord(width=3, initial=0b110)
assert counter.count_up() == 0b111
assert counter.count_up() == 0b000   # 模 8 回绕。

shift_register = SequentialWord(width=4, initial=0b1011)
assert shift_register.shift("right", serial_in=0) == 0b0101
assert shift_register.shift("left", serial_in=1) == 0b1011

有限状态机

有限状态机（FSM）是一种控制的数学与硬件模型，其相关历史可由有限状态集合表示。状态寄存器记住当前抽象情形，组合下一状态逻辑检查状态和输入，输出逻辑则生成控制信号。

当行为可以描述为阶段或协议时，FSM 很合适，例如取指与执行、识别比特模式、控制缓存未命中、安排内存请求或解析通信分组。它不适合保存大量任意数据，因为每增加一个状态位，潜在编码状态空间都会翻倍。

形式上，确定性 FSM 包含

\[ S[k+1]=\delta(S[k],X[k]), \]

其中 \(\delta\) 是转移函数，此外还有输出函数 \(\lambda\)。每一组合法的当前状态与输入都必须确定唯一下一状态；遗漏的转移会在仿真中形成意外行为，或在硬件中产生非预期默认逻辑。

Moore 与 Mealy 状态机

两种标准输出形式的区别，在于当前输入是否直接通向输出。

对于 Moore 状态机，

\[ Y[k]=\lambda(S[k]). \]

输出只依赖寄存后的状态，因此通常在状态更新后改变，并在两个边沿之间自然保持稳定，只有状态寄存器与译码延迟。

对于 Mealy 状态机，

\[ Y[k]=\lambda(S[k],X[k]). \]

输入在当前周期变化时，输出即可响应。这样通常需要更少状态，并可提前一个周期响应，但输入毛刺或较晚跳变也可能传到输出，除非输出被寄存或受到严格约束。

考虑可重叠地检测串行模式 101。Mealy 检测器只需表示有用后缀的状态：A 表示没有有用后缀，B 表示最新后缀为 1，C 表示后缀为 10。处于 C 时收到 1，会立即断言检测并回到 B，因为最后的 1 可能是下一次匹配的开头。Moore 检测器通常要增加一个输出为 1 的专用检测状态，所以可见脉冲在进入该状态后出现。

性质 Moore Mealy
输出依赖 状态 状态与当前输入
响应时间 通常在状态边沿后 可在当前周期内
状态数量 可能较多 通常较少
输出稳定性 更容易推理 对输入时序与毛刺敏感
常见用途 寄存后的控制信号 紧凑协议决策

两者没有普遍优劣。实际设计可以在内部计算 Mealy 条件，但在信号离开模块前将其寄存，从而兼顾快速检测和干净外部接口。

状态转移设计

FSM 设计应从行为而不是二进制编码开始。可靠流程是：

  1. 定义输入、输出、复位和时钟域。说明信号极性以及什么算作一次事件；
  2. 找出最小相关历史。为每种可区分情形取有意义的状态名；
  3. 画出每条转移。在边上标注输入条件；Mealy 输出还要标注输出动作；
  4. 建立转移表。枚举当前状态与合法输入组合；
  5. 选择编码。为抽象状态分配比特模式；
  6. 推导下一状态与输出逻辑。使用布尔化简或综合工具；
  7. 定义非法状态恢复。让未使用编码复位或跳回安全状态，而不是假设它们永远不会出现；
  8. 验证序列与不变量。测试正常路径、复位、重叠事件和意外输入。

101 Mealy 检测器的转移表为：

当前状态 输入 0：下一状态/输出 输入 1：下一状态/输出 记住的后缀
A A / 0 B / 0 无
B C / 0 B / 0 1
C A / 0 B / 1 10

状态编码会改变硬件组织，但不改变抽象行为：

  • 二进制编码为 \(N\) 个状态使用 \(\lceil\log_2N\rceil\) 个触发器，但可能需要更复杂的译码逻辑；
  • 独热编码使用 \(N\) 个触发器且恰有一个为 1，常能简化转移并提高 FPGA 中的速度；
  • 类格雷编码尝试让重要转移只改变一个比特，减少同时翻转与译码冒险。

触发器最少并不自动意味着电路最小或最快。独热设计使用更多状态位，却可能消除深层布尔逻辑。综合工具可以探索编码，但有意义的状态名和明确行为仍是验证基础。

Python 实现：可重叠检测串行模式 101 的 Mealy 状态机 
from enum import Enum, auto


class DetectorState(Enum):
    NONE = auto()       # 没有有用后缀。
    SAW_1 = auto()      # 最新有用后缀是 "1"。
    SAW_10 = auto()     # 最新有用后缀是 "10"。


class Pattern101Detector:
    def __init__(self) -> None:
        self.state = DetectorState.NONE

    def clock(self, bit: int) -> int:
        """返回当前输入与转移产生的 Mealy 输出。"""
        if bit not in (0, 1):
            raise ValueError("input 必须是一个比特")

        output = 0
        if self.state is DetectorState.NONE:
            next_state = DetectorState.SAW_1 if bit else DetectorState.NONE
        elif self.state is DetectorState.SAW_1:
            next_state = DetectorState.SAW_1 if bit else DetectorState.SAW_10
        else:  # SAW_10
            output = int(bit == 1)  # 完成 101 是一个 Mealy 动作。
            next_state = DetectorState.SAW_1 if bit else DetectorState.NONE

        # 所有下一状态推理都使用旧状态，最后再捕获。
        self.state = next_state
        return output


detector = Pattern101Detector()
stream = [1, 0, 1, 0, 1, 1]
outputs = [detector.clock(bit) for bit in stream]
assert outputs == [0, 0, 1, 0, 1, 0]  # 检测到两次重叠匹配。

这段代码是行为模型，而不是门级硬件，但执行顺序仍很重要：先根据旧状态决定输出与 next_state，最后只赋值一次状态。硬件描述语言在时钟过程里使用非阻塞赋值，原因相同。

寄存器文件

寄存器文件（register file）是一组小型、快速、可按地址访问的寄存器。单个寄存器负责存储，译码器和多路选择器则把它们组织为可由寄存器编号选择操作数的结构。典型标量处理器每条指令需要两个源操作数和一个目的操作数，因此常见组织有两个读端口和一个写端口，简称 2R1W。

对 \(N\) 个、每个宽 \(W\) 位的寄存器：

  • 容量为 \(N\times W\) 位；
  • 每个地址需要 \(\lceil\log_2N\rceil\) 位；
  • 写译码器把目的地址转成 \(N\) 条独热使能；
  • 每个读端口都需要能从 \(N\) 个字中选择一个的硬件。

例如，32 个寄存器需要 5 位地址，因为 \(2^5=32\)。一个 32×64 位寄存器文件保存 2048 个数据位，但面积远大于 2048 个孤立比特单元，因为读写端口还会加入导线、访问器件、译码器与多路选择。端口数量很昂贵：每周期发射多条指令可能要求大量读写端口，所以超标量设计常使用分 bank、复制、旁路网络或精心组织的物理寄存器文件。

写通常是同步的：write_enable、地址和数据必须在有效边沿附近满足时序。读可以是组合的，在地址译码与 MUX 延迟后产生数据；也可以是同步的，在后续边沿返回数据。选择不同会改变数据通路调度。

同周期对同一地址读写必须有明确契约：

  • 先读：读到旧值；
  • 先写：读到新写入数据；
  • 不变或未定义：接口不保证上述任何一种。

处理器流水线常用旁路直接转发待写结果，而不是等它写入后再读出。这不是通用寄存器文件图中可以猜测的属性，而是由具体组织规定的设计决定。

Python 模型：在边沿提交写入的双读单写寄存器文件 
class RegisterFile:
    def __init__(self, register_count: int, width: int, hardwired_zero: bool = False):
        if register_count <= 0 or width <= 0:
            raise ValueError("寄存器数量与位宽必须为正")
        self.values = [0] * register_count
        self.mask = (1 << width) - 1
        self.hardwired_zero = hardwired_zero
        self.pending_write: tuple[int, int] | None = None

    def read2(self, address_a: int, address_b: int) -> tuple[int, int]:
        # 组合读取：这里不改变任何状态。
        return self.values[address_a], self.values[address_b]

    def request_write(self, address: int, data: int, enable: bool = True) -> None:
        # 周期内准备输入，此时尚不修改数组。
        self.pending_write = (address, data & self.mask) if enable else None

    def rising_edge(self) -> None:
        # 有效边沿到达时更新一个目的寄存器。
        if self.pending_write is not None:
            address, data = self.pending_write
            if not (self.hardwired_zero and address == 0):
                self.values[address] = data
        self.pending_write = None


rf = RegisterFile(register_count=8, width=16, hardwired_zero=True)
rf.request_write(3, 0x12345)
assert rf.read2(3, 0) == (0, 0)       # 边沿前先读，看到旧值。
rf.rising_edge()
assert rf.read2(3, 0) == (0x2345, 0)  # 位宽掩码与硬连线 R0。

存储器基本模块

当系统需要大量字时，寄存器的扩展成本过高。存储阵列把比特单元排列成行列，从而共享地址译码与感测硬件。地址选择一个字，数据线传输整个字，控制信号区分读、写、使能，有时还要区分刷新。

若存储器有 \(A\) 个地址位，每个字宽 \(W\) 位，理想逻辑容量为

\[ C=2^A\times W\text{ 位}. \]

\(2^A\) 是可选择地址数量，\(W\) 是每地址的数据位数。物理容量还包括冗余位、纠错位、译码器、感测放大器、驱动器与控制电路。

ROM

只读存储器（ROM）保存从地址到字的映射，普通运行过程不会修改它。概念上，它是组合查找表：

\[ Data=ROM[Address]. \]

译码器激活一行，位线上的已编程连接决定返回模式。ROM 适合存放启动代码、固定微码、查找表、设备配置与常量；采用非易失实现时，内容断电后仍存在。

“只读”描述普通接口，而不是唯一制造方法：

  • 掩膜 ROM在制造时固定；
  • PROM制造后只能编程一次；
  • EPROM可用紫外线擦除再写入；
  • EEPROM与闪存可电气擦写，但写通常比读更慢、粒度也更粗。

小型布尔函数既可以用化简后的门实现，也可以写入 ROM。ROM 无需推导专用方程，可编程时也易于更新；但它要存储每个地址对应的输出模式，对稀疏简单函数可能不如优化逻辑高效。

Python 模型：带地址检查的不可变 ROM 查找 
class ROM:
    def __init__(self, words: list[int], width: int) -> None:
        self._mask = (1 << width) - 1
        self._words = tuple(word & self._mask for word in words)

    def read(self, address: int) -> int:
        if not 0 <= address < len(self._words):
            raise IndexError("ROM 地址超出范围")
        return self._words[address]


# 一个包含四项、返回类七段显示模式的查找表。
rom = ROM([0b0111111, 0b0000110, 0b1011011, 0b1001111], width=7)
assert rom.read(2) == 0b1011011

SRAM

静态随机存取存储器（SRAM）用双稳态反馈电路保存每个比特。传统六晶体管（6T）单元使用两个交叉耦合反相器保存 \(Q\) 与 \(\overline Q\)，另有两个由字线控制的访问晶体管。它称为“静态”，是因为只要供电存在就无需周期刷新；这并不表示它是非易失存储。

读取前通常会预充互补位线。激活字线后，单元连接到位线，存储状态产生微小差分电压，感测放大器再将其放大为完整数字值。写入时，强位线驱动器施加互补电平并压过旧状态。

读取不能意外翻转单元，写入又必须足以改变它，因此晶体管尺寸要在读稳定性、写能力、漏电、速度和面积之间平衡。这些模拟细节位于干净的 read(address) 与 write(address, data) 数字抽象之下。

SRAM 速度快且无需刷新，但 6T 单元比 DRAM 单元占用更多面积，因此用于延迟比密度更重要的场合：处理器缓存、小型片上存储、队列和查找结构。寄存器文件可能使用类似 SRAM 的定制单元，但多端口与时序要求使它成为不同的组织。

SRAM 操作 物理动作 数字结果
保持 字线关闭，反馈强化状态 供电期间比特保持
读取 字线开启，单元扰动预充位线 感测放大器返回 0 或 1
写入 位线驱动器施加新的互补电平 反馈稳定到新状态

与寄存器不同，SRAM 阵列在许多字之间共享访问电路。共享提高密度，却增加地址译码、字线、位线与感测延迟。

DRAM

动态随机存取存储器（DRAM）把一个比特保存为微小电容上的电荷，通常用一个晶体管访问。充电与放电电容代表两种逻辑状态，确切电压解释和感测方法取决于具体技术。

字线启用访问晶体管，把电容连接到位线。存储电荷很少，读取会与位线共享电荷，再由感测放大器判断原状态。该过程会扰动原电容电平，因此读后必须恢复这一行。即使不访问，电荷也会泄漏，所以还要周期性刷新。

DRAM 阵列利用几何结构提高密度。一个行地址会同时把许多单元激活到由感测放大器构成的行缓冲区，之后的列选择从已打开行中选出所需字。访问同一行内另一列相对较快；更换行则需要预充与激活。这就是物理地址映射、局部性和内存控制器调度会影响性能的原因。

单晶体管加电容的单元远比 6T SRAM 密集，因此适合主存。缺点是访问延迟更高、需要刷新、读取具有破坏性且控制更复杂。

Python 抽象：对比类 SRAM 访问与 DRAM 刷新记录 
class SRAMModel:
    def __init__(self, word_count: int, width: int) -> None:
        self.mask = (1 << width) - 1
        self.words = [0] * word_count

    def read(self, address: int) -> int:
        return self.words[address]

    def write(self, address: int, data: int) -> None:
        self.words[address] = data & self.mask


class DRAMModel(SRAMModel):
    """功能数据加上一项简化的刷新年龄约束。"""

    def __init__(self, word_count: int, width: int, refresh_limit: int) -> None:
        super().__init__(word_count, width)
        self.age = [0] * word_count
        self.refresh_limit = refresh_limit

    def tick(self) -> None:
        # 真实控制器刷新行；此模型单独老化每个字。
        self.age = [value + 1 for value in self.age]

    def refresh(self, address: int) -> None:
        self.age[address] = 0

    def read(self, address: int) -> int:
        if self.age[address] > self.refresh_limit:
            raise RuntimeError("刷新前已超过数据保持保证")
        value = super().read(address)
        self.refresh(address)  # 模拟破坏性感测后的恢复。
        return value

    def write(self, address: int, data: int) -> None:
        super().write(address, data)
        self.refresh(address)


dram = DRAMModel(word_count=4, width=8, refresh_limit=3)
dram.write(1, 0xAB)
for _ in range(3):
    dram.tick()
assert dram.read(1) == 0xAB
assert dram.age[1] == 0

该模型刻意停留在行为层。真实 DRAM 不会在每个字旁维护整数年龄；控制器会按照时序规范调度行刷新命令。代码只是让刷新义务可见，并不假装模拟电容电压。

时序约束

功能正确性规定信号稳定后电路应产生什么值；时序正确性则要求该值足够早地稳定、保持足够久，并由预期时钟边沿采样。一个电路可能通过所有零延迟真值表测试，却因为路径太慢或太快而在芯片上失败。

时序分析沿发射存储元件、组合逻辑与导线，直到捕获存储元件。最大延迟限制频率，最小延迟防止新数据过早到达。每一种相关工艺、电压、温度与时钟条件都必须同时检查两者。

传播延迟与污染延迟

传播延迟是最大值：输入事件发生后，何时能保证输出已经到达正确新值？对一个门，

\[ t_{pd}=\max(t_{PLH},t_{PHL}), \]

其中 \(t_{PLH}\) 是低到高延迟，\(t_{PHL}\) 是高到低延迟，取较大者可得到保守保证。

污染延迟是最小值：旧输出最早何时可能开始变化？通常写作

\[ t_{cd}=\min(t_{cd,LH},t_{cd,HL}). \]

两者界定一个不确定区间。在 \(t_{cd}\) 前，旧输出保证不变；在 \(t_{pd}\) 后，新正确输出保证有效；两者之间，输出可能正在转换或产生毛刺。

对多门路径，最晚到达时间沿最大延迟追踪最慢前驱，最早到达时间则沿最小延迟追踪最早前驱。导线延迟、扇出和负载都必须计入；只数门级可能错过真实物理关键路径。

延迟量 回答的问题 主要用途
\(t_{cq,max}\) 时钟后新寄存器输出最晚何时出现？ 建立分析
\(t_{cq,min}\) 寄存器输出最早何时受到扰动？ 保持分析
\(t_{comb,max}\) 组合结果最晚何时有效？ 建立分析
\(t_{comb,min}\) 组合输出最早何时变化？ 保持分析
\(t_{setup}\) 捕获边沿前需要稳定多久？ 建立分析
\(t_{hold}\) 捕获边沿后需要稳定多久？ 保持分析

增加缓冲器会增加最小延迟，因此可以修复保持违例，即使这会让路径更慢。增大时钟周期可以修复建立违例，却不能修复同边沿保持违例。这是同步时序中最重要的直觉之一。

建立时间与保持时间

捕获触发器要求输入在有效边沿周围稳定。建立时间是边沿前必须稳定的区间，保持时间是边沿后必须继续稳定的区间；两者共同形成触发器输入的禁止变化窗口。

定义时钟偏斜为

\[ t_{skew}=t_{capture}-t_{launch}, \]

正偏斜表示捕获时钟边沿比发射边沿更晚到达。一条寄存器到寄存器路径的建立约束为

\[ T_{clk}\ge t_{cq,max}+t_{comb,max}+t_{setup}-t_{skew}+t_{uncertainty}. \]

  • \(T_{clk}\) 是相邻对应发射与捕获边沿之间的周期；
  • \(t_{cq,max}\) 是发射寄存器输出最晚响应时间；
  • \(t_{comb,max}\) 是逻辑与布线最大延迟；
  • \(t_{setup}\) 是捕获寄存器建立要求；
  • 正 \(t_{skew}\) 给数据更多时间，所以以负号出现；
  • \(t_{uncertainty}\) 为抖动与模型变化预留裕量。

例如，\(t_{cq,max}=0.12\) ns、\(t_{comb,max}=1.55\) ns、\(t_{setup}=0.10\) ns、\(t_{skew}=0.04\) ns，不确定性为 0.08 ns，则周期至少为

\[ 0.12+1.55+0.10-0.04+0.08=1.81\text{ ns}, \]

该路径对应的最高频率约为 \(1/1.81\text{ ns}=552\) MHz。

保持约束使用最早到达：

\[ t_{cq,min}+t_{comb,min}\ge t_{hold}+t_{skew}+t_{uncertainty,hold}. \]

左侧是新数据最早到达捕获输入的时间，右侧是延迟捕获边沿后旧数据必须保留的时间。正偏斜现在会让要求更严格。若新数据到达太早，增大 \(T_{clk}\) 没有作用，因为发射与捕获针对同一个边沿。必须增加最小路径延迟、调整时钟分发、选择不同单元或重构体系结构。

时序裕量（slack）在建立分析中是要求时间减到达时间，在保持分析中是可用最小延迟减所需最小延迟。正裕量通过，负裕量量化违例。商业工具报告的符号约定可能不同，因此应阅读工具定义，不能盲目套用公式。

    skew: float = 0.0
    setup_uncertainty: float = 0.0
    hold_uncertainty: float = 0.0

    def setup_slack(self) -> float:
        required_period = (
            self.clock_to_q_max
            + self.combinational_max
            + self.setup
            - self.skew
            + self.setup_uncertainty
        )
        return self.clock_period - required_period

    def hold_slack(self) -> float:
        earliest_arrival = self.clock_to_q_min + self.combinational_min
        required_stability = self.hold + self.skew + self.hold_uncertainty
        return earliest_arrival - required_stability


path = TimingPath(
    clock_period=2.0,
    clock_to_q_max=0.12,
    clock_to_q_min=0.05,
    combinational_max=1.55,
    combinational_min=0.18,
    setup=0.10,
    hold=0.06,
    skew=0.04,
    setup_uncertainty=0.08,
    hold_uncertainty=0.02,
)

assert round(path.setup_slack(), 2) == 0.19
assert round(path.hold_slack(), 2) == 0.11
print("setup slack:", path.setup_slack(), "ns")
print("hold slack:", path.hold_slack(), "ns")

时钟偏斜与亚稳态

时钟通过物理分发网络到达成千上万个乃至数百万个存储元件。线长、缓冲、负载和工艺变化的差异造成时钟偏斜（clock skew）：对应边沿不会在所有位置精确同时到达。

在 \(t_{skew}=t_{capture}-t_{launch}\) 的约定下，正偏斜让接收寄存器更晚采样，因而有利于建立，却因旧值必须保持更久而不利于保持；负偏斜影响相反。设计者使用平衡时钟树或时钟网格、表征变化并预留不确定性。也可以有意引入有用偏斜，但改善一条路径可能恶化另一条。

时钟抖动（jitter）不同于偏斜。偏斜是时钟端点之间的空间差异，抖动则是多个周期中边沿相对预期时间的变化；两者都会减少可靠时序裕量。

亚稳态（metastability）发生在双稳态元件被要求在输入违反采样窗口时作出决定。内部电压不会立即落到有效 0 或 1，而可能在不稳定平衡附近停留不可预测的时间。它最终会解析，但数字逻辑无法保证最终值或准确时间。

亚稳态对异步输入与跨时钟域尤其重要。无关时钟之间无法保证任何有限建立/保持规则。单比特稳定电平的常见处理方式是两级触发器同步器：

第一级接收异步信号，可能亚稳；第二级在接近一个目的时钟周期的解析时间后采样第一级输出。这不会消除亚稳态，只会把传播概率降低到可靠性目标可接受的水平。

简化关系为

\[ MTBF\propto\frac{e^{T_{resolve}/\tau}}{f_{clk}f_{data}}. \]

  • \(MTBF\) 是可观察同步失败的平均间隔；
  • \(T_{resolve}\) 是第二级采样前留给第一级稳定的时间；
  • \(\tau\) 描述特定触发器解析亚稳态的速度；
  • \(f_{clk}\) 是目的采样频率；
  • \(f_{data}\) 是异步跳变频率；
  • 指数关系意味着稍微增加解析时间即可显著提高可靠性。

精确库模型还包含器件相关常数与实测参数；该式是可靠性模型，并不保证两级在任何场合都足够。

多比特值不能简单地给每一位单独加同步器：各位可能在不同周期解析，形成从未存在过的字。握手、格雷码计数器、异步 FIFO 或源同步协议可保持一致性。窄脉冲也可能落在目的边沿之间而消失，因此需要脉冲展宽、翻转编码或握手。

跨域对象 常见机制 原因
单个稳定控制电平 两级触发器同步器 限制亚稳态传播概率
单周期脉冲 脉冲展宽、翻转或握手 保证目的端观察到事件
变化的多比特总线 数据稳定期间握手 传输一致的完整字
连续数据流 使用格雷指针的异步 FIFO 分离读写时钟域

亚稳态无法在确定性数字仿真中被忠实模拟。验证通常检查跨域结构与协议，可靠性分析则使用经过表征的时序参数。

组合逻辑与时序逻辑对比

组合逻辑与时序逻辑不是互相竞争的方案。实用同步系统会有意交替使用二者：寄存器保存状态，组合模块计算下一状态和输出，时钟边沿提交选定结果。

维度 组合逻辑 时序逻辑
依赖关系 只依赖当前输入 当前输入加存储状态
数学形式 \(Y=F(X)\) \(S^{+}=F(S,X)\) 且 \(Y=G(S,X)\)
记忆 无 锁存器、触发器、寄存器、阵列
反馈 通常避免 受控反馈产生存储
时间模型 输入变化后稳定 在电平或边沿事件推进
主要正确性检查 真值表、等价性、关键路径 状态转移、复位、建立、保持、CDC
示例 加法器、MUX、译码器、ALU 计数器、FSM、寄存器文件、缓存状态

清晰设计会在视觉和行为上区分这些角色：时钟过程更新存储，组合过程计算候选值；每个状态变量都有复位或初始化方案；每个转移都有定义；每条寄存器到寄存器路径同时通过最大与最小延迟检查；每个异步跨域都使用适合的协议。

核心抽象是寄存器传输步骤：

\[ \text{旧状态}\;\longrightarrow\;\text{组合变换}\;\longrightarrow\;\text{新状态}. \]

一个周期内许多门并发求值，有效边沿上许多寄存器并发捕获。空间并行与离散状态更新的结合，使处理器既是一套物理电路，也是一台可预测的抽象机器。

本章小结。状态压缩相关历史，使相同输入在不同上下文中产生不同结果。交叉耦合门创造双稳态存储；SR 锁存器展示置位/复位反馈，D 锁存器提供电平敏感数据存储，D 触发器提供边沿采样。寄存器把比特组成字，计数器生成状态序列，移位寄存器在级间移动数据。FSM 把记住的情形转化为受控转移：Moore 输出依赖状态，Mealy 输出还依赖当前输入。寄存器文件增加可寻址多端口访问，ROM、SRAM 与 DRAM 则通过不同单元机制在可编程性、速度、密度、刷新和持久性之间权衡。最后，传播与污染延迟、建立与保持、偏斜、抖动和亚稳态共同决定逻辑正确的状态转移能否在物理上可靠发生。第 05 章将在这些存储与数据通路基础上解释指令集如何向软件暴露机器操作。
