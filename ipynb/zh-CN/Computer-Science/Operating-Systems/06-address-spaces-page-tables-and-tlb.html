地址空间、页表与 TLB

进程看见从低地址到高地址的私有、连续虚拟空间，物理内存却由不连续页框组成，并被内核、设备和许多进程共享。虚拟内存通过 MMU 和页表把每次内存访问从虚拟地址翻译为物理地址，同时检查权限；TLB 缓存近期翻译，使这个保护过程在常见路径上足够快。

本章关注“翻译与保护”本身，下一章再讨论页面不驻留时如何按需装入和置换。贯穿问题是：地址如何被分解，页表如何表示稀疏空间，TLB 命中/未命中如何改变访问成本，以及映射变化后如何让所有 CPU 停止使用旧翻译。

为什么要虚拟化内存？

重定位、隔离、共享与稀疏性

  • 重定位：程序使用稳定虚拟地址，内核可把页面放在任意可用页框并随时迁移。
  • 隔离：每进程页表和 user/supervisor、read/write/execute 权限阻止越权访问。
  • 共享：多个地址空间可把不同虚拟页映射到同一物理页框，用于共享库、IPC 和文件缓存。
  • 稀疏性：很大的虚拟范围可以保持未映射，不必为地址空洞分配物理内存。

虚拟内存不会凭空增加 RAM。它增加一层命名与保护，使物理资源可灵活放置、共享和延迟分配，同时付出页表内存、TLB、缺页处理与一致性成本。

地址空间与内存区域

代码、数据、堆、栈与映射区域

内核通常先用 VMA/region 描述一段虚拟区间的语义：范围、权限、匿名或文件 backing、共享/私有、增长和故障处理方式；页表再记录当前每页翻译。区域存在不代表其每个页面已经有页框或 PTE，按需分页正依赖这种分离。

代码常为读/执行，常量为只读，数据/堆/栈为读写且通常不可执行，guard page 保持不可访问以捕获越界。ASLR 随机化布局以增加利用固定地址的难度。

# 查看当前 shell 进程的内存区域。
head -n 15 /proc/$$/maps

# 查看可执行文件请求加载的 ELF 段。
readelf -W -l /proc/$$/exe

# 查看当前用户空间环境暴露的基本页大小。
getconf PAGE_SIZE

/proc/<pid>/maps 展示区域视图，readelf -l 展示 ELF 请求的 segment；二者不应与逐页驻留状态混淆。

早期地址翻译机制

基址与界限

基址-界限把进程逻辑地址 \(v\) 翻译为 \(base+v\)，前提是 \(0\le v<bound\)。它只需少量寄存器、重定位快速，但整个进程必须占用一个连续物理区间，且不同区域不能独立设置细粒度权限。

分段与外部碎片

分段让地址包含 segment 与 offset，每个代码、堆或栈段有独立 base、limit 和权限，能反映程序逻辑结构。但可变长度物理分配在段之间留下难以利用的孔洞，即外部碎片；压缩需要移动数据并更新映射，代价很高。

现代通用系统主要使用分页，某些体系结构仍保留有限分段功能，语言运行时或对象系统也可能在更高层采用逻辑分段思想。

分页

页、页框与偏移保持

分页把虚拟空间分成固定大小 page，物理内存分成相同大小 frame。若页大小为 \(P=2^k\)：

\[VA=VPN\times P+offset,\qquad 0\le offset<P.\]

页表把 VPN 映射到 PFN/PPN，物理地址为

\[PA=PFN\times P+offset.\]

低 \(k\) 位 offset 原样保留，只有高位页号被替换。

地址转换(VA, operation)：
    如果 VA >= bounds：
        触发 protection_fault
    PA = base + VA
    在 PA 执行 operation

内部碎片与页大小

固定页消除了进程放置的外部碎片，却在最后未填满页面产生内部碎片。页更大意味着更少 PTE、更高 TLB reach、更高连续 I/O 效率；也意味着分配粒度粗、COW/缺页时复制或读入更多无用数据，并要求更大连续页框。

Huge page 是工作负载与平台相关优化，不应仅因为“TLB 更少”就默认启用；需同时测量内存浪费、缺页延迟、compaction 和 NUMA 放置。

页表项与权限

存在、访问、脏、执行与用户位

PTE 除物理页号外，还包含 present/valid、read/write/execute、user/supervisor、accessed/reference、dirty 以及供 OS 使用的状态。不同 ISA 编码不同，但判断顺序相似：条目是否有效？请求模式和访问类型是否获准？若获准则形成物理地址并更新访问状态，否则触发 fault。

W^X 尽量避免页面同时可写和可执行；user 位阻止用户态访问内核映射；accessed/dirty 位帮助置换与回写。内核修改映射还必须考虑 TLB 中缓存的旧权限。

C：使用 mmap 与 mprotect 改变页权限 
#define _GNU_SOURCE
#include <errno.h>
#include <stdio.h>
#include <string.h>
#include <sys/mman.h>
#include <unistd.h>

int main(void) {
    long page_size = sysconf(_SC_PAGESIZE);
    if (page_size <= 0) {
        fputs("cannot determine page size\n", stderr);
        return 1;
    }

    char *page = mmap(NULL, (size_t)page_size,
                      PROT_READ | PROT_WRITE,
                      MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (page == MAP_FAILED) {
        perror("mmap");
        return 1;
    }

    // 该映射最初允许普通写操作。
    snprintf(page, (size_t)page_size, "translation includes permissions");

    // mprotect 作用于页对齐映射，并改变后续访问权限。
    if (mprotect(page, (size_t)page_size, PROT_READ) == -1) {
        perror("mprotect read-only");
        munmap(page, (size_t)page_size);
        return 1;
    }

    printf("read-only page says: %s\n", page);
    // 此处写入 page[0] 会违反映射权限，通常触发 SIGSEGV。

    if (mprotect(page, (size_t)page_size, PROT_READ | PROT_WRITE) == -1) {
        perror("mprotect restore");
        munmap(page, (size_t)page_size);
        return 1;
    }

    page[0] = 'T';
    if (munmap(page, (size_t)page_size) == -1) {
        perror("munmap");
        return 1;
    }
    return 0;
}

页表组织

线性页表与多级页表

线性页表为每个可能 VPN 保留一个 PTE，查找简单，但 64 位稀疏地址空间会消耗巨大内存。多级 radix tree 把 VPN 分成多个索引，只为实际使用的分支分配下级表，从而让元数据成本与映射密度相关。

table = physical_address(root_register)
按 VPN 字段从最高级到最低级遍历 index：
    entry = read(table[index])
    如果 entry 无效：
        触发 page_fault
    如果 entry 是叶条目：
        检查权限
        将叶条目的 PFN 与剩余 VPN 位和页内偏移组合
        返回 physical_address
    table = physical_address(entry.next_table)

多级表节省稀疏空间，但 TLB miss 的硬件 page walk 可能需要多次串行内存访问；page-walk cache 和上层条目缓存可缓解成本。

哈希页表与反向页表

哈希页表用 (ASID, VPN) 哈希到桶链，适合非常大且稀疏空间，但冲突和 worst-case 查找需要管理。反向页表按物理页框只保留一个所有者记录，元数据与物理内存而非虚拟空间成比例，但从虚拟地址反查映射更复杂，共享页也需额外结构。

现代 ISA 常围绕硬件支持的多级 radix 表设计，其他组织仍帮助理解设计空间和软件管理 TLB 系统。

MMU 地址翻译路径

CPU 发出虚拟地址和操作类型，MMU 先检查地址格式与当前权限模式，再用 ASID/PCID 加 VPN 查询 TLB。命中后检查权限并拼接 PFN 与 offset；未命中时由硬件或软件遍历页表，成功则填充 TLB，失败则产生 page fault。

翻译与数据访问是两种不同内存活动。TLB miss 不等于 page fault：前者可能只需从驻留页表重建缓存，后者表示映射不存在、权限不符或需要 OS 介入。

地址翻译旁路缓冲器

TLB 命中、未命中与替换

TLB 是按 VPN、页大小、权限和地址空间标签缓存的翻译。命中让每次数据访问无需完整 page walk；未命中会触发硬件或软件 refill。容量、组相联、替换、不同级 TLB 和 instruction/data TLB 都会影响性能。

TLB reach 约为条目数乘页大小。顺序扫描超大工作集可能不断替换翻译；huge page 能增大 reach，却带来上一节的分配和碎片权衡。

# 事件名称依赖平台；请先运行 `perf list | grep -i tlb`。
perf stat -e dTLB-loads,dTLB-load-misses,iTLB-load-misses ./program

# 全系统页表与大页统计提供另一种观察视角。
grep -E 'PageTables|HugePages|AnonHugePages' /proc/meminfo

性能计数器事件随 CPU 而异，必须先检查 perf list，并把 TLB miss 与 cache miss、page fault 分开解释。

ASID、PCID 与上下文切换

如果 TLB 条目没有地址空间标签，每次切换进程都必须清空，导致重新升温。RISC-V ASID 与 x86 PCID 允许不同进程翻译共存；匹配时标签成为键的一部分。标签数量有限，复用时仍需失效处理。

映射被撤销或权限降低后，本 CPU 和其他可能缓存该映射的 CPU 都必须丢弃旧条目。多核 TLB shootdown 发送跨处理器失效请求并等待确认，成本随活跃 CPU 和更新频率增加。

缺页作为受控异常

缺页不是都表示错误。内核根据 fault 地址、访问类型、用户/内核模式和区域元数据分类：地址不规范或不在 VMA 中通常拒绝；权限违规可能转为信号；合法但不 present 的页可按需分配、读文件或完成 COW；访问/脏状态异常也可能只需更新条目。

处理完成后必须更新 PTE、执行必要屏障/失效并重启产生故障的精确指令。若 fault 发生在内核访问用户指针时，内核还需使用可恢复 copy 路径，不能让坏用户地址崩溃全系统。

C：在 Linux 上观察首次访问 minor fault 
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <sys/mman.h>
#include <sys/resource.h>
#include <unistd.h>

static long minor_faults(void) {
    struct rusage usage;
    if (getrusage(RUSAGE_SELF, &usage) == -1) {
        perror("getrusage");
        exit(EXIT_FAILURE);
    }
    return usage.ru_minflt;
}

int main(void) {
    const size_t length = 64U * 1024U * 1024U;
    long page_size = sysconf(_SC_PAGESIZE);
    if (page_size <= 0) {
        fputs("cannot determine page size\n", stderr);
        return 1;
    }

    long before_map = minor_faults();
    volatile unsigned char *memory = mmap(
        NULL, length, PROT_READ | PROT_WRITE,
        MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (memory == MAP_FAILED) {
        perror("mmap");
        return 1;
    }
    long after_map = minor_faults();

    // 在每个基本页间隔访问一个字节；volatile 指针可防止
    // 编译器删除这些可观察的写操作。
    for (size_t offset = 0; offset < length; offset += (size_t)page_size) {
        memory[offset] = 1;
    }
    long after_touch = minor_faults();

    printf("minor faults during mmap:  %ld\n", after_map - before_map);
    printf("minor faults during touch: %ld\n", after_touch - after_map);

    if (munmap((void *)memory, length) == -1) {
        perror("munmap");
        return 1;
    }
    return 0;
}

比较 x86-64 与 RISC-V 翻译

x86-64 典型四级模式把虚拟地址分为多个 9 位索引与 12 位 offset，根由 CR3 指定，PTE 包含 present、R/W、U/S、A、D、NX 等；invlpg 或带 PCID 的机制负责失效。RISC-V Sv39 使用三个 9 位 VPN 与 12 位 offset，satp 保存 mode、ASID 和根 PPN，PTE 的 V/R/W/X/U/G/A/D 定义有效性与权限，sfence.vma 协调翻译更新。

两者具体保留位、large page 叶层和 fault cause 不同，但共同不变量是：根上下文选择页表，逐级条目定位叶映射，叶权限与当前模式共同决定访问，软件修改后必须使旧翻译失效。

构建最小页表遍历器

下面的 C 程序模拟 Sv39：验证 canonical 地址；从 satp 根 PPN 开始依次取 VPN[2:0]；检查 V 与非法 W-without-R 组合；遇到叶 PTE 时验证权限和 superpage 对齐；最后把 PPN 与 offset 组合。它是教学模拟，不读取真实进程页表。

C：最小模拟 RISC-V Sv39 页表遍历器 
#include <inttypes.h>
#include <stdbool.h>
#include <stdint.h>
#include <stdio.h>
#include <string.h>

enum {
    PAGE_SHIFT = 12,
    PAGE_SIZE = 1U << PAGE_SHIFT,
    PT_ENTRIES = 512,
    RAM_PAGES = 16
};

enum {
    PTE_V = 1U << 0,
    PTE_R = 1U << 1,
    PTE_W = 1U << 2,
    PTE_X = 1U << 3,
    PTE_U = 1U << 4,
    PTE_A = 1U << 6,
    PTE_D = 1U << 7
};

typedef enum {
    ACCESS_READ,
    ACCESS_WRITE,
    ACCESS_EXECUTE
} access_t;

typedef enum {
    WALK_OK,
    WALK_NONCANONICAL,
    WALK_INVALID,
    WALK_PERMISSION,
    WALK_AD_MISSING,
    WALK_MISALIGNED_SUPERPAGE,
    WALK_OUT_OF_RAM
} walk_status_t;

static unsigned char ram[RAM_PAGES * PAGE_SIZE];

static bool read_pte(uint64_t table_ppn, uint16_t index, uint64_t *pte) {
    if (index >= PT_ENTRIES) {
        return false;
    }
    uint64_t address = (table_ppn << PAGE_SHIFT) +
                       (uint64_t)index * sizeof *pte;
    if (address > sizeof ram - sizeof *pte) {
        return false;
    }
    memcpy(pte, &ram[address], sizeof *pte);
    return true;
}

static bool write_pte(uint64_t table_ppn, uint16_t index, uint64_t pte) {
    if (index >= PT_ENTRIES) {
        return false;
    }
    uint64_t address = (table_ppn << PAGE_SHIFT) +
                       (uint64_t)index * sizeof pte;
    if (address > sizeof ram - sizeof pte) {
        return false;
    }
    memcpy(&ram[address], &pte, sizeof pte);
    return true;
}

static bool is_canonical_sv39(uint64_t virtual_address) {
    uint64_t upper = virtual_address >> 39;
    uint64_t expected = ((virtual_address >> 38) & 1U)
                            ? ((UINT64_C(1) << 25) - 1U)
                            : 0U;
    return upper == expected;
}

static walk_status_t walk_sv39(uint64_t root_ppn,
                               uint64_t virtual_address,
                               access_t access,
                               bool user_mode,
                               uint64_t *physical_address) {
    if (!is_canonical_sv39(virtual_address)) {
        return WALK_NONCANONICAL;
    }

    uint16_t vpn[3] = {
        (uint16_t)((virtual_address >> 12) & 0x1ffU),
        (uint16_t)((virtual_address >> 21) & 0x1ffU),
        (uint16_t)((virtual_address >> 30) & 0x1ffU)
    };
    uint64_t table_ppn = root_ppn;

    for (int level = 2; level >= 0; --level) {
        uint64_t pte;
        if (!read_pte(table_ppn, vpn[level], &pte)) {
            return WALK_OUT_OF_RAM;
        }

        bool valid = (pte & PTE_V) != 0;
        bool readable = (pte & PTE_R) != 0;
        bool writable = (pte & PTE_W) != 0;
        bool executable = (pte & PTE_X) != 0;

        // Sv39 保留 W=1、R=0 的组合，并拒绝 V=0 的条目。
        if (!valid || (!readable && writable)) {
            return WALK_INVALID;
        }

        if (readable || executable) {
            // 已到达叶级映射。
            if (user_mode && (pte & PTE_U) == 0) {
                return WALK_PERMISSION;
            }
            if ((access == ACCESS_READ && !readable) ||
                (access == ACCESS_WRITE && !writable) ||
                (access == ACCESS_EXECUTE && !executable)) {
                return WALK_PERMISSION;
            }
            if ((pte & PTE_A) == 0 ||
                (access == ACCESS_WRITE && (pte & PTE_D) == 0)) {
                return WALK_AD_MISSING;
            }

            uint64_t ppn = pte >> 10;
            uint64_t low_ppn_mask = (level == 0)
                                        ? 0U
                                        : ((UINT64_C(1) << (9 * level)) - 1U);

            // 上层叶条目要求物理超级页对齐。
            if ((ppn & low_ppn_mask) != 0) {
                return WALK_MISALIGNED_SUPERPAGE;
            }

            // 对超级页而言，较低位 VPN 字段会成为较低位 PPN 字段。
            ppn = (ppn & ~low_ppn_mask) |
                  ((virtual_address >> PAGE_SHIFT) & low_ppn_mask);
            *physical_address = (ppn << PAGE_SHIFT) |
                                (virtual_address & (PAGE_SIZE - 1U));
            return WALK_OK;
        }

        // 非叶条目指向下一级页表页。
        if (level == 0) {
            return WALK_INVALID;
        }
        table_ppn = pte >> 10;
    }

    return WALK_INVALID;
}

int main(void) {
    const uint64_t root_ppn = 1;
    const uint64_t level1_ppn = 2;
    const uint64_t level0_ppn = 3;
    const uint64_t data_ppn = 8;
    const uint64_t virtual_address = UINT64_C(0x12345678);

    uint16_t vpn0 = (uint16_t)((virtual_address >> 12) & 0x1ffU);
    uint16_t vpn1 = (uint16_t)((virtual_address >> 21) & 0x1ffU);
    uint16_t vpn2 = (uint16_t)((virtual_address >> 30) & 0x1ffU);

    // 构造根页表 -> 第 1 级 -> 第 0 级 -> 数据页框映射。
    if (!write_pte(root_ppn, vpn2, (level1_ppn << 10) | PTE_V) ||
        !write_pte(level1_ppn, vpn1, (level0_ppn << 10) | PTE_V) ||
        !write_pte(level0_ppn, vpn0,
                   (data_ppn << 10) |
                       PTE_V | PTE_R | PTE_W | PTE_U | PTE_A | PTE_D)) {
        fputs("failed to construct simulated page tables\n", stderr);
        return 1;
    }

    uint64_t physical_address;
    walk_status_t status = walk_sv39(root_ppn, virtual_address,
                                     ACCESS_WRITE, true,
                                     &physical_address);
    if (status != WALK_OK) {
        fprintf(stderr, "walk failed with status %d\n", status);
        return 1;
    }

    printf("VA 0x%08" PRIx64 " -> PA 0x%05" PRIx64 "\n",
           virtual_address, physical_address);
    return 0;
}

遍历器最重要的价值是把“页表就是一个字典”的模糊理解变成逐层地址计算和错误检查。真实硬件还会处理 A/D 更新、PMP/PMA、TLB、缓存和 speculative walk。

对比与总结

机制 映射粒度 主要优点 主要成本/限制
Base/bounds 整个连续进程 状态少、翻译简单 连续放置、权限粗、外部碎片
Segmentation 可变长度逻辑段 反映代码/堆/栈与独立权限 外部碎片和分配复杂度
Paging 固定大小页面 任意页框放置、隔离、共享、稀疏 页表、内部碎片、TLB 与 fault
线性页表 每个 VPN 一项 索引直接 大稀疏空间浪费
多级页表 只分配使用分支 稀疏空间高效 miss 时多次内存访问
哈希/反向表 哈希 VPN 或按物理页框 面向巨大稀疏空间或限制元数据 冲突、反查和共享复杂
TLB 缓存近期翻译 常见路径快速 容量有限、失效与 shootdown

地址空间不是“连续物理内存的假象”，而是一套由 region 语义、页表、TLB、权限和异常处理共同维护的受保护命名系统。理解虚拟页到物理页框的逐步路径后，下一章的 demand paging、COW 和页面置换才会成为同一机制的自然扩展。
