进程与程序执行

cat input.txt | grep kernel > result.txt

这条管道需要的不只是把两个可执行文件读入内存。内核必须创建两个受保护的执行实体，建立它们的地址空间和文件描述符关系，在可运行、运行与等待状态之间调度它们，并在退出后回收状态。程序（program）描述可以执行什么，进程（process）则描述一次正在被操作系统管理的执行实例。

本章沿程序从磁盘映像到可运行进程的路径，解释 fork、exec、wait、copy-on-write、动态加载、上下文切换和文件描述符继承。核心问题始终是：哪些状态定义了执行，谁拥有这些状态，以及它们何时被复制、替换、共享或回收？

程序、进程与执行上下文

程序尚不是进程

程序通常是持久存储上的被动表示，包含机器指令、已初始化数据以及加载器需要的元数据。它本身没有当前程序计数器、调度状态、打开文件或正在变化的堆。只有加载器建立地址空间、内核分配身份与资源、CPU 上下文准备完成后，它才成为可执行的进程。

状态类别 典型内容 为什么需要
程序表示 机器指令、初始化数据、加载元数据 定义能够进行的计算
内存上下文 页表、映射、栈、堆、共享库 为指令和数据提供受保护虚拟地址
CPU 上下文 程序计数器、栈指针、通用寄存器、状态标志 精确记录从哪里继续执行
内核上下文 PID、凭据、调度状态、描述符、信号与核算 让内核管理、保护、观察并最终回收执行

同一个程序文件可以同时对应许多进程，它们拥有不同 PID、参数、环境变量、地址空间和打开文件。反过来，一个进程也可以通过 execve() 保留身份和部分资源，却把当前程序映像整体替换成另一个程序。

进程身份与资源所有权

PID 是查找进程的标识符，却不是完整的安全身份。内核还维护父进程、进程组、会话、用户与组凭据、安全标签、命名空间、资源限制和能力。PID 会复用，因此长期引用不能仅凭一个旧数字判断对象仍是原进程；现代接口可使用 pidfd 等带生命周期语义的句柄。

“进程拥有资源”通常表示内核在进程上下文中维护引用：描述符表引用打开文件，地址空间引用页表和映射，凭据控制权限，信号状态与计时器随进程或线程组存在。当最后一个引用消失时，内核才能回收相应对象。

进程映像

进程映像不仅是可执行文件内容，还包括运行时映射、寄存器、用户栈以及内核无法直接放入用户地址空间的管理状态。

虚拟地址空间布局

典型进程地址空间由多个用途和权限不同的区域组成：

区域 典型内容 常见权限
Text 编译后的机器指令 读、执行
只读数据 常量与不可变表 读
Data 已初始化的可写全局变量 读、写
BSS 零初始化全局变量，文件中可紧凑表示 读、写
Heap 动态分配，传统上由 brk() 扩展，也可来自映射 读、写
Memory mappings 共享库、映射文件、匿名区、线程栈 取决于映射
用户栈 调用帧、局部变量、初始参数与环境 读、写，通常不可执行
内核提供映射 例如 Linux vDSO 取决于映射

图中地址顺序只是概念模型。ASLR 会随机化位置，栈和堆也不必简单相向生长；真正不变量是每个虚拟区间都有来源、权限与生命周期。

寄存器、栈与内核状态

CPU 寄存器说明执行“此刻在哪里”，用户栈保存函数调用链和局部状态，内核栈则服务于该线程进入内核后的受保护执行。用户栈不能用作内核栈，否则恶意程序可以篡改返回路径和局部内核数据。

当线程被抢占或阻塞时，内核保存足够的寄存器状态，稍后才能像从未离开过一样恢复。并非所有状态都必须在每次切换时主动复制：部分状态已位于线程控制块或内核栈，浮点/向量状态也可按体系结构策略延迟或优化保存。

进程控制块

进程控制块（PCB）是描述内核所维护每进程信息的教学术语；实际内核可能把信息拆成多个相互引用的结构。

领域 代表性信息
身份 PID、父进程、进程组、会话
执行 保存寄存器、内核栈、当前状态
调度 优先级、策略、运行时间、队列链接、CPU 亲和性
内存 地址空间及映射的引用
资源 描述符表、工作目录、资源限制
保护 凭据、安全标签、capability
事件 信号状态、wait 状态、定时器
核算 CPU 时间、启动时间、缺页和 I/O 计数

PCB 不是“整个进程”；它是内核用于定位、调度、保护和回收该执行实体的控制记录。

进程状态与转换

就绪、运行、阻塞与终止

  • New：内核正在创建身份和基本资源，尚未进入普通调度。
  • Ready：拥有运行所需条件，正在等待 CPU。
  • Running：某个 CPU 正在执行其指令或代表它执行内核代码。
  • Blocked/Waiting：必须等待 I/O、锁、计时器或其他事件，暂时不应占用 CPU。
  • Terminated：执行已经结束，但退出状态可能仍待父进程收集。

状态属于调度实体；多线程进程中的某个线程可阻塞，其他线程仍能运行。一次系统调用也不必阻塞：命中缓存的读取可能立刻完成，而缺少数据的读取才把线程放入等待队列。

父进程、子进程、孤儿进程与僵尸进程

fork() 建立父子关系。子进程先退出时，内核保留少量终止记录，以便父进程通过 wait()/waitpid() 获得退出状态；此时它是僵尸进程（zombie），已不再执行，也不持有完整地址空间。父进程若先退出，存活子进程成为孤儿进程（orphan），会由 init/subreaper 等接管回收责任。

僵尸不是“仍在运行的死进程”，而是尚未被收割的退出状态。大量僵尸会耗尽 PID 或进程表槽位，因此长期服务必须正确处理子进程完成。

查看僵尸进程观察程序 
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void) {
    pid_t child = fork();
    if (child == -1) {
        perror("fork");
        return EXIT_FAILURE;
    }

    if (child == 0) {
        // _exit 可避免子进程刷新复制而来的 stdio 缓冲区。
        _exit(42);
    }

    printf("parent=%ld child=%ld\n", (long)getpid(), (long)child);
    printf("Inspect with: ps -o pid,ppid,stat,cmd -p %ld\n", (long)child);

    // 在这段延迟期间，子进程已经退出，但尚未被回收。
    sleep(15);

    int status;
    if (waitpid(child, &status, 0) == -1) {
        perror("waitpid");
        return EXIT_FAILURE;
    }

    if (WIFEXITED(status)) {
        printf("collected exit status %d\n", WEXITSTATUS(status));
    }
    return EXIT_SUCCESS;
}

创建与终止进程

fork、exec、wait 与 exit

Unix 把“复制执行上下文”和“装入新程序”分成两个原语：

操作 创建新 PID？ 替换地址空间？ 关键返回行为
fork() 是 否，起初以 copy-on-write 复制映射 在父子两边返回，返回值不同
execve() 否 是 只有失败时返回
waitpid() 否 否 指定子状态可用时返回，选项允许非阻塞
_exit() 否 销毁当前进程执行 永不返回

fork() 后必须依据返回值区分父子路径；子进程完成重定向后调用 execve()。若 execve() 失败，子进程应报告错误并用 _exit() 结束，避免刷新父进程复制来的 stdio 缓冲或执行不安全清理。父进程用循环处理 EINTR 并回收精确目标。

查看最小 fork-exec-wait 实现 
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void) {
    pid_t child = fork();
    if (child == -1) {
        perror("fork");
        return EXIT_FAILURE;
    }

    if (child == 0) {
        // 用 grep 替换当前子进程；execlp() 负责在 PATH 中查找程序。
        execlp("grep", "grep", "kernel", "input.txt", (char *)NULL);

        // 只有 exec 失败时才会执行到这里；errno 仍保存失败原因。
        perror("execlp grep");
        _exit(127);
    }

    int status;
    while (waitpid(child, &status, 0) == -1) {
        if (errno == EINTR) {
            continue; // A signal interrupted wait; the child may still be live.
        }
        perror("waitpid");
        return EXIT_FAILURE;
    }

    if (WIFEXITED(status)) {
        printf("grep exited with status %d\n", WEXITSTATUS(status));
        return WEXITSTATUS(status);
    }
    if (WIFSIGNALED(status)) {
        printf("grep was terminated by signal %d\n", WTERMSIG(status));
        return 128 + WTERMSIG(status);
    }
    return EXIT_FAILURE;
}

fork 之外的进程创建方式

接口 核心思路 优势 限制或风险
fork() + execve() 复制调用者、设置子进程、替换映像 Unix 组合能力最强 多线程程序中 fork 后设置非常敏感
posix_spawn() 用声明式动作描述创建和重定向 普通命令启动更方便，常更便宜安全 只支持刻意限定的定制集合
vfork() + execve() 子进程临时共享父地址空间上下文 某些实现可避免复制工作 父进程暂停，子进程在 exec/exit 前限制极严
Linux clone() 家族 选择共享哪些执行资源 线程、namespace 与运行时基础 Linux 特有，直接使用容易出错
Windows CreateProcess() 一步创建进程并加载指定程序 创建模型直接 继承和设置约定与 Unix 不同

多线程进程在 fork() 后只有调用线程存在，其他线程曾持有的锁可能永久保持“已锁定”副本。因此子进程在 exec() 前只能执行严格受限的 async-signal-safe 操作，普通应用更适合 posix_spawn()。

写时复制作为支撑机制

朴素 fork() 若立即复制全部物理页会很昂贵，而子进程常立刻 exec() 丢弃这些页。写时复制（copy-on-write, COW）让父子页表先指向同一物理页，并把映射标成只读；任何一方写入时触发保护故障，内核再为写入者复制该页并恢复写权限。

COW 推迟并避免不必要复制，却不是“完全免费的 fork”：仍需建立页表结构、增加页引用、复制内核元数据，后续写故障还会产生分配与复制成本。

加载与链接程序

可执行文件布局与加载器

Linux 常用 ELF。加载器关心 program header 描述的可加载 segment，而链接器和调试器更多使用 section。内核验证格式和体系结构，建立带权限的映射，创建初始栈和入口状态；动态链接程序还会先把控制交给动态加载器。

查看 ELF 可执行文件检查命令 
# 识别文件格式、体系结构与链接方式。
file /usr/bin/grep

# 检查 ELF 文件头以及面向加载器的程序头。
readelf -h /usr/bin/grep
readelf -l /usr/bin/grep

# 如果文件指定了程序解释器，则定位它。
readelf -l /usr/bin/grep | grep INTERP

# 在不执行文件的情况下检查节元数据与动态依赖。
readelf -S /usr/bin/grep
readelf -d /usr/bin/grep

# 观察程序运行后的内存映射。
grep -E 'grep|libc|ld-linux|\[stack\]|\[heap\]' /proc/<PID>/maps

W^X 原则要求可写页不同时可执行；代码通常映射为读/执行，数据映射为读/写。BSS 可通过“零填充内存大小大于文件大小”表示，无需在文件中存储大量零。

静态链接与动态链接

属性 静态链接 动态链接
库代码 链接时复制到可执行文件 运行时映射共享对象
部署 运行时库依赖较少 需要兼容加载器与库
文件/内存 文件更大，多个程序可能重复代码 只读库页可跨进程共享
更新 需重新链接并部署 兼容库更新可影响许多程序
启动工作 运行时符号解析较少 加载依赖并重定位
可复现性 更自包含，但仍依赖内核和外部数据 行为受运行库环境影响

动态链接通过重定位、GOT/PLT 和符号解析把编译时引用连接到运行时地址。惰性绑定可把部分解析推迟到首次调用，但会改变第一次调用时延和安全配置。

参数、环境与初始栈

内核和加载器在新用户栈上放置 argc、argv[]、envp[] 以及 auxiliary vector；后者携带页大小、入口地址、程序头、随机数据位置等启动信息。概念布局如下，实际顺序、对齐与内容由 ABI 决定：

+-------------------------------+

| NULL                           |
| envp[] 指针                   |
| NULL                           |
| argv[] 指针                   |
| argc                          |
+-------------------------------+  初始栈指针

查看检查启动数据的 C 程序 
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <sys/auxv.h>
#include <unistd.h>

extern char **environ;

int main(int argc, char **argv) {
    printf("pid=%ld argc=%d\n", (long)getpid(), argc);

    for (int i = 0; i < argc; ++i) {
        printf("argv[%d] = %s\n", i, argv[i]);
    }

    // 辅助向量由内核与加载器的启动路径提供。
    printf("page size = %lu\n", getauxval(AT_PAGESZ));
    printf("entry     = 0x%lx\n", getauxval(AT_ENTRY));

    const char *exec_name = (const char *)getauxval(AT_EXECFN);
    if (exec_name != NULL) {
        printf("exec file = %s\n", exec_name);
    }

    // 仅打印有限样本；真实环境可能很大，也可能包含敏感信息。
    for (int i = 0; environ[i] != NULL && i < 3; ++i) {
        printf("env[%d] = %s\n", i, environ[i]);
    }
    return EXIT_SUCCESS;
}

上下文切换

保存与恢复执行状态

线程因时间片到期、阻塞、主动让出或更高优先级工作到来而停止运行时，内核保存其可恢复 CPU 状态，选择另一个可运行实体，切换必要的地址空间和内核栈，再恢复目标寄存器并返回用户态。

模式切换不等于上下文切换，线程切换也不一定更换地址空间：同一进程的线程通常共享页表，而不同进程往往需要切换地址空间标识和相关翻译状态。

直接与间接上下文切换成本

成本类别 示例 变化原因
直接软件工作 入口/返回、寄存器保存、队列和核算 体系结构、内核路径、安全功能
地址翻译状态 页表上下文、TLB 影响 进程/线程切换、PCID/ASID 支持
缓存局部性 指令和数据被替换、缓存一致性 工作集及目标最近是否运行
预测状态 分支预测器与前端重新升温 处理器和负载
拓扑 跨核或 NUMA 迁移 亲和性、负载均衡、内存放置

真正昂贵的部分常是切换后的冷缓存和迁移，而不是保存几个寄存器。测量时应区分“发生了多少次切换”和“每次切换破坏了多少局部性”。

查看 Linux 上下文切换观察命令 
# Linux 为每个进程维护的主动与被动上下文切换计数。
grep -E 'voluntary_ctxt_switches|nonvoluntary_ctxt_switches' /proc/<PID>/status

# 重复报告进程级上下文切换（需要 sysstat 软件包）。
pidstat -w -p <PID> 1

# 运行一个命令时观察全系统事件（需要 perf 软件包）。
perf stat -e context-switches,cpu-migrations,page-faults -- ./your_program

# 按时间戳比较调度历史；需要相应权限。
perf sched record -- ./your_program
perf sched timehist

文件描述符作为进程能力

描述符表与打开文件描述

文件描述符是进程局部的小整数，它通过描述符表引用系统级的 open file description，后者再引用 inode、管道、套接字或设备等底层对象。

层次 代表性状态 共享行为
描述符表项 FD_CLOEXEC 等描述符标志、打开文件描述指针 fork() 复制表项；dup2()/close() 按进程修改
打开文件描述 当前偏移、访问模式、O_APPEND 等状态标志 dup() 与 fork() 产生的描述符可共享
底层对象 inode/数据、管道缓冲、socket、设备 可被多个打开文件描述或端点引用

因此父子进程继承同一打开文件描述时会共享文件偏移；两个独立 open() 即使打开同一路径，通常也拥有独立偏移。

查看共享文件偏移的确定性演示 
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void) {
    const char *path = "offset-demo.tmp";
    int fd = open(path, O_RDWR | O_CREAT | O_TRUNC, 0600);
    if (fd == -1) {
        perror("open");
        return EXIT_FAILURE;
    }

    if (write(fd, "ABCDE", 5) != 5 || lseek(fd, 0, SEEK_SET) == -1) {
        perror("prepare file");
        close(fd);
        return EXIT_FAILURE;
    }

    pid_t child = fork();
    if (child == -1) {
        perror("fork");
        close(fd);
        return EXIT_FAILURE;
    }

    if (child == 0) {
        char bytes[3] = {0};
        // 该读取把共享打开文件描述的偏移量从 0 推进到 2。
        if (read(fd, bytes, 2) == 2) {
            dprintf(STDOUT_FILENO, "child read: %s\n", bytes); // AB
        }
        close(fd);
        _exit(0);
    }

    // 等待子进程可使演示顺序保持确定。
    waitpid(child, NULL, 0);

    char bytes[3] = {0};
    if (read(fd, bytes, 2) == 2) {
        printf("parent read: %s\n", bytes); // CD, not AB
    }

    close(fd);
    unlink(path);
    return EXIT_SUCCESS;
}

重定向与描述符继承

dup2(oldfd, STDOUT_FILENO) 让描述符 1 引用与 oldfd 相同的打开对象，程序随后无需知道输出已被重定向。fork() 继承描述符，execve() 默认继续保留，只有带 FD_CLOEXEC 的描述符会在成功 exec 时关闭。

描述符继承既提供强大的组合能力，也容易泄漏权限和破坏协议。创建内部描述符时优先使用 O_CLOEXEC、pipe2(O_CLOEXEC) 等原子接口，避免多线程程序在“创建”和“设置 close-on-exec”之间被另一个线程 fork。

Shell 如何构建贯穿管道

实现要点包括：先创建管道和输出文件；分别 fork 两个子进程；在子进程中用 dup2() 安装标准流并关闭所有无关端；调用 execvp()；父进程立即关闭自己的管道端，再可靠等待两个 PID。任何遗留写端都会让 grep 永远等不到 EOF。

查看完整带注释 C 管道实现 
#define _POSIX_C_SOURCE 200809L
#include <errno.h>
#include <fcntl.h>
#include <signal.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>

static void child_failure(const char *operation) {
    // 为便于说明，这里使用 perror。生产级多线程启动器
    // 应将 fork 后的子进程路径限制为安全操作。
    perror(operation);
    _exit(127);
}

static int wait_for(pid_t child, const char *name) {
    int status;
    while (waitpid(child, &status, 0) == -1) {
        if (errno == EINTR) {
            continue;
        }
        perror("waitpid");
        return 1;
    }

    if (WIFEXITED(status)) {
        int code = WEXITSTATUS(status);
        fprintf(stderr, "%s exited with %d\n", name, code);
        return code;
    }
    if (WIFSIGNALED(status)) {
        int signal_number = WTERMSIG(status);
        fprintf(stderr, "%s terminated by signal %d\n", name, signal_number);
        return 128 + signal_number;
    }
    return 1;
}

int main(void) {
    int pipe_fd[2];
    if (pipe(pipe_fd) == -1) {
        perror("pipe");
        return EXIT_FAILURE;
    }

    int output_fd = open(
        "result.txt",
        O_WRONLY | O_CREAT | O_TRUNC,
        0644
    );
    if (output_fd == -1) {
        perror("open result.txt");
        close(pipe_fd[0]);
        close(pipe_fd[1]);
        return EXIT_FAILURE;
    }

    pid_t cat_pid = fork();
    if (cat_pid == -1) {
        perror("fork cat");
        close(pipe_fd[0]);
        close(pipe_fd[1]);
        close(output_fd);
        return EXIT_FAILURE;
    }

    if (cat_pid == 0) {
        // cat 把正常的标准输出写入管道。
        if (dup2(pipe_fd[1], STDOUT_FILENO) == -1) {
            child_failure("dup2 cat stdout");
        }

        close(pipe_fd[0]);
        close(pipe_fd[1]);
        close(output_fd);

        execlp("cat", "cat", "input.txt", (char *)NULL);
        child_failure("exec cat");
    }

    pid_t grep_pid = fork();
    if (grep_pid == -1) {
        perror("fork grep");
        close(pipe_fd[0]);
        close(pipe_fd[1]);
        close(output_fd);

        // 避免让已经创建的子进程失去管理。
        kill(cat_pid, SIGTERM);
        waitpid(cat_pid, NULL, 0);
        return EXIT_FAILURE;
    }

    if (grep_pid == 0) {
        // grep 从管道读取，并把匹配行写入文件。
        if (dup2(pipe_fd[0], STDIN_FILENO) == -1) {
            child_failure("dup2 grep stdin");
        }
        if (dup2(output_fd, STDOUT_FILENO) == -1) {
            child_failure("dup2 grep stdout");
        }

        close(pipe_fd[0]);
        close(pipe_fd[1]);
        close(output_fd);

        execlp("grep", "grep", "kernel", (char *)NULL);
        child_failure("exec grep");
    }

    // 对这个前台作业而言，shell 既不是管道读端，也不是写端。
    close(pipe_fd[0]);
    close(pipe_fd[1]);
    close(output_fd);

    int cat_status = wait_for(cat_pid, "cat");
    int grep_status = wait_for(grep_pid, "grep");

    // 简单 shell 通常报告最后一个命令的状态；真实 shell
    // 还可能提供 pipefail 策略，把前面命令的失败也纳入判断。
    (void)cat_status;
    return grep_status;
}

在 Linux 中观察进程

不同工具回答不同问题：ps 和 /proc/<pid>/status 查看身份与状态；/proc/<pid>/exe 和 cmdline 查看程序映像；maps/pmap 查看地址空间；fd/lsof 查看描述符；strace、wchan 或调试器查看阻塞位置；pstree 查看层级。

查看聚焦的 Linux 观察流程 
# 在后台启动管道，并保留 shell 作业 PID。
sh -c 'cat input.txt | grep kernel > result.txt' &
job_pid=$!

# 查看层级、状态、进程组与等待通道。
ps -eo pid,ppid,pgid,sid,stat,psr,wchan:24,cmd --forest
pstree -ap "$job_pid"

# 检查指定进程；把 PID 替换为 ps/pstree 给出的真实值。
pid=<PID>
readlink "/proc/$pid/exe"
tr '\0' ' ' < "/proc/$pid/cmdline"; echo
grep -E '^(Name|State|Pid|PPid|Threads|voluntary|nonvoluntary)' "/proc/$pid/status"
sed -n '1,20p' "/proc/$pid/maps"
ls -l "/proc/$pid/fd"

# 跟踪进程创建、描述符变化、exec、等待与退出。
strace -f -e trace=process,desc -o pipeline.trace \
  sh -c 'cat input.txt | grep kernel > result.txt'
less pipeline.trace

观测本身有竞态：进程可能在读取多个 /proc 文件之间改变状态或退出。因此应记录采样时间、PID namespace 和权限条件，并把一次快照视为证据而不是永恒事实。

对比与总结

概念 回答的稳定问题 当前不占用 CPU 时仍存在吗？
程序 有哪些可执行指令与静态数据？ 是
进程 哪些受保护资源和身份属于这次执行？ 是
线程 调度器可以运行哪条寄存器流和栈？ 是
地址空间 哪些虚拟地址与权限可见？ 是
文件描述符 进程可通过表项访问哪个内核对象？ 是

贯穿本章的生命周期是：可执行文件经加载形成地址空间；内核为执行分配身份和控制状态；调度器让线程获得 CPU；系统调用使其阻塞与唤醒；fork() 复制引用和 COW 映射；exec() 替换程序映像；exit() 释放大部分资源；wait() 最终回收终止记录。

最关键的区别是：fork() 创建新执行身份但不选择新程序，exec() 选择新程序但不创建新 PID。 Unix shell 正是利用这种分离，在 exec 之前把文件、管道和标准流组合成所需拓扑。
