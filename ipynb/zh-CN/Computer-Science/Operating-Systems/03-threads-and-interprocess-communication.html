线程与进程间通信

cat input.txt | grep kernel > result.txt

上一章把进程定义为受保护的资源容器，但真实程序经常需要让多个活动重叠：一个活动等待 I/O 时另一个继续计算，多个 CPU 同时处理请求，或者彼此隔离的进程交换数据。操作系统因此提供两组互补机制：线程（thread）在一个进程内部提供多个执行流，进程间通信（IPC）则在保护域之间建立受控数据与事件通道。

选择线程还是进程、共享内存还是消息、阻塞还是事件循环，并不是语法偏好。它决定故障范围、状态所有权、复制成本、背压方式和可推理性。本章始终用“谁共享什么、谁等待谁、容量耗尽时会怎样、关闭如何传播”来分析设计。

程序为什么需要并发执行？

并发与并行

并发（concurrency）表示多个活动的生命周期重叠；它们可以在一个 CPU 上交错推进。并行（parallelism）表示多个活动在同一时刻由不同执行资源真正运行。并发是程序组织和可观察交错的属性，并行则依赖可用核心和调度。

在单核上，线程切换仍可隐藏 I/O 等待并改善响应；在多核上，独立 CPU 工作才可能获得并行加速。Amdahl 定律给出串行比例 \(s\) 对 \(N\) 个处理器加速比的上限：

\[S(N)=\frac{1}{s+\frac{1-s}{N}}.\]

即使处理器无限多，加速也不会超过 \(1/s\)。同步、通信、负载不均和缓存争用还会使实际结果更低。

响应性、吞吐量与程序结构

目标 并发如何帮助 设计不当的典型失败
响应性 后台活动等待时交互工作仍可运行 后台线程持有共享锁或占满 CPU
吞吐量 重叠多个请求和 I/O，利用空闲资源 并发过量造成排队、缓存未命中与内存压力
隐藏时延 一个线程等待存储/网络时另一个运行 无界队列把过载隐藏到内存耗尽
并行加速 独立计算使用多个核心 争用与串行区段占主导
程序结构 把活动映射为清晰组件或阶段 可变共享状态产生时序耦合
故障遏制 独立工作进程可分别失败 线程故障会破坏或终止整个进程

更多线程并不自动更快。适当并发度取决于 CPU 核数、等待比例、工作集、锁争用和外部服务容量；吞吐达到拐点后继续增加并发通常只会增加排队时延。

线程抽象

线程是内核或运行时可调度的执行流。一个进程至少有一个线程，多线程进程中的线程共享保护域，却各自保留恢复执行所需的状态。

进程共享状态与线程私有状态

通常共享：地址空间、代码、全局变量与堆、文件描述符表、当前工作目录、进程凭据和资源限制。通常私有：程序计数器和寄存器、用户栈、内核栈、调度状态、每线程信号掩码、errno 和 TLS。

一个线程的操作 对同进程其他线程的影响
写全局或堆对象 在同步与内存序规则允许时，其他线程可见同一内存
关闭文件描述符 进程级表项消失，同行线程可能失败或遇到编号复用
改变当前工作目录 所有线程的路径解析都改变
修改信号掩码 只改变该线程接收信号的资格
修改栈局部变量 默认私有，除非把地址共享出去
调用 exit() 或从 main() 返回 整个进程及所有线程终止
从线程入口返回或调用 pthread_exit() 只终止当前线程

“共享地址空间”意味着速度和危险同时存在：传递指针很便宜，但悬空指针、数据竞争和错误写入也会直接影响同行线程。

线程生命周期与线程控制块

线程会经历创建、就绪、运行、阻塞和终止。线程控制块保存调度实体身份、寄存器恢复点、内核栈、优先级、亲和性、信号掩码和 TLS 指针等状态。进程控制信息负责共享资源，线程控制信息负责“哪条执行流可被恢复”。

线程终止并不意味着其进程终止；但最后一个线程退出或某线程调用进程级 exit() 时，内核才销毁整个进程。Joinable 线程的少量完成状态会保留到其他线程 join，类似但不等同于进程的 wait/reap。

线程实现模型

用户级线程

用户级线程由语言运行时或库在用户空间管理。运行时自行保存寄存器、选择下一个任务和切换栈，因此切换可以很轻，也能实现应用专用调度。若内核只看到一个执行实体，阻塞系统调用会让整个进程停住，且无法在多个 CPU 上同时运行。

现代运行时常把轻量任务与内核线程池结合，并通过非阻塞 I/O 或调度器感知的阻塞接口避免“一个任务阻塞所有任务”。协程、fiber、green thread 和 async task 的语义各不相同，不能仅凭名字判断映射方式。

内核线程

内核线程由内核调度器直接识别。一个线程阻塞时，同进程其他线程仍可运行；多个线程可在多个核心上并行。代价是每个线程需要内核对象、内核栈和调度核算，创建与切换通常比纯用户态任务更重。

线程数量过大时，栈预留、调度队列、缓存与 TLB 压力会显著增加。生产系统应依据工作负载和外部容量设置有界线程池，而不是为每个事件无限创建线程。

多对一、一对一与多对多模型

模型 调度关系 并行性 阻塞行为 主要实现负担
多对一 多个用户线程映射到一个内核实体 无 一个阻塞调用可停住全部用户线程 运行时切换与非阻塞集成
一对一 每个用户线程对应内核实体 有 一个阻塞线程不必阻塞同行 每线程内核对象与调度成本
多对多 多个用户线程复用到内核线程池 有 可在可用 carrier 上继续任务 两级调度、固定、阻塞和迁移规则

Linux Pthreads 通常采用一对一；Go 等运行时则在若干 OS 线程上调度大量 goroutine，属于带复杂运行时支持的多对多思路。

线程 API 与生命周期管理

创建、连接、分离与取消

pthread_create() 启动线程；joinable 线程由 pthread_join() 收集返回值并释放最终资源；detached 线程结束后自动释放，不能再 join。取消应被视为协作协议，而不是任意位置强制杀死线程，否则锁、内存和外部对象可能留在不一致状态。

生命周期 结果收集 最终资源释放 适用场景
Joinable 由同行线程 join 获取结果 成功 join 后 完成结果重要的有限任务
Detached 不 join，不收集结果 终止时自动完成 有独立停机协议的后台工作
Canceled 取决于 join/detach 状态 执行清理后 join 或自动释放 能完整核算资源的协作中断
查看带注释的 Pthreads 创建与 join 示例 
#define _POSIX_C_SOURCE 200809L
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

struct job {
    const char *text;       // Input remains valid until every join completes.
    size_t vowel_count;     // Each worker owns one distinct result slot.
};

static void report_pthread_error(const char *operation, int error) {
    // Pthread 函数直接返回错误号，通常不会设置 errno。
    fprintf(stderr, "%s: %s\n", operation, strerror(error));
}

static void *count_vowels(void *argument) {
    struct job *job = argument;
    size_t count = 0;

    for (const char *p = job->text; *p != '\0'; ++p) {
        if (strchr("AEIOUaeiou", *p) != NULL) {
            ++count;
        }
    }

    // 不会有两个线程写入同一字段；pthread_join() 保证
    // 主线程读取结果前，对应工作线程已经结束。
    job->vowel_count = count;
    return NULL;
}

int main(void) {
    struct job jobs[] = {
        {"process", 0},
        {"thread", 0},
        {"communication", 0}
    };
    enum { THREAD_COUNT = sizeof(jobs) / sizeof(jobs[0]) };
    pthread_t threads[THREAD_COUNT];
    size_t created = 0;

    for (; created < THREAD_COUNT; ++created) {
        int error = pthread_create(
            &threads[created], NULL, count_vowels, &jobs[created]
        );
        if (error != 0) {
            report_pthread_error("pthread_create", error);
            break;
        }
    }

    // 即使后续创建失败，也要 join 所有已经成功创建的线程。
    for (size_t i = 0; i < created; ++i) {
        int error = pthread_join(threads[i], NULL);
        if (error != 0) {
            report_pthread_error("pthread_join", error);
            return EXIT_FAILURE;
        }
    }

    if (created != THREAD_COUNT) {
        return EXIT_FAILURE;
    }

    for (size_t i = 0; i < THREAD_COUNT; ++i) {
        printf("%s -> %zu vowels\n", jobs[i].text, jobs[i].vowel_count);
    }
    return EXIT_SUCCESS;
}
cc -std=c11 -Wall -Wextra -O2 -pthread threads.c -o threads
./threads

传给线程的参数必须活得足够久；循环中把同一个栈变量地址交给多个线程是常见错误。线程函数返回的对象同样不能指向已经销毁的线程栈。

线程局部存储

TLS（thread-local storage）让同一个名字在不同线程中解析为不同实例，适合 errno、每线程缓存和无需显式参数传递的上下文。静态 TLS 可用 _Thread_local/thread_local 声明；动态 TLS 通过 pthread_key_create()、pthread_setspecific() 等在运行时分配键和值，并可配置退出析构器。

查看 C 中静态与动态 TLS 
#include <pthread.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

static _Thread_local unsigned long local_requests = 0;
static pthread_key_t label_key;

static void destroy_label(void *value) {
    free(value);
}

static void *worker(void *argument) {
    const char *input_label = argument;
    char *private_label = strdup(input_label);
    if (private_label == NULL) {
        return NULL;
    }

    int error = pthread_setspecific(label_key, private_label);
    if (error != 0) {
        free(private_label);
        return NULL;
    }

    for (int i = 0; i < 3; ++i) {
        ++local_requests; // This thread updates only its own TLS instance.
    }

    printf("%s handled %lu requests\n",
           (const char *)pthread_getspecific(label_key), local_requests);
    return NULL; // destroy_label releases the dynamic TLS value.
}

int main(void) {
    if (pthread_key_create(&label_key, destroy_label) != 0) {
        return EXIT_FAILURE;
    }

    pthread_t first, second;
    int error = pthread_create(&first, NULL, worker, "worker-A");
    if (error != 0) {
        fprintf(stderr, "pthread_create: %s\n", strerror(error));
        return EXIT_FAILURE;
    }

    error = pthread_create(&second, NULL, worker, "worker-B");
    if (error != 0) {
        fprintf(stderr, "pthread_create: %s\n", strerror(error));
        pthread_join(first, NULL);
        pthread_key_delete(label_key);
        return EXIT_FAILURE;
    }

    pthread_join(first, NULL);
    pthread_join(second, NULL);
    pthread_key_delete(label_key);
    return EXIT_SUCCESS;
}

TLS 隐藏依赖，因此不应滥用为任意全局状态。线程池复用线程时还必须在任务边界清理请求上下文，否则下一任务可能看到前一任务残留。

为什么需要进程间通信？

进程隔离意味着普通指针不能跨地址空间使用。IPC 必须建立内核认可的命名、传输或共享关系，同时定义等待、容量、关闭与权限语义。

命名、缓冲、顺序与背压

评估 IPC 时应逐项回答：同行如何发现对方？数据缓冲在哪里？保留字节流还是消息边界？多个发送者之间有什么顺序保证？容量用尽时阻塞、返回 EAGAIN、拒绝还是覆盖？EOF/关闭如何表达？权限如何检查？一方崩溃后哪些状态仍存在？

背压（backpressure）是让生产者感知消费者跟不上。没有有界容量和明确失败/等待语义，系统往往把短期吞吐换成不断增长的排队时延，最终以内存耗尽结束。

复制与共享状态

消息传递把边界、所有权转移和等待规则显式化，内核可执行权限与容量控制，但可能发生复制和系统调用。共享内存让两边直接访问同一页，适合大吞吐或低时延，却把记录布局、原子性、同步、崩溃恢复和背压交给应用协议。

“零拷贝”通常只是减少某些复制，不代表没有地址翻译、缓存一致性、页固定、描述符管理或同步成本。应测量端到端路径而不是依赖标签。

管道与 FIFO

匿名管道是有界、单向、内核维护的字节流，通常通过 fork() 继承端点。读取空管道会阻塞或返回 EAGAIN；写满管道同样会等待；最后一个写端关闭后，读者在缓冲区耗尽时得到 EOF。消息边界不会被保留，应用必须自行定义 framing。

FIFO（named pipe）把管道放入文件系统命名空间，使无亲缘本地进程可以打开；数据仍位于内核管道缓冲，而不是存进目录项对应的普通文件。打开时也有协调语义：仅写方式打开可能等待读者出现。

查看 FIFO 观察流程 
fifo="/tmp/os03-fifo-$$"
mkfifo -m 600 "$fifo"

# 读端先打开 FIFO，并可能一直等待写端打开。
grep kernel < "$fifo" > result.txt &
reader_pid=$!

# 写进程的标准输出成为 FIFO 字节流。
cat input.txt > "$fifo"

wait "$reader_pid"
rm -f "$fifo"
cat result.txt

信号与异步通知

信号用于传递事件和少量元数据，不适合批量数据。信号经历生成、pending、根据每线程 mask 选择可接收线程，再采取默认动作、异步 handler、sigwait() 或 signalfd 等消费路径。

异步 handler 可以打断几乎任意代码，只能调用 async-signal-safe 函数；普通 malloc、printf 和许多锁操作都不安全。更易推理的设计是在所有工作线程阻塞目标信号，由一个专用线程用 sigwait() 同步接受，再通过普通队列发起协作停机。

查看使用 sigwait 的专用线程与协作停机 
#define _POSIX_C_SOURCE 200809L
#include <pthread.h>
#include <signal.h>
#include <stdatomic.h>
#include <stdbool.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>

static atomic_bool stop_requested = false;
static sigset_t termination_signals;

static void *signal_thread(void *unused) {
    (void)unused;
    int signal_number;
    int error = sigwait(&termination_signals, &signal_number);
    if (error != 0) {
        fprintf(stderr, "sigwait: %s\n", strerror(error));
        atomic_store(&stop_requested, true);
        return NULL;
    }

    printf("accepted signal %d in ordinary thread context\n", signal_number);
    atomic_store(&stop_requested, true);
    return NULL;
}

static void *worker(void *argument) {
    const char *name = argument;
    struct timespec delay = {.tv_sec = 0, .tv_nsec = 200000000};

    while (!atomic_load(&stop_requested)) {
        printf("%s completed one unit\n", name);
        nanosleep(&delay, NULL);
    }
    printf("%s stopping cleanly\n", name);
    return NULL;
}

int main(void) {
    sigemptyset(&termination_signals);
    sigaddset(&termination_signals, SIGINT);
    sigaddset(&termination_signals, SIGTERM);

    // 创建线程前先阻塞信号；之后每个新线程都会继承该掩码。
    int error = pthread_sigmask(SIG_BLOCK, &termination_signals, NULL);
    if (error != 0) {
        fprintf(stderr, "pthread_sigmask: %s\n", strerror(error));
        return EXIT_FAILURE;
    }

    pthread_t controller, first, second;
    error = pthread_create(&first, NULL, worker, "worker-A");
    if (error != 0) {
        fprintf(stderr, "pthread_create worker-A: %s\n", strerror(error));
        return EXIT_FAILURE;
    }

    error = pthread_create(&second, NULL, worker, "worker-B");
    if (error != 0) {
        fprintf(stderr, "pthread_create worker-B: %s\n", strerror(error));
        atomic_store(&stop_requested, true);
        pthread_join(first, NULL);
        return EXIT_FAILURE;
    }

    error = pthread_create(&controller, NULL, signal_thread, NULL);
    if (error != 0) {
        fprintf(stderr, "pthread_create signal thread: %s\n", strerror(error));
        atomic_store(&stop_requested, true);
        pthread_join(first, NULL);
        pthread_join(second, NULL);
        return EXIT_FAILURE;
    }

    printf("press Ctrl-C to request shutdown\n");
    pthread_join(controller, NULL);
    pthread_join(first, NULL);
    pthread_join(second, NULL);
    return EXIT_SUCCESS;
}

共享内存与内存映射通信

POSIX 共享内存通常经历 shm_open() 命名、ftruncate() 定长、mmap() 映射、建立同步协议、munmap()/close() 解除本地引用以及 shm_unlink() 移除名字。unlink 只删除名称；已有映射可继续存在到最后引用消失。

共享布局必须使用固定宽度类型、版本和边界检查；同步原语必须明确支持 process-shared 属性；一方持锁崩溃时还要考虑 robust mutex 或恢复策略。仅把普通指针放入共享区通常无效，因为各进程映射基址可能不同，应使用偏移或稳定标识。

查看最小 POSIX 共享内存示例 
#define _POSIX_C_SOURCE 200809L
#include <fcntl.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/mman.h>
#include <sys/stat.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>

struct shared_record {
    size_t length;
    char text[256];
};

int main(void) {
    char name[64];
    snprintf(name, sizeof(name), "/os03-shm-%ld", (long)getpid());

    int fd = shm_open(name, O_CREAT | O_EXCL | O_RDWR, 0600);
    if (fd == -1) {
        perror("shm_open");
        return EXIT_FAILURE;
    }
    if (ftruncate(fd, sizeof(struct shared_record)) == -1) {
        perror("ftruncate");
        shm_unlink(name);
        close(fd);
        return EXIT_FAILURE;
    }

    struct shared_record *record = mmap(
        NULL, sizeof(*record), PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0
    );
    if (record == MAP_FAILED) {
        perror("mmap");
        shm_unlink(name);
        close(fd);
        return EXIT_FAILURE;
    }
    close(fd); // The mapping now retains the live reference we need.

    pid_t child = fork();
    if (child == -1) {
        perror("fork");
        munmap(record, sizeof(*record));
        shm_unlink(name);
        return EXIT_FAILURE;
    }

    if (child == 0) {
        const char *message = "shared pages, separate processes";
        record->length = (size_t)snprintf(
            record->text, sizeof(record->text), "%s", message
        );
        munmap(record, sizeof(*record));
        _exit(0);
    }

    // 在这个单次写入演示中，waitpid 提供执行顺序。
    // 长期并发使用的通道需要独立的同步协议。
    if (waitpid(child, NULL, 0) == -1) {
        perror("waitpid");
    } else if (record->length < sizeof(record->text)) {
        printf("received: %.*s\n", (int)record->length, record->text);
    }

    munmap(record, sizeof(*record));
    shm_unlink(name); // Remove the discovery name after the participants finish.
    return EXIT_SUCCESS;
}

消息队列与本地套接字

POSIX 消息队列提供有界离散消息和优先级；Unix domain socket 提供本地主机上的双向通信、凭据传递和文件描述符传递。SOCK_STREAM 是有序字节流，需要 framing；SOCK_DGRAM 保留数据报；SOCK_SEQPACKET 在连接语义下保留有序记录；socketpair() 可直接创建一对已连接端点。

机制 数据模型 适用关系 主要注意点
POSIX 消息队列 有界、离散、可带优先级消息 多进程打开同一名字 系统限制、名字清理、优先级策略
Unix stream socket 有序双向字节流 客户端/服务器或 socket pair framing 与部分 I/O
Unix datagram socket 离散数据报 无连接或已连接本地端点 大小与错误语义依平台而异
Unix seqpacket socket 有序可靠记录 已连接双向同行 可移植性不如 stream
socketpair() 调用者选择类型 一对已连接同行 不直接创建多客户端监听器
查看本地 SOCK_SEQPACKET 请求-响应示例 
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/socket.h>
#include <sys/types.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void) {
    int sockets[2];
    if (socketpair(
            AF_UNIX, SOCK_SEQPACKET | SOCK_CLOEXEC, 0, sockets
        ) == -1) {
        perror("socketpair");
        return EXIT_FAILURE;
    }

    pid_t child = fork();
    if (child == -1) {
        perror("fork");
        return EXIT_FAILURE;
    }

    if (child == 0) {
        close(sockets[0]);
        char request[128];
        ssize_t received = recv(sockets[1], request, sizeof(request) - 1, 0);
        if (received <= 0) {
            _exit(1);
        }
        request[received] = '\0';
        dprintf(STDOUT_FILENO, "child received one record: %s\n", request);

        const char reply[] = "ACK";
        if (send(sockets[1], reply, sizeof(reply) - 1, 0) == -1) {
            _exit(1);
        }
        close(sockets[1]);
        _exit(0);
    }

    close(sockets[1]);
    const char request[] = "filter=kernel; file=input.txt";
    if (send(sockets[0], request, sizeof(request) - 1, 0) == -1) {
        perror("send");
    }

    char reply[32];
    ssize_t received = recv(sockets[0], reply, sizeof(reply) - 1, 0);
    if (received > 0) {
        reply[received] = '\0';
        printf("parent received one record: %s\n", reply);
    }

    close(sockets[0]);
    waitpid(child, NULL, 0);
    return EXIT_SUCCESS;
}

阻塞、非阻塞与事件驱动通信

阻塞接口让代码按顺序书写，但每个等待流可能需要一个线程。非阻塞接口在暂时无法推进时返回 EAGAIN，程序用 select、poll、epoll 或 kqueue 等就绪通知等待多个端点，再显式保存每个连接的部分读写状态。

边沿触发通知通常要求循环读/写直到 EAGAIN；一次 read/write 可能只完成部分记录；慢客户端必须有独立有界输出队列。事件循环中任何阻塞调用或长 CPU 任务都会拖延所有连接，因此常把 CPU 工作交给有界 worker pool。

设计 编程模型 优势 典型限制
每流一个阻塞线程 每线程顺序操作 局部推理简单、库兼容广 海量流时栈与调度开销
单事件循环 非阻塞操作加显式状态机 少量线程管理大量空闲端点 状态复杂、回调延迟、误阻塞
事件循环加工作池 readiness 前端加有界 CPU 任务 分离 I/O 规模与计算并行度 队列尺寸、所有权转移与结果路由

用进程、线程与 IPC 连接贯穿管道

  • 进程管道：cat 与 grep 分属不同地址空间，通过内核字节流通信；隔离强、组合自然，代价是系统调用和跨边界传输。
  • 线程流水线：多个线程共享进程，通过有界队列和条件变量传递记录；数据传递便宜，但任何错误共享都会影响全进程。
  • 事件循环：一个或少量线程管理多个非阻塞描述符和显式状态机；适合 I/O 密集规模化，但必须避免阻塞并正确处理部分操作。

对比与总结

机制 载荷模型 自然同行关系 背压/等待 隔离与协议负担
匿名管道 有序字节流 通常是继承描述符的亲缘进程 有界缓冲，阻塞或 EAGAIN 地址空间隔离强，应用负责 framing
FIFO 带文件系统名字的字节流 无亲缘本地进程 管道语义加打开协调 权限与名字清理
信号 通知加少量元数据 进程或线程目标 pending/mask，不适合批量背压 异步安全或专用接收线程
共享内存 应用定义布局 映射同一对象的进程 应用定义同步与唤醒 边界传输最低，共享状态负担最高
POSIX 消息队列 有界、离散、优先级消息 打开同一名字的进程 阻塞、定时等待或 EAGAIN 内核保留记录，需清理命名对象
Unix stream socket 有序双向字节流 本地客户端/服务器或 pair socket 缓冲与 readiness 需 framing，可传凭据与描述符
Unix seqpacket socket 有序双向记录 已连接本地同行 消息感知发送/接收 保留记录，需检查平台支持

设计并发系统时，先明确状态所有权和关闭协议，再选择机制：哪些数据共享，谁能修改；队列最大多大；生产者过快时如何反馈；同行退出后对方看见 EOF、错误还是哨兵；取消时谁释放锁和描述符。机制名称不能替代这些协议答案。
