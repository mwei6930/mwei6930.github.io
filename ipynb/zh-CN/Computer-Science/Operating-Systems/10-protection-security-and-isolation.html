保护、安全与隔离

cat input.txt | grep kernel > result.txt

操作系统不仅分配资源，还必须决定谁可以对哪个对象执行什么操作，并让失败和攻击被限制在预期边界内。保护机制提供用户/内核模式、地址空间、凭据、句柄与访问检查；安全工程再把这些机制组合为适合特定威胁模型的策略、审计和恢复流程。

本章不把 sandbox、namespace 或 seccomp 当作单独的“安全按钮”。每个控制只消除一组假设：权限最小化不能防资源耗尽，cgroup 不能验证路径，ASLR 不能修复内存越界，审计也不能阻止攻击。可靠隔离来自多层、可验证且失效模式明确的组合。

保护、安全与信任

保护（protection）定义和执行系统内主体与对象的访问规则；安全（security）是在声明的对手、资产和故障假设下维护机密性、完整性、可用性及可追责性；隔离（isolation）限制组件能观察和影响的状态与资源。

安全属性必须端到端成立。应用先按路径检查权限、稍后再打开另一个对象，即使内核每次检查都正确，整体仍可能有 TOCTOU 漏洞；进程无文件权限但保留一个已打开可写 fd，也仍有对象能力。

威胁模型与可信计算基

威胁模型明确资产、对手能力、入口、要求属性和假设。对手是普通本地用户、已攻陷容器、恶意管理员、DMA 设备还是物理攻击者，会导向完全不同控制。

可信计算基（TCB）是必须正确才能维持属性的组件集合，而不是“我们觉得可信的软件”。缩小 TCB 会减少必须审计和保护的代码，但若策略服务器、密钥服务或固件仍可绕过边界，它们仍属于 TCB。Secure Boot 建立代码身份链，不自动保证被签代码无漏洞。

保护域与引用监控器

保护域描述一个执行实体当前拥有的权限集合。进程、用户、容器或 capability set 都可构成域的一部分。域可在 exec、凭据改变、namespace 切换或接收句柄时变化。

Reference monitor 理想上具备三点：每次受保护操作都被调用（complete mediation），机制不可被未授权篡改（tamper resistant），实现足够小和清晰以便分析（verifiable）。实际内核通过系统调用、MMU fault、VFS、LSM hook、网络路径和设备边界分散实现这一概念。

检查必须作用于稳定对象而不只是字符串名字，并在对象生命周期内持有引用；否则检查和使用可能指向不同实体。

身份、用户、组与凭据

Linux 任务凭据包含 real/effective/saved UID/GID、supplementary groups、filesystem IDs、capability sets、keyrings、LSM 安全上下文和 user namespace。权限检查通常使用 effective/filesystem 身份，real ID 更多记录来源；具体系统调用规则仍需查 API。

凭据对象常以不可变、引用计数方式共享，修改时构造新凭据并原子安装，避免并发读者看见半更新状态。UID 0 在 user namespace 内的权限也只对该 namespace 及其后代范围有效，不等同于宿主 root。

检查 Linux 任务、文件、namespace 与同行凭据上下文 
# 以可读形式显示真实/有效 ID 与附加组。
id

# 内核任务状态：真实/有效/保存/fs ID、组、capability、
# no_new_privs、seccomp 模式以及命名空间相关状态。
grep -E '^(Uid|Gid|Groups|Cap(Inh|Prm|Eff|Bnd|Amb)|NoNewPrivs|Seccomp):' \
  /proc/self/status

# 显示对象的数字所有者、组、模式、inode 与文件系统身份。

# 显示每个路径分量以及控制路径遍历的权限。

# 命名空间句柄标识解释 ID 与对象时所处的视图。
readlink /proc/self/ns/{user,mnt,pid,net,ipc,uts,cgroup}

# 在装有 libcap 工具的系统上解码当前 capability 集。
getpcaps $$
capsh --print

访问控制模型

访问矩阵以 subject 为行、object 为列、rights 为单元格。实际系统不会存完整稀疏矩阵，而是按对象投影为 ACL，按主体投影为 capability list，或用角色、标签和策略规则压缩。

访问矩阵与权限位

Unix mode bits 把权限分为 owner、group、other 的 rwx。对普通文件，读/写/执行含义直观；对目录，read 是列出名字，write 是增删目录项，execute/search 是穿越并查找。删除文件主要取决于父目录权限和 sticky bit，而非文件自身 write 位。

跟踪 Unix 权限与目录项行为 
# 读取全部路径分量，再检查最终 inode 与 ACL。
namei -l /srv/project/result.txt
stat -c '%A %a owner=%U(%u) group=%G(%g) inode=%i' /srv/project/result.txt
getfacl -p /srv/project/result.txt 2>/dev/null

# 在不修改它的情况下显示当前创建掩码。
umask -S

# 以下为符号化示例；仅在自己拥有的可丢弃测试目录树上运行。
# chmod 2770 project       # 组协作目录；继承组
# chmod 1777 shared        # 全局可写，并带 sticky 删除规则
# install -m 0640 /dev/null project/result.txt

Setuid/setgid/sticky 等特殊位改变执行或目录语义，需要与 mount nosuid、noexec、user namespace 和 LSM 一起解释。

访问控制列表

POSIX ACL 可为 named user/group 添加条目，mask 限制 named-user 和 group class 的最大有效权限。算法必须按 owner、named user、匹配组集合、other 的规定顺序评估，不能把 mask 当作另一组简单权限。

POSIX-ACL-检查(task, inode, requested)
    如果 task.fsuid == inode.owner：
        effective <- ACL_USER_OBJ
    否则如果某个具名 ACL_USER 条目匹配 task.fsuid：
        effective <- matching_user AND ACL_MASK
    否则如果 inode.group 或任一具名 ACL_GROUP 匹配 task 的组：
        effective <- UNION(所有匹配的组条目) AND ACL_MASK
    否则：
        effective <- ACL_OTHER

    仅当 requested 是 effective 的子集时才允许
在一次性目录树上创建并检查 POSIX ACL 
mkdir -p ./acl-demo/project
printf 'draft\n' > ./acl-demo/project/report.txt

# 在条目中授予具名用户 bob 读写权限，再把组类别上限设为只读。
setfacl -m u:bob:rw-,m::r-- ./acl-demo/project/report.txt
getfacl ./acl-demo/project/report.txt

# 用组协作默认 ACL 初始化未来创建的子对象。
setfacl -m d:u::rwx,d:g::rwx,d:o::---,d:m::rwx ./acl-demo/project
touch ./acl-demo/project/new.txt
getfacl ./acl-demo/project/new.txt

# 完成后移除扩展 ACL 条目。
setfacl -b ./acl-demo/project/report.txt
setfacl -k ./acl-demo/project

默认 ACL 可被新子对象继承，但最终 mode 仍受创建 mode、umask 与文件系统规则影响。复制、备份和部署工具若忽略 ACL/xattr 会悄悄改变安全策略。

能力（Capabilities）

在 capability-based security 中，持有不可伪造句柄本身授予对特定对象的权限。Unix fd 具有 capability 风格：已打开的只写 fd 可传给另一个进程，接收者无需重新解析路径，也不能仅靠猜整数访问其他对象。

Linux capabilities 则把传统 root 权限拆成 CAP_NET_BIND_SERVICE、CAP_SYS_ADMIN 等位集合，概念相关但不是纯对象 capability。它们分为 permitted/effective/inheritable/bounding/ambient，并受 user namespace 和 exec 规则影响。

检查 Linux capabilities，而不授予新权限 
# 查看进程 capability 掩码与不可逆的 no-new-privileges 状态。
grep -E '^(Cap(Inh|Prm|Eff|Bnd|Amb)|NoNewPrivs):' /proc/self/status
getpcaps $$ 2>/dev/null || true

# 查看指定可执行文件已有的文件 capability。
getcap /usr/bin/ping /usr/bin/passwd 2>/dev/null

# 安装 libcap 工具后，可用 capsh 解码十六进制掩码。
capsh --decode="$(awk '/^CapEff:/ {print "0x" $2}' /proc/self/status)"

# 仅为管理示例；不要随意对生产二进制文件运行：
# sudo setcap cap_net_bind_service=ep ./small-server
# getcap ./small-server
# sudo setcap -r ./small-server

权限与最小权威

最小权限要求主体只拥有完成当前任务所需的最少对象、操作和时间范围。最小权威（least authority）进一步强调避免环境式、可用于无关对象的广泛权限，优先传递已解析、rights-reduced 的句柄。

权限分离与受控提升

把复杂解析器和网络协议放入无特权 worker，只保留小型 broker 负责打开受保护对象、绑定低端口或配置设备。两者经有界、验证的 IPC 通信，broker 传递最小句柄而非任意路径能力。

execve 可根据 setuid 或 file capability 改变凭据；no_new_privs 一旦设置，后续 exec 不得增加权限，是 seccomp/sandbox 的重要前提。

Linux C：打开一个输出后不可逆地降低身份，再 exec 
#define _GNU_SOURCE
#include <errno.h>
#include <fcntl.h>
#include <grp.h>
#include <pwd.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/prctl.h>
#include <sys/types.h>
#include <unistd.h>

static void die(const char *operation) {
    perror(operation);
    exit(EXIT_FAILURE);
}

static void drop_ids(uid_t uid, gid_t gid) {
    // 附加组独立于主 GID 携带权限。
    if (setgroups(0, NULL) == -1) die("setgroups");

    // 同时设置真实、有效与保存 ID，使该进程以后无法
    // 恢复旧的特权有效 ID。
    if (setresgid(gid, gid, gid) == -1) die("setresgid");
    if (setresuid(uid, uid, uid) == -1) die("setresuid");

    // 防止后续 exec 通过 setuid 位、
    // setgid 位或文件 capability 获得权限；该标志不可逆。
    if (prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0) == -1) {
        die("PR_SET_NO_NEW_PRIVS");
    }

    if (getuid() != uid || geteuid() != uid ||
        getgid() != gid || getegid() != gid) {
        fputs("credential verification failed\n", stderr);
        exit(EXIT_FAILURE);
    }
}

int main(int argc, char **argv) {
    if (argc != 4) {
        fprintf(stderr, "usage: %s USER OUTPUT PATTERN\n", argv[0]);
        return EXIT_FAILURE;
    }

    // 在放弃访问身份服务的权限前解析账户信息。
    errno = 0;
    struct passwd *account = getpwnam(argv[1]);
    if (account == NULL) {
        if (errno != 0) perror("getpwnam");
        else fprintf(stderr, "unknown user: %s\n", argv[1]);
        return EXIT_FAILURE;
    }
    uid_t target_uid = account->pw_uid;
    gid_t target_gid = account->pw_gid;

    // 特权阶段只获取一个刻意收窄的对象句柄。
    // 生产级代理应相对于受信任目录描述符解析
    // 管理员控制的路径，而不是接受任意路径。
    int output = open(argv[2], O_WRONLY | O_APPEND | O_CLOEXEC);
    if (output == -1) die("open output");

    drop_ids(target_uid, target_gid);

    // dup2 创建不带 close-on-exec 的 stdout；还要处理一种少见情况：
    // 调用者已关闭 stdout，导致 open() 复用了描述符 1。
    if (output == STDOUT_FILENO) {
        int descriptor_flags = fcntl(output, F_GETFD);
        if (descriptor_flags == -1) die("F_GETFD stdout");
        if (fcntl(output, F_SETFD, descriptor_flags & ~FD_CLOEXEC) == -1) {
            die("clear FD_CLOEXEC on stdout");
        }
    } else {
        if (dup2(output, STDOUT_FILENO) == -1) die("dup2");
        if (close(output) == -1) die("close output");
    }

    // 使用固定可执行文件与最小环境，不依赖 PATH 查找
    // 或从特权调用者继承的加载器变量。
    char *const child_argv[] = {"/usr/bin/grep", "--", argv[3], NULL};
    char *const child_env[] = {"PATH=/usr/bin:/bin", "LANG=C", NULL};
    execve(child_argv[0], child_argv, child_env);
    die("execve grep");
}
cc -std=c11 -Wall -Wextra -O2 drop_exec.c -o drop_exec
# 示例启动要求输出文件已创建，并具有适当权限：
# cat input.txt | sudo ./drop_exec nobody /safe/output/result.txt kernel

降低权限前应先取得必要句柄，清理 supplementary groups/capabilities，验证无法重新获得身份，并避免把多余 fd 继承给新程序。

防守系统调用边界

输入验证、句柄与 TOCTOU

内核必须验证长度、整数溢出、枚举、指针范围、对象类型、生命周期与并发状态。用户指针可能在检查后变化，路径可能被 rename 或替换为 symlink，fd 编号也可能在 close 后复用。

以下模式存在竞态：

if (access(path, W_OK) == 0) {       // checks one resolution, often real IDs
    int fd = open(path, O_WRONLY);   // resolves the pathname again
    /* 通过 fd 执行特权写入 */
}

access() 与 open() 分别解析路径，攻击者可在两者之间替换对象。更可靠方法是从可信目录 fd 开始，用 openat/openat2 施加 RESOLVE_BENEATH、禁止 symlink/magic link 等约束，一次解析得到稳定 fd，之后对该句柄操作。

Linux C：在可信目录下创建文件且不跟随符号链接 
#define _GNU_SOURCE
#include <errno.h>
#include <fcntl.h>
#include <linux/openat2.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <sys/stat.h>
#include <sys/syscall.h>
#include <unistd.h>

static void die(const char *operation) {
    perror(operation);
    exit(EXIT_FAILURE);
}

static int open_new_beneath(int directory_fd, const char *relative_path) {
    struct open_how how = {
        .flags = O_WRONLY | O_CREAT | O_EXCL | O_CLOEXEC | O_NOFOLLOW,
        .mode = 0640,
        .resolve = RESOLVE_BENEATH |
                   RESOLVE_NO_SYMLINKS |
                   RESOLVE_NO_MAGICLINKS |
                   RESOLVE_NO_XDEV,
    };

    return (int)syscall(SYS_openat2, directory_fd, relative_path,
                        &how, sizeof how);
}

static void write_all(int fd, const char *data, size_t length) {
    size_t done = 0;
    while (done < length) {
        ssize_t written = write(fd, data + done, length - done);
        if (written > 0) {
            done += (size_t)written;
        } else if (written == -1 && errno == EINTR) {
            continue;
        } else {
            die("write");
        }
    }
}

int main(int argc, char **argv) {
    if (argc != 4) {
        fprintf(stderr, "usage: %s TRUSTED_DIRECTORY RELATIVE_NAME CONTENT\n",
                argv[0]);
        return EXIT_FAILURE;
    }

    int directory_fd = open(argv[1], O_RDONLY | O_DIRECTORY | O_CLOEXEC);
    if (directory_fd == -1) die("open trusted directory");

    int file_fd = open_new_beneath(directory_fd, argv[2]);
    if (file_fd == -1) {
        if (errno == ENOSYS) {
            fputs("openat2 is not supported by this kernel\n", stderr);
        }
        die("openat2 relative output");
    }

    // 验证已经打开的对象；检查后绝不重新打开 argv[2]。
    struct stat status;
    if (fstat(file_fd, &status) == -1) die("fstat output");
    if (!S_ISREG(status.st_mode)) {
        fputs("output is not a regular file\n", stderr);
        return EXIT_FAILURE;
    }

    write_all(file_fd, argv[3], strlen(argv[3]));
    if (fsync(file_fd) == -1) die("fsync output");
    if (close(file_fd) == -1) die("close output");

    // 新目录项是一个独立的持久对象（见第 09 章）。
    if (fsync(directory_fd) == -1) die("fsync directory");
    if (close(directory_fd) == -1) die("close directory");
    return EXIT_SUCCESS;
}
cc -std=c11 -Wall -Wextra -O2 safe_openat2.c -o safe_openat2
mkdir -p ./safe-output
./safe_openat2 ./safe-output result.txt 'bounded content'

句柄方法仍需限制 descriptor inheritance、校验对象类型，并处理 mount crossing、硬链接和网络文件系统语义。

内存与执行防御

W^X、地址空间随机化与 Guard Page

W^X 使页面不同时可写可执行，降低把注入数据直接当代码执行的机会；ASLR 随机化代码、库、堆和栈位置，提高依赖已知地址的攻击成本；guard page 用不可访问映射捕获栈/缓冲区越界；stack canary、CFI、shadow stack 与 pointer authentication 保护不同控制流假设。

这些都是缓解而非内存安全证明。信息泄露可削弱 ASLR，JIT 需要受控的写/执行阶段转换，ROP 可复用现有可执行代码。根本修复仍是消除越界、use-after-free 和未初始化数据。

检查 Linux 可执行映射与加固状态 
# 地址空间随机化策略：0 关闭，1 部分随机化，2 更完整的随机化。
sysctl kernel.randomize_va_space

# 当前 shell 的映射及其 r/w/x 权限。
cat /proc/$$/maps

# ELF 程序头：GNU_STACK 通常不应请求执行权限。
readelf -W -l /usr/bin/grep | grep -E 'LOAD|GNU_STACK|GNU_RELRO'

# 对普通程序而言，ELF 类型 DYN 通常表示 PIE 可执行文件。
readelf -W -h /usr/bin/grep | grep 'Type:'

# 比较多次全新执行中的指定映射基址。
for i in 1 2 3; do
  sh -c 'grep -m1 "libc.*r-xp" /proc/$$/maps'
done

沙箱与系统调用过滤

沙箱为不可信代码建立一组明确边界：削减身份和 capabilities；用 namespace 改变可见对象；用 cgroup 限制资源；用 LSM/Landlock 限制对象访问；用 seccomp 限制系统调用；结合 W^X/ASLR 等内存防御。

seccomp 与策略执行

Seccomp BPF 根据 syscall number、architecture 和原始参数选择 ALLOW、ERRNO、LOG、TRAP、USER_NOTIF 或 KILL。它适合减少内核入口面，却不适合根据路径字符串或 fd 指向对象做完整授权，因为过滤器不能安全解引用用户指针，也看不到 VFS 最终对象。

默认拒绝 allowlist 比 denylist 更能控制未来新 syscall，但必须覆盖 libc、loader、线程和信号实际需求。过滤应在设置 no_new_privs、初始化资源后安装，并对体系结构号和 x32/兼容 ABI 谨慎处理。

Linux C：演示小型 libseccomp 限制 
#define _GNU_SOURCE
#include <errno.h>
#include <seccomp.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/prctl.h>
#include <sys/stat.h>

static void die(const char *operation) {
    perror(operation);
    exit(EXIT_FAILURE);
}

static void check_seccomp(int result, const char *operation) {
    if (result < 0) {
        errno = -result;          // libseccomp returns negative errno values.
        die(operation);
    }
}

int main(void) {
    // 本演示默认允许其他调用，并拒绝创建目录。
    // 生产沙箱应针对真实工作负载使用经过测试的允许列表。
    scmp_filter_ctx filter = seccomp_init(SCMP_ACT_ALLOW);
    if (filter == NULL) die("seccomp_init");

    check_seccomp(seccomp_rule_add(filter, SCMP_ACT_ERRNO(EPERM),
                                   SCMP_SYS(mkdir), 0),
                  "seccomp_rule_add mkdir");
    check_seccomp(seccomp_rule_add(filter, SCMP_ACT_ERRNO(EPERM),
                                   SCMP_SYS(mkdirat), 0),
                  "seccomp_rule_add mkdirat");

    // 设置后，execve 无法通过 setuid 或文件 capability 增加权限。
    if (prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0) == -1) {
        seccomp_release(filter);
        die("PR_SET_NO_NEW_PRIVS");
    }

    check_seccomp(seccomp_load(filter), "seccomp_load");
    seccomp_release(filter);      // Kernel retains the installed filter.

    errno = 0;
    if (mkdir("seccomp-should-fail", 0700) == -1 && errno == EPERM) {
        puts("mkdir blocked with EPERM as required");
        return EXIT_SUCCESS;
    }

    fputs("unexpected sandbox result\n", stderr);
    return EXIT_FAILURE;
}
cc -std=c11 -Wall -Wextra -O2 seccomp_demo.c -o seccomp_demo -lseccomp
./seccomp_demo

Namespace 与资源隔离

Linux namespaces 改变进程看见的 PID、mount、network、IPC、UTS、user、cgroup 和 time 视图。它们隔离名字和可见拓扑，不自动限制 CPU、内存、I/O，也不创建独立内核。

检查 namespace 身份并创建一次性视图 
# 命名空间符号链接目标标识本进程的命名空间对象。
readlink /proc/self/ns/{user,mnt,pid,net,ipc,uts,cgroup,time} 2>/dev/null

# 权限允许时与另一个进程比较。
target_pid=1
ls -l /proc/$target_pid/ns 2>/dev/null

# 显示当前用户命名空间的 UID/GID 映射。
cat /proc/self/uid_map
cat /proc/self/gid_map

# 创建可丢弃的 user+UTS 命名空间；可用性取决于主机策略。
# -r 把调用者映射为内部 root；主机身份仍无特权。
unshare --user --map-root-user --uts sh -c '
  echo "inside: uid=$(id -u), namespace=$(readlink /proc/self/ns/user)"
  hostname sandbox-name
  echo "hostname=$(hostname)"
'

# 在不修改的情况下观察 mount/PID/network 视图。
findmnt
ps -eo pid,ppid,user,comm
ip link show 2>/dev/null

User namespace 映射 UID/GID，使内部 root 对宿主对象仍是非特权身份；但内核过去出现过 namespace 可达攻击面，因此是否允许无特权 user namespace 是安全策略选择。

cgroups 与资源治理

cgroup v2 形成层次树，对后代应用 CPU weight/quota、memory low/high/max、PID 数、I/O 上限和 cpuset。它既能限制恶意耗尽，也能实现服务隔离和可观测核算。

memory.max 是硬上限，memory.high 触发节流/reclaim，memory.low/min 表达保护；cpu.weight 是竞争下相对份额，cpu.max 是 quota。资源限制必须和应用背压配合，否则只会把 OOM 或 throttling 变成不可预测失败。

检查 cgroup v2 并启动有界 transient scope 
# 判断统一 cgroup v2 文件系统是否已挂载。
findmnt -t cgroup2

# 在层级中定位当前 shell，并检查可用控制器。
cat /proc/self/cgroup
cat /sys/fs/cgroup/cgroup.controllers

# 在可用时读取实际使用量与压力。
cat /sys/fs/cgroup/memory.current 2>/dev/null
cat /sys/fs/cgroup/memory.events 2>/dev/null
cat /sys/fs/cgroup/cpu.stat 2>/dev/null
cat /proc/pressure/{cpu,memory,io} 2>/dev/null

# 在 systemd 主机上，策略允许时创建临时用户 scope。
# 本例限制内存与任务数，并请求平均半个 CPU。
systemd-run --user --scope \
  -p MemoryMax=256M \
  -p TasksMax=64 \
  -p CPUQuota=50% \
  -- /usr/bin/grep kernel input.txt

审计、日志与事件证据

安全审计要记录谁、何时、对哪个稳定对象、请求什么操作、结果和策略上下文。普通应用日志可能被攻陷进程篡改，内核 audit 能在系统调用/对象钩子处生成更强证据，但仍受 backlog、规则范围、存储保护和时钟影响。

高噪声规则会造成性能负担和 backlog 丢失，规则太窄则漏掉关键事件。必须监控 lost count、failure mode、守护进程健康与磁盘容量，统一 event ID 关联 PATH、SYSCALL、CWD 等多记录事件，并保护日志免于同权限攻击者修改。

检查 Linux audit 状态并关联一个事件 
# 管理状态：启用状态、积压、丢失事件数与失败模式。
sudo auditctl -s

# 列出活动规则及其可搜索键。
sudo auditctl -l

# 搜索近期系统调用/文件事件，并解释数字字段。
sudo ausearch --start recent -m SYSCALL,PATH,CWD -i

# 搜索带有指定规则键的事件。
sudo ausearch --start today -k protected-output -i

# 在适用系统上查看 SELinux/LSM 拒绝记录。
sudo ausearch --start recent -m AVC,USER_AVC,SELINUX_ERR -i

# 服务日志是补充性运行证据，并非内核审计记录。
journalctl --since '10 minutes ago' --no-pager

审计是检测、归因和恢复证据，不是预防控制；同时也可能包含敏感路径与身份，需要访问控制、保留期限和隐私策略。

对贯穿管道进行威胁建模

cat input.txt | grep kernel > result.txt

资产包括输入机密性、结果完整性、宿主可用性和审计证据。威胁包括：攻击者替换 result.txt 路径为 symlink；shell 泄漏额外 fd；恶意输入触发 grep 解析错误；无限输入填满磁盘/CPU；审计 backlog 丢事件。

对应控制应放在正确边界：从可信 dirfd 安全打开并把稳定 fd 委派给子进程；设置 O_CLOEXEC 并关闭无关描述符；降低子进程权限并用 seccomp/LSM 限制；用 cgroup、rlimit 和文件系统 quota 限制资源；记录打开对象、凭据、退出状态并监控审计丢失。

单一“在容器里运行”不会自动解决这些问题，因为容器仍共享内核、可拥有过宽 mount/capability，资源也可能未限制。威胁模型决定是否需要普通进程隔离、强化 sandbox、microVM 或完整 VM。

对比与总结

控制 主要约束 不能单独解决
UID/GID/mode/ACL 主体对对象的访问 内存漏洞、资源耗尽、路径竞态
对象句柄/capability 对具体对象的可委派权限 句柄泄漏、被授权对象自身漏洞
Privilege separation 缩小高权限复杂代码 Broker 协议错误与过宽请求
W^X/ASLR/guard 内存利用假设 根本内存安全错误与信息泄露
seccomp 可进入的 syscall 集合 路径/对象级策略与 CPU/内存限制
Namespace 名字和系统视图 资源上限与独立内核边界
cgroup CPU、内存、PID 与 I/O 治理 文件授权与 syscall 语义
LSM/Landlock 对象/标签策略 所有应用逻辑和资源治理
Audit 事件证据与归因 实时阻止和完整恢复

安全设计应从资产和对手出发，找到每条权威路径，把字符串解析转为稳定句柄，把环境权限削减为最小对象权限，并为 CPU、内存、PID、I/O 和日志设置有界策略。最重要的检验不是“启用了多少安全功能”，而是每个攻击步骤究竟在哪一层被阻断，以及该层失败时下一层还能限制多大损害。
