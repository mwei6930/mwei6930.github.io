按需分页与内存管理

页表让进程拥有受保护虚拟地址，但 PTE 不必始终指向驻留 RAM 的页框。按需分页（demand paging）把“地址合法”与“页面当前驻留”分开：只有首次访问时才分配或读取页面；内存紧张时，内核又可回收冷页并在之后重新 fault。

这种延迟工作支撑稀疏堆、快速 fork()、文件映射和超出物理内存的工作集，却把普通 load/store 连接到复杂的异常、I/O、置换和 OOM 路径。本章重点是完整生命周期，而不是只背几种置换算法。

从地址翻译到按需分页

一个 VMA 可以存在，而其中页面尚无私有页框。CPU 访问时发现 PTE 不 present，触发精确异常；内核根据区域语义决定页面来自全零页、可执行文件、page cache、swap，还是 COW 副本。

若普通内存访问时间为 \(t_m\)，缺页概率为 \(p\)，平均 fault 服务时间为 \(t_f\)，简化有效访问时间为

\[E[T]=(1-p)t_m+p(t_f+t_m).\]

由于 \(t_f\) 可能包含微秒级分配甚至毫秒级存储 I/O，即使极小的 \(p\) 也会显著影响平均值和尾延迟。因此“缺页次数”必须区分 minor/major、来源和等待时间。

缺页分类

内核首先判断地址是否 canonical、是否属于 VMA、访问类型是否符合区域权限、故障来自用户态还是内核态，以及条目是缺失、只读 COW、交换条目还是保护违规。

  • Minor fault：通常不需从慢速存储读取，例如分配零页、映射已在 page cache 的文件页或完成 COW。
  • Major fault：需要等待 backing storage，常显著阻塞线程。
  • Invalid/protection fault：地址无映射或权限不允许，用户进程通常收到 SIGSEGV/SIGBUS。

同一个“page fault”名称覆盖性能机制和程序错误，诊断时不能混为一谈。

定位、装入并安装页面

合法 fault 的 backing 由 VMA 决定。匿名页可分配清零；文件页查询 page cache 并发起读取；swap 条目定位交换槽；COW 复制旧页。内核需要分配页框，必要时触发 reclaim/compaction，等待 I/O，验证操作期间映射未被其他线程改变，再原子更新 PTE。

并发线程可能同时 fault 同一页，文件也可能截断，进程可能在 I/O 期间 unmap。正确实现必须用锁、引用计数和重检避免重复安装、use-after-free 或把过期数据映射回来。

重启产生故障的指令

硬件保存精确 fault 地址与访问原因。内核完成映射、更新必要 accessed/dirty 状态、执行 TLB 失效或同步后，返回同一程序计数器；原 load/store 再执行一次。应用通常只观察到一次较慢访问。

并非所有指令都易于重启，体系结构必须定义精确异常语义。内核也要避免在持有不可重入锁时访问可能 fault 的用户页，常先使用 copy_from_user 等受保护路径或预先 fault/pin。

惰性分配与首次访问零填充

申请虚拟内存并不必立即分配物理页。匿名映射可先只创建 VMA；首次读取可映射共享、只读的全零页，首次写入再 fault 并获得私有清零页。

这减少未使用分配的启动和内存成本，也避免泄露旧物理页数据。代价是首次触碰延迟和内存承诺不确定；实时程序可能选择 prefault/lock 以把延迟移到可控阶段。

C：使用 mmap、mincore 与 madvise 观察首次访问 
#define _GNU_SOURCE
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/mman.h>
#include <unistd.h>

static size_t resident_pages(void *base, size_t length, size_t page_size) {
    size_t pages = (length + page_size - 1) / page_size;
    unsigned char *state = calloc(pages, 1);
    if (state == NULL) {
        perror("calloc");
        exit(EXIT_FAILURE);
    }

    // mincore() 查询某一时刻的驻留状态，而不是页面所有权。
    if (mincore(base, length, state) == -1) {
        perror("mincore");
        free(state);
        exit(EXIT_FAILURE);
    }

    size_t resident = 0;
    for (size_t i = 0; i < pages; ++i) {
        resident += (state[i] & 1U) != 0;
    }
    free(state);
    return resident;
}

int main(void) {
    long result = sysconf(_SC_PAGESIZE);
    if (result <= 0) {
        fputs("cannot determine page size\n", stderr);
        return EXIT_FAILURE;
    }

    size_t page_size = (size_t)result;
    size_t pages = 64;
    size_t length = pages * page_size;
    unsigned char *region = mmap(NULL, length, PROT_READ | PROT_WRITE,
                                 MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (region == MAP_FAILED) {
        perror("mmap");
        return EXIT_FAILURE;
    }

    printf("after mmap:       %zu / %zu pages reported resident\n",
           resident_pages(region, length, page_size), pages);

    // 每隔四页读取一个字节；读取可能使用共享零页。
    volatile unsigned int sum = 0;
    for (size_t i = 0; i < pages; i += 4) {
        sum += region[i * page_size];
    }
    printf("after sparse read: %zu / %zu pages reported resident\n",
           resident_pages(region, length, page_size), pages);

    // 每隔四页写入一次会要求可写的私有页面内容。
    for (size_t i = 0; i < pages; i += 4) {
        region[i * page_size] = (unsigned char)i;
    }
    printf("after sparse write:%zu / %zu pages reported resident\n",
           resident_pages(region, length, page_size), pages);

    // 对私有匿名内存，DONTNEED 会丢弃当前内容；
    // 后续访问将再次看到用零填充的页面。
    if (madvise(region, length, MADV_DONTNEED) == -1) {
        perror("madvise");
    }
    printf("after DONTNEED:    %zu / %zu pages reported resident\n",
           resident_pages(region, length, page_size), pages);

    if (munmap(region, length) == -1) {
        perror("munmap");
        return EXIT_FAILURE;
    }
    return sum != 0;  // keeps the reads observable to the compiler
}

写时复制

fork() 后父子把原本可写页面都映射为只读 COW 并共享页框。任一方写入时，fault handler 分配新页、复制内容，只让写入方映射新页为可写，并减少旧页引用。

若旧页引用只剩当前进程，内核可直接恢复写权限而无需复制。COW 需要与 pin、DMA、huge page、并发 unmap 和 dirty tracking 正确交互；它节省的是未发生的写复制，不会消除页表和 fault 成本。

C：观察 fork 后私有内存语义 
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <sys/mman.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void) {
    long result = sysconf(_SC_PAGESIZE);
    if (result <= 0) {
        fputs("cannot determine page size\n", stderr);
        return EXIT_FAILURE;
    }

    size_t page_size = (size_t)result;
    int *value = mmap(NULL, page_size, PROT_READ | PROT_WRITE,
                      MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (value == MAP_FAILED) {
        perror("mmap");
        return EXIT_FAILURE;
    }
    *value = 41;  // 在 fork() 前让该页实际物化。

    int ready[2];
    if (pipe(ready) == -1) {
        perror("pipe");
        munmap(value, page_size);
        return EXIT_FAILURE;
    }

    pid_t pid = fork();
    if (pid == -1) {
        perror("fork");
        return EXIT_FAILURE;
    }

    if (pid == 0) {
        close(ready[0]);
        *value = 99;  // 通常会为子进程映射触发写时复制。
        dprintf(STDOUT_FILENO, "child sees  %d\n", *value);
        if (write(ready[1], "x", 1) != 1) {
            _exit(2);
        }
        close(ready[1]);
        _exit(0);
    }

    close(ready[1]);
    char byte;
    if (read(ready[0], &byte, 1) != 1) {
        fputs("child did not signal completion\n", stderr);
    }
    close(ready[0]);

    // 子进程的写入修改的是其私有映射，而不是父进程的映射。
    printf("parent sees %d\n", *value);
    if (waitpid(pid, NULL, 0) == -1) {
        perror("waitpid");
    }

    if (munmap(value, page_size) == -1) {
        perror("munmap");
        return EXIT_FAILURE;
    }
    return EXIT_SUCCESS;
}

内存映射文件与共享页面

文件 read/write 和 mmap 常汇聚到同一个 page cache。MAP_SHARED 写入修改缓存页并可回写文件；MAP_PRIVATE 初始读取同一文件页，写入时创建匿名 COW 页，不把私有修改写回文件。

映射不等于立即持久化。msync、fsync、写回策略和存储缓存共同决定耐久性；文件截断、映射越界和 I/O 错误还可能通过 SIGBUS 表现，而不是普通返回码。

页面置换

内存不足时，reclaim 必须选择牺牲页。干净文件页可直接丢弃并从文件重读；脏文件页需先回写；匿名页若要保留内容通常需要 swap。置换成本因此不仅取决于“多久未访问”，也取决于页类型、dirty、写回拥塞、NUMA 和 cgroup 范围。

OPT、FIFO 与随机置换

OPT/Belady 淘汰未来最久不用的页，给定完整未来引用时 fault 最少，只能作为离线下界。FIFO 淘汰最早装入页，实现简单却可能出现 Belady anomaly：页框增加反而 fault 更多。Random 随机选 victim，状态低且避免某些对抗模式，但不利用局部性。

LRU 与 Clock 近似

LRU 淘汰过去最久未使用页，利用时间局部性，但精确维护每次访问顺序会产生高成本。硬件 accessed/reference 位提供近似证据。Clock/second chance 用环形指针扫描：引用位为 1 时清零并跳过，为 0 时选择 victim。

访问页面(page)时：
    更新策略为 page 记录的历史

发生缺页(requested_page)时：
    如果存在空闲页框：
        装入 requested_page
    否则：
        victim = 从可淘汰驻留页中选择牺牲页
        必要时保存 victim 的内容
        移除 victim 的映射
        装入 requested_page
选择 Clock 牺牲页：
    循环：
        page = frame_at(clock_hand)
        如果 page 不可回收：
            advance(clock_hand)
        否则如果 page.referenced == 1：
            page.referenced = 0
            advance(clock_hand)       // 给予第二次机会
        否则：
            victim = page
            advance(clock_hand)
            返回 victim

Dirty 位、active/inactive 列表和多代 LRU 可进一步区分回收成本与年龄。任何近似都应在真实访问分布上评估，而不是只看一条教学引用串。

Python：在同一引用串上比较 OPT、FIFO、LRU、Random 与 Clock 
from __future__ import annotations

from collections import deque
from dataclasses import dataclass
from math import inf
from random import Random
from typing import Iterable


@dataclass(frozen=True)
class Step:
    time: int
    page: int
    hit: bool
    victim: int | None
    frames: tuple[int, ...]


def simulate_stack_policy(
    references: Iterable[int],
    capacity: int,
    policy: str,
    *,
    seed: int = 7,
) -> list[Step]:
    """模拟 OPT、FIFO、LRU 或使用确定种子的 Random。"""
    refs = list(references)
    if capacity <= 0:
        raise ValueError("capacity must be positive")
    if policy not in {"OPT", "FIFO", "LRU", "Random"}:
        raise ValueError(f"unknown policy: {policy}")

    frames: list[int] = []
    fifo_order: deque[int] = deque()
    last_used: dict[int, int] = {}
    rng = Random(seed)
    trace: list[Step] = []

    for time, page in enumerate(refs):
        if page in frames:
            last_used[page] = time
            trace.append(Step(time, page, True, None, tuple(frames)))
            continue

        victim = None
        if len(frames) == capacity:
            if policy == "FIFO":
                victim = fifo_order.popleft()
            elif policy == "LRU":
                victim = min(frames, key=last_used.__getitem__)
            elif policy == "Random":
                victim = rng.choice(frames)
            else:  # OPT：选择下一次使用距离最远的页面。
                def next_use(candidate: int) -> float:
                    for future_time in range(time + 1, len(refs)):
                        if refs[future_time] == candidate:
                            return future_time
                    return inf

                victim = max(frames, key=next_use)

            frames.remove(victim)
            last_used.pop(victim, None)

        frames.append(page)
        if policy == "FIFO":
            fifo_order.append(page)
        last_used[page] = time
        trace.append(Step(time, page, False, victim, tuple(frames)))

    return trace


def simulate_clock(references: Iterable[int], capacity: int) -> list[Step]:
    """模拟每个页框带一个引用位的第二次机会 Clock。"""
    refs = list(references)
    frames: list[int | None] = [None] * capacity
    referenced = [0] * capacity
    hand = 0
    trace: list[Step] = []

    for time, page in enumerate(refs):
        if page in frames:
            slot = frames.index(page)
            referenced[slot] = 1
            visible = tuple(x for x in frames if x is not None)
            trace.append(Step(time, page, True, None, visible))
            continue

        # 循环搜索；已被引用的页面获得第二次机会。
        while frames[hand] is not None and referenced[hand] == 1:
            referenced[hand] = 0
            hand = (hand + 1) % capacity

        victim = frames[hand]
        frames[hand] = page
        referenced[hand] = 1
        hand = (hand + 1) % capacity
        visible = tuple(x for x in frames if x is not None)
        trace.append(Step(time, page, False, victim, visible))

    return trace


references = [7, 0, 1, 2, 0, 3, 0, 4, 2, 3, 0, 3, 2]
for name in ["OPT", "FIFO", "LRU", "Random"]:
    run = simulate_stack_policy(references, 3, name, seed=7)
    faults = sum(not step.hit for step in run)
    print(f"{name:6s}: faults={faults}, hits={len(run) - faults}")

clock_run = simulate_clock(references, 3)
clock_faults = sum(not step.hit for step in clock_run)
print(f"{'Clock':6s}: faults={clock_faults}, hits={len(clock_run) - clock_faults}")

典型输出：

OPT   ：缺页=7，命中=6
FIFO  ：缺页=10，命中=3
LRU   ：缺页=9，命中=4
Random：缺页=11，命中=2
Clock ：缺页=9，命中=4

局部与全局置换

局部置换只从当前进程/组配额中选 victim，提供隔离但可能让一方在自己配额内 thrash，而系统其他内存空闲。全局置换可从更大池中选冷页，提高容量利用率，却可能让一个激进工作负载驱逐无关进程热页。

现代系统常用 cgroup/容器形成层次边界：组内全局、组间受限制，并依据压力、优先级和保护水位调节。

工作集、抖动与内存压力

进程 \(i\) 在最近窗口 \(\Delta\) 内引用的页面集合为

\[W_i(t,\Delta)=\{p\mid p\text{ 在 }(t-\Delta,t]\text{ 内被进程 }i\text{ 引用}\}.\]

总需求

\[D(t,\Delta)=\sum_i|W_i(t,\Delta)|.\]

若活跃工作集总和超过可用页框，系统会淘汰仍将很快使用的页，随后再次 fault，形成 reclaim、I/O、阻塞和低有效进度的反馈环，即 thrashing。

CPU 利用率下降不应误导系统继续提高并发度；更多进程可能使工作集更超额。应观察 fault rate、reclaim、swap、PSI、I/O 和有用吞吐，必要时降低并发、增加内存、缩小工作集或建立更强隔离。

Swap、过量承诺与 OOM 处理

Swap 为匿名页提供磁盘 backing，可把冷页移出 RAM，却比内存慢几个数量级。Swap 可缓冲短期压力，不应被解释为与 RAM 等价容量。

Linux overcommit 允许虚拟承诺大于当前物理内存，因为许多保留永远不会全部触碰。严格核算模式下，一个概念 CommitLimit 为

\[CommitLimit=(RAM-reserved\ hugeTLB)\times\frac{overcommit\ ratio}{100}+swap.\]

Commit、RSS、page cache 和 swap 是不同量：虚拟地址承诺不等于驻留，也不等于当前可回收。

分配失败时内核先尝试直接/后台 reclaim、写回或 swap，连续高阶分配还可能 compaction。仍失败时 OOM killer 在系统或 memory cgroup 作用域选择牺牲者。选择进程只是恢复策略，不能修复内存泄漏、无界队列或错误容量规划。

物理内存分配

伙伴分配器

Buddy allocator 按 \(2^k\) 个连续页框管理 free list。大块可反复二分满足较小请求，释放时与同阶且对齐的伙伴合并。块起点 start 的伙伴为

\[buddy(start,k)=start\operatorname{XOR}2^k.\]

allocate_pages(order, constraints) -> 对齐内存块或失败
free_pages(block, order)
分配(requested_pages)：
    target = ceil(log2(requested_pages))
    order = 第一个满足 order >= target 且空闲链表非空的阶
    如果不存在这样的 order：
        失败
    block = remove_one(free_list[order])
    当 order > target：
        order = order - 1
        left, right = split(block)
        insert(right, free_list[order])
        block = left
    返回 block, target

释放(block, order)：
    当 order < MAX_ORDER：
        buddy = block.start XOR (1 << order)
        如果 buddy 并非恰好以该阶空闲：
            退出循环
        remove(buddy, free_list[order])
        block = lower_address(block, buddy)
        order = order + 1
    insert(block, free_list[order])

伙伴系统快速提供页级连续块，但向上取整会产生内部碎片；长期运行后，高阶连续块可能短缺，即使总空闲页不少。

Slab 与对象缓存

内核频繁分配 inode、dentry、task 等固定类型对象。Slab/SLUB 缓存从页分配器取得块并切成对象，保留构造状态、对齐和 per-CPU fast path，减少通用分配与锁成本。

缓存也会保留空闲对象而增加内存占用；调试选项可加入 red zone、poisoning 和 quarantine，以成本换取越界或 use-after-free 检测。

大页、NUMA 与现代内存系统

Huge page 减少页表项并提高 TLB reach，适合大而连续的热点映射；代价是内部碎片、fault/COW 粒度和连续页框需求。Transparent Huge Pages 可自动 promotion/split，但 compaction 可能带来延迟尖峰。

NUMA 中 first touch 常决定物理页节点。线程迁移而页面不迁移会增加远程访问；迁移页面本身也消耗带宽。正确调优要联合 CPU affinity、线程工作集与页面放置，而不是只把线程固定在一个核。

在 Linux 中观察内存行为

单个指标不足以诊断。/proc/<pid>/smaps 区分匿名、文件、共享、dirty 与 huge page；/proc/meminfo 和 vmstat 查看系统状态；PSI 显示任务因内存压力停顿的时间；numastat 查看放置；perf 可观察 fault、TLB 和 cache 事件。

pid=${1:-$$}

# 进程总量：PSS 按比例分摊共享页，RSS 则对每个映射完整计数。
grep -E '^(Rss|Pss|Private_|Shared_|Anonymous|AnonHugePages|Swap):' \
  "/proc/$pid/smaps_rollup"

# 查看系统内存构成与提交量。
grep -E '^(MemTotal|MemAvailable|Cached|AnonPages|Slab|PageTables|SwapTotal|SwapFree|CommitLimit|Committed_AS):' \
  /proc/meminfo

# 压力指标报告因争用损失的时间，而不只是容量消耗。
cat /proc/pressure/memory

# 时间序列：运行队列、空闲内存、分页、块 I/O 与 CPU 活动。
vmstat 1 5

# 在已安装 numactl 工具的 NUMA 系统上可选运行。
command -v numastat >/dev/null && numastat -p "$pid"

一次有用的解释应连接时间：应用延迟上升前，RSS/working set 是否增长？随后是否出现 direct reclaim、major fault、swap I/O 或 PSI？NUMA remote 是否同时增加？只截取 OOM 之后的 free 很难还原因果。

观察：RSS 与活跃匿名内存上升。
观察：随后 pgscan/pgsteal 与换入/换出增加。
观察：memory full PSI 与请求延迟同时上升。
假设：工作负载的活跃匿名集合超过其内存预算。
检验：降低并发度或提高受控 cgroup 预算，然后重复实验。

对比与总结

机制 延迟了什么工作 优势 主要风险
Lazy allocation 物理页分配与清零 未使用保留几乎不耗 RAM 首次访问延迟、承诺不确定
COW fork 后私有复制 exec-heavy 创建高效 写 fault、复制与复杂生命周期
Page cache/mmap 文件读入与共享 I/O 与映射复用缓存页 持久化语义、截断与回写
Replacement 为冷页保留 RAM 活跃工作集利用有限内存 错误 victim 导致 thrashing
Swap 匿名页驻留 缓冲短期压力 高时延与 I/O 放大
Buddy 连续页框块 分裂/合并快速 高阶碎片与向上取整
Slab 内核对象构造 类型化缓存和 per-CPU 快路 缓存保留与调试复杂度
Huge page 翻译项数量 更大 TLB reach 粒度、compaction 与碎片

按需分页的本质是把“映射契约”和“当前物理实现”分离。Fault handler 必须在并发变化中重建合法实现；reclaim 必须在局部性、回写成本和隔离之间选择；OOM 则是在所有正常策略失败后的作用域恢复。理解这些路径，才能把 RSS、fault、swap 与真实性能联系起来。
