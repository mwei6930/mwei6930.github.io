Text Representation

Discrete Representation(Frequency Based)

Discrete representations are one of the earliest approaches for representing text in NLP. They treat each word as a unique symbol and represent it using a vector based on its position in the vocabulary. These methods usually generate high-dimensional sparse vectors, meaning most values in the vector are zero. Although they are simple and interpretable, they cannot capture semantic similarities between words.

One-Hot Encoding

One-Hot Encoding is one of the simplest ways to represent words numerically in Natural Language Processing. The basic idea is to assign each word in the vocabulary a unique index, and represent the word as a vector where:

  • one position is 1
  • all other positions are 0

If the vocabulary size is \(V\), each word is represented by a \(V\)-dimensional vector.

Limitation:

  • High-dimensional vectors, Computationally expensive, infficient and Memory-intensive
  • Does not capture Semantic Relationships/Similarity
  • Restricted to the seen training vocabulary
Python Implementation 
def one_hot_encode(text):
    words = text.split() # Split the text by whitespace
    vocabulary = set(words) # Keep the elements unique in the set
    word_to_index = {word: i for i, word in enumerate(vocabulary)} # Assign index for each word in vocabulary, output will be like {word0 : 0, word1: 1, ...}
    one_hot_encoded = []
    for word in words: # For every word, create the vector with 0 and lenght of vocabulary firstly, then set the corresponding position to 1 according to the word index
        one_hot_vector = [0] * len(vocabulary) 
        one_hot_vector[word_to_index[word]] = 1
        one_hot_encoded.append(one_hot_vector)
    return one_hot_encoded, word_to_index, vocabulary

Bag of Words (BoW)

Bag of Words is a simple and widely used method for representing text as numerical vectors. The core idea is to represent a document based on the frequency of words that appear in it, without considering the order of the words.

In the Bag of Words model, a vocabulary is first constructed from all unique words in the corpus. Each document is then represented as a vector whose length equals the size of the vocabulary. Each element in the vector indicates how many times a particular word appears in the document.

Limitations:

  • It ignores word order and grammar
  • It cannot capture semantic relationships between words
  • It will be very hign-dimensinal when the vocabulary is large
Python Implementation 
"""
Document
   ↓
Tokenization
   ↓
Count word frequency
   ↓
Map to vocabulary index
   ↓
Vector representation
"""
import numpy as np

# vocabulary (normally built from a corpus)
vocab = ["cat", "dog", "fish"]

# word -> index
word_to_index = {word: i for i, word in enumerate(vocab)}

def bow_encode(document):
    vector = np.zeros(len(vocab))
    
    words = document.split()
    
    for word in words:
        if word in word_to_index:
            vector[word_to_index[word]] += 1
    
    return vector

doc = "cat dog cat"

print(bow_encode(doc))

TF-IDF

\(\text{TF-IDF: } w_{t,d} = tf_{t,d} \times idf_{t}\)

TF-IDF (Term Frequency–Inverse Document Frequency) is a weighted text representation method based on Bag of Words. It measures not only how often a word appears in a document, but also how important that word is across the whole corpus.

The basic idea is that a word should receive a high weight if it appears frequently in the current document but rarely in other documents. This makes TF-IDF more informative than simple word counts, because common words across many documents are given lower importance. TF-IDF is widely used in text classification, information retrieval, keyword extraction, and document similarity tasks. However, like other discrete representations, it still produces sparse vectors and cannot capture semantic or contextual relationships between words.

Term Frequency:

  • \(\text{Raw TF: } TF(t,d) = \text{count}(t,d)\)

  • \(\text{Normal TF: } TF(t,d) = \frac{\text{Number of times term t appears in document d}}{\text{Total number of terms in documnet d}}\)

  • \(\text{Log TF: } tf_{t,d} = \begin{cases} 1 + \log_{10}(\text{count}(t,d)) & \text{if } \text{count}(t,d) > 0 \\ 0 & \text{otherwise} \end{cases}\)

  • \(\text{Binary TF: } TF(t,d) = \begin{cases} 1 & t \in d \\ 0 & \text{otherwise} \end{cases}\)

  • \(\text{Augmented TF: }TF(t,d) = 0.5 + 0.5 \frac{\text{count}(t,d)} {\max_{t'} \text{count}(t',d)}\)

Inverse Document Frequency(N = number of documents, df(t) = how many documents token t occurs in):

  • \(\text{Raw IDF: } IDF(t,D) = \log \frac{\text{Total number of documents in corpus N}}{\text{Number of documnents containing term t}}\) \(idf(t) = \log\left(\frac{N}{df_t} \right)\)
  • \(\text{Smoothed IDF: } idf(t) = \log \left(\frac{N}{1+df_t} \right) + 1\)
  • \(\text{Probabilistic IDF: }idf(t) = \log\left(\frac{N - df_t}{df_t} \right)\)
  • \(\text{Max IDF: }\log\left(\frac{\max_{t' \in D} d_{t'}}{1 + d_t}\right)\)

Example

Suppose we have the following corpus:

  • D1: data science is fun
  • D2: data science uses data
  • D3: machine learning is fun

We want to compute the Log TF-IDF of the term \(data\) in document \(D2\).

The log-scaled term frequency is defined as:

\[ tf(t,d) = \begin{cases} 1 + \log_{10}(count(t,d)) & \text{if } count(t,d) > 0 \\ 0 & \text{otherwise} \end{cases} \]

Since \(count(data, D2) = 2\),

\[ tf(data, D2) = 1 + \log_{10}(2) \approx 1.301 \]

The inverse document frequency is:

\[ idf(t) = \log_{10}\left(\frac{N}{df_t}\right) \]

Here, \(N = 3\) and \(df_{data} = 2\), so:

\[ idf(data) = \log_{10}\left(\frac{3}{2}\right) \approx 0.176 \]

Therefore, the TF-IDF value is:

\[ tfidf(data, D2) = tf(data, D2) \times idf(data) \]

\[ tfidf(data, D2) = 1.301 \times 0.176 \approx 0.229 \]

Python Implementation 
import math
from collections import Counter

def compute_tfidf(documents):
    """
    Compute TF-IDF vectors for a list of documents.
    
    Parameters:
        documents (list[str]): A list of input documents.
        
    Returns:
        tfidf_vectors (list[dict]): TF-IDF vector for each document.
        vocabulary (list[str]): Sorted list of all unique terms.
        idf (dict): IDF value for each term.
    """
    
    # Step 1: Tokenize documents
    tokenized_docs = [doc.lower().split() for doc in documents]
    
    # Step 2: Build vocabulary
    vocabulary = sorted(set(word for doc in tokenized_docs for word in doc))
    
    # Step 3: Compute document frequency (df)
    N = len(documents)
    df = {}
    for term in vocabulary:
        df[term] = sum(1 for doc in tokenized_docs if term in doc)
    
    # Step 4: Compute IDF
    idf = {}
    for term in vocabulary:
        idf[term] = math.log10(N / df[term])
    
    # Step 5: Compute TF-IDF for each document
    tfidf_vectors = []
    
    for doc in tokenized_docs:
        term_counts = Counter(doc)
        tfidf = {}
        
        for term in vocabulary:
            count = term_counts.get(term, 0)
            
            # Log-scaled TF
            if count > 0:
                tf = 1 + math.log10(count)
            else:
                tf = 0
            
            tfidf[term] = tf * idf[term]
        
        tfidf_vectors.append(tfidf)
        
    return tfidf_vectors, vocabulary, idf


# Example usage
documents = [
    "data science is fun",
    "data science uses data",
    "machine learning is fun"
]

tfidf_vectors, vocabulary, idf = compute_tfidf(documents)

print("Vocabulary:")
print(vocabulary)

print("\nIDF values:")
for term, value in idf.items():
    print(f"{term}: {value:.3f}")

print("\nTF-IDF vectors:")
for i, vec in enumerate(tfidf_vectors, start=1):
    print(f"\nDocument D{i}:")
    for term in vocabulary:
        print(f"{term}: {vec[term]:.3f}")

    for word, tfidf_value in values.items():
        print(f"{word}: {tfidf_value}")
    print("\n")

BM-25(Okapi Best Matching 25)

BM25 (Best Matching 25) is a ranking function used in information retrieval to estimate the relevance of documents to a search query. It scores documents based on term frequency, term rarity, and document length normalization. It is widely considered the state-of-the-art evolution of TF-IDF. The core idea of BM25 is to estimate document relevance through term matching while improving upon TF-IDF with more realistic assumptions:

  • TF Saturation(Term Frequency Effect): Terms appearing more frequently in a document are more important, but their contribution saturates to avoid overemphasis. Unlike TF-IDF, BM25 applies a saturation function to term frequency. This means that as a term appears more frequently in a document, its contribution to the overall score increases at a diminishing rate. For example, increasing frequency from 1 to 2 significantly boosts relevance, but increasing from 10 to 11 has only a minor effect. This prevents documents from gaining unfair advantage by simply repeating the same terms excessively.
  • IDF(Term Importance): Rare terms are more informative and contribute more to relevance. IDF measures the importance of a term across the entire document collection. If a term appears in many documents (e.g., “the”, “is”), it has low discriminative power and thus a low IDF value. In contrast, rare terms (e.g., “transformer”, “BM25”) have higher IDF values because they carry more informative content. Therefore, IDF emphasizes terms that are more useful for distinguishing relevant documents.
  • Length Normalization: Longer documents are penalized to prevent bias toward documents that match terms by chance. BM25 introduces document length normalization to address the bias toward longer documents. Since longer documents are more likely to contain query terms by chance, BM25 penalizes them using the factor \(\frac{|D|}{\text{avgdl}}\). This ensures that shorter documents that match the query precisely are not unfairly disadvantaged, resulting in a more balanced and fair ranking.
  • Parameters \(k_1\) and \(b\) (Control Mechanism): BM25 uses two key hyperparameters: \(k_1\) and \(b\). The parameter \(k_1\) controls the influence of term frequency—larger values make TF more impactful and reduce the saturation effect, while smaller values lead to faster saturation. The parameter \(b\) controls the strength of document length normalization: \(b = 0\) means no length normalization, while \(b = 1\) applies full normalization. In practice, \(k_1\) is typically set between 1.2 and 2.0, and \(b\) is commonly set to 0.75. Together, these parameters balance the influence of term frequency and document length.

Pros: - Term Frequency Saturation: It recognizes that the importance of a word doesn’t increase linearly with its frequency. - Document Length Normalization: It penalizes overly long documents to ensure fairness across different content lengths.

Cons: - Lexical Only: It relies on exact word matches and doesn’t understand semantics or synonyms. - Parameter Tuning: Performance depends on tuning variables (\(k_1\) and \(b\)) which can vary by dataset.

BM25 = IDF × TF_saturation × Length_normalization

\(\text{BM25}(D, Q) = \sum_{i=1}^{n}\text{IDF}(q_i)\cdot\frac{f(q_i, D)\cdot (k_1 + 1)}{f(q_i, D) + k_1 \cdot \left(1 - b + b \cdot \frac{|D|}{\text{avgdl}}\right)}\)

\(\text{BM25}(D, Q) = \sum_{i=1}^{n} \log\left(\frac{N - n_i + 0.5}{n_i + 0.5}\right) \cdot \frac{f(q_i, D)\cdot (k_1 + 1)} {f(q_i, D) + k_1 \cdot \left(1 - b + b \cdot \frac{|D|}{\text{avgdl}}\right)}\)

  • \(D\): Document.
  • \(Q\): Query.
  • \(q_i\): The \(i\)-th query term in \(Q\).
  • \(n\): The number of query terms in \(Q\).
  • \(\text{IDF}(q_i)\): The inverse document frequency of query term \(q_i\).
  • \(N\): The total number of documents in the collection.
  • \(n_i\): The number of documents that contain query term \(q_i\).
  • \(|D|\): The length of document \(D\).
  • \(\text{avgdl}\): The average document length in the collection.
  • \(k_1\): A hyperparameter controlling term frequency saturation. A common value is around \(1.2\) to \(2.0\).
  • \(b\): A hyperparameter controlling document length normalization. A common value is \(0.75\).

Python Implementation 
import math
from collections import Counter, defaultdict


class BM25:
    def __init__(self, corpus, k1=1.5, b=0.75):
        """
        corpus: list[list[str]]
        Example:
        [
            ["this", "is", "a", "document"],
            ["this", "document", "is", "about", "nlp"]
        ]
        """
        self.corpus = corpus
        self.k1 = k1
        self.b = b
        self.N = len(corpus)
        self.doc_len = [len(doc) for doc in corpus]
        self.avgdl = sum(self.doc_len) / self.N

        self.doc_freq = defaultdict(int)
        self.term_freqs = []

        for doc in corpus:
            tf = Counter(doc)
            self.term_freqs.append(tf)

            for term in tf:
                self.doc_freq[term] += 1

    def idf(self, term):
        n_i = self.doc_freq.get(term, 0)

        return math.log((self.N - n_i + 0.5) / (n_i + 0.5) + 1)

    def score(self, query, doc_index):
        score = 0.0
        doc_tf = self.term_freqs[doc_index]
        doc_len = self.doc_len[doc_index]

        for term in query:
            f = doc_tf.get(term, 0)
            if f == 0:
                continue

            numerator = f * (self.k1 + 1)
            denominator = f + self.k1 * (
                1 - self.b + self.b * doc_len / self.avgdl
            )

            score += self.idf(term) * numerator / denominator

        return score

    def rank(self, query):
        scores = []

        for i in range(self.N):
            scores.append((i, self.score(query, i)))

        return sorted(scores, key=lambda x: x[1], reverse=True)

corpus = [
    "machine learning is useful",
    "deep learning is a part of machine learning",
    "natural language processing uses machine learning",
    "cooking recipes and food"
]

tokenized_corpus = [doc.lower().split() for doc in corpus]

bm25 = BM25(tokenized_corpus)

query = "machine learning"
tokenized_query = query.lower().split()

results = bm25.rank(tokenized_query)

for doc_id, score in results:
    print(score, corpus[doc_id])

Vector Similarity

After converting text into vector representations (such as BoW or TF-IDF), we often need to measure how similar two documents are. This is done by computing the similarity between their vector representations. Two common methods for measuring vector similarity are Dot Product and Cosine Similarity.

Dot Product

The dot product measures the similarity between two vectors by multiplying corresponding elements and summing the results.

For two vectors:

\[ \mathbf{A} = (a_1, a_2, ..., a_n) \]

\[ \mathbf{B} = (b_1, b_2, ..., b_n) \]

the dot product is defined as:

\[ A \cdot B = \sum_{i=1}^{n} a_i b_i \]

If two document vectors share many words with large values, the dot product will be larger. However, the dot product is affected by the length of the vectors.
Longer documents often produce larger values even if the documents are not very similar.

Cosine Similarity

Cosine similarity is one of the most widely used similarity measures in NLP. Instead of comparing raw vector values, it measures the angle between two vectors. The cosine similarity between two vectors is defined as:

\[ \cos(\theta) = \frac{A \cdot B}{||A|| \, ||B||} \]

where:

  • A.B is the dot product of the vectors
  • ||A|| and ||B|| are the magnitudes (lengths) of the vectors

The value of cosine similarity ranges from:

  • 1 → vectors are identical
  • 0 → vectors are orthogonal (no similarity)
  • -1 → vectors are opposite

Because cosine similarity normalizes vector length, it works well for comparing documents of different sizes. For this reason, it is widely used in information retrieval, document clustering, and text similarity tasks.

Python Similarity Implementation 
import numpy as np
from sklearn.metrics.pairwise import cosine_similarity

# Example TF-IDF-like document vectors
A = np.array([1, 2, 0, 1])
B = np.array([0, 1, 1, 1])

# Dot product
dot_product = np.dot(A, B)
print("Dot product:", dot_product)

# Cosine similarity from scratch
cosine = np.dot(A, B) / (np.linalg.norm(A) * np.linalg.norm(B))
print("Cosine similarity:", cosine)

# Cosine similarity using scikit-learn
cosine_sklearn = cosine_similarity([A], [B])[0][0]
print("Cosine similarity (sklearn):", cosine_sklearn)

Distributed Representation (Word Embedding / Prediction Based)

Discrete representations such as One-Hot, BoW, TF-IDF, and BM25 represent words mainly by symbol identity or frequency statistics. They are useful and interpretable, but they usually produce sparse vectors and cannot directly capture semantic similarity. For example, in a one-hot space, the words cat, dog, and car are all equally different from each other, even though cat and dog are semantically closer.

Distributed representations solve this problem by representing each word as a dense low-dimensional vector. Instead of using one dimension per word, each word is represented by a point in a continuous vector space.

The key assumption is the distributional hypothesis:

Words that occur in similar contexts tend to have similar meanings.

For example, if doctor and nurse often appear near words such as hospital, patient, and medicine, their vectors should be close in the embedding space.

Compared with discrete representations, distributed representations are usually:

  • Dense: most vector values are non-zero.
  • Low-dimensional: common sizes are 50, 100, 300, 768, etc.
  • Semantic: similar words tend to have similar vectors.
  • Reusable: pretrained embeddings can be transferred to downstream NLP tasks.

However, traditional word embeddings are usually static: each word has one fixed vector regardless of context. For example, bank has the same vector in river bank and bank account, which motivates contextual embeddings such as ELMo, BERT, and GPT.

One-Hot Sparse No No Basic encoding
BoW / TF-IDF Sparse Weak No Classification, retrieval
Word2Vec / GloVe / FastText Dense Yes No Word similarity, feature initialization
ELMo / BERT / GPT Dense Yes Yes Modern NLP systems

Word2Vec

Word2Vec is a neural word embedding method that learns dense word vectors from large text corpora. It does not require manually labeled data. Instead, it creates a self-supervised learning problem from raw text.

The central idea is:

  • A word can be understood by the words around it.
  • If two words appear in similar contexts, their embeddings should become similar.

Word2Vec has two main architectures:

  • CBOW: predict the center word from surrounding context words.
  • Skip-gram: predict surrounding context words from the center word.

Suppose we have the sentence:

I love natural language processing

If the center word is natural and the window size is 2, then:

context = [I, love, language, processing]
center  = natural

Word2Vec learns embeddings by adjusting vectors so that real word-context pairs receive higher scores than unrelated pairs.

A common scoring function is the dot product:

\[ score(w, c) = v_w \cdot v_c \]

where:

  • \(v_w\) is the vector of the target word.
  • \(v_c\) is the vector of a context word.
  • A larger dot product means the word and context are more compatible.
CBOW

CBOW stands for Continuous Bag of Words. It predicts the center word using surrounding context words.

The learning task is:

\[ P(w_t \mid w_{t-m}, ..., w_{t-1}, w_{t+1}, ..., w_{t+m}) \]

where:

  • \(w_t\) is the target center word.
  • \(m\) is the context window size.
  • The surrounding words are used as input.

Example:

Sentence: I love natural language processing
Input context: I, love, language, processing
Target word: natural

CBOW usually averages or sums the context word vectors and uses them to predict the missing center word.

Characteristics:

  • Faster to train than Skip-gram.
  • Works well for frequent words.
  • Less sensitive to rare words because context vectors are averaged.
  • Often used when training efficiency is important.
Skip-gram

Skip-gram does the opposite of CBOW. It predicts surrounding context words from the center word.

The learning task is:

\[ P(w_{t-m}, ..., w_{t-1}, w_{t+1}, ..., w_{t+m} \mid w_t) \]

Example:

Sentence: I love natural language processing
Input word: natural
Target context: I, love, language, processing

Instead of using context to predict a word, Skip-gram uses one word to predict multiple context words.

Characteristics:

  • Slower than CBOW because it creates more training pairs.
  • Often better for rare words.
  • Learns more fine-grained semantic relationships.
  • Commonly preferred when embedding quality matters more than speed.
Negative Sampling

A naive Word2Vec model would need to compute probabilities over the whole vocabulary, which is expensive when the vocabulary is large. Negative sampling makes training more efficient.

Instead of asking:

Which word among all vocabulary words is the correct context word?

Negative sampling asks:

Is this word-context pair real or fake?

For a real pair such as:

(natural, language)

we sample several fake pairs, such as:

(natural, banana)
(natural, table)
(natural, window)

The model learns to assign high scores to real pairs and low scores to fake pairs.

The objective can be written as:

\[ \log \sigma(v_w \cdot v_c) + \sum_{i=1}^{k} \log \sigma(-v_w \cdot v_{n_i}) \]

where:

  • \((w,c)\) is a real word-context pair.
  • \(n_i\) are negative samples.
  • \(k\) is the number of negative samples.
  • \(\sigma\) is the sigmoid function.

GloVe

GloVe stands for Global Vectors for Word Representation. Unlike Word2Vec, which learns from local prediction tasks, GloVe learns embeddings from global word co-occurrence statistics.

The idea is that word meaning can be captured by how often words co-occur with other words across the entire corpus.

First, GloVe builds a co-occurrence matrix \(X\), where:

\[ X_{ij} = \text{number of times word } j \text{ appears in the context of word } i \]

Then it learns word vectors so that their dot product approximates the logarithm of their co-occurrence count:

\[ w_i^T \tilde{w}_j + b_i + \tilde{b}_j \approx \log(X_{ij}) \]

where:

  • \(w_i\) is the vector of the target word.
  • \(\tilde{w}_j\) is the vector of the context word.
  • \(b_i\) and \(\tilde{b}_j\) are bias terms.
  • \(X_{ij}\) is the co-occurrence count.

Why log?

Raw co-occurrence counts can be very large and highly skewed. Taking the logarithm reduces the effect of extremely frequent pairs.

Characteristics:

  • Uses global corpus statistics.
  • Often performs well on word analogy tasks.
  • Produces static word embeddings.
  • Requires building a co-occurrence matrix, which can be memory intensive for large vocabularies.

Example analogy:

\[ vector(king) - vector(man) + vector(woman) \approx vector(queen) \]

Python GloVe-style Co-occurrence Example 
from collections import defaultdict
import numpy as np

sentences = [
    ["natural", "language", "processing", "is", "fun"],
    ["machine", "learning", "is", "useful"],
    ["language", "models", "learn", "representations"]
]

window_size = 2
cooccurrence = defaultdict(float)

for sentence in sentences:
    for i, word in enumerate(sentence):
        start = max(0, i - window_size)
        end = min(len(sentence), i + window_size + 1)
        for j in range(start, end):
            if i == j:
                continue
            context_word = sentence[j]
            distance = abs(i - j)
            cooccurrence[(word, context_word)] += 1.0 / distance

for pair, count in cooccurrence.items():
    print(pair, count)

# In the real GloVe algorithm, these co-occurrence counts are used
# to learn dense vectors whose dot products approximate log counts.

    positive=["woman", "king"],
    negative=["man"],
    topn=1
)
print(result)

FastText

FastText is an extension of Word2Vec developed by Facebook AI Research. Its key idea is to represent a word as a collection of character n-grams rather than treating each word as a single atomic unit.

For example, with character 3-grams, the word where may be represented as:

<wh, whe, her, ere, re>

The word vector is formed by combining the vectors of its subword units.

This is useful because words with similar morphology can share information. For example:

run, runs, running, runner

These words share subword patterns, so FastText can learn related representations.

Advantages:

  • Handles rare words better than Word2Vec.
  • Can produce vectors for out-of-vocabulary words if their character n-grams are known.
  • Useful for morphologically rich languages.
  • Captures prefixes, suffixes, and word shapes.

Limitations:

  • Still produces static embeddings.
  • Subword similarity does not always imply semantic similarity.
  • Slightly more complex than Word2Vec.
Method Main Signal Handles OOV? Static or Contextual
Word2Vec Local prediction No Static
GloVe Global co-occurrence No Static
FastText Subword + prediction Better Static
Python FastText Implementation with gensim 
from gensim.models import FastText

sentences = [
    ["run", "runs", "running", "runner"],
    ["natural", "language", "processing"],
    ["machine", "learning", "models"]
]

model = FastText(
    sentences=sentences,
    vector_size=50,
    window=3,
    min_count=1,
    workers=1,
    sg=1
)

print(model.wv["running"])
print(model.wv.most_similar("run"))

# FastText can infer a vector for a word that was not directly seen,
# as long as its character n-grams are informative.
print(model.wv["runners"])

Word Embedding Evaluation

Word embeddings can be evaluated in two main ways: intrinsic evaluation and extrinsic evaluation.

Intrinsic Evaluation

Intrinsic evaluation directly tests the quality of embeddings without using a full downstream NLP system.

Common intrinsic tasks include:

  • Word similarity: check whether embedding similarity agrees with human similarity judgments.
  • Word analogy: solve analogy questions such as king - man + woman = queen.
  • Nearest neighbors: inspect the most similar words for a given word.
  • Clustering: check whether semantically related words group together.

Cosine similarity is commonly used:

\[ \text{sim}(w_1, w_2) = \frac{v_{w_1} \cdot v_{w_2}}{||v_{w_1}|| ||v_{w_2}||} \]

Example:

similarity(cat, dog) > similarity(cat, table)
Extrinsic Evaluation

Extrinsic evaluation measures whether embeddings improve performance on a downstream NLP task, such as:

  • Sentiment analysis
  • Named entity recognition
  • Machine translation
  • Text classification
  • Question answering

This is usually more meaningful than intrinsic evaluation, because a good embedding should help real tasks. However, it is also more expensive because it requires training and evaluating a full model.

Common Problems in Word Embeddings
  • Polysemy: one word may have multiple meanings, but static embeddings assign only one vector.
  • Bias: embeddings may learn social or cultural biases from the training corpus.
  • Domain mismatch: embeddings trained on news may not work well for medical or legal text.
  • OOV words: unknown words may not have embeddings, especially for Word2Vec and GloVe.
Python Word Similarity and Analogy Evaluation 
import gensim.downloader as api

# Requires internet access the first time it downloads the model.

# Word similarity

    ("cat", "table"),
    ("king", "queen")
]

    print(w1, w2, model.similarity(w1, w2))

# Word analogy: king - man + woman ? queen

    model.most_similar(

        negative=["man"],

Contextual Embedding

Traditional word embeddings such as Word2Vec, GloVe, and FastText are static embeddings. Each word has one fixed vector.

For example, the word bank has the same embedding in both sentences:

I deposited money in the bank.
The boat stopped near the river bank.

However, the meaning of bank is different in these two contexts. Contextual embeddings solve this problem by generating word representations based on the surrounding words.

The core idea is:

\[ \text{embedding}(word) = f(word, context) \]

So the same word can have different vectors in different sentences.

Model Architecture Direction Representation Type
ELMo BiLSTM Bidirectional Contextual word embedding
BERT Transformer Encoder Bidirectional Contextual token embedding
GPT Transformer Decoder Left-to-right Contextual token embedding / generation

ELMo (Based on LSTM)

ELMo stands for Embeddings from Language Models. It produces contextual word embeddings using a deep bidirectional LSTM language model.

ELMo uses two language models:

  • A forward language model that reads text from left to right.
  • A backward language model that reads text from right to left.

This allows each word representation to depend on both previous and following words.

For a word \(w_t\), ELMo uses information from:

\[ w_1, ..., w_{t-1}, w_t, w_{t+1}, ..., w_n \]

Why ELMo matters:

  • It was an important step from static embeddings to contextual embeddings.
  • It can represent different meanings of the same word in different contexts.
  • It improves many sequence labeling and classification tasks.

Limitations:

  • Based on LSTMs, so it is harder to parallelize than Transformers.
  • Usually used as a feature extractor rather than a fully fine-tuned model.
  • Has been largely replaced by Transformer-based models such as BERT.
Python ELMo-style Contextual Embedding Example 
# ELMo is commonly accessed through libraries such as AllenNLP.
# Installation can be heavy, so this is a reference example.

from allennlp.commands.elmo import ElmoEmbedder

elmo = ElmoEmbedder()

sentences = [
    ["I", "deposited", "money", "in", "the", "bank", "."],
    ["The", "boat", "stopped", "near", "the", "river", "bank", "."]
]

for sentence in sentences:
    embeddings = elmo.embed_sentence(sentence)
    # Shape: (3 layers, sentence_length, embedding_dim)
    print(sentence)
    print(embeddings.shape)

BERT (Based on Transformer)

BERT stands for Bidirectional Encoder Representations from Transformers. It uses the Transformer encoder architecture to learn deep bidirectional contextual representations.

Unlike a left-to-right language model, BERT can attend to words on both sides of a token at the same time.

Example:

The [MASK] sat on the mat.

BERT learns to predict the masked word using both left and right context.

BERT is pretrained mainly using Masked Language Modeling (MLM):

  • Randomly mask some tokens in a sentence.
  • Use the surrounding context to predict the masked tokens.

For example:

Input:  Natural language [MASK] is useful.
Target: processing

BERT representations are widely used for:

  • Text classification
  • Named entity recognition
  • Question answering
  • Semantic textual similarity
  • Natural language inference

Characteristics:

  • Strong at understanding tasks.
  • Bidirectional context.
  • Usually fine-tuned for downstream tasks.
  • Not naturally designed for left-to-right text generation.
Python BERT Embedding Example with transformers 
import torch
from transformers import AutoTokenizer, AutoModel

model_name = "bert-base-uncased"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModel.from_pretrained(model_name)

sentences = [
    "I deposited money in the bank.",
    "The boat stopped near the river bank."
]

inputs = tokenizer(sentences, padding=True, return_tensors="pt")

with torch.no_grad():
    outputs = model(**inputs)

# last_hidden_state shape: (batch_size, sequence_length, hidden_size)
token_embeddings = outputs.last_hidden_state

# A simple sentence embedding can be made by averaging token embeddings.
attention_mask = inputs["attention_mask"].unsqueeze(-1)
sentence_embeddings = (token_embeddings * attention_mask).sum(dim=1) / attention_mask.sum(dim=1)

print(sentence_embeddings.shape)
Python Masked Word Prediction with BERT 
from transformers import pipeline

fill_mask = pipeline("fill-mask", model="bert-base-uncased")

results = fill_mask("Natural language [MASK] is useful.")

for item in results[:5]:
    print(item["token_str"], item["score"])

GPT

GPT stands for Generative Pre-trained Transformer. It uses a Transformer decoder architecture and is trained as an autoregressive language model.

The learning objective is to predict the next token:

\[ P(w_t \mid w_1, w_2, ..., w_{t-1}) \]

For example:

Input:  Natural language processing is
Target: useful

GPT reads text from left to right and generates one token at a time. This makes it especially suitable for generation tasks.

Common GPT-style applications include:

  • Text generation
  • Summarization
  • Dialogue systems
  • Code generation
  • Instruction following
  • Question answering

BERT vs GPT:

Aspect BERT GPT
Architecture Transformer Encoder Transformer Decoder
Direction Bidirectional Left-to-right
Main Objective Masked token prediction Next-token prediction
Strength Understanding Generation
Typical Use Classification, NER, QA Generation, chat, completion

Python Next-token Prediction Sketch 
import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

model_name = "gpt2"
tokenizer = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(model_name)

text = "Natural language processing is"
inputs = tokenizer(text, return_tensors="pt")

with torch.no_grad():
    outputs = model(**inputs)

next_token_logits = outputs.logits[0, -1, :]
top_tokens = torch.topk(next_token_logits, k=5)

for token_id, score in zip(top_tokens.indices, top_tokens.values):
    print(tokenizer.decode(token_id), score.item())

Summary: Choosing a Text Representation

Goal Suitable Representation
Simple baseline classification BoW / TF-IDF
Search and ranking BM25
Word similarity or clustering Word2Vec / GloVe / FastText
Handling rare or morphologically complex words FastText
Context-sensitive understanding BERT / ELMo
Text generation GPT

In modern NLP systems, contextual embeddings are usually the default choice. However, classical methods such as TF-IDF and BM25 are still important because they are simple, fast, interpretable, and very strong baselines.
